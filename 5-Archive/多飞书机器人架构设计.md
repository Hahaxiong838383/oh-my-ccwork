# 多飞书机器人架构设计

**归档时间**: 2026-02-24

## 需求背景

用户希望 mycc 后端支持两个不同的飞书机器人，核心要求：
- **灵魂独立**: 每个机器人有不同的人设/性格
- **记忆独立**: 每个机器人的会话历史分开存储
- **知识库共用**: 共享 RAG 向量数据库

---

## 方案对比

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **方案一** | 环境变量双配置 (FEISHU_APP_ID_1/2) | 改动最小，无需改代码 | 配置耦合，无法独立控制 |
| **方案二** | Channel 数组 + 路由规则 | 配置解耦，灵活扩展 | 需修改 Channel 管理逻辑 |
| **方案三** | 多实例进程 + 端口分离 | 完全隔离，独立部署 | 资源占用翻倍，需进程管理 |

---

## 推荐架构

```
┌─────────────────────────────────────────────────────────┐
│                      请求入口                            │
│            (飞书机器人 A / 飞书机器人 B)                  │
└─────────────────┬───────────────────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────────────────────┐
│                    MyCC 后端                            │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐    │
│  │ Bot A 配置  │  │ Bot B 配置  │  │ 通用配置    │    │
│  │ - appId    │  │ - appId    │  │ - 知识库    │    │
│  │ - soul     │  │ - soul     │  │ - 模型配置  │    │
│  │ - memory   │  │ - memory   │  │             │    │
│  └─────────────┘  └─────────────┘  └─────────────┘    │
└─────────────────────────────────────────────────────────┘
```

### 数据分离策略

| 维度 | 方案 |
|------|------|
| **灵魂 (Soul)** | 独立配置文件 `souls/bot-a.md`, `souls/bot-b.md` |
| **记忆 (Memory)** | 独立 session 存储，按 `bot_id` 隔离 |
| **知识库 (RAG)** | 共用向量数据库，按 `namespace` 共享 |

### 配置目录结构

```
config/
├── bots/
│   ├── bot-a/
│   │   ├── feishu.json      # 飞书凭证
│   │   └── soul.md          # 机器人灵魂/人设
│   └── bot-b/
│       ├── feishu.json
│       └── soul.md
├── knowledge/
│   └── shared/              # 共享知识库
└── memory/                  # 记忆按 bot_id 目录隔离
    ├── bot-a/
    └── bot-b/
```
