# AESL 论文分析：轻量级 SFT 如何让 LLM 准备好接受强化学习

> 论文：*Getting Your LLMs Ready for Reinforcement Learning with Lightweight SFT*
> 发表：ICLR 2026 | 作者：Xinran Li 等
> 代码：https://github.com/LXXXXR/AESL
> OpenReview：https://openreview.net/forum?id=yezWGJmODg

---

## 一、论文核心方法

### 1.1 问题定义：SFT Cold Start 的隐性陷阱

传统 LLM 强化学习流水线是 `Base Model → SFT（冷启动）→ RL（RLHF/RLVR）`。论文揭示了一个关键发现：

**SFT 阶段表现最好的 checkpoint，往往不是 RL 阶段效果最好的起点。**

原因是 **distributional forgetting（分布遗忘）** —— 模型在 SFT 过程中过度拟合训练数据的分布模式，偏离了 base model 原有的多样性分布，即使在传统评测指标上还没出现过拟合。这个现象比传统过拟合更早发生，也更隐蔽。

打个比方：SFT 让模型「学会了一种正确的回答方式」，但代价是「忘了还有很多种正确的回答方式」。而 RL 恰恰需要模型保持探索能力，需要多样性。

### 1.2 核心发现：多样性比准确率更重要

论文通过实验证明：

- **传统做法**（基于 eval loss / accuracy 选 checkpoint）→ 选出的模型在 RL 后表现次优
- **AESL 做法**（基于 entropy / self-BLEU 等多样性指标选 checkpoint）→ RL 后效果显著更好
- 多样性峰值（peak diversity）出现在 SFT 过程的**较早阶段**，此后多样性单调下降

### 1.3 AESL 方法：Adaptive Early-Stop Loss

AESL（Adaptive Early-Stop Loss）是论文提出的核心方法，在两个粒度上操作：

#### Token 级别
对每个 token 的 loss 进行自适应调节。当某个 token 已经被模型学得很好（loss 很低），就降低它的 loss 权重，防止模型继续朝着过度确定的方向优化。反之，对还没学好的 token 保持正常 loss。

核心思想：**已经会的就别再练了，避免从「会」变成「只会这一种」**。

#### Subsequence 级别
在子序列（如推理步骤）层面做类似处理。对于模型已经掌握的推理子模式（subsequence），降低其训练权重，把训练资源留给模型还不熟悉的模式。

#### 关键超参数
- **Temperature（T=5.0）**：控制 loss 调节的激进程度。T 太小 → 学不到新模式；T 太大 → base 分布遗忘严重
- **训练数据量**：使用 RL 训练数据量的不到 1/10（轻量级）
- **训练周期**：10 epochs，但核心是通过多样性指标决定 early stop

### 1.4 与传统 SFT→RLHF 的关键区别

| 维度 | 传统做法 | AESL |
|------|---------|------|
| 选 checkpoint 标准 | eval loss / accuracy | entropy / self-BLEU（多样性） |
| SFT 目标 | 让模型输出尽可能接近标准答案 | 让模型学会新模式但保持分布多样性 |
| 数据量 | 大量 SFT 数据 | <1/10 的 RL 数据量（轻量级） |
| Loss 函数 | 标准 cross-entropy | 自适应加权 cross-entropy（token + subsequence） |
| 核心理念 | 模型「学好了」才能做 RL | 模型「刚好学到一点」时做 RL 最好 |

## 二、对 mycc 的具体借鉴

### 2.1 当前状态速览

| 组件 | 现状 |
|------|------|
| 基座模型 | Qwen3.5-27B（主力）+ 4B（intake） |
| 经验流 | experience-stream.ts，JSONL 格式，含 query/response/latency/categories/valence/arousal |
| 预测引擎 | prediction-engine.ts，纯规则驱动，hit/miss 验证 |
| 情感标注 | GAP4 valence/arousal 已实现，规则标注 |
| Eval 框架 | 38 条用例，Faithfulness 3.05（5 分制，未达标） |
| P5 SFT | 挂起中，等经验 >= 1000 条 |

### 2.2 核心借鉴：忠实度（Faithfulness）问题的新视角

mycc 当前最大的痛点是 **Faithfulness 3.05 未达标**。AESL 提供了一个全新视角：

**问题可能不在于 SFT 数据不够多，而在于 SFT 过程让模型丢失了基于检索内容回答的「忠实分布」。**

传统 SFT 如果在「模型自己编造看起来合理的答案」这种模式上过度训练，模型会越来越倾向于「创造性回答」而非「基于上下文的忠实回答」。AESL 的核心启示是：训练时要主动监控和保护模型原有的多样性分布，特别是「引用式」回答模式。

### 2.3 经验流数据格式调整建议

当前 `ExperienceEntry` 格式需要增加几个关键字段以适配 AESL 理念：

```typescript
interface ExperienceEntry {
  // ... 现有字段 ...

  // 新增：SFT 训练对标签
  groundTruthResponse?: string;   // 「忠实」的参考回答（从检索内容构建）
  faithfulnessScore?: number;     // [0, 5] 忠实度评分（eval 框架打分）

  // 新增：预测验证信号（来自 prediction-engine）
  predictionHit?: boolean;        // 该次请求是否命中了上一次预测
  predictionConfidence?: number;  // 上一次预测的置信度

  // 新增：多样性度量（训练时用）
  responseEntropy?: number;       // 回复的 token 熵值（越高越多样）
}
```

**关键设计决策**：不需要所有字段每次都填。`groundTruthResponse` 只在有高质量检索结果时构建，作为 SFT 的正样本。

### 2.4 Prediction hit/miss 作为 Reward Signal

这是 AESL 最直接的落地点。mycc 的 prediction-engine 已经有完整的 hit/miss 验证机制，可以直接作为 RL 的 reward signal：

| 信号 | 来源 | 用法 |
|------|------|------|
| prediction hit | prediction-engine.ts | reward = +1：模型正确预测了用户需求 |
| prediction miss（高置信度） | prediction-engine.ts | reward = -1：模型高置信度但预测错了 |
| prediction miss（低置信度） | prediction-engine.ts | reward = 0：不确定，不惩罚 |
| faithfulness 评分 | eval 框架 | reward ∝ score：忠实度越高 reward 越大 |

**具体实现路径**：在每条经验流记录中追加 reward 字段，巩固任务（P2 @04:00）负责回填 prediction 验证结果。

### 2.5 Valence/Arousal 作为 Preference Signal

GAP4 的情感标注可以转化为 RLHF 中的 preference signal：

- **valence > 0.5 且 arousal < 0.5**（正面、平静）→ 用户满意，response 作为正样本
- **valence < -0.3**（负面）→ 用户不满，response 作为负样本
- **arousal > 0.8**（高唤醒度）→ 情绪激动，需人工审查后再决定正负

构造 preference pair 的方式：
```
(preferred, rejected) = (高 valence 的 response, 低 valence 的相似 query response)
```

同一类别（injectedCategories 交集 > 50%）、不同满意度的 query-response 对自然形成 preference pair。

### 2.6 AESL 的多样性监控 → mycc 的 SFT 健康度指标

AESL 最重要的工程启示是**训练过程中要监控多样性指标**。对 mycc 的建议：

在 P5 SFT 训练脚本中，每个 epoch 后计算并记录：

1. **Response Entropy**：模型在 eval set 上生成回复的 token 级别熵。下降 >20% 时触发 early stop
2. **Self-BLEU**：在同类 query 上生成多个回复，计算 self-BLEU。上升 >15% 时触发 early stop
3. **Faithfulness on eval**：38 条用例的 Faithfulness 分数。如果 Faithfulness 提升但 entropy 明显下降，优先保护 entropy

## 三、P5 SFT 启动时机和方法建议

### 3.1 启动时机

不建议等到 1000 条就直接全量 SFT。AESL 的核心教训是**数据量不如数据质量 + 训练策略重要**。

**修订后的触发条件**：

| 条件 | 原计划 | 建议调整 |
|------|--------|---------|
| 经验条数 | >= 1000 | >= 500 条（有 faithfulness 标注的） |
| 数据质量 | 无要求 | faithfulness >= 4.0 的占比 > 30% |
| 覆盖度 | 无要求 | 至少覆盖 80% 的记忆命名空间 |
| 多样性基线 | 无要求 | 先测量 base model 的 entropy 基线 |

### 3.2 训练方法：三阶段递进

#### 阶段 1: Lightweight SFT（AESL 式冷启动）
- **目标**：让模型学会 brain 场景的基本模式（记忆检索 + 忠实回答）
- **数据量**：200-500 条高质量样本（faithfulness >= 4.0）
- **Loss**：采用 AESL loss（token-level adaptive weight + temperature 调控）
- **Early Stop 标准**：entropy 下降到基线的 80% 时停止（不是 eval loss 最低时）
- **硬件**：Studio M2 Max 足够，不需要多 GPU

#### 阶段 2: Reward Model Training（可选）
- 用 valence/arousal 构造 preference pairs
- 训练轻量 reward model（或直接用规则 reward）
- 样本量要求：至少 200 个有效 preference pairs

#### 阶段 3: RL（如果阶段 1 已经足够好则跳过）
- 用 prediction hit/miss + faithfulness score 作为 reward
- 使用 AESL 代码库的 RL 框架（基于 OpenRLHF）
- KL 系数设小（0.001），避免偏离 SFT checkpoint 太远

### 3.3 具体落地 Checklist

1. **[ ] 经验流格式升级**：在 `ExperienceEntry` 中增加 `groundTruthResponse`、`faithfulnessScore`、`predictionHit` 字段
2. **[ ] 多样性基线测量**：在当前 base model（Qwen3.5-27B）上跑 eval set，记录 entropy 和 self-BLEU 基线
3. **[ ] SFT 数据构造脚本**：从经验流 JSONL 中筛选 faithfulness >= 4.0 的样本，构造 `(query + context, faithful_response)` 格式
4. **[ ] Preference pair 构造**：从相似 query、不同 valence 的经验中配对
5. **[ ] 训练脚本适配**：基于 AESL 代码库，配置 `AESL_loss` + temperature=5.0 + 多样性监控
6. **[ ] Early Stop 监控**：每 epoch 记录 entropy / self-BLEU / faithfulness，三指标联合决策
7. **[ ] 巩固任务集成**：在 P2 @04:00 巩固任务中增加 prediction 验证回填 + reward 计算

## 四、风险与注意事项

1. **小模型（4B）更脆弱**：AESL 论文用的是 7B+ 模型。4B intake 模型的多样性空间本就有限，SFT 时 temperature 可能需要调高（T=7-10），且 early stop 要更激进
2. **brain 场景不是数学推理**：AESL 的实验在数学推理 benchmark 上做的，brain 的记忆检索 + 忠实回答场景可能需要调整 diversity 指标的权重
3. **数据量小的风险**：200-500 条做 SFT 效果高度依赖数据质量。建议先在 eval 框架的 38 条用例上做 sanity check
4. **reward hacking**：如果只用 prediction hit/miss 作为 reward，模型可能学会永远预测「build」（最高频 intent）。需要加入 diversity bonus

---

## 五、总结

AESL 对 mycc 最核心的启示是一句话：

**不要追求 SFT 阶段的「最好」，追求 SFT 阶段的「刚好」。**

mycc 的 Faithfulness 问题，可能不需要大量数据来「教会」模型忠实回答，而是需要用 AESL 的思路，在少量高质量数据上轻触一下，同时严格监控多样性指标，确保模型不丧失灵活性。prediction-engine 的 hit/miss 和 valence/arousal 情感数据是现成的 reward signal，无需额外标注成本。

建议 P5 SFT 启动条件从「经验 >= 1000」调整为「高质量标注经验 >= 500 + faithfulness 覆盖率 > 30%」，优先跑一个 AESL 式冷启动实验。
