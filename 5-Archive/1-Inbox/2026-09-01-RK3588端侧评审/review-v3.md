# 端侧多模态语音 Agent（RK3588）— 端云协同分支规划

> 承接 [`W1.md`](./W1.md)（端侧 VLM 部署横向对比与算子级诊断），把单一的「视觉理解」扩展为完整的「**看 · 听 · 想 · 说 · 记**」实时对话 Agent。
>
> 日期：2026-06-23　平台：Orange Pi 5 Plus（RK3588）　形态：**端云协同**（端侧感知 + 云端大脑）

---

## 0. 一句话

> **端侧负责感知与隐私边界（看 / 听 / 记），云端负责大脑（LLM）；原始音视频止于端侧，过网的只有文字。**

这条边界同时给出三件东西：隐私护城河（音视频不出端）、算力可行性（板子不扛大 LLM）、体验上限（大脑用云端强模型）。

---

## 1. 背景与定位

### 1.1 已完成（W1，实测）
- 端侧 VLM 跑通并横向对比：SmolVLM2-256M / InternVL3.5-1B/2B/4B / MiniCPM-V 2.6，吞吐与显存均与官方吻合。
- 自建 RKNN 逐层剖析，定位 4B 视觉慢一倍的根因为 `Erf` 算子 CPU 回退，给出 tanh-GELU 提速方案。
- 摸清工具链硬约束：`rkllm-runtime 1.2.3`；**NPU 不支持线性注意力**（Qwen3.5 / MiniCPM-V 4.6 转换卡死），选型须为「标准注意力 + NPU 友好算子」。

### 1.2 本分支要补的
W1 把端侧的「**看**」做到了算子级。本分支补齐「**听 · 想 · 说 · 记**」，让它成为一个能对话、能记住、隐私不外泄的端侧 Agent。

### 1.3 与配套云端语音 Agent 的关系
本项目不是从零另起，而是配套的通用实时语音 Agent 的**端侧体验引擎**。后者的核心设计是「**可插拔体验引擎 + 恒定记忆内核 + 中间一份稳定契约**」——

- 端侧只需把自己的事件（开口 / 转写 / 判停 / 打断）映射到那份**归一化契约**，即可复用云端大脑与可审计记忆内核，**记忆逻辑零重写**。
- 记忆内核为纯逻辑、零外部依赖，能直接运行在 RK3588 的 Python 上。**其实现保持私有**，本公开仓只放端侧适配层、部署与 demo。

## 2. 架构：端 / 云职责切分

```
         ┌──────────────────────── 端侧 RK3588（感知 + 隐私边界）────────────────────────┐
摄像头 ─► │ VLM（画面→文字描述，InternVL3.5-1B / SmolVLM2，NPU）                          │
麦克风 ─► │ 唤醒(KWS) → VAD → 流式 STT（音频→文字）→ 语义判停                              │
         │ 记忆 Working Set 召回（端侧投影镜像）                                          │
         │             │                                                                 │
         │   组装上下文 = [语音转写] + [画面描述] + [召回的记忆]  ── 只有文字过网 ──┐      │
         └──────────────────────────────────────────────────────────────────────┼──────┘
                                                                                  ▼
                                              ┌──────────── 云端（大脑）────────────┐
                                              │ LLM（热插主项目 Tier A cascade /     │
                                              │      Tier B 托管 Realtime）→ 回复文字 │
                                              └──────────────────┬───────────────────┘
                                                                 ▼
         ┌──────────────────────── 端侧 RK3588 ────────────────────────────────────────┐
         │ 回复文字 → 流式 TTS（中文，低 TTFA）→ 扬声器                                   │
         │ turn 提交 → 写记忆（仅此刻，打断则零成本回滚）                                 │
         └──────────────────────────────────────────────────────────────────────────────┘
```

**隐私边界**：摄像头画面与麦克风原始音频**只在端侧存在**，离开设备的仅为脱敏后的文字（转写 / 画面描述 / 记忆摘要）。这是相对纯云方案的核心差异化。

**算力账（端云协同的红利）**：端侧不再常驻大 LLM，只跑 VLM-1B（~1.9GB）+ STT + VAD + TTS。W1 中逼近板子上限的内存压力主要来自大模型推理；移走 LLM 后，端侧负载在 16GB 板上有充足余量（具体预算见 §5 未决项）。

**一致性**：端侧事件 → 归一化契约 → 记忆内核。写记忆只发生在「语义 EOU（turn committed）+ 抽取完成」，STT 中间结果永远是 DRAFT，被打断即零成本回滚——与云端主项目共用同一组不变量。

| **E-D0** | 最短链路出效果：「看图说话 + 语音」——复用已跑通 VLM，加 TTS 让它**开口说出看到了什么** | 板上一句话语音描述画面 |

## 5. 优劣势与风险（诚实）

### 优势
- **隐私护城河拉满**：原始音视频不出端，差异化明确。
- **算力可行**：端云协同把大 LLM 移到云端，端侧负载落回板子舒适区。
- **离线降级**：网络断时仍可保留唤醒 / VLM / 本地记忆（大脑降级或排队）。
- **复用主项目 IP**：记忆内核零改接入，验证「引擎可插拔、记忆恒定」的架构设计。

### 劣势 / 风险
- **延迟预期要重设**：主项目北极星是云端 ~1s；端侧 STT/判停在弱算力上更难压，端到端预算需重新实测建模（先打判停 + 云端 LLM TTFT，别埋头优化 STT/TTS）。
- **端侧中文 STT / TTS 质量** 与云端有差距，CER 与 TTFA 未实测。
- **工具链受限**：若未来要把 LLM 也下沉端侧，选型被 rkllm 锁死在标准注意力 + NPU 友好算子（W1 已踩 Erf / 线性注意力两坑）。
- **隐私边界并非绝对**：文字（转写 / 画面描述）仍过网，"不出端"指原始音视频，需在对外表述上严谨。

### 未决项（须实测 / 确认）
1. **板子内存配置**（8/16/32GB）——决定端侧能否多模型常驻、能否本地缓存大脑。
2. 端侧 STT（sherpa-onnx）在 RK3588 的流式延迟与中文 CER。
3. 中文 TTS 端侧 TTFA（候选：sherpa-onnx VITS / Piper）。
4. 唤醒词端侧召回率与功耗。
5. 端云链路的网络往返预算（判停后 → 云 LLM 首 token → 端侧首音频）。
