# Worker可达性与倾听收口取证

适用：P003 Worker SSH/监控显示异常、跨会话已有修复但本会话读取失败、收到安卓真机验收后补做服务端核验。本文不授予部署、改SSH身份或扩大设备范围的权限。

## 先定位失败在哪一层

| 现象 | 能证明什么 | 下一步 |
|---|---|---|
| TCP连接超时 | 当前源机器/目标/路径在本次未连通 | 核最新现役目标、既有可用入口和引用会话 |
| host key拒绝 | 本机信任材料不足或发生变化 | 对照已可信指纹；保留严格校验 |
| Permission denied | 错误所指的那一跳已抵达SSH鉴权，当前身份未被接受 | 先核失败发生在哪一跳、谁执行最终SSH、用哪个既有身份 |
| 监控采集超时/缓存过期 | 采集链不完整或数据陈旧 | 分查采集耗时、缓存时刻与真实服务健康 |
| unit/proc可读 | 当前运维通道可用 | 按原故障时间/trace补读，当前active不能代替历史证据 |

用户引用“已修复”的会话时，先读其最终回执、实际成功命令与执行入口。目录里名字像transport的脚本不一定是最后成功使用的脚本；核参数/调用来源并在任务允许远端读取时，做一次连接和整体执行时间均有界的只读探针。

跳板顺序相同不等于SSH认证位置相同：`ssh home 'ssh worker ...'`在home发起最终认证；由Air运行最终`ssh`并以`ssh home -W %h:%p`作ProxyCommand，认证在Air，home只转发TCP。优先复用已成功入口，不复制私钥、不为一次认证失败新增密钥或降低hostkey校验。具体目标、账号和入口以最新运维记录为准，不把历史IP写成永久值。

## 有界日志读取

- 限定实际unit、CST/UTC换算后的时间窗和可信trace/room；留读取时间、PID、源行数及摘要。
- journald JSON的`MESSAGE`可能是字符串或字节数组；读工具需校验数组为0–255整数并兼容解码，保留异常类型/计数，不能静默丢行。解析失败是读工具失败，不能记成业务无日志/服务异常。
- ASR/部分TTS行可能没有room。以含trace的job/room锚、PID和生命周期关联；只有明确无并发job的区间才按时窗归属；有重叠时须靠独立job键唯一归属，否则标“无法唯一归属”。跨重启还要核进程启动记录，避免只靠PID，也不要只grep room后认定无ASR。
- 原始正文在源端过滤，只返回批准的测试句、状态和脱敏ID。保留输入hash及事件行号；不要为凑证据拉全天用户对话。

## 三端证据各自回答不同问题

| 证据 | 可支持的结论 |
|---|---|
| Brain签票/authority/lease/close | 可信设备、授权、历史配置、模式租约及成功关闭 |
| Worker历史journal | 收到口令、普通回复是否抑制/恢复、输出流水、房间生命周期 |
| Android真机回执 | proposal消费、UI转换、实际实听、端侧计时器及设备稳定性 |
| 当前proc+磁盘binary+release SHA | 当前运行产物与发布产物是否一致 |

Brain的倾听授权close不是删房；`SourceDrained`是服务端播放记账，不等于物理扬声器结束。使用同一服务器时钟对账“模式close→普通问答→输出结束→客户端关房控制→房间删除”，不要把删房网络耗时算作Android idle预算。

若固定源码根本不记录proposal/ACK成功日志，不把缺行当未发送，也不宣称独立看到了Android消费。用设备/trace/版本/时间均匹配、明确标注范围的客户端回执补足对应证据层；关键证据缺失只做必要定向补验，仅为归档不新增协议、日志改造或重跑全套真机。

## 收口与后续归档

对通过的具体场景收口。独立但缺trace的问题、少量非阻断观测分别保留，不能一并宣称修好，也不因此重开所有已通过用例。新证据到来时更新最新状态/统一回执，旧失败原件保留并链接补充结论，防止历史“不可达”继续充当当前状态。

汇总多分支前同时查祖先/patch等价、文件实际差异、各工作树dirty和部署清单；已部署并不表示已合main，已被Git标记合入也不必然保留全部功能。将文档归档、源码集成、生产部署分开记录。存在不同发布基线或未提交的已部署改动时，先把现有差异作私有可恢复备份、核部署映射，再给出隔离工作树的集成清单和验证顺序，不用整树覆盖、全选ours/theirs或空合并掩盖差异。
