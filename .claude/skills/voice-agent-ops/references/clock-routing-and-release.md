# 小可报时、开放时间与上线验收

## 根据整句选择工具

- 普通设备对话复用服务端时钟和已有城市时区表。“现在才几点啊就跟我说晚安”也在问钟点。把新出现的真机错例加到回归集中，普通对话与显式搜索共用识别器。
- “故宫明天开放吗帮我查一下”问场馆安排。用场馆当地日期和可信公告核对；“什么时候开始”若承接上一轮赛事，就保留赛事对象。游戏奖励等待沿用对应设备的数据入口。单独出现“时间、几点、明天”时先看整句和上下文。
- 后台可能只存了“故宫明天开放吗帮我”。从设备签发房间找同一轮 Worker 的完整 ASR；相同转写片段不能重复计数、建任务或口播。灰度联调实录与自然用户需求分别标明。

## 确认上线范围与质量

- 分开查普通对话的设备鉴权和时钟开关、签发端灰度开关/名单/截止/健康租约、最近票据实际选择的 Worker。注册表给出可覆盖数量，已签票、已对话与现场听到回音各用对应证据。方舟配额和 Analytics 授权属于各自的业务。
- 三个 Brain 可能处在不同源码版本。用当前运行文件构造增量和逐池回滚点，回读部署文件 SHA。主池可选 API key 缺省是合法状态；探针核获准/受拒路径、完整正文和服务错误。对普通生成式聊天允许合理的不同措辞，对确定性报时才逐项核对数字和时区。
- 把重启窗口内的真实失败也写进回执，单列首轮与重试。上线后优先使用历史真机原话进行自然短验；同房间 ASR、工具路由、答案来源、Worker 正文首帧和设备实听分别取证。服务端首帧只能计服务端耗时。没人操作时记录待验。
