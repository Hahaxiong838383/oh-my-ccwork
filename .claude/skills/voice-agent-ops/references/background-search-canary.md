# 后台搜索与指定 SN 灰度：实施和验收约束

用于 P003 Worker 搜索、DeepSeek Search/Fetch/Tool Calls、单机真语音灰度。此页固化约束，不代表现场已经开窗；当前部署以最新签名回执、运行产物和有效开关为准。

## 代码隔离与运行隔离

- Brain 与 Worker 的生产源码基线可能不同，分别核实 SHA、目录与产物；独立分支和工作树，按各自目录交付，不整树覆盖或强凑一条分支。
- 搜索灰度通常继续其已有功能分支；只有并行版本或冻结发布线需要新建。并行复盘用文档分支，不抢写正在执行的功能工作树。
- 独立 Git 分支不能隔离线上设备。需要独立 agent 名称、候选 Worker/Brain 进程、限定 SN 的派单、鉴权及数据目录。
- 使用经认证的完整 MCU SN / Device Bearer sub；末8位只供报告展示，ADB 序列号不是云端授权身份。
- 保留既有首句能力合同。派单结果在 token agentName、响应 expected_agent_name、自检三处一致；只影响新会话，旧房间须退出重连。
- 空名单语义逐项查源码。当前搜索 `P003_SEARCH_DEVICE_ALLOWLIST` 与 Brain `p003.search.allowlist` 空值为关闭，不继承其他历史灰度“空=全开”的约定。
- 必须补签发路由时承认存在共享入口变更；备份、最小补丁、回归、空闲发布，不声称启动旁路进程即可零影响。候选与现役同机仍共享资源，先核余量和限额。

## 后台任务不阻塞正常对话

- 仅明确且已确认的搜索需求创建任务；投机/prewarm 不调用搜索。网络/模型操作走有界后台任务，语音循环只非阻塞收发消息。
- 搜索结果与普通回复分开，达到空闲门后补播；普通轮次变化不自动取消任务，明确取消、改查、离房按生命周期处理。
- queued/running/ready、claim、实际播放回执是不同状态。accepted/ready/HTTP200 都不是“设备已听到”。
- 为超时、队列、并发、日额度、结果期限和响应大小设置上限；取消/revision/epoch 防止迟到结果，重试使用原幂等键。
- 查询原话只留必要的内存范围；日志记录关联 ID 与阶段耗时，凭据不上 URL/日志，公开回执不含儿童原始正文。

## 隔离入口与数据

- 当前 Worker 搜索端点限制生产 HTTPS 主域名、443。候选优先用同域独立路径+严格反代；不临时关闭 TLS 或放开任意 host。
- 候选不能只改 `SEARCH_TASK_DB_PATH`：账号、设备、人格、配置、音频目录与定时任务也需要隔离。相对路径、符号链接和 import 时副作用必须检查；不用生产库验证候选迁移。
- 保留角色/accountId/真实房间SN校验；客户端自述的 room/SN 不得绕过服务端授权。工具抓取限制域名、协议、端口、重定向与尺寸，网页文本不能成为工具指令。
- 真实 Search 成功不等于 Tool Calls 成功；P2 自动没选 Fetch 不等于 Fetch 验收通过。按实际调用链与 tool_call_id 分别记证据，受控强制 Fetch 样例单独标注。

## 测试证据分层

| 层 | 证明什么 | 不能替代什么 |
|---|---|---|
| 单测、类型检查、构建 | 协议/状态/边界与目标 ABI | 线上部署、真实音频 |
| 真实搜索/工具 API | 身份、网络、provider协议、执行预算 | 回答事实质量、自动选工具质量 |
| 合成 admin/临时 DB 预览 | UI交互和配置回读 | 真实设备配置应用 |
| 本机账本延迟/压力样本 | 该数据量下的操作耗时 | 生产RTC尾延迟、并发容量 |
| 真机 audio/transcription/metrics | 同房间链路、实际播放与字幕 | 24小时长稳及全设备放量 |

SQLite 全表反序列化/序列化落在高频路径会造成尾延迟；用有界内存索引、逐行持久化和清晰恢复语义后，仍分别测存储与RTC。平均耗时不能替代 P95/P99。

真机按同机/同网络/同配置测旧版基线，搜索中继续多轮普通聊天，记录首声、空闲补播、真实插话、明确取消/改查、退出/断线、关闸撤权和来源核对。服务端发送日志不足以证明扬声器实际播放。续讲若按文本/played_samples估算而非字级对齐，必须实测极早打断的重复片段，不把估计进度写成精确续播。

## 开窗、回滚与交接

1. R0 是历史恢复点；上线前重新核现役产物/配置/PID/job，变化就建 R1，保留别人新改动。
2. 默认关闭部署候选，证明非目标设备不受路由影响、候选无生产目录写入，再开启单机 P1；实机过门再 P2。
3. 限时窗口必须有真实起止时间、有效名单和到期关闭验证。关闭新派单不等于踢出已有房间；在途任务/已播缓冲单独处理。不要拿 Git rollback 当运行回滚。
4. 先关新派单与候选搜索，目标退出重连回原agent；无候选job后再停候选。必要时恢复本次共享补丁，不回灌旧人格/Analytics DB或旧整份env。
5. 设备持有人回执在实际开窗后生成：北京时间起止、SN后8位、已核APK、已开P1/P2、重连方法、可照读话术、预期表现、失败记录模板、恢复方法。待端侧项写“未验”，不提前写通过。
6. 用户要求 Air Downloads 时按设备网络真值传输，核目标身份和文件哈希；仅落文件不代表已发同事，未明确授权不代发消息。
