# TTS 建连长等待与流中停顿

用于句子已生成却迟迟无声、TLS/WebSocket 超时、句中断续和传输修复验收。这里规定排查与恢复边界，不授权扩大部署范围。参数、设备、IP、PID 与回滚目录取最新项目记录；主技能下方旧部署命令是历史资料，SSH 前查共享记忆中的设备网络真值。

## 先分段，再归因

为同一房间/turn/句子/连接建立时间线：文本 ready → 等待预热 → DNS(A/AAAA) → TCP → TLS/WS → 发文本 → 首 PCM → 后续 PCM → channel 交付 → 播放/欠载/结束。标出暂停、取消和测试主动断连。连接总预算耗尽不等于 TLS 本身耗时已测出。

- ready 到 PCM 必须包含 `prewarm.take().await`，不能等预热后才开始计时。承接音首声、正文首 PCM、设备扬声器实听分开记录。
- DNS 慢要分别观察本机 stub、上游和地址族响应。一次 A 快/AAAA 慢的证据不能覆盖所有历史 5 秒慢请求。改解析保持域名、TTL、TLS SNI/证书校验，不将供应商 IP 永久写死。
- 搜索任务数为 0 只说明该任务路径未执行，不排除公共 TTS/路由代码回归；旧源码对比不能冒充旧部署实测。Worker 发起的供应商请求不归给安卓执行，但也不排除端侧其他独立问题。
- 同城正常 `curl` 或旁路脚本不能排除真实进程的偶发故障，也不足以归咎测试者代理；核同时间、进程、链路和连接才能比较。

## 前台连接恢复的合同

| 条件 | 应有行为 |
|---|---|
| 句子 ready | 建立一个前台绝对截止；预热等待、失败替换、备用连接共用它，禁止每次失败重新获得完整预算 |
| 预热已完成且 fresh | 直接使用，不额外建连 |
| 预热已失败/过龄 | 用冷 primary；它不是额外并发 spare，不应因 spare 许可耗尽而无法启动 |
| primary 持续挂起 | 达延迟阈值才尝试一次并发 spare；进程限额用非阻塞获取，无许可继续等 primary，不排队、不层层竞速 |
| primary 失败，或并发一方失败 | 在剩余预算内替换/等另一方；不能让失败的一方取消健康的一方 |
| 成功、超时或取消 | 输家 future/socket/permit 释放；预热 JoinHandle 保持 guard 所有权并 abort，drop handle 本身可能 detach |
| 即将发文本 | 再核连接 fresh；过龄报错，不在 `synthesize_connected` 暗中启动第三次冷连；仅赢家发送一次文本 |

2026-11-05 修复实例：`P003_TTS_CONNECT_RECOVERY_V1` 独立于 `P003_TTS_LATENCY_V1`；后者还影响衔接语，不能为了恢复连接直接开启。实例采用 **10 秒共享预算、650ms 后最多一个并发 spare、进程额外 spare 上限 2**，预热本身单连接，避免嵌套竞速；建连恢复流程成功或失败后为下一句 arm 一次。保留原 10 秒连接成功容忍度，未采用早期 4 秒稿。数字是该版本合同，不是永久推荐值。两路都失败仍会报错，不能保证供应商整体故障时仍发声。

## 流中恢复与背压

本次恢复只竞争连接。首个 PCM 成功交付播放队列后，禁止把同一整句再合成到同一播放通道，避免重播和字幕错位。若以后设计首 PCM 前的重试，也须单独验证首帧是否已交付、取消、共享预算和文本唯一性；当前实现没有流中重试。

正常长句的 channel 累计等待可以达到数秒。判断异常同时看：每次等待的最大值/时间线、收到 PCM 的节奏、播放缓冲、暂停恢复、实际欠载。累计等待 6 秒不能直接判为 6 秒网络断供；channel 满的背压与 channel 空的播放欠载不是同一件事。首 PCM 已成功后的欠载要单独归因，不能用建连提速销号。

部分 PCM 后收到错误还要核播放/字幕进度是否记录，不能只在合成成功返回时更新进度。它是单独的错误边界，未证实前不当作历史停顿根因。

## 双向包头证据的边界

1. 对齐同 PID/连接 ID/本地及对端端口，先核采集起止、方向、ring 截断、文件上限及内核 drop。用户态未截断不等于内核没有丢弃；两个方向都有包不等于完整捕获。
2. 重复 seq/len 只证明范围重复；无载荷不能确认内容相同。本机已发累计 ACK/SACK 不证明对端已收到，不能据此断言是回程丢包、供应商重传或本机故障。
3. 分开统计新 TCP 字节与重复覆盖；将新字节供给、PCM 到达及播放欠载对齐。新的正常对照包不能倒推历史另一连接的缺包。
4. `PACKET_STATISTICS` 是该 packet socket 捕获范围的内核计数，不是某条 TTS 流的链路丢包。读后重置时必须累计；counter=0 也不能证明端到端零丢包。TCP options/SACK/时间戳可以补证，不能替代缺失的另一端证据。
5. 默认采集受限元数据：白名单日志、DNS时序、TCP头；不保存 TLS 载荷、音频、原文或凭据。记录器必须有到期和容量上限，保留旧版本尾记录。自动采集不等于安排了智能体全天分析；报告到期计划与实际结束分别取证。

## 自检与收口

连接测试先复现旧等待语义失败，再覆盖：主握手挂起→备用接管→输家关闭→文本唯一；双挂起共享截止；许可耗尽仍可用 primary；失败/过龄/取消与真实 owner 清理。流中测试另覆盖断供、partial close、zero PCM 和正常 channel 背压，不与建连测试混为一项。

验收表分别列：隔离故障复现、固定源码回归、构建/ABI、真实供应商、RTC 探针、目标设备真人实听、历史同型故障。正常 RTC 两轮加数百单测只证明这些覆盖项，不证明历史 TLS 挂起或流中欠载根治；未完成项保持 OPEN。provider 首包指标不代替用户端总延迟。

每次发布记录运行源码 commit、测试/文档 HEAD、磁盘与 `/proc/PID/exe` SHA、配置来源、起止时间和实际保护范围。后续只有文档/测试变化时，不把新 HEAD 当作已部署运行源。回滚保留**本次部署前现役**二进制/环境及摘要，不误用更早回滚点；执行前核无漂移和自然空闲。
