# 固定 Web 隧道：断联、登录与直连

适用：公网网页间歇不可达、已有反向SSH入口排障，或要求服务/API不走代理。不要把已有固定入口换成临时Quick Tunnel作为默认处理。

## 四层分别举证

| 层 | 证据 | 不能替代的检查 |
|---|---|---|
| 客户端到公网 | DNS、TCP连接、TLS、HTTP各阶段耗时；同目标多路径与同路径控制站点 | 单次TCP/SSH banner成功不代表反向转发可用 |
| 中继与回源 | Nginx/SSH对应时间日志、回环端口、隧道服务PID/重启计数、回源请求 | 进程active不代表转发目标正确或可读 |
| 原生服务与认证 | 本机HTTP、有效Cookie、API/WS匿名拒绝与认证成功 | 首页200可能只是密码表单；401不一定是网络故障 |
| 浏览器应用 | 真实页面内容、静态资源、控制台、WS及重连 | curl成功不代表面板正常；mesh HTTP另查安全上下文 |

取同一时间窗口对照。多端到目标所有端口都TCP超时、国内控制目标正常，只能缩小到路径/出口/云边界；缺乏进一步证据时，不归因到某运营商或应用代码。重启计数可能包含部署和人工验收，不能直接当掉线次数。

## 保留有效路径，精确处理隧道

- 服务本机正常而某公网路径故障时，保留已经验证可用的中转。切回直连须验证回源和认证WebSocket，不能用几次短握手代替。
- SSH `MaxStartups` 是服务端未认证连接限流，核对时间、来源、专用账号和端口；不把共享服务器其他项目的重试算到当前Bot，也不直接提高全局限制。
- 旧反向转发占端口：先确认连接/进程归属，再只清本项目残留；keepalive、账号、监听范围限定到本任务。禁止宽泛pkill或顺手重启其他隧道。
- 更新网页网关时可只重载网关，避免中断Host中的用户任务；若必须停Host，应先识别运行中任务及实际影响，再按现有授权推进。

## “不走代理”指哪一段

公网Nginx/SSH是网页入站转发，HTTP_PROXY/系统代理是服务出站选择；mesh P2P又是访问路径。分别报告，不用“全直连”掩盖仍保留的中转。

- 先检查实际服务进程的代理环境、系统代理、启动器、应用用户/工作区 `.env` 或自身proxy配置；进程环境和配置可能含秘密，仅输出变量名和脱敏判定。
- 对明确要求全部直连的服务，局部启动器清除HTTP/HTTPS/ALL_PROXY及相应小写变量，按运行时支持设置NO_PROXY/no_proxy；Node的NODE_USE_ENV_PROXY开关只能作其中一层，不能代替应用代理模块检查。不要改全机配置影响其他服务。
- 以当前官方DNS、实际进程socket/路由与真实应用代理模块共同核验。域名解析结果只作当时证据，不固化IP。缺少持续socket时用无Key的只读TLS/HTTP探针即可，不为了诊断产生模型费用。
- 对支持环境回填的应用，注入本机不可用代理再调用它自己的环境解析/代理模块，验证目标仍判为直连。只用curl的 `--noproxy` 不能证明运行中的Node应用直连。
- 区分“磁盘脚本已修改”和“当前进程已加载”。若当前进程已经直连且有任务运行，可保留进程，明确新环境在下次正常启动生效；不要虚报重启或生效状态。

## 登录交付和凭据

DSH的启动token可换原生签名Cookie，但干净网址不能给新浏览器自动授权。用户要求常规密码登录时，可采用服务端验证密码哈希后交换原生Cookie的适配层；API Key不是网页登录密码。不要覆盖原签名凭据、向普通访问日志输出启动URL，或把token嵌入公开页面。

表单返回403时用真实浏览器检查Origin：已有 `no-referrer` 策略可能使表单Origin为null。修复当前页面策略后继续拒绝跨站/null来源，不用放宽校验掩盖问题。分别验证错误密码、正确密码、记住登录、Cookie属性、关闭重开、退出及API/WS权限。HTTP私网差异见 [Mesh Web验收](../../easytier-mesh-ops/references/mesh-web-access.md)。
