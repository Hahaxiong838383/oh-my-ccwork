# 家长任务联调与到账对账

## 家长能看周报，任务列表却返回 404

用同一家长的正常登录会话，在同一设备上重放客户端的完整任务 URL。分别登记任务列表和已知可读接口的读取时间、HTTP 状态、Content-Type 及脱敏响应。纯文本 `404 Not Found` 没有 JSON 字段时，记录“未返回 error/reason”。检查运行中服务的入口、实际注册的路径、相关开关及该次请求日志。若收到 `not_found / resource_not_found`，核对当前家长、设备归属和绑定代次。周报 200 只能证明周报可读。

部署时先比对目标文件和生产版本，保留生产独有的路由、归档和写入逻辑。隔离环境创建一条任务，再从列表读回同一个任务 ID，并验证另一家长的读取被拒绝。生产用原绑定账号复读客户反馈的 URL；真实空列表可按当时的条数回执。

专用审核账号调用 `POST /api/auth/password/login`。用成功响应里的 parent 会话检查原设备权限，再测错密返回 401。记录账号掩码、接口结果和客户端版本。小程序密码表单需在现役构建上另验。

## 从“达标”查到“一笔收益”

V1.1 沿用 V1.0 的九条路由，设备请求正文的 `contract_version` 传 `"1.0"`。联调依次核对以下事实。

| 看到的状态 | 核对依据 |
|---|---|
| 进行中 → 待家长确认 | 按北京时间周期累计归属明确、遥测已接收的 `focus_segment`。周报中的姿态、在位及其他补充估算独立显示。达标提示按 `occurrence_id` 去重。 |
| 已确认，待到账 | 家长按周期确认，同期重复确认返回同一 `settlement_id`。核对当前绑定代次、正常钱包快照和当前存档的正常逐笔流水，再向设备发放授权。 |
| 已到账，余额可能仍在同步 | 方舟钱包提交后，以可信的 `wallet_applied` 核对本笔授权、币种、金额和存档。到账提示按 `settlement_id` 单独去重。余额取真实钱包快照，无可信数值时保留 `null`。 |
| 小程序和 Worker 各一条收入 | 在两端的 `ark/records`、`miniapp/records` 入口按 `resource_id=family_coin` 查询。用实际记录号、存档、币种和金额核对 R1；其 `source_kind=parent_task`、`source_id=occurrence_id`、`reward_instance_id=settlement_id` 必须指向同一笔。 |

遇到“已确认却没有币”，先查看最新快照的来源和接收时间。若为 `gm` 或 `unknown`，让方舟切回正常存档，同步当前钱包及可核对的存档流水，再重读原结算。设备重启、回执重发、R1 与快照先后到达时，都沿用原 ID 对账。金额相同的两个不同结算分别保留。关闭主动提醒时，两种提示均不弹，任务状态和到账结果仍可查。

## 实机回执

先验“20 分钟奖 35 币”。记录现役小程序和方舟版本、同一组 `task_id`、`occurrence_id`、`settlement_id`、两次提示的展示与重放次数，以及两端各一条 +35 的记录。起始余额 100 且期间没有其他收支，最终快照才应为 135。随后验证跨期共存与删除后补传。

部署、生产账号读取、隔离库结算、真实设备到账分别写明环境和证据。现场基线及原始回执见[联调登记](../../../../2-Projects/P003GameDemo20260513/docs/parent-tasks-20261118/P003_PARENT_TASK_V1_1_MINIAPP_READINESS_20261118.md)。
