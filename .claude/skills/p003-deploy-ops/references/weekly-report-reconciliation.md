# 周报计算与验收

适用于 P003 已上线周报的维护和联调。具体来源见仓库 `2-Projects/P003GameDemo20260513/docs/weekly-guard-20261117/README.md` 及同目录测试/发布证据。以下是周报合同，不自动成为任务奖励的发币规则。

## 1. 保留原接口，明确新字段

家长沿用 `GET /v1/parent/devices/{public_id}/weekly-report`，后台使用 `GET /api/admin/devices/{sn}/miniapp/weekly-report`；同一计算服务输出新增 `data.report`。旧 `guarded_minutes`、`eye_health_rate` 仍有原口径，不能给新三张卡兜底。旧绑定只能读旧字段时可能 HTTP200、report=null；其他家长404，授权存储故障503，不能把依赖故障当无数据。所有响应 no-store。

默认周按 Asia/Shanghai 的周一零点计算，不能对北京时间零点直接取 UTC 星期。兼容旧调用显式非周一参数时，旧字段仍从该日算7天，新 report 是包含该日的自然周；新页面发周一并核对响应设备、周与时区。非法真实日历日期拒绝。

## 2. 三项指标分开计算

- 提醒仅计鉴权设备的唯一 `(sn,event_id)`、`posture_reminder`、原值 `outcome=played`。672是待核参考上限，超过仍展示实数；不能截断或用冷却/姿态轮/批次ACK代替。
- 真实使用：focus 原始毫秒区间按ID去重后求并集，重叠或端点相接连续，任意正间隙分开；先按北京时间午夜拆日。日均=整周真实总秒数÷7，最后才做显示取整。
- 活跃天数：每天真实最长连续区间达到原始300000ms才计1天；299999ms不够，跨午夜两段各3分钟也不够，估算不能证明连续使用。
- 姿态/在位/奖励累计为补充时长，真实、补充、合计分别列出。各指标独立 available/reason：缺测为null，已知0为0，未来为pending，不能用一个字段可用推导其余都可用。

周报调用历史使用计算时保留精确秒数；旧首页取整默认保持，避免把取整残差误判为补充量。

## 3. 保历史，也允许迟到事实纠错

保存日/周派生结果及必要的白名单证据，原始日志清理后仍可重算。保留有位置的 focus/在位/姿态证据求并集；晚到离位事件允许缩短先前估算。仅无位置的奖励累计保留每日高水位（301→600→902取902），不对混合总量做高水位，也不把计数倒推为某一连续区间。区间并集与奖励高水位每日取max。

周日22点首次发布注明本周未结束，周一零点补齐自然周，补传修订原发生周；首次发布时间稳定。data_cutoff_at_ms 是统计区间截止，不是最后接收时刻；来源接收与修订另记时间。短暂依赖故障只改变本次覆盖提示，没有新事实不增 revision。其他周的无效事件不能污染本周质量计数。

缓存范围取有效绑定/单调binding_version/Ark epoch/明确历史授权，不能哈希整份原始配置文本：仅JSON换排版或改另一台设备不得使本设备缓存消失。只继承明确授权的旧历史；读取中发生换绑、A→B→A、角色/代际变化，迟到结果丢弃，不把旧主人证据带到新范围。

## 4. 验收和发布经验

用独立原始区间复算对照家长API、后台API和真实页面同响应；测恰好门槛/差1ms、跨午夜、补传/清理、空周、瞬时故障、绑定竞态。发布只覆盖已核文件，入口文件基于生产差异合并，保留生产独有路由；回滚仅源码，不能回灌业务库。

后台上线、参考小程序构建、现役微信源码接入、手机实测分别写状态。RealDataHome通过不代表LiveApp/liveHomeView已接线；找不到现役源码时保存查找范围和接线合同，不能无限搜索、换旧源码冒充完成，或以后台页面代替手机验收。

交叉测试须记录真实引擎/任务/提交/结果。审查原报告若有与兼容合同不同的表述，保留原文并在正式回执明确更正，不能修改署名报告制造一致。测试数和C机数值均附取证时刻；周中结果不称完整周或长期最新值。
