# 小程序真实数据与历史授权对账

用于旧后台有数据、小程序空白或全0、端云各自宣称R1完成但不能对接、旧历史需要新增家长读取入口等场景。下列规则来自已复现故障；具体SN、计数、版本和上线状态仍以本轮只读证据为准。

## 1. 先按数据域填表

每行固定填写：**能力｜生产者及存储｜原始数量/覆盖期｜归属授权｜API字段及空态｜客户端入口/构建｜验证证据及待验项**。

| 域 | 不可混淆的口径 |
|---|---|
| conversation | 消息数不等于会话数；统一session_id不能用于计算会话次数或时长 |
| telemetry snapshot/event/daily | 状态、姿态、在位变化与focus_segment分别查；聚合默认0不等于有效采集值 |
| Ark current | 快照来源unknown、钱包null与真实normal余额0分别处理 |
| Ark records | 新流水0不能否定旧对话、遥测、快照；基线不是新增收入或获得 |
| 摘要 | 仅已同步正向收益与最新获得，不能称完整昨日收益、全库存；未知来源/时间不回退旧正常数据冒充最新 |

只读计数和字段先核数据库，再核API、客户端映射与实际构建。`available=false/null`按原因展示未知、未开放、依赖故障或缺测；只有有效观测口径支持的0才展示0。不用对话首末时间、签票耗时或token TTL推算使用分钟。2026-11-17用户明确奖励进度秒也属使用时长，并允许在位/姿态推导；按第5节去重、有界计算并标来源，旧“只能认focus_segment”限制已被该指令覆盖。

## 2. 无归属代际的旧历史，先明确授权边界

当前设备绑定不是旧记录的原始授权证明。单机显式授权历史时，冻结完整的public_id/SN/parent/device-account/binding_version/epoch元组，核active、真实角色及device-account唯一；默认不开放其他设备。换绑后又换回同一owner也要因单调代际变化失效。不能把该单机例外变成全设备自动追认。

SQLite ATTACH的WAL库可能各自建立不同快照：事务内查绑定一次不足以证明返回前仍授权。读取前校验，COMMIT释放旧快照后重新读取当前完整元组；任何变化都不返回历史。测试用真实第二连接制造A→B→A和读中换绑，不能仅mock检查函数。若归属版本不能可靠单调，先补权威机制，不能只比owner。

详情只返回产品必需字段，no-store；摘要故障只降级本域。计数/时间缺失保持null。会话正文只在进程内对账，不进工具输出、日志、记忆或交付证据。

新增异步历史调用后，不能只重查绑定六元组。已复现等待期间Ark settings/revision撤销而家长接口仍返回旧Ark数据：前后还须比较epoch、grant、账号角色、Brain唯一占用及scope；失败不返回旧整包。兼容旧家长域降级时可保留静态依赖失败状态，但不得吞掉实际权限变化。Analytics与遥测要双向独立降级，连同步Dashboard前置读取也要覆盖故障测试。

## 3. 同路径的两份合同也要做真实wire对撞

先核既有远端最新回执与**精确构建提交**，不能只凭Downloads最晚发现的文件断言尚未开发。按下表逐字段对比实际序列化器、服务端严格解析器、ACK消费者和持久队列，再用客户端真实fixture打隔离HTTP/SQLite。

| 必查项 | 通过条件 |
|---|---|
| 协商、信封、记录结构 | contract版本/开关、允许键、类型、资源ID、批量与数值上限与所选已知格式分支一致；不要求legacy字段与v1相同 |
| origin与历史授权 | 原生带origin时核产生时冻结值；已知legacy无origin时可单独明确历史授权并保留原归属未验证，不能伪填；换绑/换回与续token分别验证 |
| 稳定业务语义 | v1核原reason/来源/实例/引用；legacy可依已有grant与库存差异只读投影，无需补原生实例框架；baseline不算收入，混合事务不重复拆分钱包delta |
| ACK | accepted/duplicated/rejected互斥、子集、批次匹配；旧端不懂retryable时服务端可整批503/429保原ID重试，不必强制先改ACK；永久拒绝才进死信 |
| 身份scope | JWT的binding_version与Ark epoch不是同义字段；缺epoch退token指纹可能让正常续凭据导致同save暂停 |
| 覆盖与满队列 | dropped/容量/覆盖缺口有明确合同；不能删字段只为通过strict schema，不能pending=0就称完整 |

**优先最小兼容，不把现役schema差异一律升级成端侧重构。** 已知legacy可同接口按精确contract_id分支解析，保不可变原文/原ID/哈希，读取时投影小程序字段；只要求语义可证明的部分进入摘要。baseline可收可查但不算收入，混合事务不重复拆分钱包，激活不新增获得。需要时一张原始表比硬塞v1强制origin/实例字段更小；不要先造通用版本平台。

单机已明确授权历史时冻结完整范围，标“兼容历史授权、原发生归属未验证”，不要把缺origin当永久不能接入，也不补造原owner。临时失败可整批503（限流429），部分已耐久入库者下次duplicated，无需额外整批回滚框架。正常续token的队列scope用已校验稳定绑定键；binding_version与Ark epoch分开校验，旧指纹队列只迁移已核同代际范围。无法验证的字段保留未知，不妨碍接收已授权原始事实。

兼容须有真实序列化fixture→HTTP→SQLite→家长读取证据，覆盖旧端重试/原ID幂等/换绑与摘要口径；实现验证前不直接开旧不兼容链路。严格已知格式适配是兼容，任意放宽校验或只改合同名不是兼容。区分“兼容尚未实现”和“无法兼容”。

兼容摘要还要核三个真实语义边界：卡类资源可能实际在inventory而非wallet；收益日期用真实提交record.occurred_at_ms，不能借动作开始参数grant.granted_at_ms跨日归属；legacy的聚合item_id激活不能修改v1精确实例。对原奖励ID跨记录重放取原始序列证据、冲突来源排除，不因到达先后挪动收益日。以上来自独立复核的实际P2，需有行为回归而非仅字段接线测试。

## 4. 分页是状态机，测连续失败

稳定分页绑定scope、filters、limit、高水位和过期时间；检查锚点删除/复用，刷新首屏才能纳入新消息。

客户端400/410立即废弃旧cursor，并保持needsRefresh；随后刷新首屏503不得解除该状态或复活旧cursor。只有首屏成功才恢复翻页。必测链：首屏成功→旧cursor失效→首屏503→loadMore不请求→首屏成功→新cursor续页。切账号、退出、切设备和组件卸载使迟到响应失效。

## 5. 使用时长先追真实采集门

把物理状态、原始MCU值、桥接数组字段、解码枚举、摄像头在位、OTA/配对阻塞、时钟、Tracker片段、队列、逐ID ACK、DB、家长API依次连接。对同一MCU原始值，各消费者应复用权威常量；精确mini008/009曾将工作/开盖误写1/1，而同源欢迎策略为4/0，正常输入因此挡住计时。

复现测试直接调用生产解码器，并把结果送入真实Tracker验证60秒段、暂停/合盖尾段、无效状态不累计；源码接线测试只证明接线，不能称传感器实测。已有姿态ACK、focus_active=false或旧Ark403不能单独证明focus片段失败原因。macOS主机出现路径安全拒绝时，先核/var、/tmp与canonical路径；测试环境改正确路径，不放宽生产路径校验。

用户允许云端计算后，分别保留设备直接计时与补充计算量。连续累计检查点301→600→902只计902，合法0仍是有效观测；不能将902倒推成结束前连续902秒。已有位置的focus/在位/姿态区间先求并集，再与同日奖励计数高水位取max，作为保守合并值；不把位置未知的累计秒数额外加到在位时间上。本轮在位窗口上限300秒、有效姿态回看60秒，no_person和0有效帧排除，窗口与partial coverage写入DTO，不称完整精确使用史。历史累计另列，不能只展示近7日；秒数优先，24秒不能因分钟四舍五入显示0分钟。

旧奖励/库存应查已有Analytics原始事件，不以新R1流水0断言没有历史。历史观测、当前余额和正常来源业务摘要分别展示；来源unknown保持未核实，库存快照不是新增收入，记录数不是获得数量。当前原始事件保留14天，页面与回执注明覆盖，不把该窗口称永久完整账本。

## 6. 回执固定分层

| 层级 | 必须有的证据 |
|---|---|
| 源码修复 | 精确构建基线、最小diff、失败复现和修后测试；后续基线保留已交付的新功能 |
| 编译 | 具体编译任务/运行环境；Release Kotlin成功不等于完整APK |
| 签名产物 | 原完整构建门禁、包名/版本/证书/字节数/SHA、DEX/资源闭包 |
| 设备身份 | 自报版本带时间，另核pm path→活动APK字节/SHA；自报不能代替安装回读 |
| 云端/API | 同事件/record_id逐字段核，负例归属、去重及原域兼容；服务端签名探针不是手机登录 |
| 页面/真人 | H5真实响应传输夹具、微信构建、微信发布、真人手机操作分别记录；CORS夹具只补传输头，不替换业务数据 |

缺字段写“待验/缺测”，不把下一层当默认通过。无实机入口时继续交可审查代码、补丁、构建和接口证据，保留已授权范围；不造记录、不清绑定/队列。后续明确授权优先于先前等待状态；完成本轮已授权实施/发布/验证后再等待，不自主扩大安装、开闸或探针范围。

微信标识分开验：客户端getAccountInfoSync提供AppID核对，wx.login code由服务端换取OpenID/UnionID；不能直接信任客户端裸ID。手机号授权code与登录code不同，同号复用原账号、冲突不合并，旧短信/H5继续兼容。缺AppSecret、尚未授权、微信未返回UnionID是三种状态；AppID已显示或mock测试通过均不等于真人微信授权通过。
