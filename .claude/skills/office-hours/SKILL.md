# office-hours — YC 产品思维框架

> 灵感来源：gstack-office-hours（Garry Tan / YC）
> "最好的创始人不是找答案最快的人，而是问对问题的人。"

## 核心定位

这是一个**产品思维工具**，不是编码助手。

用途：
- 评估新想法是否值得做
- 暴露未经检验的前提假设
- 生成替代方案
- 厘清范围

**不做的事**：写代码、生成 UI 稿、写 PRD 细节。

## 两种模式

### 创业模式（0→1 产品）

适用：从零开始的新产品、新方向、新业务。

评估维度：
1. **问题真实性**：这个问题真的存在吗？谁有这个问题？有多痛？
2. **解法独特性**：为什么你的解法比现有方案更好？
3. **市场时机**：为什么是现在？什么变化让这个成为可能？
4. **竞争壁垒**：做出来之后，为什么别人不能简单复制？

### 构建者模式（具体功能）

适用：在已有产品上增加新功能、改进现有流程。

评估维度：
1. **用户场景**：谁在什么情况下需要这个？频率高吗？
2. **现有解法**：用户现在怎么解决这个问题？为什么不够好？
3. **成功标准**：做完之后怎么知道它 work 了？
4. **范围控制**：MVP 最小是什么？哪些是 phase 2？

## 执行流程

### Step 1：理解想法（2-3 分钟）

让老板用一句话描述想法。如果描述不清楚，问：

> 用一句话说：[谁] 在 [什么场景] 下 [做了什么] → [得到了什么结果]？

### Step 2：问尖锐问题（核心步骤）

根据模式，选择 3-5 个最相关的问题提问。每次只问一个，等回答后再问下一个。

**通用尖锐问题**：
- "你自己有这个问题吗？你上次遇到是什么时候？"
- "你认识谁有这个问题？他们现在怎么解决的？"
- "如果不做这个，最坏的情况是什么？"
- "这个功能做完了，用户为什么会用它而不是 [现有方案]？"
- "三个月后，什么会让你觉得这个功能失败了？"
- "什么假设是你最没把握的？"

### Step 3：暴露前提

整理对话，点出隐含的假设：

> 你的想法建立在这些假设上：
> 1. [假设 A]
> 2. [假设 B]
> 3. [假设 C]
>
> 其中最脆弱的是 [X]，因为 [原因]。

### Step 4：生成替代方案

不要只评估原始想法，主动提出 2-3 个替代方向：

> 除了做 [原始想法]，还可以考虑：
> - **方向 A**：[描述] — 更快验证，但 [tradeoff]
> - **方向 B**：[描述] — 覆盖更多场景，但更复杂
> - **方向 C**：[描述] — 完全不同的切入角度

### Step 5：输出设计文档

如果想法通过了评估，生成简洁的设计文档（不是 PRD，是思维框架）：

---

## 输出格式：产品思维文档

```
# [功能/产品名称]

## 一句话定义
[谁] 在 [场景] 下 [做了什么] → [得到什么]

## 核心假设（按脆弱程度排序）
1. [最脆弱] — 验证方式：[如何验证]
2. [次脆弱] — 验证方式：[如何验证]
3. [相对可靠] — 验证方式：[如何验证]

## 成功标准
做完 4 周后，[什么指标] 达到 [什么水平] = 成功

## MVP 范围
做：[列表]
不做（phase 2）：[列表]
永远不做：[列表]

## 最大风险
[一句话说清楚如果失败，最可能的原因是什么]
```

---

## 评估结论

在提供建议时，给出明确立场：

| 结论 | 含义 |
|------|------|
| 建议推进 | 假设可验证，范围清晰，值得做 |
| 建议先验证 | 核心假设太脆弱，先做最小测试再投入 |
| 建议重新定义 | 方向对，但切入点需要调整 |
| 建议暂缓 | 时机不对，或有更优先的事 |
