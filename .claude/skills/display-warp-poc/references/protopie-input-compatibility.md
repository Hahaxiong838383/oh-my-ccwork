# ProtoPie 播放器与输入兼容性核查

用于回答“预览是否原生”“新加按键是否需要适配”“所有键鼠能否透传”，或排查独立内容屏下输入丢失。该方法来自 NIO Warp v0.13.9 审计；版本能力和缺陷应以当次源码、安装包与运行状态重新核对，不能永久沿用旧结论。

## 先确认三层身份

- 播放器：区分 Studio 本机 Preview、官方 Cloud 网页与自建播放器。运行在 Chrome 的官方页面仍使用官方原型交互，但不能称作 Studio 本机预览。
- 显示：全屏、缩放、取景、虚拟内容屏、捕获和 Warp 可能由宿主实现；改变布局不等于重写交互引擎。
- 输入：确认是操作系统直接投递、同屏穿透，还是实体输出到独立页面的桥接。官方页面本身支持某键，不代表宿主桥接也会发送。

只读核查当前包版本、进程/绑定来源、页面 origin 与播放器根节点、视口、布局脚本。页面证据只记录必要布尔值和尺寸，不归档私有分享地址、完整 DOM、凭据或全量偏好。

## 按类别检查真实转发路径

从本机捕获、作用域/焦点、按键过滤、持有状态、队列，追到页面派发；不要只查看键码表。

| 类别 | 要核实的差异 |
|---|---|
| 常规按键 | 字母、主键盘数字、小键盘数字是否分别正确；布局字符、key/code、按下/释放与重复是否一致 |
| 修饰键 | Shift/Option/Cmd/Ctrl、左右侧、系统保留组合；键盘与鼠标修饰位的策略可能不同 |
| 特殊键 | Esc 是否先被宿主退出监听截走；F 键是否被 macOS 转成媒体键；Caps/Fn 是否只有系统侧作用 |
| 鼠标 | 三键、侧键、单/双/三击、持键拖动、滚轮两轴、同时持有与释放 |
| 高级输入 | 输入法 composition/提交、多点触控、缩放旋转、压力、外部文件拖放是否有独立桥接；不能由 key/mouse 支持推断 |
| 生命周期 | 焦点变化、Esc、页面刷新、导航、断连、重新绑定时是否释放旧键，是否把旧事件误投新文档 |

如果没有原型业务键位白名单，通用桥接支持的新增按键/按钮可在页面加载新版后继续使用；这不代表在线更新无需刷新，也不代表未实现的事件类别会自动得到支持。

## 容易漏掉的状态问题

- 左右 Shift 或 Option 同按时，聚合 modifier mask 仍为真，不能据此判断刚变化的那一侧仍为按下。测试需覆盖先按左、再按右、依次释放，以及反向顺序；检查重复 down、遗漏 up、退出后 drain 与重新进入。
- 紧急退出与原型业务键需要明确分工。官方 Press 包含 Esc；若宿主占用普通 Esc，就应将其列为兼容性缺口。更换退出组合键属于产品行为调整，不能把建议记为已实施；实现时需同步所有退出入口、提示和测试。
- 页面 reload/navigation 可能使旧输入绑定失效。确认新文档重新绑定的真实方式，并阻止旧队列或持键状态进入新文档；不要为了“无缝”而跳过身份检查。
- 边缘取样要统一输入事件与光标查询的坐标：渲染网格可能允许 UV 闭端点 0/1 和微小浮点误差，而网页事件使用半开范围。合法几何边缘不应被样式查询判为致命越界；转换后仍保留传输层严格校验。
- 验证 AA 限制时同时比较目标热点与系统实际热点。Retina／负桌面原点下，系统取整可能把目标边缘推到 AA 外；仅在最终放置时处理可表示精度，避免大幅缩小 AA 或用“映射仍 active”代替落点检查。见 [AA 边缘案例](../../../../2-Projects/nio-warp-demo/docs/aa-boundary-v01311.md)。

## 证据与验收口径

将结果分为“源码有实现”“离线或自动事件验证”“用户本机验收”三层。`201234`、一次长按或一次 Esc 重入的成功只覆盖对应场景，不能写成全键盘全鼠标验收。发现静态可推导的问题时，注明是否已实机复现、修复、安装和人验。

需要扩大验证时，先用隔离测试页/原型记录 key/code/location/modifiers、down/up/repeat 与鼠标事件顺序，再做真实硬件检查；不要向用户正在演示的正式原型盲发全键盘序列。单有桥接编码测试也不等于官方原型对全部操作已响应。
