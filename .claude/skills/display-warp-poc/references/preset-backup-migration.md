# 预设备份与跨机迁移

用于导出全部命名预设、误重置恢复、跨机迁移及解释预设/配置文件关系。以下存储名来自 NIO Warp；先读当前 `PresetStore`、`ConfigurationHistoryStore`、`ConfigurationStore` 和 UI 导入入口，再确定本次范围。

## 参数结构相同，不等于同一备份文件

| 数据 | 常见保存对象 | 迁移区别 |
|---|---|---|
| 当前完整参数 | 一套 `WarpConfiguration` | 单 JSON 可应用到当前画面；未必自动进入命名预设列表 |
| 命名预设集合 | 名称、UUID、创建时间、完整 configuration 数组 | 单配置导入器未必接受数组或预设外壳 |
| 显示器当前档 | 每个硬件标识分别保存的 configuration | 最新手调可能还没有保存为命名预设 |
| 操作历史 | 时间、原因、configuration 列表 | 不随普通单配置导出迁移 |

“屏幕参数”在这里指 App 的 AA、画布、位置、镜像等字段及校畸变参数，不自动涵盖 macOS 显示器排列、TCC 权限、ProtoPie 链接或鼠标偏好。按具体序列化字段说明范围。

## 非破坏性完整导出

1. 从运行设备的当前偏好获取一次快照，确定实际预设数量和存储类型。导出只读，不通过反复应用预设切换正在演示的画面。
2. 保留集合的原始 Data，另把每项完整 `configuration` 导出为独立 JSON，便于现有单配置 UI 使用。不要只选常见滑块字段；嵌套控制点、外扩参考域和旧版裁切字段都需保留。
3. 用 typed plist 保留必要的预设/历史/各屏当前档/最后档名。它是局部参数快照，不等同于整个 App 设置备份；其他范围按用户要求另导。
4. 文件名防冲突，清单记录数量、名称、ID、原日期、原屏幕尺寸、文件映射与哈希。原始时间编码保持，便于阅读的 ISO 时间只作附加字段。
5. 独立 JSON 与源 configuration 深层比较，原始 Data 逐字节或 SHA 比较；核对 typed plist、ZIP CRC及重新读取。另一台设备副本也核对哈希，导出后复查相关偏好是否保持。
6. 备份附准确恢复步骤与版本范围。原参数和私有链接不因“push 代码”而自动入库；按当前授权交付附件、指定备份位置及可入库的校验摘要。

当前 NIO 案例中 `canvasReference` 保存外扩所依赖的参考画布、坐标域与输出边界，遗漏它可能使相同滑块值还原出不同形状。旧预设原本缺少的字段不要伪造补入，避免把导出变成配置迁移。

## 两种恢复不能混称

**通过现有 UI 逐个迁移**：在对应屏幕和分辨率下，导入单个 configuration JSON，核对画面，再填名称保存为预设。说明导入通常立即应用；“保存预设”可能替换同名项、重建 UUID 和创建时间。不能把参数导入成功称为完整集合无损恢复，也不能把 ZIP/预设数组交给只支持单配置的入口。

**维护方式无损恢复集合**：确认恢复范围，正常退出 App，先另存当时最新值，再仅恢复备份的相应键和原数据类型。恢复后重读数量、名称、ID、时间和完整参数。局部 plist 不应覆盖导入整个偏好域，以免删除其他设置。

导入器可能按当前屏幕尺寸 sanitize，而“应用预设”按钮可能直接拒绝尺寸不匹配，两条路径需要分别说明。不同物理屏即使像素相同也不保证光学校正相同；换屏后的验证不能省略。

## 功能事实与后续建议分开

- 回答“当前支持吗”时区分：文件能够逐个导入、程序具有批量预设库导入、维护人员能够写回原存储，三者不同。
- 若用户只问现有能力，不自行新增批量导入功能。建议可以归档，但不能写进记忆为已上线。
- 命名预设、当前参数、历史的重置/删除行为各自检查，不能从某一个按钮推断整个库都会被清除。
- 用户正在调参时以明确时间点保存快照，记录选择依据；后续安装/回滚不得自动拿旧备份覆盖更新值。
