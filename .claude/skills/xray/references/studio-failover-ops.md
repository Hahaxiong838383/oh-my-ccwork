# Studio 容灾升级与验收

适用于 Codeg 模型请求重试、Air 与 Studio 表现不同、控制器频繁切入 block。不要直接把模型重试当成远程工作区掉线，或把全部异常归于公司到 DMIT。

1. **运行文件是真值**：分别核 Air、Studio、交付目录的 controller.py SHA、启动参数、状态新鲜度。历史上 Air 已采用新策略，Studio 仍运行旧版；不能用仓库 README 代替部署证据。
2. **探针有时间预算**：连接/总超时与成功请求的实测耗时对照。4/6 秒可能将慢请求判为不可用；本次对齐 Air 的8/12秒。不是永久推荐值，也不把无限延长超时当修复。记录退出码及完整响应，收到401头后超时仍是失败。
3. **健康与可达分开**：两项目标均成功才算服务完整健康；仅部分目标成功记DEGRADED。自动模式无完整健康候选时保留可达线路，连续三轮三路全失败才从既有路径进入block。冷启动、严格pin、真实全断保护、配置漂移保护与API读回保持。只读观测不能擅自pin或关阻断。
4. **关联时间线**：将Codex responses_retry、控制器切入block与恢复、正式入口请求对齐。block期间会阻断新请求；不能据此推定每次长流断开都由切换造成，旧连接不会随override迁移。
5. **控制器增量升级**：备份当前代码、配置摘要和状态；测试候选、校验guard/override后原子替换。只重新拉起控制器，核launchd服务/UID/命令行再操作准确PID；不杀Xray。确认Xray与Codeg进程、主配置和认证未变。已有安装禁止套首次安装器、旧manifest或整套Air配置，尤其不能覆盖设备自己的home链路。
6. **验收与回滚**：同等前后时间窗口统计切换、进入block、控制错误和原任务网络重试；补正式HTTP/SOCKS入口与真实任务后续模型/工具活动。保留失败样本，不能只报成功率或state=OK。回滚校验备份/当前版本及配置漂移，仅恢复控制器，支持文件已恢复但重拉失败后的重试。回滚校验通过不等于已做生产回滚演练。
