# VPS 迁移、双栈入口与电视后台验证

用于 RackNerd 同类完整迁移后的节点维护。具体地址、端口、设备、主机指纹和服务身份取当次真值；
已有用户授权持续有效，缺后台凭据属于访问能力缺口，不能反复当成待审批。用户明确搁置的域名或协议不继续测试。

## 迁移前后各自证明什么

- 机房以供应商对实例的回执为准；IP 地理库、主机名、Cloudflare `colo=LAX` 不能独立证明机房。
- 在停写窗口或一致性快照上制作文件备份，记录源服务集合并安排失败恢复；按实际独立挂载补齐数据范围。
  归档需异机保存、源端/目标全量 SHA 一致、实际解压、关键文件逐 SHA 和离线 SQLite integrity_check。
  格式检查不代替恢复检查；文件级冷备不等于 VM 快照或已完成整机启动演练。
- 非 root 解压的设备节点/权限失败要逐项记录并精确补还原，不能把非零退出改写成成功；
  源端临时归档仅在异机验证通过后按精确路径清理。含凭据备份只存受限目录，不入 Git。
- 新 IP 首次 SSH 比对迁移前可信公钥，保留严格主机校验；不凭新 IP 就盲接受新指纹。
  验证原身份、文件和业务恢复；不能直接覆盖旧 netplan/fstab/GRUB 到新硬件。

大文件分块续传复用 `cross-site-file-transfer` 的单写入方与全量校验约束。

## 迁移旧地址：清点实际消费点

| 消费点 | 验收位置 |
|---|---|
| SSH 别名 | 在当前执行机器 `ssh -G` 与真实登录；别把另一台机器的别名当本机已存在 |
| Homepage | 允许主机环境变量需重建对应容器；卡片需查页面使用的 API 响应，文件替换不等于已生效 |
| Kuma | 备份/停止写入后精确更新目标行，恢复对应进程；核重启后的新 heartbeat 与实际目标 |
| Cloudflare 橙云 | 公网 DNS 返回边缘 IP；通过 API/后台读源记录，不能仅据 522 推断记录具体值 |
| 电视 | live 主配置、发布副本、worker、SHA/manifest 与启动事务是同一组；按 [冷启动约束](tv-dns-coldboot.md) 处理 |

只更新当前有效引用，历史报告保留原时点地址；记录明确的“已替代/未完成/用户搁置”状态。
单项运维配置变更只重建/重启对应服务，回读其他服务身份不变。操作范围不默认扩展到整栈升级或电视切换。

## IPv6 从地址到可用代理

依次检查实际公网地址/前缀、默认路由、出网、使用网络入站、代理监听及防火墙。
`[::]:22`、一条 AAAA 或 IPv6 出网成功都不能证明代理端口可用。
`listen=::` 是否同时接受 IPv4 取决于内核与程序；读取 `bindv6only` 后仍必须从外部对两个地址各做真实代理请求。

新增入口使用独立配置/unit/端口，保留现有服务与认证；不因新增 IPv6 或更换 SNI 轮换凭据。
SNI 目标需验证 TLS1.3、h2、证书和不回指自身。REALITY 的握手目标与客户端连接地址不同：
自有域名托管在 Cloudflare 不代表代理数据走 CDN，也不意味着要把目标域名 DNS 改到 VPS。

客户端导出从现网认证派生；私钥留服务端，确需导出的公钥可通过 stdin 派生，避免把私钥放命令参数。
IPv6 URI authority 使用 `[地址]:端口`。由**实际交付 URI 重新解析**构造临时客户端，分别验证：

- 进程正常启动、出口地址属于目标 VPS、至少一个目标的有效正文。
- 有界完整载荷（如 1 MiB）与精确长度，避免只验 TCP/小页面。保护前台时限流，并注明限流值，不据此汇报峰值速度。
- 新公开入口可用错误 UUID 负例确认请求失败；客户端未启动等探针自身错误不算认证拒绝。

暂存配置用受限目录/600，临时实例按精确身份退出并清理。两条 IPv4/IPv6 URI 是独立节点，
不是自动切换；蜂窝网络能力、手机实测、自启配置、真实冷启动分别记录。
保留首次失败和复测记录；间歇故障复测成功时不盲改 MTU/拥塞控制，也不承诺长期稳定。

## 电视正在播放时的独立探针

先核前台应用、音频/媒体归属、解码帧/错误、原代理/guardian/worker 的完整 argv、PID/startticks、boot 与配置哈希。
本 X96 默认 `/system/bin/su -c` 被拒不等于无 root；已验证路径是 `/system/xbin/su 0 sh -c ...`，先用 `id` 回读。
root 命令输出涉及配置时只提取所需字段，禁止整份配置进入日志。

使用现有二进制启动独立临时 sing-box，只开空闲回环 SOCKS 端口，不复用生产 TUN/API/探针端口。
无 TUN、无选择器、无健康历史写入；出站绑定当次物理网卡与已验证绕过标记，本 X96 为 eth0/mark255。
先查该标记的实际路由；通过 ADB 转发临时 SOCKS 后从主机发请求，数据出站仍发生在盒子。
这验证盒子的候选路径，不等同于 SmartTube UID/TUN 或真实影片播放链已切换成功。

设设备端自动退出上限和主控 finally 清理。配置必须受限，启动后取精确进程身份；失联时自动上限仍有效。
探测限时限量，必要复测使用交错的 IPv4 正对照。避免有状态 `/delay` API、PUT selector、重载主代理、清全连接、强停应用或按遥控键。

前后回读前台归属、帧增量/错误、进程身份、配置哈希与实际选路；不同前台的视频样本不能冒充 SmartTube 验收。
主探针以外的观察者看到短暂新连接，要先核是否来自测试进程，不能当作生产迁移证据。
最后核临时监听/配置/ADB 转发已清，正式配置是否迁移独立汇报。
