# 播放诊断与资源语义

## 先定位哪一跳

片库可见只证明目录接口可用。按实际客户端链路检查：搜索/匹配 → 播放清单 → 回源完整分片 → 网关交付 → 终端解码与缓冲。搜索无精确匹配时不能拿第一部无关影片兜底。

手机可见、TV不可见时核各客户端实际连接的服务入口和端口；手机与TV都不能播放时核媒体回源。不能仅凭另一终端成功排除当前终端网络。NAS低负载、NAS到维护机有线吞吐正常，不代表TV/手机无线正常。

只读日志先统计时间窗、端点、状态、字节数和脱敏上下文数。已知自身匿名鉴权探针可按精确特征排除，不能广泛过滤所有401/499来制造健康结果。不要输出完整请求URI（可能含签名）、Cookie、标题或个人观看记录。

## 分片测量

- 持续供给看 `r = 完整分片请求耗时 / EXTINF时长`。从发起请求计时，包含连接、等待响应头和正文；另列TTFB。`r > 1` 表示该样本供给赶不上播放，不能外推整部片或全部源。
- 清单耗时、首包、1KiB范围请求只能证明有限层面的可达性。必须核正文长度/格式及完整读完；对缓存复读校验正文一致。中断或超限样本记“不确定/不完整”，不能伪装成完整速率或断言源已死。
- 完整网络样本、完整缓存命中、加入在途下载分开统计；缓存命中不计入网络速率。请求晚到一秒不证明预取已完成。
- nginx请求间隔不是卡顿时长；206不是正文有效的证明；sid/proof说明采用了新上下文链接，不单独证明稳定选线或预取命中。ASGI到网关耗时不等于播放器缓冲时间。
- 客户端量化A/B需明确终端、同片同线路、时段、开关、观看时长、停顿次数和累计时长；P95需足够起播样本。先检查能否不影响正在看的用户，再安排受控复测。

当前管理员状态入口为 `GET /v/api/ext/status`，只提取 `playback.session` 和 `playback.buffer`；不要原样输出整个响应里的配置。使用已有合法会话，缺少会话时不伪造身份。累计计数需取同一进程的窗口差分；现有指标是进程汇总，不能归因到某个终端会话。下一步根据证据选择：完整网络样本反复 `r>1` 优先评估源和选线；冷测频繁而有效健康样本充足时检查成绩消费与候选排序；缓存命中低且取消浪费高时先查拖动/并发和生命周期；源供给正常但终端仍卡顿时补终端缓冲/解码和无线证据。仅有206/499日志不足以决定扩大预取。

## 修改选线/预取时保留的语义

以可信源码 `proxy/app.py`、`proxy/playback_stability.py`、`proxy/segment_buffer.py` 为准：

- 新自动入口与手动线、历史 `line+auto=1` 分开；首次媒体清单返回后锁源。续播重新评估只能在新上下文发布前，不能拿另一个源的同序号分片拼入旧流。
- 现实现已有300秒内至少3条完整样本的内存健康评分；旧10分钟“最快线”是另一套机制。增强历史排序前先核消费路径，不重复造状态，也不把旧清单延迟当新吞吐成绩。冷测同一时间一个选择上下文、最多两候选，不能误读为总共只测一条线路。
- 普通TS VOD的一段预取是当前保守边界。AES、PNG包装、fMP4、BYTERANGE、live、特殊Range按已有回退路径处理。扩大范围须单独验证格式与Range语义；不能因一条TS成功声称覆盖全部内容。
- 资源预算分别核单段、上下文、全局缓存、在途双份缓冲及冷采样。视频对象预算不是整个Python进程RSS上限；源站持续供给不足不能靠增加缓存永久解决。
- 每请求官方鉴权与按用户隔离仍覆盖缓存命中；有签名链接不等于有播放权限。

## 并发与取消的回归判据

| 场景 | 必须观察的行为 |
|---|---|
| 关闭优化/取消预取，但已有前台等待 | 保留仍有前台消费者的下载，取消无人工作 |
| 取消下载后新请求竞争容量 | 等连接、读缓冲实际清理完成再归还槽位/预算；设置cancel不算结束 |
| invalidate后新请求与旧请求交错 | 新generation不join旧flight；旧退出不能扣减新代计数 |
| 同index更换URL | 无人旧预取先完成本地关闭，新URL再发GET |
| 很长的前台请求结束后新预取 | 空闲时钟从前台结束更新，不能立刻判新任务idle |
| 重复读取刚缓存的段 | 不取消恰好下一段的有效预取 |
| 字节缓冲增长/转不可变bytes | 写入前检查上限并预留双份峰值，不能仅按最终正文长度计账 |

真实HTTP回归观察本地 `aclose` 完成与新GET的顺序，必要时控制资源清理窗口。远端server的aborted记录可能晚于本地关闭；反过来TCP已断也不代表本地缓冲和生产者已清理完。累计max_inflight不证明当前新请求已经启动。等待清理是设计的一部分，但“卡住”是否正常还需核本地清理进度和终态，不能只读代码就排除永久等待或泄漏。旧实现负锚失败、新实现通过，才支持回归的区分力；测试时序修正须保留原行为断言。

测试环境先排除Unix socket路径过长（使用短 `--basetemp`）与可移动Python复制后stdlib定位失败（核正确 `PYTHONHOME`）。不要为测试环境问题修改生产逻辑；不要留下指向已删除临时运行时的全局Python链接。

历史证据：home-lan项目16号诊断、17号方案、18号实施、19号复盘。数字是带日期样本，不是未来验收的默认值。
