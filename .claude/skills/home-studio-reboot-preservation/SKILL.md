# home-studio 重启前保全与找回

目标是让需要保留的文件跨重启可恢复，并给出有时间点、有权限边界的就绪结论。用户说“准备维护”“能否重启”不等于命令你立即重启；按已有保全授权继续复制、校验、备份，不反复申请这些授权。

用户已经完成重启、需要检查系统/服务恢复或排查 Plymouth 启动收尾时，使用 [home-studio-boot-maintenance](../home-studio-boot-maintenance/SKILL.md)。文件找回仍按本技能执行，重启验收不自动触发恢复或再次重启。

## 先找真源

1. 读 `~/AGENTS.md`、`~/mycc/CLAUDE.md` 和 `~/mycc/docs/rules/HOME-STUDIO-STORAGE.md`。确认主机身份、`/data` 实际挂载及可用空间；挂载缺失就停止向 data 写入。
2. 用共享记忆检索 `home-studio-reboot-preservation`，读取存储规则指向的最新归档 README、采集时刻和验收报告。已有可靠基线时先检查增量，不因开启新会话就重新复制或哈希整个归档。机械盘上的批量复制、全量 SHA 与 NAS 扫描串行调度，先并行收集低 IO 元数据，避免多个全盘读任务互相拖慢。
3. 复用本机已有工具时读 [references/existing-tools.md](references/existing-tools.md)；需要了解已验案例和验收层级时读 [references/case-20261102.md](references/case-20261102.md)。历史数字不能替代当前测量。

## 盘点与保全

- 覆盖 `/tmp`、`/var/tmp`、`/dev/shm`、当前用户的 `/run/user/<uid>`，以及仍打开但已删除的普通文件、临时 cwd/exe、transient unit。不输出环境、完整命令行、配置密钥或数据库业务行。
- 清单记录普通文件、隐藏文件、软链接目标、目录（包括空目录）、mode/mtime/uid/gid、扫描失败和挂载边界。socket/FIFO/设备/PID/锁只记录，不当成可复制的进程状态。
- 新私密归档用 `/data/home-studio/archives/` 下有明确时间的目录、权限 0700。保留原路径映射和可读 README；活动源保留，复制更新保留旧版本，不加 `--delete`，不将冷归档用作新的开发工作区。
- 临时 Git/worktree 包括未提交和未跟踪文件。读取 `.git` 指针及 `git rev-parse --git-common-dir`，闭合外部主仓元数据、对象库/alternates依赖；只有工作树源码副本不能证明 Git 可恢复。不要为保全强行提交全部脏仓。
- 在用 SQLite 用只读连接的 backup API 生成新快照，对目标做 `quick_check` 和 SHA256。散拷 DB/WAL 不冒充一致性快照，各库也不假设同一原子时刻；锁超时逐库记录。数据库实际运行位置仍在 NVMe。
- deleted exe 的单个二进制不是完整安装。确需修复缺失运行时，用对应工具的正式安装入口，核真实启动器和应用状态；保全任务不默认授权升级其他软件、停止会话或把诊断任务设为开机启动。

## 验收和收尾

1. 首轮普通文件做源/档案内容哈希，确认哈希期间源稳定；软链核目标，目录核存在及元数据。扫描权限错误与复制成功分开计数，不能只看 rsync 退出码。档案所有者若与源不同，保留原 uid/gid 清单并在恢复时处理。
2. 从独立恢复目录验证有区分力的真实样本：至少覆盖本任务涉及的未提交源码、关键数据库以及一种特殊存放位置/软链。恢复先对可信封存清单核 SHA，再验证应用相关条件；不能只用档案和副本互相一致证明档案没损坏。
3. 沿用实际运行的 Backrest 计划，核其显式来源和排除规则。HOME 里的软链不证明 data 被备份。只读快照树核路径/大小/类型，实际恢复样本核内容；清楚区分二者，不声称已逐文件从 NAS 恢复。
4. 以真实 backup operation 的成功状态、错误数和 snapshot ID 判定备份完成，不能只看请求被接受、配置存在或 hook 成功。用解析后的共享记忆普通文件做恢复验收，禁止跟软链读 live 文件冒充恢复结果。
5. 报告、恢复索引、共享记忆写完后补备份一次；补备份自己的验收报告留待下一次计划，避免为了自引用无限补备份。校验通过后只清理自己创建的恢复测试副本。
6. 正式重启前复核基线后的新增/变化文件、活跃任务、deleted fd 和数据库新写入；已验证文件只做必要增量校验，不重复整盘 IO。新增保全产物和刷新数据库须纳入最后一份成功备份，再核覆盖；分别记录本地采集与 NAS 截止时刻。收尾 `sync`，写共享 `RECENT_EVENTS.md`、必要的原子 memory item 与任务日志；用户要 commit 时只提交本任务的非敏感技能/规则/复盘与记忆增量，私密载荷留 data/NAS。

## 回答“现在能重启吗”与找回

分别报告：①可读文件截至哪个时间已保全、NAS 验到哪层；②当前是否有未保存编辑、训练/编译或需完成的智能体任务；③不可读范围和已知失败。通常文件层面就绪后可安排**正常系统重启**，但执行中的会话和进程内存会终止，不保证原推理原地续跑。不要把历史备份说成“以后随时零丢失”。实际重启仍须有用户执行授权。

恢复时先查旧→新映射、可信哈希和现存源；恢复到不存在的持久目标，不能覆盖活跃文件。源码恢复到 NVMe 项目工作区，独立产物按存储规则使用 data；Git 依赖、路径注册与应用权限逐项核验后再启动。现存主仓仍在使用时，不得用历史 `.git` 覆盖它；优先验证并复用现有对象库，仅注册所需恢复工作树，保护其他工作树。数据库须协调其写入者、保存现状并处理旧 WAL/SHM；不整批恢复历史 socket、锁或 transient unit。
