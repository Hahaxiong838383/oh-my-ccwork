# Mesh Web 接入与真实验收

适用：已加入 EasyTier 的设备新增网页入口，或用户反馈“公网不稳、想改用mesh”“登录后空白、面板不全”。这不是安装新节点或全网调参的指令。

## 先判断缺的是节点还是服务入口

- 先读取设备网络真值，再现查进程、VIP、有效身份及至少一个远端 peer。已有节点不重新分配IP、不复制整个配置覆盖现场。
- 同时查服务实际监听地址。只监听 `127.0.0.1` 的网页不会因机器已入网就自动经mesh可达。
- 新入口优先限制在明确的mesh地址，保留应用认证。不要为了方便直接绑定 `0.0.0.0` 或关闭原认证；启动时VIP尚未出现要有有限重试/服务管理器恢复。
- 已废弃的connector仍需逐机现查。先私有备份，再只删确认失效的条目，运行态与持久配置一致；不为清一条重试记录重启全网或唯一发现节点。
- `node info`、配置和TOML解析异常可能内嵌网络密钥；在进程内筛字段，仅输出必要状态，不能直接回显整份对象。

## 入口选择与浏览器差异

加密mesh不等于浏览器HTTPS安全上下文。需要密码管理器完整支持、麦克风或剪贴板等功能时，应评估可信HTTPS；HTTP仅是已限定私网的具体方案，不推广为默认。

| 症状 | 先核对 | 不应据此做什么 |
|---|---|---|
| 首页200但仍是登录页 | 登录表单、Cookie、认证后的API | 宣称业务已经恢复 |
| 登录后Bot面板空白，但资源与WS成功 | 控制台异常、`isSecureContext`、所需浏览器API | 直接重启EasyTier或改TCP/UDP |
| HTTP私网报 `crypto.randomUUID is not a function` | 是否只有UUID调用失败；库版本与真实调用栈 | 用Math.random替代、假冒安全上下文 |
| HTTP记住登录失效 | Secure/Path/Domain/SameSite、浏览器关闭重开 | 把密码放localStorage |
| 资源探测404而浏览器正常 | HTML实体解码、合并资源清单、实际请求URL | 猜一个插件路径就判服务故障 |

若确认仅缺UUID，可在该入口给缺失实现补基于 `crypto.getRandomValues` 的UUIDv4，先验证格式、版本/variant位、真实浏览器，再部署；不覆盖原生实现，不对公网页面无差别注入。该补丁不会补齐所有Secure Context功能。

复用原生认证的专用网关：先校验外部Host/Origin，再转换为固定上游authority；不能任意信任请求提供的目标。API和WS保持原生鉴权。HTTPS Cookie继续Secure；HTTP私网无法使用Secure Cookie，需明确记录这一边界，且不能把该例外应用于公网。两个入口一般需要分别登录一次。

## 验收与结论

1. 在用户实际设备测匿名页面、密码认证与干净URL重访，凭据只在内存/受限文件里传递；不将token放argv或输出日志。
2. 下载浏览器实际加载的至少一份 ≥1MB 资源，记录字节数、耗时、HTTP状态；禁代理、避缓存，不能拿首页几百字节作为吞吐证据。
3. 真实浏览器确认应用内容、WebSocket、错误日志、关闭重开记住登录、退出及匿名拒绝。自动化在Studio而HTTP在Air，应分别说明，不能声称完成Air浏览器人工验收。
4. 连续观察记录时间窗口、成功/总数、延迟、WS断开数和当时peer路径。不发业务消息、不触发模型调用来替代只读网络测试。
5. 若当前P2P绕开不稳公网入口，可推荐为当前设备的日常路径；换网可能转中继，短测不保证长稳。新入口通过前保留可用回退，切换网页不要求停掉用户正在运行的任务。
