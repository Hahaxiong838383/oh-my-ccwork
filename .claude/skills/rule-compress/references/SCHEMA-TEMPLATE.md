# 规则书写规范模板（万能公式 v1）

> 本模板从 `mycc/docs/rules/SCHEMA.md` 精简而来，用于在新项目中初始化规则压缩结构。
> 正式完整版见 `mycc/docs/rules/SCHEMA.md`。

---

## 4 维优先级矩阵

| 维度 | 取值 | 含义 |
|------|------|------|
| 是否常用 | 必需 / 常用 / 可选 | 实际触发频率 |
| 是否必选 | 必选 / 可选 | 缺了规则还成立吗 |
| 优先级 | P0 / P1 / P2 / P3 | 抽取/加载顺序 |
| 权重 | 0.35 / 0.60 / 0.75 / 0.85 / 1.00 | 连续值打分 |

## P0 规则格式（主文件全文）

```markdown
## N. 规则名

**触发**：在什么条件下生效
**动作**：cc 必须做什么
**反模式**（可选）：禁止什么行为
**Why**：一句话说为什么
```

## P1 规则格式（主文件表格行）

```markdown
| RULE-ID | 触发 | 动作 | P/权重 | Why |
|---------|------|------|--------|-----|
| HANDOFF | 说"留到下个 session" | 追 RECENT_EVENTS + 写 HANDOFF | P1/0.85 | 异步交接零返工 |
```

详细 Why+How+例外 → `docs/rules/<RULE-ID>.md`

## P2/P3 子文件格式

```markdown
# RULE-ID: 规则名

| 字段 | 值 |
|------|-----|
| 优先级 | P2 |
| 权重 | 0.60 |
| 是否常用 | 可选 |
| 是否必选 | 可选 |
| 触发条件 | <什么场景下生效> |

## 动作
<cc 必须做什么>

## Why
<为什么这么做>

## How to apply（可选）
<判断边缘情况>

## 例外（可选）
<什么时候不适用>
```

## RULE-ID 命名

- **大写 + 连字符**：`HANDOFF` / `HOT-CONF` / `TOOL-PRIO`
- **3-15 字符**，全局唯一
- 领域前缀：`FEISHU-CONFIRM` / `FEISHU-FALLBACK`

## 反模式

| 反模式 | 危害 |
|--------|------|
| P0 的 Why 被砍 | 边缘情况无法判断 |
| P2/P3 详情塞回主文件 | 上下文膨胀 |
| 同一规则两处都有详情 | 事实分叉 |
| 没打 RULE-ID | 跨 session 召回失败 |
