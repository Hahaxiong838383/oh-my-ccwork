## 0. 一句话产品定义

**一个能"陪你数年"的 AI 伙伴：在居家与车载两个场景里持续运行，用万能语法把你说的、看到的、做的事统一编码，用液态神经网络（LNN）作为永远在线的心智核心，把记住你这件事做到产品级。**

---

## 1. 它解决什么问题

### 1.1 它不是什么（行业坐标系）

> 它不是 ChatGPT Memory——那只是把你的偏好存成静态卡片，对话开始时贴回 prompt 里。
> 它不是 Mem0/Letta——那是给开发者的记忆中间件，没有连续运行的"它"。
> 它不是 Replika/Character.ai——那是角色扮演型娱乐，不是真正理解你处境的伙伴。
>
> 它是**第一款把"长期连续运行 + 真正记得你 + 跨场景同一个它"作为产品承诺的伴侣型 AI**。

### 1.2 当前 AI 助手的根本性缺陷

| 缺陷 | 用户感知 | 根因 |
|------|---------|------|
| **失忆症** | "我上次跟你说过了" | 上下文窗口 + 简单 RAG 替代不了真正的情景记忆 |
| **断片症** | 关掉对话就清零 | 没有跨会话的连续心智状态 |
| **场景割裂** | 家里、车里、手机互相不认识 | 缺少统一的事件 schema 和跨设备记忆同步 |
| **黑箱学习** | 它学了什么用户不知道 | 没有用户可读、可改、可删的记忆界面 |

### 1.3 产品承诺（一年内可验证）

1. **它会记得**：能回答"上周三晚上和谁吃饭"、"我最近一周心情怎么样"
2. **它会变化**：用一个月后的它，比第一天更懂你——不是更"聪明"，是更"懂你"
3. **它在场景间无缝**：早晨在家说的事，下午在车里它还知道；晚上回家继续接着聊
4. **它知道边界**：你能看到它记了什么、能让它忘掉什么、能把记忆带走
5. **它会让你看见**：每天它新学到了什么、对你的理解如何变化、哪些是它推断的而非你说的。你可以纠正、降权、删除——把"AI 学习你"从黑箱变成对账单。这是行业首创

## 2. 用户与场景

### 2.1 首批种子用户画像（10 → 25–50）

- **核心人群**：30–45 岁，家庭+通勤双场景，技术好奇但不一定 geek
- **共性需求**：希望有个"懂自己"的助手处理生活琐事 + 偶尔的情绪陪伴
- **差异化筛选**：愿意签授权协议接受多模态记录、愿意每周给反馈、愿意忍受 v0–v1 的不完美

### 2.2 三大产品场景 + 60 秒微剧本

#### 场景 A · 居家：早晨—夜间连续陪伴

> **微剧本**（早晨 7:30）
>
> 「早，今天精神看起来比昨天好。昨晚 11 点睡的，比上周平均早一小时。」
> 用户："今天有什么安排？"
> 「上午 10 点和小李的需求评审——上次他提的那个改版方向你说要再想想，要不要现在花十分钟整理一下要点？另外提醒一下，下午 3 点到 4 点你之前说要留给写代码的专注时段，我会把消息屏蔽。」
> 用户："3 点的会议改一下，我忘了王总今天来。"
> 「好，那我把专注时段挪到 5 点之后？还是干脆今天放弃专注，明天早上补？」
>
> **它做对了什么**：记得昨晚睡觉时间、记得上次评审的争议点、记得"留给写代码的专注时段"是用户原话、面对冲突给出可决策选项而不是自作主张。

#### 场景 B · 车载：通勤场景

> **微剧本**（晚 19:15，下班回家路上）
>
> 系统检测到：晚高峰、下雨、用户语速比平时慢 15%。
> 「晚上好。今天看着挺累的。要听今早那个评审的会议总结，还是放点音乐？」
> 用户："放点轻的吧。"
> 「在听之前——你今早提的那个王总会议，已经记完要点了，回到家可以让我念给你听。这个不急。」
> 系统播放用户偏好的轻爵士。28 分钟后到家。
> 「到了。今天值得记一下：你忍住了没在评审里反驳小李，回头他自己想通了。这是这个月第三次。我把它加进了'你正在变得更耐心'这条画像里——你确认还是删掉？」
>
> **它做对了什么**：从家里场景迁移记忆没断、识别情绪状态主动调整方式、把零散事件归纳为"你正在变得"的人格观察、问用户确认而不是偷偷记下。

#### 场景 C · 跨场景记忆贯通

> **微剧本**（连续三天）
>
> **周一早晨**（家里）："最近膝盖跑步老疼，可能要换鞋了。"
> **周二上午**（车里）："今天午饭去哪？" → 「公司楼下那家越南粉，你上周三说汤底偏咸了——离你新提的'少盐'目标有点远。换隔壁那家清炒？」
> **周三晚上**（家里）："那个跑步鞋的事我快忘了。" → 「你周一早晨在家里说膝盖疼。我推断你可能在找缓震好一点的，要不要我把上次你说喜欢的那两个品牌列一下？」
>
> **它做对了什么**：周一在家里说的话周三还能精准回溯（场景切换无失忆）；不仅记得话还能从话推断意图（少盐 → 换餐厅）；明确说"我推断"而不是冒充事实——可解释。

**Why**：剧本不追求完美——保留了"问用户确认"和"我推断"的不完美，因为真实产品就是这样运作的。

## 4. 系统架构总览

### 4.1 七层认知架构 + 万能语法横切骨架

```
┌─────────────────────────────────────────────────────────┐
│ L7  共生协议  · per-user LoRA + 槽位偏好向量            │
│ L6  元认知    · 槽位置信度 + 心流监控                   │
│ L5  意图共情  · LLM + 主动推理（v0 规则）               │
│ L4  自传记忆  · Graphiti KG + 万能语法 20 槽            │ ← 记忆系统核心
│ L3  处境理解  · LLM + schema-guided 槽位补全            │
│ L2  工作记忆  · LNN τ≈分钟（CfC 慢层）                  │
│ L1  感知层    · LNN τ≈秒（CfC 快层）+ 多模态特征       │
└─────────────────────────────────────────────────────────┘
        ↑                    ↑                    ↑
    [万能语法 20 槽事件张量贯穿 L2–L5 横切骨架]
```

### 4.2 关键技术选型

| 层 | 技术选型 | 理由 |
|----|---------|------|
| L1–L2 LNN | `ncps` 库 LTC/CfC，两层 64+32 神经元 | 唯一在 12 月内可工程化的液态网络方案 |
| 多模态感知 | Qwen3-VL-7B（云）+ Qwen3-VL-2B / LFM2（端） | 国产可用 + 端侧兜底 |
| 语音 | Fun-ASR / GLM-ASR-Nano-2512 | 中文方言+地方口音覆盖 |
| L3/L5 LLM | DeepSeek-V4 主 + GLM-5.1 自托管 fallback | 双 provider 灰度 |
| L4 记忆 KG | Graphiti（fork 自 getzep/graphiti） | 唯一成熟 bi-temporal KG |
| 个性化 | LoRA on LLM + 偏好向量 + BitFit-on-LTC | State-offset Tuning 不可行（详见研究 §1.4） |
| 事件分割 | v0 规则 + LLM 心跳；v1 On-GEBD-on-LNN | 流式多模态无现成方案 |

### 4.3 万能语法 20 槽 schema（横切骨架）

- **P0（权重 1.00）**：句子类型 / 主语 / 谓语 — 必填，未填触发主动澄清
- **P1（权重 0.75–0.85）**：时间 / 地点 / 直接宾语 / 补语 — 情景检索主排序键
- **P2（权重 0.60）**：时态 — 时间感知 KG 的辅助推理
- **P3（权重 0.35）**：修饰词 / 连接词 — 仅向量化，不进符号检索

**Why 这是核心 IP**：跨模态、跨设备、跨子系统都用同一份 20 槽 schema，省掉所有中间转换层；填充率/置信度天然可解释；per-user 偏好向量直接低维可学。

## 5. 记忆系统架构（产品定义级）

> 内容由 codex（gpt-5.4）深度审视，cc 整合。技术依据见 [`source-research.md`](source-research.md) §1.1–§1.4 / §2.1 / §3.2 / §3.3 / §4.1。

### 5.1 记忆系统的产品角色定义

记忆系统不是"聊天记录仓库"，而是伴侣智能体的**连续关系引擎**。三个可感知场景：

- **早晨**：基于昨夜 consolidation 产出"今日精华回顾 + 一条行动建议"
- **通勤**：优先读取近 24h 情景记忆，主动避开你不喜欢的提醒方式
- **夜间**：展示"今天新增了哪些长期记忆"，你可一键保留、降权或删除

**Why**：把"记住"变成用户每天可验证的体验闭环，避免记忆能力只停留在后台指标。

### 5.2 三层记忆架构（产品视角）

#### L1 · 工作记忆（秒~分钟）—— 承载"正在发生什么"

| 维度 | 产品定义 |
|------|---------|
| **写入触发** | 新事件进入当前会话窗口；P0 槽更新；事件边界未成立时持续覆盖 |
| **读取场景** | 实时对话接续、打断恢复、连续追问 |
| **遗忘策略** | 超时衰减（5–30 min）；新事件覆盖；只把高价值上卷到 L2 |
| **失败回退** | L1 异常时回退到"最近一次 L2 快照 + 当前用户原话"，确保不中断 |

**Why**：L1 追求"连贯不断线"，不是"永久记住"。

#### L2 · 情景记忆（小时~天）—— 承载"何时何地与谁做了什么"

| 维度 | 产品定义 |
|------|---------|
| **写入触发** | 事件分割门控判定 boundary 成立；关键槽位完整度达标；用户显式说"记一下" |
| **读取场景** | 回答"上周三晚上和谁吃饭""今天下午会议决议"；生成日内复盘 |
| **遗忘策略** | bi-temporal 生效期管理；低价值情景自动降权归档；重复事件去重合并 |
| **失败回退** | 中文实体抽取质量下降时降级为"时间过滤+关键词/BM25+向量召回"混合检索 |

**Why**：L2 是"可检索事实层"，要先保证能找回，再追求复杂推理。

#### L3 · 语义/人格记忆（周~年）—— 承载"主人是怎样的人"

| 维度 | 产品定义 |
|------|---------|
| **写入触发** | 夜间 consolidation 提升高频偏好、稳定习惯、长期价值观；用户主动确认 |
| **读取场景** | 个性化语气、建议风格、主动行为阈值；跨周连续陪伴 |
| **遗忘策略** | 置信度随时间衰减；与近期行为冲突时触发"待确认"；未确认特征不进强人格 |
| **失败回退** | 个性化模块不可用时回退到"通用人格基线 + 最近 7 天 L2 事实"，避免性格突变 |

**Why**：L3 的价值是"长期一致性"，不能让短期噪声直接改写人格。

#### L3 技术原理（v0.3.x · LNN 原生轻量个性化三件套）

> v0.3.1 替代原 v0.3 的 LoRA per-user 方案。原方案问题：50MB/用户 + 单卡 24GB 微调，10 用户即排队，规模化路径空白。新方案在 LTC 数学结构内做个性化，3KB/用户，CPU 可推理，10K 用户同服务器无压力。

**三件套**：

1. **Per-user τ 偏置**（< 1KB/用户）：在 LTC 时间常数上加 per-user 偏置向量 Δτ_user，决定"什么信息在该用户的 LNN 隐状态里留多久"——LTC 原论文（Hasani et al. 2021）中 τ 本就是可学参数，加 per-user 偏置是数学结构内生延伸，方程仍是 `dx/dt = -x/(τ+Δτ_user) + f(input, state)`，不破坏 ODE 形式
2. **输入侧 FiLM 调制**（~2KB/用户）：`f(γ_user · x + β_user, state)`，等价于"用户特化的输入透镜"。Perez et al. 2018 在 ResNet/Transformer 验证 7 年成熟。冷启 γ=1, β=0 即"无个性化"，渐进展开
3. **万能语法槽位偏好向量**（80 字节/用户）：直接注入 LNN 输入维度，和 §1.4 万能语法核心 IP 完美契合（之前 LoRA 路径其实没用上这个 IP）

**LLM 语言风格个性化**：
- 路径 1（MVP α 默认）：偏好向量序列化为 system prompt 注入，零训练成本，秒级生效
- 路径 2（M7+ 评估后）：极轻量 LoRA rank=2，仅当路径 1 推理 token 成本 > 训练摊销时切换

**与 v0.1 否决的 State-offset Tuning 区别**：
- State-offset 直接加在连续时间状态 x 上 → 破坏 ODE 求解 → v0.1 否决
- v0.3.x τ 偏置作用在衰减常数、FiLM 作用在输入侧 → ODE 形式不变 → 是 v0.1 否决的延续修正而非推翻

**M2-M3 必须校验**（进三色判定）：① τ 偏置容量曲线（1/4/16KB 行为区分度）② FiLM × LTC 训练稳定率（loss 发散用户比例）③ system prompt 平均 token 长度（>1000 红 / 500-1000 黄 / <500 绿）

**潜在学术贡献**：M2-M3 容量曲线如果对数收敛（小预算大收益），M6 启动论文准备《Per-user τ-Bias for LTC Networks》——LNN 学术界目前几乎空白。详见 [`memory-architecture.md`](memory-architecture.md) §7。

### 5.3 万能语法 20 槽作为记忆 schema 的承诺与边界

#### 它解决什么（承诺）

- **跨模态对齐**：语音/文本/视觉都落同一 Event Tensor
- **检索写入同 schema**：写入 KG 字段与检索字段一致，减少"写得进、找不回"
- **可解释**：槽位填充率、缺失槽、置信度可直接展示给用户

#### 它解决不了什么（边界）

- 情感/态度的细腻变化无法完整落入固定槽位，容易"语义过压缩"
- 长尾叙事（跨多天、多角色、含反转）会被切分后丢失叙事张力
- 价值判断类内容（"我为什么后悔"）仅靠槽位字段不足以表达因果链

**Why**：先承认固定槽位是"高吞吐结构化工具"，不是"完整心理模型"。

#### 槽位外溢通道：分阶段实现

| 阶段 | 实现 |
|------|------|
| **v0（M0–M4）** | **不做自动判断**——记忆卡片上加"这条记得不全，让我详细说说"按钮，由用户主动触发 |
| **v1（M5+）** | 基于 v0 用户行为数据，训练自动外溢判断模型 |

**结构**：`Overflow Capsule = 事件ID + 自由文本摘要 + 情绪轨迹 + 证据引用`。

**场景差异化**：
- **车载场景**：只走槽位检索，外溢内容不参与，保证延迟
- **居家场景**：可启用二级检索，槽位命中置信不足时再展开

**Why**：v0 优先让用户教系统"哪些值得详细记"，比让系统自动猜更稳。

### 5.4 CLS 离线 Consolidation 的产品仪式感

夜间 consolidation **不是后台批处理**，而是用户每天可感知的"关系更新时刻"。

> **对外用户界面采用有温度的命名，对内工程文档保留代号——这是产品和工程的分层。**

#### 5.4.1 可见产品行为

| 工程代号（内部） | 用户界面命名（对外） | 内容 |
|----------------|------------------|------|
| 今日精华回顾 | **「今天」** 或 **「今日小结」** | 3 条以内："事实-情绪-未完成事项" |
| 主人画像微调 | **「我对你的新理解」** | 本周新增/减弱的偏好 + 证据来源 |
| 记忆变更日志 | **「记忆账本」** | 新增了什么、合并了什么、降权了什么 |

#### 5.4.2 用户可干预点

- 对每条精华：保留 / 降权 / 删除 / 标注"理解错了"
- 对画像微调：确认生效 / 延迟观察 / 永久拒绝该类推断
- 对 consolidation 策略：仅本地 / 允许云侧 / 完全关闭

#### 5.4.3 用户可授权点

- **授权范围**：仅设备内 / 加密云备份 / 跨设备同步
- **授权时长**：一次性 / 7 天 / 常开
- **授权对象**：记忆计算 / 模型微调 / 匿名改进样本——三项拆分授权

**Why**：授权颗粒度越细，长期留存越稳。

### 5.5 记忆系统单独的关键路径与里程碑（压缩后 M0–M12）

> **KG 治理是 M5 起逐步建设、M11 全量生效——主动设计而非应急降级。** 如果建设滞后才被动启用，详见 §5.6 风险 ②。

| 月 | 记忆相关关键路径 | 用户可感知的记忆升级 |
|----|----------------|-------------------|
| M0 | 20 槽 schema 冻结 + Graphiti 接入 + UniversalGrammarParser v0 | 用户能看到结构化条目；时间感知问答能用 |
| M1 | LNN Layer 1-2 雏形 + L1/L2 联动 | 不跳线、不失忆；追问能跟住 |
| M2 | 事件分割门控 + 状态摘要工具链 | 噪声下降，回溯成"片段故事" |
| M3 | 个性化偏好接入 + 多设备同步基础 + **记忆"读/删"界面 v0** | 风格"像我习惯的方式"；用户首次能看到 AI 记了什么、并删除任意一条 |
| **M4** | **MVP α 记忆系统验证** | 6/10 用户感到"它真的记得我" |
| M5 | CLS 雏形 + 居家→车载场景迁移 + KG 分层雏形启动 + **记忆"编辑"界面 + 「记忆账本」v0** | 「今日小结」首次出现；用户能修正 AI 的错误理解 |
| M6 | 车载噪声鲁棒性 + 端侧 LFM2 兜底 | 不同场景说同一件事不"失忆重来" |
| **M7-M8** | LoRA + 偏好向量 + BitFit 三件套联动 | 长期习惯被稳定继承，回复语气更一致 |
| M9 | 记忆驱动主动建议（疲惫/专注） | 打扰感下降；建议接受率 ≥ 30% |
| M10 | 跨设备稳定 + 个性化 v1 | 跨设备保有连续个人记忆 |
| M11 | **长期 KG 治理全量生效（热/温/冷分层 + 自动归档）** | 30 天零重大记忆丢失 |
| M12 | L6/L7 启动（元认知 + 共生协议） | 元认知开始辅助决策；18 月架构成型 |

### 5.6 对抗性审查：3 个最可能让记忆翻车的风险

#### 风险 ① 中文 entity extraction 质量不稳

- **翻车场景**：用户用口语、方言、代词省略后系统抽错"谁做了什么"
- **早期信号**：`P0 槽冲突率`升高；同一人名出现多别名节点；用户纠错率周环比上升
- **降级**：切换"弱图强检索"——时间过滤+关键词+向量召回，并加"记忆置信提示"

#### 风险 ② 长期连续运行导致 KG 膨胀

- **翻车场景**：3–6 个月后节点和边暴涨，查询变慢、重复事件堆积
- **早期信号**：`日新增节点 / 有效检索贡献节点`比值失衡；P95 检索时延持续上升
- **降级**：**如果 §5.5 中 M5–M11 的主动 KG 治理建设滞后，应急启用热/温/冷分层 + 强制归档**——这是兜底而非主路径

#### 风险 ③ 隐私授权撤回后的级联清理失败

- **翻车场景**：删除主库后衍生摘要、向量索引、LoRA 适配痕迹仍残留
- **早期信号**：删除后仍可被近义检索命中；审计日志"主删成功、副本未删"不一致
- **降级**：执行"撤回即冻结"两阶段——先停读取，再异步级联清理；未清完前对外回答强制屏蔽

**Why（贯穿三大风险）**：记忆系统首要目标是"不乱编、不膨胀、不偷藏"——这是信任底线。

### 5.7 隐私与可控性产品规范

#### 5.7.1 三键开关（默认显性）

| 键 | 控制 |
|---|------|
| **录音键** | 是否采集原始语音/环境音 |
| **记忆键** | 是否把当前会话写入 L2/L3 |
| **共享键** | 是否允许记忆用于跨设备或云侧能力 |

最小规则：三个开关相互独立，任何时刻可切换；关闭即刻生效于"后续写入"，并提示"历史数据处理选项"。

#### 5.7.2 读 / 编 / 删一段记忆

- **读**：搜索框输入自然语言+时间筛选 → 记忆卡片含"事件摘要、时间、来源、置信度、是否影响画像"
- **编辑**：改文本/改关键槽位/标注"理解错误类型" → 立即更新主记录 + 触发下游索引重建 + 保留版本
- **删除**：软删除（24h 可恢复）或硬删除（立即级联清理）→ 返回"已删除范围"+审计编号

**Why**：编辑必须立即生效；删除反馈必须可核验，避免"看似删除、实际残留"。

### 5.8 记忆系统在系统架构中的位置回看

```
   用户开关 ──┐
            │
[录音][记忆][共享]
            ↓
[Multi-modal Sensors] → [Universal Grammar Parser]
                              ↓
                       [EventTensor: 20 slots + Overflow Capsule]
                              ↓
                ┌─────────────┴─────────────┐
                ↓                           ↓
          L1 工作记忆                  Event Boundary Gate
                                            │ boundary=true
                                            ↓
                                      L2 情景记忆 (Graphiti KG)
                                            │
                                       夜间 Consolidation
                                            ↓
                                      L3 语义/人格记忆
                                            │
                                            ↓

                                            ↓
                                      [用户可读/编/删]
```

**Why（架构总命题）**：三层记忆协同 + 万能语法 schema 横切 + 用户可治理——共同支撑"陪伴 = 关系而非会话"。

## 6. 冷启动数据策略

> **背景**：种子用户只有 10 人，真实多模态日志远不足以训练 LNN 和验证记忆系统。但 AI 工具能大规模生成模拟数据。

### 6.1 三类合成数据的产出策略

#### 类型 1：日常交互对话语料

| 维度 | 设计 |
|------|------|
| **来源** | DeepSeek-V4 / Qwen3-VL / Claude Opus 4.7 / GPT-5.5 多模型联合生成 |
| **形式** | 单轮+多轮对话脚本，覆盖典型场景：早晨规划、通勤、工作专注、情绪低谷、夜间反思、家庭琐事、健康话题、关系处理 |
| **量级** | M0–M1 内产出 1 万条，每条已用 20 槽预填充作为 ground truth |
| **用途** | 训练 `UniversalGrammarParser` 槽位填充准确率；作为 LNN Layer 1-2 预训练监督信号 |

**Why**：四模型联合生成而非单一模型，是为了让槽位 ground truth 不被某一模型的偏见污染——交叉一致的样本才进训练集。

#### 类型 2：长期记忆轨迹模拟

| 维度 | 设计 |
|------|------|
| **来源** | LLM 生成"虚拟主人"——同一虚拟人格在多日内的事件序列、情绪变化、关系演化 |
| **形式** | 每个虚拟主人产出连续日历事件 + 对话片段 + 心情标签 + 关系图谱演变 |
| **量级** | 50 个虚拟主人 × ≥30 天连续轨迹（部分扩展到 90/365 天） |
| **用途** | 训练自传记忆 bi-temporal 推理；验证 CLS pipeline；测试 KG 长期膨胀处理 |

**Why**：30 天连续轨迹是验证 L3 人格记忆能否"稳定继承长期习惯"的最低必要长度。

#### 类型 3：日常使用 Claude/Codex 的真实交互记忆（v0.3 用途收窄 + 三层脱敏）

| 维度 | 设计 |
|------|------|
| **来源** | 团队成员（首先是老板自己）日常使用 Claude Code、Claude Web、Codex 的真实工作和生活交互 |
| **形式** | **经过三层脱敏 + 老板亲自一审**的对话记录、长期项目讨论、跨周连续话题 |
| **量级** | M0–M3 累积 100+ 小时真实交互 |
| **用途收窄（v0.3）** | **仅用于训练对话连贯性和长上下文跟踪**——不用于训练人格画像、不用于训练情感识别、不进入 L3 人格记忆训练 |
| **占比限制（v0.3）** | 在所有训练数据混合中占比不超过 20% |

**Why 用途收窄**：程序员 / 产品经理 + AI 工具的对话风格，和真实种子用户（30-45 岁普通人，技术好奇但不 geek）人口结构完全不同。如果让 LNN 的"长上下文连续性"金标准全靠这个，模型可能学会"懂程序员"而不是"懂普通人"。

**三层脱敏 + 一审制**（v0.3 强制流程）：

| 层级 | 处理 | 谁负责 |
|------|------|--------|
| **L1 内容过滤** | 删除商业敏感（项目代码、客户名单、谈判内容、第三方私密信息） | 数据贡献者本人初筛 |
| **L2 实体替换** | 命名实体替换：人名→角色（"老板"、"同事 A"），公司名→行业类别，产品名→品类 | 数据工程师执行（脚本+人工抽检） |
| **L3 老板一审** | 老板本人作为最终审核人，每批数据进训练前签字确认 | 老板 |

**Why**：v0.2 只写"经过脱敏"过于模糊。这种数据风险大、决策权重高，必须有清晰的责任链。

### 6.2 合成数据的能力边界（诚实声明）

| 能解决 | 不能解决 |
|-------|---------|
| 槽位填充准确率冷启动 | 真实人类情感的复杂性 |
| 记忆检索的 schema 训练 | 车载噪声等真实环境信号 |
| KG 工程链路的端到端验证 | 跨设备真实使用模式 |
| CLS pipeline 的离线测试 | 心流状态的真实生理特征 |

**必须用真实用户验证的指标**：留存、主观满意度、记忆"准确度的人类感知"、心流监测的有效性。

**Why**：合成数据是"伪用户"——不能替代真人对产品的判断。混淆这两件事是激进时间线最容易踩的坑。

### 6.3 合成数据工程化 pipeline

| 组件 | 设计 |
|------|------|
| **数据生成器** | M0 第 1 周建立 `synthetic-data-generator/`，配置多 LLM 路由 |
| **质量评估** | 每批数据自动评估：P0 槽位完整度、槽位间一致性、长期轨迹连贯性、模型间交叉一致率 |
| **数据版本化** | DVC 或 LFS 管理；每个数据集打 hash；模型训练记录用了哪批数据 |
| **持续更新** | 随项目进展定期生成新批次，覆盖新出现的场景类型 |

**评估指标硬阈值**：
- P0 槽位完整度 ≥ 95%
- 模型间交叉一致率 ≥ 75%（低于此线整批丢弃）
- 长期轨迹中"虚拟人格漂移率" ≤ 5%

**Why（章节总命题）**：合成数据是激进时间线下的"伪用户"——能让 LNN 在没有真实用户的前 6 个月就开始训练。但它的局限性必须在产品哲学里被诚实承认，否则真实用户的真实反馈会让我们措手不及。

### 7.2 M2-M5 惊喜时刻清单

> 每个时刻是用户告诉朋友"我用了一个 AI 它真的⋯⋯"的素材。必须刻意埋点、刻意演练。

| 时刻 | 触发月 | 设计要点 |
|------|-------|---------|

### 7.3 vibecoding 提速失败的回退机制（红/黄/绿三色判定）

不是单点判断、不是脆触发，是三次渐进早期预警 + 红黄绿三色判定：

| 评估时点 | 检查项 | 红区（立即回退） | 黄区（加强不回退） | 绿区（按计划） |
|---------|-------|----------------|-----------------|--------------|
| **M1 末** | P0 召回 / Graphiti 中文闭环 / 合成数据 pipeline | P0 < 60% 或 Graphiti 完全不可用 或 pipeline 没跑通 | P0 60-80% / Graphiti F1 < 0.5 / pipeline 跑通但质量不稳 | 全部达标 |
| **M2 末** | LNN Layer 1-2 状态有效性 / 事件分割 v0 可用性 | LNN 训练完全发散 或 事件分割 F1 < 0.3 | LNN 状态弱可用 / 事件分割 F1 0.3-0.5 | 全部达标 |
| **M3 末** | 整体进度 vs vibecoding 预期 | 滞后 > 50% | 滞后 30-50% | 滞后 < 30% |

**红区行动**：M4 改为"内测 demo（仅团队内部）"，外部种子用户推到 M5 / 进一步推到 M6 / 回退到 M5 上 MVP α
**黄区行动**：保持 M4 节奏 + 该项目加配资源 + 下次评估前必须爬出黄区
**绿区行动**：按计划推进

**Why（红黄绿）**：刚性"任一项不达标"在新工程 M1 末几乎必然触发，摧毁团队心理动量本身就是激进时间线的失败模式。三色判定让"亚黄区"——刚低于阈值但有上升趋势——继续推进，避免误杀好状态。

### 7.4 vibecoding 协作如何让时间线成立

| 角色 | 主导工作 |
|------|---------|
| **Claude Code（cc）** | 架构设计、代码实现、文档生成、测试编写 |
| **Codex（gpt-5.4）** | 工程规范深挖、对抗性审查、边界条件、性能优化 |
| **老板（人）** | 产品决策、用户访谈、最终架构判断 |

4 人 + vibecoding ≈ 传统 8–10 人团队的产出。这是把 M6 → M4 的根本依据。

**协作磨合期（M0 第一周必须跑出 SOP）**：vibecoding 提速最大的不确定性不是"代码写得多快"，是协作磨合期。M0 第一周不是开发期，是"vibecoding 协作流程定型期"——PR 三道门、文档双引擎、milestone 前置防御清单的具体操作流程必须在第一周建立，否则前两周熟悉过程会拖慢整个 M0。

## 9. 风险与降级矩阵

| 风险 | 严重度 | 早期信号 | 降级路径 |
|------|-------|---------|---------|
| 国产 LLM API 限流/降速 | 🔴 高 | 周级延迟波动 > 30% | 双 provider 灰度 + 本地兜底 |
| Graphiti 中文 entity 质量差 | 🔴 高 | M2 闭环测试 F1 < 0.6 | 退化到向量+关键词索引 |
| 用户真实付费意愿/使用频率未知 | 🔴 高 | M4 验证后留存断崖式下跌 / 用户访谈反馈分裂 | M2-M3 提前做"假门测试"——给种子用户看 demo 视频问"你愿意每月付多少钱" |
| **合成数据污染 LNN 训练**（v0.3 升级） | 🔴 **高** | M2 末用真实种子用户对照测试，模型在真实用户数据上表现 < 合成数据测试集 70%；模型间交叉一致率持续低于 75% | **立即停止合成数据训练**，全部回退用真实数据 + 多模态大模型直出；考虑承认时间线压缩失败回到 v0.1 节奏 |
| LNN 多模态训练不稳 | 🟡 中 | 梯度爆炸 / 推理 > 100ms | LSTM/GRU mock，先把流水线跑通 |
| State-offset Tuning（已知失败） | ✅ 已规划 | — | 已采用 LoRA + 偏好向量 + BitFit |
| 事件分割长尾不鲁棒 | 🟡 中 | M2 评测 F1 < 0.5 | 纯 LLM 规则替代 |
| 车载集成成本被低估 | 🟡 中 | M5 找不到合作车厂 | Jetson + USB 投屏，不验证集成只验证算法 |
| 隐私合规风险 | 🟢 低 | 用户提撤回时清理不全 | 默认本地优先 + 端到端加密 + 可审计删除日志 |

**Why（合成数据污染升级到 🔴）**：v0.2 时间线压缩的根本依据是"用合成数据替代真实数据冷启动"。如果合成数据污染训练，整个时间线压缩基础崩了——这不是"中等风险"，是"产品方法论存亡级风险"。

## 10. 不可妥协 vs 可妥协（v0.3 重组为技术 + 产品双组）

### 10.1 六项不可妥协（12 月内必须做出来）

#### 技术不可妥协（核心架构必须立住）

1. **万能语法 20 槽作为全系统共享 schema**（核心 IP / 护城河）
2. **多时间尺度 LNN 心智核心（哪怕只有两层）**（区分于纯 LLM agent 的关键）
3. **CLS 双系统离线 consolidation 流程**（"数年长期连续运行"的工程基础）

#### 产品不可妥协（差异化体验必须做到）

4. **per-user 个性化栈**（"特别懂主人"的算法基础。**v0.3.x 实现路径**：LNN 原生轻量个性化三件套 = τ 偏置 + FiLM + 槽位偏好向量，3KB/用户，CPU 可推理；LLM 语言风格走 system prompt 注入，M7+ 评估后可选启动 LoRA rank=2。详见 §5.2 L3 技术原理段）
5. **居家+车载双场景统一架构**（市场定位的核心）
6. **用户可见、可编辑、可治理的记忆界面**（"AI 学习你"从黑箱变成对账单——行业首创）

**Why（拆分理由）**：技术不可妥协决定"系统能不能立住"；产品不可妥协决定"立住后用户为什么选我们"。两套并列、缺一不可。

### 10.2 可妥协（M4 MVP α 可降级）

- 主动推理可以是规则化的，不必跑真实 free-energy 最小化
- 心流监控可以是简单启发式（专注时长、切换频率）
- 现象学时间意识在工程上就是"多时间尺度 + 事件分割"
- Layer 6/7 在 M4 MVP α 可完全 mock；M12 启动真实实现

### 11.2 vibecoding 工程方法论

- **每份代码 PR 经过 cc 实现 + codex 对抗审查 + 人最终判断**——三道门
- **每份文档 cc 主写 + codex 提对立观点 + 人定调**——避免单一视角偏见
- **每个 milestone 启动前 codex 做"5 个最容易翻车的点"清单**——前置防御
- **每周一次 cc/codex 联合 retro**：复盘上周 PR 质量，调整协作模式

#### 11.2.1 AI 同事的责任边界（v0.3 新增）

| 主体 | 责任 |
|------|------|
| **Claude Code（cc）** | 产出代码 / 文档 / 测试用例。**不是责任主体** |
| **Codex** | 对抗审查 / 边界条件提示。**不是责任主体** |
| **对应人类工程师** | 所有 AI 产出的 PR、文档、测试，必须由人类工程师署名确认后才合并 |
| **架构 lead（老板）** | 跨模块决策的最终责任人 |

**核心原则**：AI 是工具不是替罪羊。这一条不是法律免责，是工程纪律——避免出 bug 时大家互相推给 AI。

**具体执行**：
- 所有 PR 描述里必须写明"AI 协作贡献" + "人类工程师确认人"
- Code review 不能写"AI 生成的代码看起来 OK"——必须给出实质审查意见
- 出问题的 post-mortem 不归咎于 AI，归咎于"哪个环节的人类审查没到位"

### 11.3 算力与成本（月度估算）

- 训练/实验：2–4× RTX 4090 或 1× A100 80GB → ≤ 3 万 RMB/月
- LLM 推理 + 合成数据生成：OpenRouter 统一接入 → 1–3 万 RMB/月（M0–M1 集中支出 +2 万一次性）
- 端侧硬件：Jetson Orin Nano（~3000 RMB/台）
- **MVP β 阶段总月成本估算：5–8 万 RMB**

## 13. Caveats（局限性与不确定性）

- 本产品定义基于 [`source-research.md`](source-research.md) §Caveats 的所有不确定性，不重复列举

### 13.1 MVP α 验证标准（v0.3 双门 + 四象限）

两个独立门，独立诊断：

**用户行为门**（验证产品方向）
- 必要：10 名种子用户中至少 6 名第 2 周仍主动使用
- 必要：周交互 ≥ 5 次，每次 ≥ 3 分钟
- 必要：2 周内无超过 3 次系统级崩溃
- 理想：8 名以上日均 ≥ 5 分钟连续 2 周；至少 3 名主动表达"它真的懂我"

**能力门**（验证技术路线）
- 必要：记忆系统能正确回答 60% 的"你还记得吗"类问题
- 必要：万能语法 P0 槽召回 ≥ 90% / P1 ≥ 70%
- 必要：事件分割与人工标注一致率 ≥ 0.5
- 理想：记忆正确率 ≥ 75%；P0 召回 ≥ 95%

**四象限行动决策**：

| 用户行为门 | 能力门 | 含义 | 行动 |
|----------|-------|------|------|
| 过 | 过 | 双赢 | 按计划进入 M5；可考虑提前扩用户 |
| 过 | 不过 | 用户喜欢但记忆没立住 | M5 暂停新功能，专攻记忆质量；调研用户为何喜欢（可能是别的原因） |
| 不过 | 过 | 技术行但产品方向有问题 | 暂停工程，做用户访谈+假门测试，可能要重新定义产品 |
| 不过 | 不过 | 两件事都有问题 | 回炉重做，分别诊断哪边更要命 |

**Why**：单一门会出现"留存达标但记忆质量差"或反过来的尴尬——把"记忆系统差"的信号埋掉，或在错误方向加速。两个独立信号、两个独立诊断路径。

### 13.2 哲学补丁

**激进时间线下最大的失败模式不是技术做不出来，而是用错误的标准否定了正确的进展。MVP α 的目的是验证产品方向，不是验证产品成熟度。** 必要门槛过线就继续，别强求理想门槛。

### 13.3 老板三重身份的潜在偏差（v0.3 新增）

老板既是类型 3 数据主要提供者、产品决策人、潜在早期用户。这种身份重叠可能导致"老板视角偏差"——模型在老板使用习惯上过拟合、产品决策被老板个人体验过度影响、产品方向偏向老板个人需求而非真实种子用户。

**缓解措施**：
- M2 假门测试必须包含至少 5 名与老板画像不同的用户（不同年龄段、不同职业、不同技术熟悉度）
- M4 MVP α 验证采用"10 名独立种子用户主验证 + 老板作'第 0 号用户'平行体验"双轨制——老板独立计数提供深度定性观察，但不进入 6/10 留存等量化样本统计
- 产品决策有重大分歧时引入第三方用户研究
- 类型 3 数据中老板个人贡献占比不超过 50%（避免单人风格主导）

**Why**：这种身份偏差比技术风险隐蔽得多。技术问题会通过指标暴露，但"老板视角偏差"只有真实用户上线后才会暴露——那时候已经晚了。

### 13.4 范围外

- 12 月之外（自研芯片 / 隐私合规深化 / 心流硬件传感器 / Layer 3-5 真 LNN 替换）不在本稿讨论
