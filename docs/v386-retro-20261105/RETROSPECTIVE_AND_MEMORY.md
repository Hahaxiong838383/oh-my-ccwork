## 经验教训

| 发生的问题 | 修正后的做法 |
|---|---|
| 主13遗漏用户引用会话93已修复的证据，沿用旧路径并概括成Worker不可达 | 先读取引用会话最终结果和实际成功入口；把网络、SSH信任、认证、采集超时和业务运行状态分别判断 |
| 同样经过Air/home/hk2，但旧脚本在home认证、成功入口在Air认证 | 核最终SSH客户端在哪里；home仅TCP转发与home运行最终ssh不同，复用既有可用身份即可 |
| 监控把长时间历史日志扫描失败显示成机器不可达 | 现役目标、实时采集、历史缓存和错误状态分开；监控返回和业务健康分别取证，93修复证据已归档 |
| journald MESSAGE类型兼容失败，以及只grep room会漏ASR | 读工具兼容字符串/字节数组；基于PID与无重叠job时窗关联，不能把解析失败或筛选缺失当业务没发生 |
| 原收口缺口在新证据到来后仍保留成当前状态 | 保留旧失败原件，增加补验、修订最新回执/状态和索引；不抹除历史，也不继续传播过期结论 |
| 多会话开发、生产按模块部署，但Git分支没有统一 | 同时审查祖先/patch等价、实际源码、dirty和部署清单；先形成可验证的集成候选，不用整树覆盖假装完成 |

有效做法：固定版本与原件hash；由原会话补证、主会话独立核来源和事件；限定窗口并脱敏；通过的具体功能及时收口，独立观察项不牵连全套重测。未获证据的项目不标通过。
