# 任务自动验证规则

> cc 完成任务时的自检闭环。目标：摩擦标注从手动变自动。
> 灵感来源：Phil Schmid — "验证能力决定改进能力"。

---

## 验证时机

任务完成时（标记 task-log 之前）自动执行五维验证。

---

## 五维验证

### 1. 文件验证
- 任务中声称创建/修改的文件是否存在且非空
- 检查方法：`ls -la` 目标文件

### 2. 归档验证
- 新文件是否在正确目录（不在根目录）
- 是否遵守了三条铁律
- 检查方法：`git diff --name-only` 查看新增文件路径

### 3. 格式验证
- 署名是否正确（格式：`署名：[昵称]（[引擎]）| [完成时间]`）
- 回复语言是否中文
- task-log 条目格式是否合规

### 4. 回归验证
- `git diff` 无意外改动（只改了该改的文件）
- 没有引入新的硬编码密钥/凭证
- 没有删除不该删的内容

### 5. 测试验证（如适用）
- 如任务涉及代码修改且有测试，运行测试
- 如任务涉及配置修改，执行 dry-run 验证

---

## 摩擦自动分类

| 验证结果 | 摩擦标记 | 说明 |
|---------|---------|------|
| 五维全部通过 | `—` | 顺畅完成 |
| 文件缺失/归档错误 | `返工` | 产出不完整 |
| 首次方案被否后修正 | `误诊` | 方向判断有误 |
| 执行时间 > 2x 预估 | `超时` | 效率问题 |
| 回归验证发现意外改动 | `返工` | 副作用 |

---

## 执行流程

```
任务完成
  ↓
五维验证（自动）
  ↓
├── 全部通过 → task-log 标记 `—`
├── 部分失败 → 自动修复（如归档位置错误）→ 重新验证
└── 修复失败 → task-log 标记对应摩擦类型 → 记录到 trajectories
```

---

## 与进化闭环的关系

```
自动验证 → 摩擦标记（task-log）
              ↓
insights 摩擦提取（每3天）
              ↓
进化自查 → 新增改进项（evolution-log）
              ↓
自主升级（红/黄标）
```

验证数据是进化闭环的**起点**。验证越精确，进化方向越准。
