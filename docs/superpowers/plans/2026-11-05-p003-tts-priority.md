# P003 TTS 建连与流中停顿 Implementation Plan

> **For agentic workers:** 使用 executing-plans 逐项执行。用户要求主13亲自编写业务代码；Grok仅做独立评审。

**Goal:** 消除已证实的预建连串行等待放大，并查清、修复流中停顿；两项分别验收，不用DNS局部修复替代整体收口。

**Architecture:** 保留一句一连接、一份文本请求；仅在发送文本前对慢连接做有界竞速，连接预算不在预热失败后重置。流中以真实WS收流/播放背压/网络证据区分原因，部分PCM后不重播整句。

**Tech Stack:** 现有Rust/Tokio/tokio-tungstenite/LiveKit；无新增依赖。

**Spec:** `2-Projects/realtime-voice-agent/docs/transport-20261105/ROOT_CAUSE_AND_REPAIR.md`、`GROK-RECOVERY-BOUNDARIES.md`及本轮用户优先级要求。

## 评审重点

1. 单条连接挂起，另一连接成功：不用等10秒；只向赢家发一次文本。
2. 两条都失败/挂起：共享截止，不串行重置；保留错误，不能伪报成功。
3. 取消/过龄/容量耗尽：无脱离任务、无排队爆发、无第三次隐式连接。
4. 部分PCM之后失败：不整句重播、不把未交付PCM当已播放；字幕/历史风险另行取证。
5. 正常长句背压与真实断供分别计时，取消和人为暂停不算供应商断流。
