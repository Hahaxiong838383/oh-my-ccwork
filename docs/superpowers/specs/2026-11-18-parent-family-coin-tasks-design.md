# 家长任务：执行思路与最小闭环方案

状态：方案草案，未实现、未上线，路径与字段是建议合同。依据2026-11-17《家长任务接口问题》及2026-11-18用户明确修订：完成后孩子收到反馈，家长在小程序再次确认后才发币；本分支审计基线62bee411。本轮先固化已有周报，再规划任务，不宣称新接口已可调用。

## 目标与当前缺口

家长在小程序选中已绑定读写台，填写任务描述、目标时长、奖励家族币。服务器保存任务；安卓方舟收到后显示任务并跟踪真实使用；达到条件后孩子收到“家长任务已完成，等待家长确认奖励”的反馈；家长在小程序再次确认后，设备钱包才实际加币，服务端、后台、小程序显示同一任务结果和已同步资产。孩子无需点击领取。

当前只有部分积木：设备身份/绑定、真实focus片段、方舟钱包、奖励唯一ID、R1上行流水、Ark资产快照。缺正式任务CRUD、周期核算、设备任务接收回执、服务端奖励授权和到账核对。参考小程序的任务页是Demo本地加币，不是业务服务；附件11/10的404是历史证据，本轮未复测公网路径。

## 方案选择

| 选择 | 做法 | 取舍 |
|---|---|---|
| **推荐：服务端管任务和发奖，设备保留现有钱包** | 服务端判达标，家长再次确认后给唯一奖励授权；安卓原子加币并回传；小程序读服务端的设备余额副本 | 改动集中，保留离线游戏；离线时明确“待到账/余额上次同步”，不承诺离线两端实时一致 |
| 全部钱包迁到服务端 | 所有任务和游戏收入、消费都走服务端总账，设备改离线消费策略 | 可做服务端实时权威总余额，但影响现有经济系统，本轮不选 |

本方案权威范围要说清：**任务资格、应发金额、是否已结算以服务端为准；游戏可花余额仍在设备钱包，云端保存其已确认副本。** 这与附件希望服务端事务返回全局新权威余额有差异，不能伪称已满足。云端接口返回真实余额时间、可用性、待到账金额；绝不拿旧快照直接加奖励来冒充新余额。奖励是游戏内新增家族币，不从家长账户扣款。

**已确定的产品规则（2026-11-18）：任务完成反馈与家族币到账分开。** 孩子完成后收到任务完成反馈；家族币必须由家长在小程序再次确认后才能发放。确认前不加币，不提供孩子主动领取或未经家长确认自动发币模式；家长确认成功但设备尚未执行时显示“家长已确认，待设备到账”。其余尚未明确的规则继续按下文建议规划。

## 一条任务怎么跑通

1. **创建**：家长用现有短信登录，在绑定设备下创建任务。服务器校验归属/参数/同模板数量，保存规则版本、周期和生效时间。小程序显示“已创建，等待设备接收”。
2. **下发**：安卓沿现有设备凭据和HTTPS主动拉取任务，存盘成功后回执任务版本、当前存档；后台才能显示“设备已接收”。启动、联网、进入方舟任务页立即拉取，在线任务界面低频刷新；先不新增MQTT或常驻推送服务。现有30分钟配置轮询不足以支撑即时任务体验，不把任务列表塞进标量config。
3. **计时**：安卓显示本地进度，继续用已有focus_segment上报；服务端用同一份真实区间核算。页面可显示“本地已达标，等待云端核算”，不让客户端自报一个完成布尔值就发币。
4. **完成反馈**：服务端核定达标后将该周期标为“已完成，待家长确认”。安卓同步到该状态后向孩子反馈任务已完成、奖励等待家长确认；小程序出现待确认任务。完成反馈按周期去重，重启或重复同步不反复弹出；此时不发奖励授权、不增加钱包余额。
5. **家长确认**：家长在小程序再次确认该周期奖励。服务端复核达标、当前归属和任务状态，奖励数量取创建时保存的规则快照，原子登记唯一结算授权，生成固定settlement_id、金额和目标身份/存档。重复点击或超时重试返回同一结算，不重复发币。小程序显示“家长已确认，待设备到账”，不能立即冒充到账。
6. **到账**：安卓通过任务GET拉取家长已确认的待执行结算，核当前身份后自动执行，无需孩子再次领取。把“增加家族币、保存已执行settlement_id、生成业务流水”放入现有同一次持久化提交，成功后才向孩子反馈家族币到账。重复授权重放返回原结果，不能再加一次币。设备离线时结算保持待到账，恢复联网后继续原结算。
7. **同步**：安卓回传到账回执、原有R1流水和新Ark快照。服务端关联同一settlement_id，显示已到账；小程序与Worker后台读取同一DTO。R1/回执/快照乱序到达时允许中间态，补齐后自动对账，不用人工改库。

任务周期展示：`等待设备接收 → 进行中 → 已完成待家长确认 → 家长已确认待到账 → 已到账`，另有已结束未达标/已取消/归属变更暂停。设备同步状态独立显示，不能用“云端已保存”代替“设备已应用”。

## 计时和任务规则

| 项目 | 第一版建议 |
|---|---|
| 模板 | 按附件保留阅读打卡和使用频次；每个当前绑定设备每模板最多1个未归档任务 |
| 描述/数值 | 描述非空、建议不超过200字；分钟为1–300整数，奖励为1–500整数；频次每周1–7天，每天1–300分钟。服务端校验，客户端只辅助 |
| 阅读打卡 | 当日有效真实使用累计达到目标分钟即达标；不是强制连续使用。周期按北京时间自然日，重复则下一日生成新周期 |
| 使用频次 | 北京时间自然周内，达到每日分钟门槛的天数达到目标即达标；日门槛按任务配置，不复用周报连续5分钟活跃规则 |
| 首次周期 | 从服务器保存任务时间开始计算；首日/首周是剩余窗口。新增任务不使用创建前历史换取奖励。旧历史继续在原历史页显示 |
| 可用时长 | 当前归属内、时间有效的真实focus片段。重叠取并集、原始毫秒保精度，跨北京时间午夜拆日。设备日常奖励与家长任务共享计时输入、独立发奖 |
| 估算边界 | 首页merged_observations、姿态/心跳推算、位置不明的奖励累计不参与发币。它们仍可用于原使用展示。真实使用只能证明设备使用，不能据此证明孩子读了某本书 |
| 修改 | 规则版本变更，进行中本周期保持原规则，下一周期生效；已达标未结算周期不可改删。一次性进行中任务如要改目标，取消后新建，不将旧进度搬到新任务 |
| 删除 | 实际做归档/取消未来周期，保留既有任务、证据和到账流水；取消前已完成但尚未上传的真实片段仍可补算奖励，归档详情保留该旧周期的家长确认入口，仍须家长确认才发币；取消后片段不计，已到账币不回收 |
| 重复/补传 | 每个日/周周期独立ID。晚到的合法片段归原周期，未达标旧周期可被补传纠正；创建前、取消后片段不计。已经发过的周期不再次发币 |
| 设备同步 | 本轮需求固定开启sync_to_robot；不实现只有云端任务的第二套模式。设备旧版本不支持时显示“不支持，待升级”，不假报已下发 |

上表是建议规则，尤其“累计用时”“首次剩余窗口”“下一周期改规则”在正式接口实现前写入联调合同；不能默认为用户已逐项批准。单设备首轮闭环，不做跨多个设备拼一个任务或整套任务编排系统。

## 拟新增接口与页面

沿用已经工作的parent/devices归属体系，不要求先建立另一套children体系。以下都尚未上线。

| 调用方 | 建议路径 | 用途 |
|---|---|---|
| 家长 | GET/POST `/v1/parent/devices/{public_id}/tasks` | 列表、待家长确认/待到账筛选、新建 |
| 家长 | GET/PATCH/DELETE `/v1/parent/devices/{public_id}/tasks/{task_id}` | 详情、改未来规则、归档；写入带expected_version |
| 家长 | POST `…/tasks/{task_id}/occurrences/{occurrence_id}/confirm` | 必经发币确认；只传周期/版本/幂等键，金额由服务器取规则；返回唯一结算和待到账/已到账状态 |
| 安卓 | GET `/v1/device/ark/parent-tasks` | 取当前任务、周期进度、完成反馈和家长已确认的待执行结算，沿用设备鉴权；不创建或确认奖励 |
| 安卓 | POST `/v1/device/ark/parent-tasks/receipts` | 任务存盘/拒绝、完成反馈已展示、奖励实际到账回执，按ID幂等 |
| 后台 | GET `/api/admin/devices/{sn}/miniapp/tasks` 与详情 | 与家长同源显示规则、进度、周期、结算/流水和同步时间 |

列表/详情返回task_id、模板、描述、目标分钟/天数、奖励币数、重复规则、规则版本、周期起止、服务端已核算秒数/天数、状态、可编辑/删除标志、同步状态及更新时间。结算返回settlement_id、reward_amount、到账状态、关联record_id、余额副本及其版本/时间；尚未到账不返回假新余额。

沿用现有401/404隔离；参数错误400、版本或状态冲突409、同幂等键不同正文409、依赖不可用503；空列表200且items为空。新建和家长确认都支持幂等键；发奖另有“身份范围+任务+周期”数据库唯一约束，不因换请求键或换规则版本重复发同一周期。正式回执给有数据/空列表/校验失败/冲突/重试JSON和A/B权限样例。

小程序与后台都展示：描述、奖励、今日/本周进度、设备收到的版本、待家长确认/待到账、最后同步时间；点开可看到原始证据ID、结算ID和到账流水，诊断不展示孩子正文或凭据。后台保留原隐藏历史对话、短信身份说明、微信后置提示和解绑二次确认。

## 可靠性：只补必需能力

- 使用现有SQLite，新增任务/周期/结算记录和必要的最小证据；一个结算记录兼作待执行列表即可，不新上队列平台。原始日志清理前确保任务所需证据已保留，有可恢复游标和补算，不能依赖14天原始日志永久存在。
- 家长确认前，服务端只记录完成状态，不创建可执行奖励授权；家长确认后先原子登记唯一授权，安卓再原子执行。两边不能假装一个跨网络事务：下发/回执失败重试原ID，云端保留处理中并可补查。落盘失败不显示成功、不先ACK应用成功。
- 任务与结算锁定家长账号、SN/public_id、binding_version、Ark epoch及家长确认时核定save_id；任务应用后换档暂停核验。解绑后停止新授权和旧任务下发，新主人不继承；尚未发出的奖励冻结。安卓执行前联网取当前授权并核本地身份，不能离线执行缓存旧奖励授权。
- 已发授权可能在核验通过与设备落盘之间遇到解绑，不能承诺跨网络瞬时撤销。此时结算标待核：执行只能针对授权时的旧身份/旧存档，端侧获知身份切换即冻结旧授权，不投入新身份钱包；服务端接受旧范围的迟到到账事实用于对账，不重新发奖或自动补到新账户。已到账不回收，结果不确定先保留处理中。
- 已到账奖励的去重账随存档持久化；保存ID不变的普通重启、重复点击、到账后回执丢失不能重发。旧存档回灌/重置不自动补发历史奖励；身份/存档不确定显示待核。
- 设备离线可继续积累真实时长，联网补传后服务端核算；第一版不离线发放新增家长任务奖励，避免重复和旧身份到账。离线期间钱包依旧支持现有游戏收支。
- 新奖励沿用现有R1形状：reward_instance_id=settlement_id、source_kind=parent_task、source_id=周期ID；原上传URL、envelope、ACK无需变更。服务端新增关联投影，核授权、金额、币种、归属和存档后进入任务收益。不能只扩字符串白名单；一笔结算与R1关联后只算一次。
- 源码目前的正常收益白名单没有parent_task，这是必须补的读取侧缺口，否则会再次出现“ACK成功，资产/历史没有刷新”。GM/unknown仍保持来源标签，不因新增任务强制改成normal。快照余额与任务收入历史分开，不把一条任务收入当作整个钱包可信的证明。
- 当前C机R1为显式兼容授权。先在C闭环，扩设备时核该设备能力、当前授权与存档，不能复制C历史归属配置。

## 实施顺序及验收

1. **冻结小合同**：以已经确定的“孩子收到完成反馈、家长再次确认发币”规则签收本方案余额语义；输出上述新接口JSON/枚举/单位/幂等规则。保留所有旧上传协议。
2. **服务端与后台**：任务持久化、归属校验、真实片段核算、完成/待确认状态、家长确认后的唯一授权、R1到账关联和查询同源。用隔离数据测重试/并发/跨日/补传/换绑，不向生产造奖励。
3. **安卓方舟**：任务拉取与持久化回执、真实进度及完成反馈、自动执行家长已确认授权、独立到账反馈，复用已有原子钱包/奖励账/R1/快照；构建、签名、安装分别留证。
4. **现役小程序接入**：真实CRUD、任务进度、待确认列表及家长确认操作、待到账/已到账状态替换Demo行为；目前仍缺现役LiveApp源码/仓库入口，不能用本仓参考端构建冒充真机完成。服务端及安卓准备可独立先行。
5. **C机三端联调**：家长A建1分钟/小额币任务→C收到→实际使用→原片段ACK→服务端达标→孩子收到完成反馈且余额不变→家长在小程序确认→唯一结算→安卓自动加币/R1→设备和后台/小程序同步。对比余额须包含同期其他收入和消费，不能只看简单差值。

同时覆盖：未确认时反复同步/伪造设备完成回执均不发币、家长连续确认/不同幂等键并发、家长确认成功但设备离线保持待到账、完成与到账反馈分别去重、发币落盘后断网、回执丢失、R1先到或快照先到、跨午夜及补传、旧日志清理、目标修改/取消、A/B越权、解绑重绑、换档、GM/unknown、设备旧版本。验收要求同一周期只有一笔奖励，真正设备到账与只收到ACK明确分开。

前一版独立方案审阅已完成，补齐“取消前已完成但取消后才补传”和“授权后解绑竞态”两条规则；本次进一步按用户明确决定统一为家长再次确认发币，删除孩子claim接口。本轮未运行或新增业务测试，以上测试均为后续实施验收项。
