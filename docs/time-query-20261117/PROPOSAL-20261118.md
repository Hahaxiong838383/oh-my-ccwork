## 5. 435 已核对的能力开关与限制

- **报时开关：** `P003_CLOCK_ENABLED !== '0'` 即开启，未设置也开；这是进程级开关，无独立时钟 SN 白名单。普通直答要求 worker 与解析后身份均为 `device`，工作台 prompt override、吐槽模式不拦截。直答不依赖搜索总开关。
- **搜索任务入口：** 时钟也受 `SEARCH_ENABLED=1`、任务 DB、模型 key、鉴权 secret、worker account、域名列表等既有配置完整性门禁；还需 `p003.search.enabled=1`、有效 scope/名单/排除项、已激活且绑定账号的设备。候选池另需有效截止；路由版本须有效。供应商暂停时本地时钟可继续，但搜索关闭/到期/身份不符仍拒绝。
- **P1/P2：** 时钟不需打开 P2。`searchSettings().tools` 仍要求候选池、scope 匹配和 `p003.search.tools=1`；不要为报时扩大权限或续开旧窗口。倾听是否启用由既有独立配置决定，本轮未核实实时值。
- **额度：** 当前源码任务默认单设备每日 100、全局 1000、队列 8、并发 2、同房未领取任务上限 2、任务期限 20 秒；显式报时也占任务额度。这是源码默认值，不是今日各池配置证明。
- **关闭的含义：** `P003_CLOCK_ENABLED=0` 关闭确定性入口后会回原模型/搜索路径，并非自动返回“报时已关闭”；它也不等于逐文件回滚。历史过滤 `stripClockTurns` 仍会运行。
- **上下文：** 普通对话仅从紧邻上一条用户原文识别时间语境，没有 10 秒窗口。“现在几点→那纽约呢”支持；“现在几点→那纽约呢→那伦敦呢”本地实测第三轮不命中。搜索执行器只接独立 query，无上一轮历史，不能承诺城市追问同等支持。
- **时效：** 时钟准确性依赖服务器校时及运行时 tzdata；11-17 NTP 同步成功不代表今日状态。后台/重播只能说“查询时”，不能把旧时间当当前时间。
