# 方舟收益问答：37条产品裁定落地

产品口径以本目录 USER-DECISIONS.md 为准。金币对应家族币，游戏道具兑换介绍星尘。小可只能查询与介绍，不能代兑、代领或展示游戏页面。家族币可在小程序查看已同步数据，约定奖励由家长确认和兑现，不杜撰兑换按钮。

完整指定谐音用于理解校正：捕禽卡、古琴卡、抚琴卡、抚琴弹、补签卡→补勤卡；加组币→家族币。原始聊天文本不改写。不行卡、文章捕不加入资源别名；行卡、仙卡先确认。未完成语句只做简短澄清，不让大段旧世界观和历史错误回答补全含义，保留小可读写台的方舟身份。“咱俩”指用户和小可。

明确的资源用途、当前状态与领取问题走有限事实回答。屏幕上的币用途、使用时间达到但领不了、未说完的界面问题也进入对应路径，不杜撰界面位置、商品、充能状态。待领状态只用新鲜快照；确认可领后指导用户点击进度条上已点亮的奖励，当前版本不能代操作。

今日收益新增只读、有界的已收到发奖记录查询，按稳定 reward_instance_id 去重；同ID冲突、GM、时钟异常、截断、坏行、超限均不报不可信汇总。钱包余额不是今日收入。progress_checkpoint.elapsed_seconds来自客户端封顶奖励计时，只能说“奖励进度”，不能说全天累计使用时长。没有记录不补0，后续收到更多记录可补齐。

模型仍使用已有一次生成/既有赛马，不新增语义分类调用。对非控制的方舟与未完成请求，移除控制协议提示并过滤分段DEV标记。显式设备操作、退出、搜索和倾听现役路径保留。旧对话只能帮助辨别话题，不能证明余额、界面、能力或兑换已执行。

## 复盘

首次HTTP成功不代表语义正确；多次复验发现模型可能错误关房、假称已兑换、编造按钮、混用两种币和旧奖励机制。独立审查结果必须逐句核对。即使评审将模型错误列为“部分通过”，与用户明确产品口径冲突的内容仍应修复后再发布。

只对改动相关问题重跑必要测试。最终有限路由补丁使用全量路径等价检查和定向HTTP复验，不反复调用所有无关模型请求以挑选好看的答案。历史失败与新结果分别保留。
