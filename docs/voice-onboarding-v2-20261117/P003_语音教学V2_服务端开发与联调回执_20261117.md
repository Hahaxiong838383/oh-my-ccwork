## 已接受的产品规则

- 本地固定三问：年龄、性别、称呼；云端已有资料不减少题目。
- 每题实际播完后才等答案；无回答、未识别、拒答、保存失败、回执超时均可继续，不反复追问、不抢话。
- 教学完成由客户端在4A/4B实际播完后持久化；服务端不代写完成位，3C未唤醒退出不算完成。
- 服务器负责ASR接入、保守答案判定和尝试保存；教学期间不启动普通LLM、搜索或额外TTS。退出/普通聊天恢复继续复用现有通路。
- 不擅自覆盖既有资料，不根据年龄编造生日；GM模拟不写云端，清游戏档不动账号、绑定、凭据。

## 安卓对接要点

完整可执行字段见同目录[CONTRACT.md](CONTRACT.md)，不沿用v1的服务端选题/audio_token合同。

1. 新包会话声明`voice_onboarding_v2`；只在签票返回相同v2合同时走真实协作。没拿到v2或服务器异常，端侧按有界本地流程完成，并阻止教学音频落入普通聊天；不能伪报saved。
2. 同一可信RTC control通道发送`begin → question_started(1) → audio_complete(1) → … → question_started(3) → audio_complete(3) → finish/cancel`。可用`question_skipped`关闭超时题。begin revision=0，此后新动作递增，同字节重发保持原ID/revision。
3. 回答回执`action=answer_result`；`request_id`对应当前题的`audio_complete`，还须同时比对trace/session/lesson/question_index/revision。旧回执不推进题目。
4. `result=accepted/unrecognized/declined/failed`与`memory_write=none/saved/skipped/failed`分开处理。有效回答但已有资料是accepted+skipped；保存错误是accepted+failed；不等待saved才前进。
5. 每题静默5秒从实际播放完成开始；请求重试3秒间隔、同字节最多3次；整课180秒。过期只标expired，不当成4A/4B完成。服务端超时不会主动转普通闲聊抢占本课。
6. 如果房间带原ordered首句合同，v2 begin会触发既有`session.input_phase`切到rtc，reason=`voice_onboarding_v2`；端侧按既有相位切换处理，不能继续向旧首句任务送答案。此时还可能收到原ordered通道的failed/timeout/repeat_prompt终态数据；教学状态下不能据它重复播问句或误关房。服务端不会据这条数据合成TTS。若原begin_timeout已先排队，phase reason会保持begin_timeout，仍应切到rtc。普通房间首句机制不变。
