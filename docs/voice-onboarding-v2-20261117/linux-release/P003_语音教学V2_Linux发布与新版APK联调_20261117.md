## 这版分工与产品行为

- 安卓本地固定问三题：年龄、性别、叫什么；播放、5 秒等待、跳题、结束和完成位由本地管理。已有资料也不省略题目。
- 5 秒从每题提示音**实际播完**开始计。静默、未识别、拒答、保存失败、回执超时均有界继续，不反复追问。
- 服务端负责接收 ASR、保守识别答案并按当前设备所属账号尝试保存。已知字段不覆盖；年龄不推算生日；只有数据库真正提交才返回 `saved`。
- 教学期间不启动普通聊天 LLM、搜索和额外 TTS。云端失败不能导致本地教学无限等待或抢话。
- 只有结束音频 4A/4B 真正播完才持久化完成；未唤醒而退出的 3C 不算完成。模拟流程不写正式完成位或云端资料。

## 测试设备与派单：开始前必须对齐

1. 安卓回传新版 versionCode/versionName、APK SHA256、当前 SN；服务端核对同一个真实签票 trace 下的 `voice_onboarding.version=2`，不能只检查客户端自报 supports。
2. 教学 V2 当前仅支持普通主池 `rust-worker`。`03800006` 现处于倾听灰度路由，直接在此路由上请求教学不会取得 V2 授权。
3. 选择已安装新版的普通池测试设备，或服务端在明确的联调时段内把**该一台**从倾听灰度派单临时切回普通池，并记录原配置以便恢复；不覆盖倾听池二进制，不改其他 SN。尚未执行这项切换。
4. 服务端按同一 SN 开启教学总闸、V2 版本门及名单，并回传配置/起止时间和实际 agent。当前没有确认开窗，测试同事不得把“已部署兼容代码”理解成“窗口已开”。
5. Android 仍走真实登录、设备签票和 RTC；禁止把测试 token、Device Bearer 或服务端凭据贴到群中。

## 控制协议摘要

完整字段和样例见 [CONTRACT.md](../CONTRACT.md)。与旧 V1 合同分开，不使用 V1 的服务端选题或 audio_token。

- capability：`voice_onboarding_v2`。
- 可信 RTC 数据通道：topic=`control`，type=`voice_onboarding.request`，lane=`voice_onboarding`，payload 包含 v=2、trace_id、session_id、lesson_id、request_id、question_index、revision。
- 正常顺序：`begin(0,0)` → `question_started(1)` → `audio_complete(1)` → 后续第2、3题 → `finish`；静默超时可发 `question_skipped`；取消发 `cancel`。
- 每个新动作递增 revision；重发同一动作必须同 ID、同 revision、同字节。重试间隔3秒、最多3次，整课180秒。
- `answer_result` 的 request_id 对应当前题 `audio_complete`，同时校验 trace/session/lesson/题号/revision。迟到的旧回执不能推进新题。
- `result=accepted/unrecognized/declined/failed` 与 `memory_write=none/saved/skipped/failed` 分开。accepted+skipped 表示已有资料不覆盖；accepted+failed 表示答案有效但保存失败。不得等待 saved 才继续。
- 带 ordered 首句合同的房间，V2 begin 触发已有 `session.input_phase` 转 RTC。通常 reason=`voice_onboarding_v2`；原 begin_timeout 若已排队，也可能保留该 reason。安卓须切换输入，不能把旧 ordered failed/timeout/repeat_prompt 数据当作教学重播或关房指令。服务端不会依据这条旧数据播放 TTS。

## 回传格式

每条用例：`版本/APK SHA + SN末8位 + CST开始结束 + trace/session/lesson + 预期/实际 + PASS/FAIL/未测 + 日志位置`。不需要儿童回答正文，不提供凭据。服务端回传实际派单池、授权版本、接收/保存/回执时间、关房结果。双方按同一 trace 对齐后才宣布整体验收。
