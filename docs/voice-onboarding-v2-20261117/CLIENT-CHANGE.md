# P003｜语音交互教学规则变更与服务端对接回执

日期：2026-11-17（北京时间）  
状态：**已收到产品确认的新规则，客户端修复开发中；不是新包已部署或真实云端联调通过的回执。**

## 一、变更结论

本次按产品与用户最新确认执行：**客户端负责固定三问及跳题、退出和完成状态；服务端负责语音识别、答案有效性判定与记忆保存。**

这将替代上一份 v398 回执中“服务端选择缺失问题、缺少教学能力则转普通聊天”的教学策略。普通聊天的日常补问和记忆系统不因此取消，但不能在本次教学中抢占三问流程。

已只读核对飞书需求文档当前 revision 4370。其中原 4B 为“某题静默即直接进入退出提示”；用户本次已与产品同步修改为“未回答或未识别也继续下一题”。**本回执以本次明确变更为准，不把旧文档规则混用进实现。**

## 二、客户端要实现的流程

1. 首日完成设置引导后，播放自我介绍：“嗨～我是小可，你的专属陪伴机器人，你可以说‘小可小可’叫我出来，来试试吧。”
2. 此教学中的真实唤醒由教学流程接管，不能直接进入无约束的普通聊天。提前主动唤醒路径保留，不再重复要求孩子呼叫。
3. 按顺序进行三问，已有本地预制语音：
   - 第 1 题：你多大了呀。
   - 第 2 题：指挥官是男孩还是女孩呀。
   - 第 3 题：我怎么称呼你呢。
4. 每题必须等该题语音实际播完才进入回答等待，播音时间不计入静默超时，也不能把播放回声当孩子答案。
5. 回答有效：接收服务端确认后进入下一题；没有回答：静默等待结束后跳到下一题；识别不正确、无有效结果或回执超时：同样跳到下一题。**不反复追问、不因某一题失败整课退出、不等待记忆保存成功才允许孩子继续。**
6. 三题走完，再播放原表 4A／4B 的结束教学语音。
7. **4A 或 4B 的语音实际播放结束后，持久记录教学完成。**后续普通唤醒、返回游戏、切日和重启都不得再次弹出本课。完成不等于三个资料都已保存。
8. 退出词、“不聊了／退下”、退出等待和恢复原游戏流程仍需正常工作；若孩子继续聊，属于普通聊天，不循环新手文案。
9. GM 清游戏存档可重新测试教学，但不清服务器孩子资料、绑定、设备凭据或 Wi-Fi。

未唤醒的 3C 分支与已到达 4A／4B 必须区分：介绍后约 5 秒提醒一次，提醒播完仍静默约 10 秒则退出；这种情况尚未完成本课，不能伪装成 4A／4B 已完成。

4A／4B 文案使用现有已内置文件：

|节点|本地音频 key|文案|
|---|---|---|
|4A|`g1.voice_onboarding.complete_exit`|说得太棒啦！你可以和我说“退下”或者“不聊了”，结束对话。下次想和我聊天时，叫我“小可小可”，我就会出来啦。|
|4B|`g1.voice_onboarding.quiet_exit`|你可以和我说“退下”或者“不聊了”，结束对话。下次想和我聊天时，叫我“小可小可”，我就会出来啦。|

分支按答题情况选择；无论哪条均为本课终结，不再触发次日补课。具体分支选择口径会随新版端侧实现及测试结果写入下一份部署回执，不影响服务端先确认接口。

## 三、服务端需要配合

### 1. 教学会话与普通聊天隔离

- 仍复用现有设备鉴权、语音会话及可信 RTC control 通道，不新增 Godot 直连地址，不更改设备凭据或现行 401 策略。
- 按当前 `trace_id / session_id / lesson_id` 标识教学；教学进行时，不把三题回答当普通开放问题去启动闲聊、搜索或额外 TTS。
- 年龄、性别、昵称三题的顺序由客户端控制，服务端不能因已有资料、识别失败或保存失败而反复发题、打断或重新开始本课。
- 预制语音由客户端播放；服务端不要同时合成或播出同一句。

### 2. 识别结果与保存结果必须分开

- 每题返回可关联的识别/处理状态，例如 `accepted / unrecognized / declined / failed`；客户端据此或有界超时进入下一题。
- 记忆保存结果单独返回 `none / saved / skipped / failed`，只能在真实提交后标记 `saved`。
- 允许孩子不回答、不愿意回答；不能编造年龄、性别或昵称，不能把年龄擅自换算为一个精确生日。
- 已有资料的覆盖、冲突及写入精度沿用记忆系统规则。资料写入失败不阻塞游戏，不将“教学完成”伪装成“记忆保存成功”。
- 正文回答仍在现有语音/服务端链路处理；控制回执及 Godot 教学层只需要状态，不需要生日、昵称等明文值。

### 3. 新合同提案：v2，待双方冻结

上一份 v398 的 v1 是“服务端编排问题”，本次是“客户端固定三问”，**不能在 v1 名下原地改变含义。**建议新能力名 `voice_onboarding_v2`，通过既有会话能力协商；下面是待确认提案，不代表服务端已实现或客户端当前 v398 已支持。

沿用 `topic=control`、`lane=voice_onboarding` 和既有 envelope 的鉴权/可信发送方验证。每个请求/响应至少绑定：

`v=2 + trace_id + session_id + lesson_id + request_id + question_index + revision`

|方向|拟定动作/结果|用途|
|---|---|---|
|客户端→服务端|`begin`|进入本课，隔离普通聊天；重复请求幂等|
|客户端→服务端|`question_started`，`question_index=1/2/3`|标记当前年龄／性别／称呼题；客户端已决定顺序|
|客户端→服务端|`audio_complete`|该题音频实际播完，才允许开始本题回答等待|
|服务端→客户端|`answer_result`|返回该题识别状态及独立记忆处理状态，不指挥重复问同一题|
|客户端→服务端|`question_skipped`|静默、无有效识别或回执超时；关闭旧题，不接受迟到结果推进新题|
|客户端→服务端|`finish / cancel`|4A／4B 完成或用户/系统中断；结束本课隔离|

拟定仍保留现有每次请求 3 秒间隔、同字节最多 3 次重发及整课最长 180 秒的有界保护；单题静默沿用播完后 5 秒。识别处理等待及前后端动作名以本次 v2 冻结为准，差异须书面列出。

- 同一请求重发不能重复记忆写入。
- 迟到、旧题、旧课、旧 trace、非可信 worker 的回执不能推进当前题。
- 一题跳过后，即使旧题识别或保存结果稍后返回，也不能让客户端倒退或重复播问句。
- 未协商教学能力或服务器异常时，端侧仍需有界完成本地教学，不掉回普通聊天抢占本课；不虚报云端保存成功。

请服务端先回：是否接受上述业务规则、教学/普通聊天隔离方式、v2 能力名和动作字段；如与现有接口不一致，列明差异后冻结，不直接在 v1 上改含义。

## 四、端侧模拟和真实联调的边界

客户端正在补 GM“服务器全成功／逐步模拟”按钮，用屏幕按钮模拟唤醒成功、回答成功和退出，走相同的教学画面、三段问句、思考等待及 4A／4B 结束流程。

- 模拟明确标记 `simulation`，不声称真实 ASR 成功，不写孩子云端资料，不消耗正式教学完成状态。
- 正常三题、三题全静默、部分不识别、保存失败、超时、旧回执、重启不再弹出，都会加入端侧回归。
- 真实唤醒、真实音频上行、服务端识别、实际记忆落库及普通聊天隔离，仍需双方使用同一 trace 做联合验收，不能用 GM 模拟替代。
