# P003 T5 未通过原因与人工决策清单

结论：T5 尚未通过，不进入 T6、不将已验证容量档位提升至 50。以下前三项实测失败，第四项为容量阻塞及未完成验收，不能混为已发现业务故障。

本次只整理决策，不继续压测、不购买或挂载存储、不修改生产开关。语音教学 Linux 发布验证是独立任务，不算 T5 通过。

## 1. 集中上传时，确认响应偏慢

- 固定场景：50 个合成设备身份，各 12,000 条，合计 600,000 条、3,000 个成功批次；同时有维护和备份。
- 入库对账正确，全部处理用时 1,350 秒（约 22.5 分钟），未发现丢数。
- 成功响应 p95=525.924ms，超过原标准 500ms；p99=1,738.339ms，满足 2 秒。
- 共 9,839 次请求：3,000 次成功、6,839 次 503 背压重试。重试最终成功不代表请求首次均成功，不能删掉 503 后宣称整条上传体验无问题。
- **已证实**：该并发场景的 p95 超标。**尚未证实**：磁盘、SQLite 锁、维护/备份重叠、重试集中各占多少；不能直接归因服务器太差。半量 300,000 条场景 p95=395ms，通过该子项。
- **建议决策**：保持 500ms / 2s；允许先在现有隔离数据上做一次“上传完成再维护”的对照，并保留完整 503 统计，定位争用来源。即使顺序执行通过，也只证明对照场景，原混合负载标准仍须重验；若正式产品采用错峰，应明确更新运行策略与验收场景。
- **收益**：先用小成本试验判断是否能靠调度解决，再决定是否需要更快存储。

## 2. 冷数据汇总，在 30 秒预算内未完成

- 600,000 条记录实际扫描到 442,624 条便达到 30.012 秒，约 74%，该天仍待处理。
- 同期 CPU 只消耗约 3.091 秒，读盘 155,459,584 字节；表现更像等待 I/O，但还不能精确归因磁盘型号、宿主争用或资源权重。
- 减少读取列的候选 `416a4898` 仅证明本地 CPU 约改善 12%，没有减少索引叶页读取量，**尚未部署，不能称已修好冷盘问题**。
- **建议决策**：保持单次 30 秒预算，不为了跑完而让维护长时间占资源；先查明实际存储吞吐与争用，再决定独立数据盘或针对性改动。当前不直接引入复杂增量状态系统。
- **收益**：维护工作有上限，保护正在发生的语音对话与业务请求。90 天成熟库的清理净吞吐仍是待验，不是此项已经验证失败。

## 3. 首次查询有一次超过内部时限

- 同一隔离 600,000 条库，50 个合成身份共 1,000 次真实 HTTP 查询：p95=34.873ms、p99=50.060ms，事实内容核对无误，但 **1 次 transport failure**。
- 失败发生在首个请求：客户端约 155.528ms，响应体不完整；服务端读取约 137.420ms，超过内部 120ms 时限。HTTP 200 记录不能掩盖客户端未完整收到响应。
- 组件探针测得证据查询占主要时间，另一次组件总计 124.609ms；它不包含完整 HTTP 和全部事实处理，不能替代端到端验收。
- **建议决策**：保留 120ms 内部时限、p99≤100ms 和健康负载零超时标准；先对同一库做真实 HTTP 冷启动首请求复验和分段定位，再做针对性优化，不给普通聊天添加长等待。与上传/维护/备份同时查询，以及超时后普通聊天仍可回答，仍待验。
- **收益**：优先保证“刚开始问也能及时返回”，而不只看平均值或热缓存结果。

## 4. 完整规模验收被存储空间挡住，后续长测尚未运行

- 成熟测试库实际 44,871,368,704 字节，约 41.79GiB；现服务器整个系统盘只有 40GiB，该库连整盘都放不下。
- 当时系统盘仍余约 8.95GB，安全预留还在；**不是生产已经磁盘满，也不是现有真实设备数据丢失**。
- 约 23.5 分钟样本的 CPU 平均 18.01%，最低可用内存约 45.84%，未观察到 OOM；不能据此说 CPU/内存不足，也不能冒充 24 小时稳定性验收。
- 尚未完成：成熟数据下 50 身份上传+查询+备份+维护混跑、90 天 TTL 净清理、NAS 72 小时积压及实际断网 1 小时后的续传、语音 A/B 各至少 50 轮、连续 24 小时、超过 32 个授权时的回滚。
- T2 已有的 PRnas 断线续传/大库恢复证据继续有效，但不能替代上述 T5 混合场景。
- **建议决策**：先保持当前容量档位，完成 1/3 的低成本定位。若仍要求按原 50 台完整规模标准验收，再单独决定提供隔离存储或调整真实业务保留方案。曾建议 500GiB 只是容量规划，不是必须购买的结论，更不保证加盘就自动解决延迟；未报价、未购买。
- **收益**：把“容量不够”和“响应太慢”分开处理，避免未经验证就整体换服务器。
