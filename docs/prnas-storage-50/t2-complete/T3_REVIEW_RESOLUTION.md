# T3计划评审采纳记录

Grok 4.7对2183eb0c源码的计划审查结论为T3_READY_AS_PLAN；主实现逐条核源码后更新T3_HANDOFF.md。此记录不代表T3代码已实现。

采纳：现有duplicate优先、不能全局唯一snapshot_id；Ark事务前读取配置，避免锁顺序反转；明确留档谓词及服务器时钟；503与授权409分离；持久批次和manifest仅使用publish_prepared；保留旧占位包兼容；归档开关独立CAS，不动设备配置。

对评审建议做了以下必要收敛，避免直接照搬产生新问题：

| 评审建议 | 最终口径及原因 |
|---|---|
| 与上一条outbox比较 | 正文ACK清理后仍保留轻量检查点基线，否则清空outbox会使下一条噪声被当首次快照 |
| JSONL直接写snapshot原文 | 改为含身份、内部序号、接收时间、body_hash及完整snapshot的封套；裸snapshot没有owner/epoch，无法完成归属隔离验收 |
| 8GiB只统计outbox正文 | 实施时还须涵盖生成中/待发副本及磁盘预留；只数正文不能保证实际磁盘预算 |
| 关闭时停止导出器 | 关闭仅停止新增历史，已accepted积压仍补送/确认；否则关闭功能会把已接受记录永久搁置 |
| 关闭仍显示not_implemented | 已实现后显示关闭和积压实际状态，保持既有字段兼容；不能把已实现功能误标为未实现 |
| list完全不变 | 优先源端正文GC、SQL LIMIT和20包队列；真实积压若超清单边界，才补兼容分页，不提前建复杂索引服务 |

最终规则和用例以[T3_HANDOFF.md](T3_HANDOFF.md)为准。主实现不因评审建议增加GM鉴权、设备历史API、新服务或OTA依赖。
