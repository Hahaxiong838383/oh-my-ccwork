# T2剩余实现：固定候选前说明

基线ac476d3c，用户授权完成T2、准备T3；当前文档记录实现范围，不替代最终验收。

- 独立Backup API任务：单任务锁、每个CST自然日最多生成一份（未确认时保持等待），未确认则只报告等待；ready manifest持久化后同卷采用已完成文件，避免再拷贝一份整库。发布中断可重入，重试重复fsync屏障。
- 云端新份ACK之前保留上一份；新份确认后仅清理更旧analytics_backup正文，保留manifest/receipt用于确认响应丢失恢复。Ark和未知任务文件不进入该清理范围。
- NAS保最新7个CST日桶和4个周桶的并集，不要求11份重复文件。删除前恢复最新备份并验证SHA、integrity和全部表计数。轮换保留确认墓碑，避免源端尚未清理时重新下载旧份。
- 按文件大小分配独立预算，Python各阶段检查deadline，外层7220秒，systemd7260秒（含等锁20秒），任务硬工作上限7200秒；oneshot Restart=no，失败等下一次调度，避免两小时失败无限重启。
- 备份与rollup分别持锁，长备份不占用维护任务锁。旧keep2入口兼容保留；T6通过强制归档入口及drop-in替换原单个timer，不并行启动另一条keep2备份。
- NAS实际有/usr/local/bin/python2.7及fcntl，原PATH只证明没有python3。宿主kernel flock监督程序兼容2.7/3，锁文件不删除；fork/exec继承、专属进程组清理；容器内另持校验锁，防Docker CLI退出后的遗留校验并发。
- 拿锁前核卷标记及同一设备；标记不存在、错误或根路径链接时失败关闭。预算/实际可用空间双检查，NAS离线保留实际最近成功和备份年龄。
- 原容量四副本系数及archive_enabled=false保持；T4按实测副本与容量共同切换，T6才启用生产调度。

90天夹具使用实际AnalyticsStore schema、50设备×6000事件/天；raw/settlement各420万、fact5400万、seen2700万，并保留所有二级索引。生成、备份、恢复在PRnas隔离卷进行，不将NAS性能当阿里云满载性能。最终规模和耗时见验收回执。

补充修正：归档模式last_backup_success_ms采用manifest.created_at_ms，ready恢复不得把旧快照年龄归零。成熟夹具生成可在同schema/同规模下从完整提交行数续建，索引排序临时目录必须放NAS隔离卷（SQLITE_TMPDIR），不是128MiB容器tmpfs；这不改变实际备份校验128MiB缓存、两小时预算或50×6000×90行数。

固定候选独立评审发现的两项均修复：旧ready水位不归零；NAS锁入口没有两项卷标记配置时，在创建任何锁文件前失败。新反例纳入套件，保留首次RED。大库实际2700万seen计数对照显示默认覆盖索引扫描明显较慢，改用count(1)+NOT INDEXED，同值且可触发SQLite进度/截止检查；这是离线备份/校验任务优化，不修改实时摄入、查询或数据库索引。最终耗时以实测记录为准。

主实现追加真实反例：原严格24小时判断在次日timer比前日早400毫秒时会跳过整天，已改为CST自然日判定并验证同日不重复、次日轻微提前仍生成。原RED与修复GREEN独立保留。
