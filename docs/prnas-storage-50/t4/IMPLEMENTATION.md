## 实现

- 容量同时返回30/90/180天模型。raw新增天数封顶14、两维度facts封顶90、seen随窗口增长且不设TTL。准入选180天；更长期仍持续增长，不能解读成永久可用容量。
- 成熟库实测raw含结算/索引2093.89B，两维facts961.85B，seen373.97B。raw由1280校准上取整为2304，facts/seen保留1024/400字节，另留10%规划余量。全部已有占用已经反映在实际磁盘空闲中，不把freelist当可用磁盘。50只是规划值，已验证额度仍14。
- 同卷按4.5GiB底线＋完整8GiB Ark待归档缓冲保守预留。即使归档未开也为规划中的归档预留；不是宣称8GiB文件已经落盘。此方案不支持把spool迁往另一卷后无验证地复用同卷预算。
- 迁移期保守按五份：live、原keep2、最新已确认归档包、下份构建快照。Ark开关不代表Analytics备份调度状态，不能用它切换副本数。T6必须替换旧单一timer并证明没有并行旧备份；旧keep2未处置前不下调系数。
- 全库备份默认保留空间由4GiB对齐4.5GiB；原命令参数仍可用于隔离测试。
- 统计整轮150秒预算，在日边界停下；连同最多一日30秒和TTL30秒，留在240秒外层超时之前写出水位。统计用同一DEFERRED读快照扫描，收集最多1000设备摘要后短写提交。期间有其他连接写入，SQLite拒绝陈旧快照升级，保留dirty和旧完整结果，下轮重算。不会把读快照关闭后无版本保护地覆盖新数据。持续摄入可能暂延迟统计，待上传间歇收敛；不能承诺实时统计。
- TTL每轮最多300个短事务，每个最多10条raw/tier与fact；每事务最多1批及其至多200条结算，避免单事务删千批关联记录。总预算30秒、事务间让出10ms。JSON报告实际facts、events、batches、事务峰值、耗时和预算耗尽；永久seen从不删除。
- 容量中的维护上限是该固定5分钟周期预算的保守计算（另扣30%），不是实机验证档。实际净清理吞吐和云端持锁证据必须在本阶段回执列明；T5另验连续稳定性。

## 测试夹具纠错

首个本地性能夹具尚未生成完成就启动HTTP，未取得有效性能结论；原日志保留。随后增加PREPARED完成标记。云端首次性能脚本总闸文件权限非0600且单身份请求频率超合同，已停止该隔离unit并作废ACK数据；修正权限、50次/100ms间隔及现有checkpointer后用全新夹具复验。NAS首次dbstat重复传入镜像已有python入口，未执行数据库读取；修正镜像参数后重跑。UI首次缺离线依赖目录，补充仓内固定vendor文件后58项通过。均非线上业务故障。

补充失败与修正：正式prune→rollup顺序下500行事务仍导致11/50可重试503；成熟字段宽度、同时存在另一隔离I/O任务的压力轮中100行事务也出现长等待，不能作最终通过。后续进一步改为10行/单批，300段/30秒有界总预算，维护纸面额度相应降至50（原验证档仍14）。最终验收只使用无其他本轮I/O测试重叠的新一轮结果。

NAS dbstat扫描961.88秒完成。该工具的aggregate字节列出现精确2^32整数倍回绕；原数值保留，使用对象页数×4096重新计算，所有对象合计加未归对象的一页等于文件44871368704字节。原数据与复核算法均归档，不将负字节或6.2GB错误合计作为容量依据。
