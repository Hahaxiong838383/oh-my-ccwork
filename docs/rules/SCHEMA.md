# 规则书写规范（万能公式 v1）

> 本文档定义 mycc 项目所有"行为规则"的统一书写格式。
> 灵感来自飞书"万能语法-修正版2"（[wiki/GbUKwTTWFiIL0JkYL0HcXnNqnog](https://futurus.feishu.cn/wiki/GbUKwTTWFiIL0JkYL0HcXnNqnog)）。
>
> 立项时间：2026-04-28
> 状态：试运行 v1（首次套用：CLAUDE.md 主文件压缩）

---

## 核心思想

把所有"对 cc 行为有约束的指令"看作**槽位填充模板**：
- 不定形规则 → 固定槽位 + 量化优先级
- 主文件只载入 **P0 全文 + P1 速览表**，P2/P3 按需 grep 召回
- 决定一条规则放在哪一层，靠 **4 维量化指标**，不靠拍脑袋

## 4 维优先级矩阵

每条规则必须打 4 个分：

| 维度 | 取值 | 含义 |
|------|------|------|
| **是否常用** | 必需 / 常用 / 可选 | 实际触发频率（语料统计） |
| **是否必选** | 必选 / 可选 | 缺了规则还成立吗（语义最低门槛） |
| **优先级** | P0 / P1 / P2 / P3 | 抽取/加载顺序 |
| **权重** | 0.35 / 0.60 / 0.75 / 0.85 / 1.00 | 连续值，用于打分排序 |

### P 分级与权重对照

| 级别 | 权重 | 默认载入 | 触发场景 | 例子 |
|------|------|---------|---------|------|
| **P0** | 1.00 | 主文件全文 | 每次对话都生效 | 中文回复 / 任务署名 / BRO-PDCA 接收 / 调试前置 5 项检查 / 文件归档铁律 |
| **P1** | 0.75-0.85 | 主文件压成万能公式表 | 启动条件触发 | 跨 session 交接 / 置信度自评 / 质量门 / RPT 验证 / 多智能体路由 |
| **P2** | 0.60 | 仅索引在主文件 / 详情下沉 | 特定场景才相关 | 工具选择优先级 / 自进化授权 / 上下文预算 / 依赖本地化 |
| **P3** | 0.35 | 仅索引 | 极少触发 / 一次性配置 | 飞书通知 429 降级 / 多设备 git 区分 / 移动端启动 |

## 单条规则的标准格式

### P0 规则（主文件全文）

```markdown
## N. 规则名

**触发**：在什么条件下生效
**动作**：cc 必须做什么（用动词开头的祈使句）
**反模式**（可选）：禁止什么行为
**Why**：一句话说为什么（保留这一行让边缘情况可判断）
```

### P1 规则（主文件表格行）

```markdown
| RULE-ID | 触发 | 动作 | P/权重 | Why（一句话） |
|---------|------|------|--------|--------------|
| HANDOFF | 说"留到下个 session"或还有后续 Phase | 追 RECENT_EVENTS + 写 HANDOFF + 给可粘贴提示词 | P1/0.85 | 异步交接零返工 |
```

详细的 Why+How+例外+案例放到 `docs/rules/<RULE-ID>.md`。

### P2/P3 规则（主文件索引行 + 子文件全文）

主文件：

```markdown
| RULE-ID | 文件 | P/权重 |
|---------|------|--------|
| TOOL-PRIO | docs/rules/tool-priority.md | P2/0.60 |
```

`docs/rules/<RULE-ID>.md` 全文格式：

```markdown
# RULE-ID: 规则名

| 字段 | 值 |
|------|-----|
| 优先级 | P2 |
| 权重 | 0.60 |
| 是否常用 | 可选 |
| 是否必选 | 可选 |
| 触发条件 | <什么场景下生效> |

## 动作
<cc 必须做什么>

## Why
<为什么这么做，含历史背景/案例>

## How to apply（可选）
<判断边缘情况的具体方法>

## 例外（可选）
<什么时候不适用>
```

## RULE-ID 命名规范

- **大写字母 + 连字符**：`HANDOFF` / `HOT-CONF` / `QUALITY-GATE` / `TOOL-PRIO`
- **领域前缀**（多于一条相关规则时用）：`FEISHU-CONFIRM` / `FEISHU-FALLBACK`
- **简短可记**：3-15 字符，不用句子（不是 "RULE-FOR-DEBUG-BEFORE-FIX"）
- **唯一性**：跨 CLAUDE.md / docs/rules/ / memory/ 全局唯一

## 增删规则的工作流

### 新增规则

1. **打 4 维分数**：是否常用/必选 + P 级 + 权重
2. **决定位置**：
   - P0 → 直接写到 CLAUDE.md 对应章节
   - P1 → 加到 CLAUDE.md 的"P1 万能公式表"一行 + 写 `docs/rules/<ID>.md` 详情
   - P2/P3 → 只在 CLAUDE.md 索引表加一行 + 写 `docs/rules/<ID>.md` 详情
3. **打 RULE-ID**：见命名规范
4. **必填 Why**：哪怕一句话，也必须有

### 修改规则

1. 改动只在 `docs/rules/<ID>.md` 里改 → CLAUDE.md 的索引行不动
2. 改动涉及 P 级降级/升级 → 必须同步移动文件位置（P0↔P1↔P2/P3）
3. 改动涉及触发条件 → CLAUDE.md 表格的"触发"列必须同步

### 删除规则

1. 在 `docs/rules/<ID>.md` 标记 deprecated（不立即删文件）
2. CLAUDE.md 移除对应行
3. 30 天后无回滚需求才物理删除

## 反模式（禁止）

| 反模式 | 危害 |
|--------|------|
| P0 规则的 Why 被砍掉 | 边缘情况无法判断，cc 凭感觉走偏 |
| P2/P3 规则塞进 CLAUDE.md 主文件 | 上下文膨胀，长任务质量衰减 |
| 同一规则同时在 CLAUDE.md 和 docs/rules/ 里有详情 | 一处更新另一处过期，形成事实分叉 |
| 没打 RULE-ID，靠"上下文锚定" | 跨 session 召回失败 |
| 4 维优先级靠拍脑袋 | 标准失效，最终回归散文式书写 |

## 与其他记忆系统的关系

本规范定义"项目级行为规则"（`mycc/CLAUDE.md` + `mycc/docs/rules/`）的格式。

- **`~/.claude/rules/*.md`**：全局规则（跨项目），格式自由，**本规范不强制**——但建议下次重构时套用
- **`~/.claude/projects/-Users-rayman-chen-mycc/memory/MEMORY.md`**：自动记忆索引，**本规范不强制**——但 4 维优先级思路可借鉴（哪些自动召回 / 哪些按 grep 关键词触发）
- **`0-System/RECENT_EVENTS.md` / `task-log.md`**：事件流，不属于"规则"范畴，**本规范不适用**
