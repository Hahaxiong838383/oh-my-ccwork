## 行为变化与收益

1. 正常轮先只请求大脑；大脑仍带现有人设、记忆、方舟数据与搜索路由。
2. 大脑明确失败、空回复，或 2 秒仍无可播正文时，才启动一次外层备用。备用启动后大脑仍可率先完成。
3. 有正文后固定该路回复，不在半句话中换模型。用户打断、关房或总首正文超时，会取消未完成请求。
4. 去掉外层备用的生成式预热，避免每次开房额外生成一轮。
5. 各供应商/套餐独立保存密钥；切换不会串用。保存沿用通话拦截、重启健康检查、失败恢复，多个配置发布操作不会同时覆盖环境文件。

**大脑内部 DeepSeek＋火山赛马保留。** 本次减少的是 Worker 外层的额外调用，不能理解为火山总调用或额度消耗归零。单次请求取消也不能保证供应商不计入已产生的用量。

外层是应急基础回答，不具有完整大脑的实时搜索、个人数据与记忆注入。DeepSeek 默认用于绕过大脑服务故障；需要跨供应商容灾时可切火山。新安装未显式配置开关时默认关闭；本次已运行主池显式开启有界策略，替代原来每轮双发。

## 后台怎么操作

- 切模型：选择“备用调用选择”，核对模型；已配置的端点无需再填密钥，未配置的填写后保存。
- 调整策略：启动等待允许 500～5000ms；总等待不得超过 15000ms，且至少比启动等待多 2000ms。
- 只用大脑：关闭“有界灾备开关”，保存后生效，已有密钥不删除。
- 保存约需 15 秒，并重启主 Worker。建议无通话时操作，保留现有通话检查。
- “当前进程”显示实际生效值，下拉框表示准备保存的值；未保存前不会冒充生效。
- 延时测试使用已保存端点和密钥，会真实调用模型并计费；不会在保存后自动运行。
- 旧 grace 参数已经停用，新的时间参数是独立的首正文触发与截止预算，不是整段播报时长。
