§0

一句话方案

RK3588 单板（不加算力卡）分两阶段落地：阶段 A 直接移植（2–3 天，gaze 模型上 NPU、mediapipe 留 CPU），用于验证精度与全链可行；达标后视需要进阶段 B（NPU 原生管线，1–2 周），预期 30fps+ 反超 MacBook Air 现状。每一阶段都有量化验收门，任一门不过按预案回退，不带病前进。

先决结论（已调研实锤） ① resnet18 在 RK3588 NPU 实测 4.09ms/244FPS，反超 M5 MPS；② mediapipe 0.10.15 的 aarch64 Linux wheel 已在 PyPI 验证存在（cp39–cp312）；③ RK1828 对本方案过配，定位为将来 MyJavis 融合时的 LLM 协处理器；④ Hailo-8 路线有实测反证（MediaPipe 模型 multi-context 仅 12fps），不采用。

§4

阶段 A：直接移植 POC（2–3 天）

A1 · 系统与环境（0.5 天）

# Ubuntu 22.04/24.04 aarch64（Joshua Riek 镜像或官方）
sudo apt install python3.12-venv v4l-utils cmake
python3.12 -m venv .venv
# mediapipe 版本是硬边界：0.10.35 起 legacy solutions 被删，1.x 彻底移除
.venv/bin/pip install "mediapipe==0.10.15" "opencv-python>=4.8" numpy
# RKNN 板端运行时（版本必须与转换端 toolkit2 配对）
.venv/bin/pip install rknn-toolkit-lite2
毒药防御 · 铁律 任何后续 pip/uv install 都可能静默升级 mediapipe 导致全链炸（Mac 上已实踩：测试全绿也测不出，因为单测不碰 FaceMesh 构造）。装完立刻 pip freeze | grep mediapipe 钉死，每次装新包后复查。

A2 · gaze 模型转换（0.5 天，可在 Mac 上先做）

  1. 导出：ptgaze 的 model.safetensors（resnet18）→ ONNX（输入 1×3×224×224，输出 pitch/yaw）。
  2. 转换：rknn-toolkit2（x86 Linux 容器里跑）ONNX → RKNN，INT8 量化校准集用探针采的真实注视帧（probe_ab_samples 对应的画面截帧，覆盖四方位注视姿态），不用随机图。
  3. 若 INT8 精度塌（见门 1），回退混合量化或 FP16——RKNN 支持逐层配置。

A3 · 代码改造（1 天）

架构上是现成的插槽：gaze_estimator.py 加 GAZE_BACKEND="rknn" 分支——构造时加载 .rknn 模型，_ptgaze_infer 对应实现换成 rknnlite 调用，归一化/符号约定/隔帧推理（GAZE_INFER_EVERY）/丢脸回退全部复用。其余改动：

  • hand_tracker.py 摄像头打开逻辑加 V4L2 设备号探测（Linux 分支已有 CAP_DSHOW 的 Windows 分支先例）。
  • MPS 检测代码在无 torch 环境下短路（rknn 分支 lazy import，不装 torch 也能跑）。
  • 校准档元数据里 backend="rknn" 自动与 Mac 档案隔离——无需新代码，v3.9 的毒药防御设计天然覆盖跨设备场景。

A4 · 交互层阈值复查（0.5 天）

教训条款（threshold_dead_signal）：换信号源必须 grep 全部消费 gaze 绝对值的阈值。本架构已免疫大半——垂直门控是布局几何推导、校准档按元数据隔离；仍需人工复查的只有 GAZE_PT_DEG_SCALE（INT8 输出分布若有系统偏移，由 9 点标定吸收，预期不用动）与到位门 CALIB_ARRIVAL_MIN_SHIFT。

§5

阶段 B：NPU 原生管线（1–2 周，达标后再投）

触发条件：阶段 A 六道门全过，且确认要把帧率从 ~12–15 提到 25+（例如产品化演示需要）。改造：

  • 人脸：RetinaFace + 106/468 关键点 rknn 模型替代 FaceMesh（rknn_model_zoo 生态现成），EAR/眨眼公式按新关键点索引重写。
  • 手部：rknn 生态手部检测+21 关键点替代 MediaPipe Hands，pinch 比例公式复用，PINCH_ON/OFF 阈值按新模型重标（同一教训条款，手部信号也换源了）。
  • 三模型绑 NPU 三核并行；主循环改流水线（读帧与推理重叠）。

阶段 B 的验收 = 六道门整套重跑 + 手势专项（pinch 准确率与 Mac 版对拍视频逐帧比对）。

§6

§7

风险登记与回退

风险概率对策 / 回退
INT8 量化后 gaze 精度塌（门 1/3 不过）中逐层混合量化 → FP16 → 最坏 CPU float 跑 onnxruntime（帧率降但可用）
rknn-toolkit2 与板端 librknnrt 版本不配对中转换端与板端版本号写进环境文档钉死；报错特征是加载期 version mismatch
mediapipe 被后续安装静默升级中§4 毒药防御；requirements 上限硬边界 + 每次装包后 freeze 复查
UVC 摄像头实际交付帧率/曝光不达标低选购时验 v4l2-ctl 真实模式表；备选 MIPI-CSI 摄像头
散热降频（门 6 不过）低加强散热；NPU 三核只用一核（阶段 A 本来只需一核）
阶段 B 手部模型精度不及 MediaPipe中pinch 对拍视频逐帧比对不过 → 手部保留 CPU MediaPipe（混合架构，帧率介于 A/B 之间）

总回退原则与 Mac 侧一致：每阶段开工前 git 锚点；配置级开关优先于代码回滚（GAZE_BACKEND 三态：ptgaze / rknn / legacy）；板上任何阶段失败不影响 Mac 版——两平台代码同仓同源，校准档天然隔离。
