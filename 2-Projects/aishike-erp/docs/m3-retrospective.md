### M3：渠道订单、发货和激活

- 天猫、京东、线下经销渠道 SKU 映射到已批准内部 SKU；
- `渠道 + 渠道范围 + 外部订单号` 保证订单幂等；
- 只有 `STOCKED`、SKU 匹配且在库的设备可以扫码分配；
- 发货必须保存实际出库仓库、承运商和物流单号；
- 激活必须发生在发货后，只保存脱敏激活和客户引用；
- 分配、发货、激活凭证不可修改、不可删除，并驱动订单和设备投影；
- 销售履约工作台完成订单查询、扫码分配、发货、激活、列表筛选和时间线追溯。

## 3. 主要失误与根因

### 3.1 阶段授权曾被误当成代码进度

M2.3 曾在未获明确指令时被提前恢复和部署。根因是把“代码已有草稿”误当成“阶段已获授权”。纠偏后，阶段闸门同时约束源码、部署、数据库和 UI，并要求用户明确回复后才能推进。

### 3.2 Frappe 元数据删除不等于残留清零

回退 M2.2 时，即使 DocType 和 Page 元数据已不存在，物理表、隐藏列、生命周期事件和错误设备投影仍可能保留。最终通过幂等清理器删除残留，并由真实组装/烧录凭证重新派生设备状态。

### 3.3 权限矩阵不等于真实岗位能力

初版仅检查 DocType 权限和 UI 按钮显隐，无法证明控制器中的岗位动作约束。完成度审计后补充五岗位真实用户动作链，并验证事务回滚无残留。

### 3.4 隐私校验曾漏掉原始报文引用

收货对象、激活和客户引用已有手机号/邮箱阻断，但 `raw_payload_ref` 仅靠字段名称声明“脱敏”。修复为所有脱敏引用统一调用隐私校验，并补纯规则与真实 Frappe 负向验收。

### 3.5 浏览器登录工具回显了密码

Playwright CLI 的 `fill` 执行日志回显了输入值。发现后立即轮换管理员密码，后续改为从服务器受限文件直接写入本机剪贴板，密码不再进入聊天、文档、Git、记忆或截图。

### 3.6 公网目标曾因口误指向 Studio

用户随后澄清应连接 `company-vm`。此后将主机真值检查放到部署前，Studio 只做连通性验证，爱视可 ERP 固定部署 `/home/futurus/aishike-erp`。

## 4. 固化方法

- **阶段闸门**：代码完成、自动验收、人工验收和下一阶段授权是四个独立状态；
- **状态派生**：业务状态只能由不可修改凭证推进，投影字段禁止人工覆盖；
- **真实权限**：权限验收必须执行真实动作，而不是只读取权限配置；
- **负向精确性**：每个预期失败同时检查目标错误文本、事务回滚和残留为 0；
- **浏览器真值**：全新会话检查中文、用户路径、列表筛选、响应式布局和控制台；
- **部署安全**：源码与数据库双备份，secret 指针化，选择性同步与选择性 Git 暂存；
- **稳定复验**：部署成功后至少执行连续验收、容器重启复验和服务器源码一致性检查；
- **人工样本隔离**：自动、浏览器、角色和人工验收分别使用独立批次与订单，防止自动检查污染人工体验。
