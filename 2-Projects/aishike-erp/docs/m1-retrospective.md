## 经验教训

### 1. 展示名称不能破坏内部标识

Frappe Workspace 的名称、路由和显示标题存在耦合。直接把内部 `label/title` 改成中文，会生成不存在的中文路由。最终采用：

- Workspace 内部名称、`label`、`title` 固定为 `Aishike ERP`；
- 中文展示通过 `zh.csv` 和工作台内容实现；
- 静态校验锁定内部标识，防止后续改动重新破坏路由。

### 2. 迁移钩子必须兼容目标版本的完整必填字段

Frappe v16 的 Workspace 新增必填 `type`。旧记录为空时，`after_migrate` 中直接保存会让迁移在最后阶段失败。修复方式：

- 静态 Workspace JSON 显式写入 `type: Workspace`；
- 迁移钩子保存前补齐 `workspace.type`；
- 校验脚本增加 Workspace 类型和内部标识断言。

### 3. 数据库正确不等于用户可用

仅验证数据库、容器状态和 HTTP 200，无法发现中文路由失效、默认工作台错误或前端资源异常。M1 的最终验收链固定为：

1. 全新浏览器会话打开登录页；
2. 使用真实管理员登录；
3. 自动进入爱视可工作台；
4. 打开 SKU 列表；
5. 分别检查草稿和已批准 SKU；
6. 检查浏览器控制台错误；
7. 保存最终截图作为人工验收证据。

### 4. 翻译资源必须进入部署流水线

只修改 `zh.csv` 不会自动更新运行环境。部署脚本必须在迁移后执行 `build-message-files`，并通过全新会话确认翻译资源实际加载。

### 5. 密钥必须只在运行时短暂使用

浏览器自动登录时，管理员密码只读入临时 shell 变量，命令输出被抑制，使用后立即清除。密码、Token、服务器私钥、部署 `.env`、`secrets/` 和备份文件均不得进入源码、日志、截图或记忆。

## M2 入口条件

M2 从设备 SN 与生产质检闭环开始，不提前实现渠道订单或售后。首个可验收切片必须包含：

- 可配置 SN 生成规则；
- 批量生成且全局唯一；
- 条形码和二维码输出；
- USB/蓝牙扫码枪键盘模式录入；
- 扫码后打开设备档案并校验状态；
- 组装登记入口和追加式生命周期事件。
