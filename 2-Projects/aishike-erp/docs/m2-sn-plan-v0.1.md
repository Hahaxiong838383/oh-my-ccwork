# 爱视可 ERP M2：设备 SN 与扫码闭环方案 V0.1

## 1. 结论

M2 的 SN 能力按三个可独立验收阶段推进：

1. **M2.1：SN 规则、批量生成、条形码、二维码、扫码识别和组装登记**；
2. **M2.2：固件烧录和六项测试**；
3. **M2.3：质量门、成品入库和全链路追溯**。

当前只实施 M2.1。川哥完成真实界面验收后，再进入 M2.2。

## 1.1 当前实施状态

- M2.1 已部署到公司虚拟机测试环境，等待人工验收；
- 工作台入口：`http://aishike.localhost:18081/desk/aishike-sn-console`；
- 已验证连续生成、Code 128 条形码、二维码、原始 SN/二维码内容扫码定位和组装登记；
- HID 键盘模式扫码枪可直接录入并以回车触发识别；
- 串口、COM 或厂家 SDK 设备仍保留在后续本地工位 Agent/Web Serial 范围；
- M2.2、M2.3 未提前开发，继续遵守人工验收闸门。

## 2. 设备 SN 设计

### 2.1 基本原则

- SN 全局唯一，创建后永久不可修改；
- SN 不包含客户、儿童、视光或语音数据；
- 条形码和二维码都是 SN 的派生展示，不单独保存图片真值；
- 每次批量生成保留规则、SKU、生产批次、序号范围、操作人和时间；
- 生成请求要么全部成功，要么全部失败，不允许部分生成；
- 并发生成必须锁定规则序号，避免重复号；
- 设备创建时写入追加式生命周期事件。

### 2.2 自定义规则

规则模板允许以下占位符：

| 占位符 | 含义 | 示例 |
|---|---|---|
| `{PREFIX}` | 规则前缀 | `ASK` |
| `{DATE}` | 按规则配置的日期格式 | `250805` |
| `{SKU}` | SKU 配置编号标准化结果 | `ASKRWDESKWHITEPRO` |
| `{BATCH}` | 生产批次标准化结果 | `LOT01` |
| `{SEQ}` | 按位数补零的流水号 | `000001` |
| `{SUFFIX}` | 可选后缀 | `CN` |

默认模板：`{PREFIX}-{SEQ}`。需要日期的规则必须由生成批次显式选择生产日期，不能依赖服务器时钟。

日期格式支持：`YYMMDD`、`YYYYMMDD`、`YYMM`、不使用日期。流水号支持 4–10 位。

序号重置策略：

- 永不重置；
- 每日重置；
- 每月重置；
- 按生产批次重置。

### 2.3 码制

- **条形码**：默认 Code 128，内容为原始 SN，适合字母、数字和连字符；
- **二维码**：内容为 `ASK:DEVICE:<SN>`，便于与普通文本区分；
- **标签打印**：浏览器生成 60mm × 30mm 标签，包含产品名、SN、条形码和二维码；
- 码图随时由 SN 重新生成，不把 SVG/PNG 作为业务主数据保存。

## 3. 扫码设备兼容性

### 3.1 直接支持

- USB 扫码枪的 HID 键盘模式；
- 蓝牙扫码枪的键盘模式；
- 二维扫码枪读取 Code 128 或二维码；
- 手机或平板摄像头，通过 Frappe 内置扫码器识别二维码和常见条码；
- 扫描完成后自动回车的扫码枪；没有自动回车时可手动确认。

键盘模式扫码枪会像键盘一样向当前输入框写入字符，因此浏览器无需安装厂家驱动或插件。

### 3.2 暂不直接支持

- 串口/COM 模式扫码枪；
- 只提供厂家 SDK、不提供键盘模式的工业设备；
- 需要后台常驻监听的串行秤、PLC 或工位控制器。

这些设备后续通过 Web Serial、本地工位 Agent 或 MES 网关接入，不进入 M2.1。

## 4. 数据模型

### 4.1 Aishike Serial Number Rule

- 规则编号、规则名称；
- 模板、前缀、后缀；
- 日期格式、序号位数、重置策略；
- 当前作用域、下一个序号；
- 条码格式、二维码前缀；
- 启用状态和示例 SN。

### 4.2 Aishike Serial Number Batch

- 生成批次号；
- SN 规则、SKU 配置、生产批次；
- 显式生产日期；
- 请求数量、序号开始/结束；
- 实际生成数量、生成状态；
- 生成操作人和生成时间。

### 4.3 Aishike Device Unit 增量字段

- SN 生成批次；
- 设备标识码预览区；
- 生成规则追溯关系。

## 5. M2.1 界面

新增“SN 工作台”，采用单页操作台：

1. 左侧选择规则、SKU、生产批次和数量；
2. 实时预览前三个 SN；
3. 一次生成 1–200 台设备；
4. 展示最新生成批次和标签预览；
5. 扫码输入框持续聚焦，支持外部扫码枪；
6. 扫码后展示设备、SKU、状态、批次和最近事件；
7. `CREATED` 状态设备可在工作台登记组装完成；
8. 支持打开完整设备档案和打印单张标签。

## 6. 验收标准

- 相同规则连续两次生成不得重复；
- 两个并发请求不得取得相同序号；
- 非法模板、未知占位符、数量越界必须失败且不产生设备；
- 已停用规则不能生成；
- 未批准 SKU 不能生成设备；
- 条形码内容等于原始 SN；
- 二维码内容等于 `ASK:DEVICE:<SN>`；
- 扫描原始 SN、二维码内容或设备档案 URL 都能定位同一设备；
- 扫描不存在的 SN 明确提示未找到；
- 组装登记只允许 `CREATED → ASSEMBLED`，并新增生命周期事件；
- 全新浏览器会话控制台 0 错误；
- 一台真实或模拟键盘扫码枪完成扫码识别验收。

## 7. M2.1 实施经验

1. 业务生产日期必须由操作员显式选择，不能直接使用服务器日期生成 SN；
2. 条形码和二维码应由 SN 即时派生，数据库只保存可追溯的编号与生成批次；
3. 通用扫码枪优先按 HID 键盘协议接入，避免第一阶段引入工位驱动和浏览器插件；
4. 序号分配必须在数据库事务中锁定规则记录，批量生成保持全成功或全失败；
5. 页面验收必须同时覆盖正常扫码、未知 SN、组装状态变化、标签渲染和全新会话控制台。
