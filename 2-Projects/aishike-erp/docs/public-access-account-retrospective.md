# 公网发布与企业邮箱账号复盘

> 完成日期：2026-08-06

## 结论

- 正式入口为 `https://erp.hahaxiong.cc`，阿里云 DNS 显式 A 记录指向香港入口 `8.218.26.17`；
- 旧 `sslip.io` 域名保留有效证书并统一 301 跳转正式入口；
- 日常管理员改为 `rayman.chen@futurus.co`，`Administrator` 只作为紧急恢复账号；
- 后续新增员工 `System User` 由运行时校验强制使用 `@futurus.co` 飞书企业邮箱。

## 经验教训

1. DNS 读权限成功不代表写权限可用。AccessKey 被平台判定泄露后，查询仍可能成功，但写入会被强制拒绝；正式切换必须准备控制台人工写入或已轮换凭据的回退路径。
2. 公共 DNS 生效不代表本机缓存立即刷新。验收要同时检查权威/公共解析、本机系统解析和真实浏览器，不能只看单次 `dig`。
3. 正式域名切换采用双入口更安全。先签发新证书并验证主站，再把旧域名改为 301，避免一次性替换导致无回滚入口。
4. Frappe 多站点路由与 WebSocket Origin 是两套语义。内部继续使用 `X-Frappe-Site-Name=aishike.localhost`，公网 Origin 必须以 `X-Forwarded-Host` 校验。
5. 浏览器自动化中的密码和一次性链接都属于秘密。不得把值拼入会回显的 Playwright 代码；填充后必须立即跳离登录页，并按真实秘密值扫描和清理产物。
6. ERP 没有出站 SMTP 时，不应在服务器临时硬编码邮箱密码。可由 ERP 生成一次性链接，再通过已验证的飞书用户邮箱发送，并分别验证 SENT、INBOX、链接用户和登录记录。
7. 企业邮箱要求不能只写在 SOP。运行时必须阻断非 `@futurus.co` 的员工系统账号，doctor 同时审计历史存量，避免人工操作绕过约定。
8. 自动检查不能替代人工闭环。最终证据必须包括 DNS、TLS、两地连续请求、真实登录、业务页面、Socket.IO、密码设置完成和数据库 `Login Success`。

## 回滚边界

- DNS 回滚前先恢复旧入口代理，避免域名重新命中通配记录后不可访问；
- 新企业邮箱账号不可登录时，使用受限文件中的 `Administrator` 凭据恢复，不在聊天中传递密码；
- 企业邮箱校验异常时，可回滚自定义 App 与 hooks，但不得删除已验证的企业邮箱管理员账号。
