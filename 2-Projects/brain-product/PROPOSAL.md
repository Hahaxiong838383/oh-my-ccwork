# mycc-brain：自进化认知操作系统

> 版本：v2.0 | 2026-04-02 | 作者：cc + 川哥
> 评审历史：v1.0 独立评审 → 6 轮深度讨论 → v2.0 二次评审重写
> 定位：**自用升级**（架构留口子，不做产品化投入）

---

## 一、问题定义

mycc 已有完整的认知架构（6 大意识理论映射、记忆系统 v5.5、自进化闭环），但存在三个结构性瓶颈：

1. **认知规则全靠 prompt 传递** — CLAUDE.md + rules/ 已超 3000 行，每个 session 消耗大量 context，且模型只能「读」不能「内化」
2. **经验数据没有闭环** — 轨迹记录了但没有系统性地反哺模型训练，用户纠正被处理了但没有保存对比对
3. **跨 session 状态靠文件手工同步** — hot-patches 机制是正确方向但还不存在，记忆更新延迟到 session 结束

**目标：建立一套自进化机制，让 cc 的大脑被经验持续塑造，最终通过微调把行为模式内化到模型权重中。**

---

## 二、核心洞察（v1 + 讨论推导）

### 洞察 1：大脑 = 机制 × 模型，不追求完全解耦

~~v1 的「规范是核心资产，模型是可替换的壳」~~ → 认知能力和模型能力是共生关系。14B 本地模型做不到 Claude Sonnet 的元认知深度，硬套同一套规范只会降级为无效指令。

**正确姿势：经验数据是核心资产，机制是提取经验的管道，模型是执行经验的硬件。** 模型来来去去，你的经验和记忆永远跟着你。

### 洞察 2：协议下沉到代码，模型只做「填空」

现有认知协议（BRO-PDCA 档位判断、HOT 置信度标注、RPT 验证循环）全在 prompt 里，依赖模型自觉遵守。

**正确姿势：把确定性逻辑下沉到代码（hook/脚本/daemon），模型只在需要判断力的环节做决策。** 比如：档位分类的规则是代码，但「这个任务做错了代价有多大」是模型判断。

### 洞察 3：对比对比单点记录值钱 10 倍

用户纠正 = 天然的 DPO 偏好对。同问题的成功轨迹 vs 失败轨迹 = 天然的 SFT 正负样本。**当前只存了纠正结果，丢失了纠正前的错误版本——这是巨大的训练数据浪费。**

### 洞察 4：日终整理 = 经验编译器

日终整理不只是「整理记忆」，而是一个**编译器**：输入原始经验流，输出多种编译产物——记忆条目、行为规则、SFT 训练对、DPO 偏好对、prompt 片段。编译器本身随着经验积累而改进。

### 洞察 5：规则应该趋于收敛，不是无限增长

类比免疫系统：成熟的免疫系统不是抗体越来越多，而是越来越精准。周期循环应该包含**规则压缩/合并**步骤，防止规则膨胀。

### 3.1 经验流 Schema

```jsonl
{
  "id": "exp_20260402_143021_a7f3",
  "ts": "2026-04-02T14:30:21+08:00",
  "source": "task_trajectory",
  "surprise": 4,
  "tags": ["user_correction", "routing_decision"],
  "payload": {
    "task": "发送飞书通知",
    "action": "调用 tell-me skill",
    "outcome": "429 限速失败",
    "resolution": "用户指示切换到 open-feishu-mcp"
  },
  "contrast": {
    "before": "重试 tell-me skill 3 次",
    "after": "立即切换到 open-feishu-mcp send_message",
    "signal": "user_correction",
    "dpo_eligible": true
  }
}
```

关键设计决策：
- `contrast` 字段可选，有对比对时记录，无对比时省略
- `dpo_eligible` 标记：true 表示可直接用于 DPO 训练
- `surprise` 由本地 4B 模型打分，日终整理时强模型校准

### 3.2 热修复机制（Hot Patches）

```
用户纠正 → hook 实时捕获 → 写入 hot-patches.jsonl
  → 同时保存 contrast（纠正前 vs 纠正后）
  → 下个 session 启动时立刻注入 system prompt
  → 日终整理时决定：升级为规则 / 合并到记忆 / 过期删除
```

类比：工作记忆（立刻生效，临时）vs 长期记忆（延迟生效，永久）。

**冲突处理**：日终整理如果产生与某条 hot-patch 矛盾的结论，标记为 `needs-review` 等人工确认，不自动覆盖。

### 3.3 双模式大脑

| 维度 | 完整模式 | 生存模式 |
|------|---------|---------|
| 主力模型 | Claude Sonnet API | 本地 Qwen3-14B（后续微调版） |
| 认知深度 | 元认知 + 深度推理 + 记忆整合 | 日常任务执行，只读取已有适应 |
| 适用场景 | 复杂决策、新问题、架构变更 | 重复性任务、离线场景、成本敏感 |
| 自进化 | 可以提出新规则和新适应 | 只执行已有规则，不产生新适应 |
| 切换条件 | API 可用 + 任务复杂度 > 阈值 | API 不可用 / 简单任务 / 用户指定 |

**切换协议**：
- 进行中的任务不中断切换，等当前步骤完成后在下一步切换
- 两种模式产生的经验流格式完全一致
- 生存模式的经验流标记 `mode: survival`，日终整理时由强模型处理

### 3.4 惊讶度评估器

**冷启动方案**：
1. 人工标注 50-100 条经验的惊讶度，作为 few-shot 示例
2. 4B 模型基于示例打分
3. 日终整理时，强模型回顾当天高/低惊讶度事件，反向校准阈值
4. 每周输出校准报告：误判率、漏判率、阈值调整建议

### 3.5 日终编译器

输入：当天经验流（已按惊讶度过滤）+ hot-patches + 现有记忆

输出（多种编译产物）：
1. **记忆更新**：新增/修改/删除 memory-items
2. **行为适应**：新增/修改 adaptations.yaml 条目
3. **SFT 训练对**：从成功轨迹提取 instruction-response 对
4. **DPO 偏好对**：从 contrast 字段提取 chosen-rejected 对
5. **prompt 补丁**：建议修改的 rules/ 文件片段
6. **hot-patch 处置**：每条 hot-patch 的去向（升级/合并/过期）

**失败处理**：
- 重试 3 次后放弃，标记为 `pending`
- 下次日终整理时累积处理
- 连续 3 天失败 → 飞书告警

## 四、微调闭环

### 四层进化，渐进深入

| 层级 | 频率 | 输入 | 工具 | 产出 |
|------|------|------|------|------|
| L1 prompt 进化 | 天级 | 日终编译产物 | 代码 + 强模型 | rules/ 和 memory 更新 |
| L2 SFT 微调 | 月级 | sft-pairs.jsonl | MLX QLoRA | Qwen3-14B-cc-v{N} |
| L3 DPO 对齐 | 季度级 | dpo-pairs.jsonl | MLX DPO | 偏好对齐版模型 |
| L4 GRPO 自博弈 | 远期 | 自生成轨迹 | 待定 | 待定 |

### 微调安全网

**灾难性遗忘防护**：
- 维护固定 benchmark（20 个测试任务：代码生成×5、推理×5、工具调用×5、格式遵循×5）
- 每次微调后跑 benchmark，通用能力下降 >10% 则回滚
- QLoRA rank 从低开始（r=8），验证无遗忘后再尝试更高

**里程碑**：
- 50 条 SFT 样本 → 验证 pipeline 通不通（工程验证）
- 200 条 → 第一个可用模型（质量验证）
- 500 条 → 正式替换生存模式主力
- 50 条 DPO 偏好对 → 首次偏好对齐

### prompt 压缩预期

不预设终态数字。分阶段测量：
- 基线：当前 prompt 总量（~3000 行）+ benchmark 得分
- 每次微调后测量：用缩减版 prompt 跑 benchmark，看能删多少行不损失性能
- 记录到 `experiment-log.tsv`，用数据说话

## 十一、关键推演记录

以下是 v1→v2 过程中的关键转折点，保留供未来回溯：

1. **「规范=核心资产」→「经验=核心资产」**：规范是概率性的不是确定性的，不能当配置文件对待
2. **「完全模型解耦」→「双模式共生」**：14B 模型跑不了 Claude 级别的元认知，硬套同一规范等于降级
3. **「靠 prompt 约束」→「协议下沉到代码」**：确定性逻辑用代码实现，模型只做需要判断力的决策
4. **「静态规范迭代」→「活的经验流持续塑造」**：大脑不是被配置出来的，是被经验长出来的
5. **（v2 新增）「单点记录」→「对比对优先」**：用户纠正自带 DPO 信号，成功/失败轨迹对比自带 SFT 信号
6. **（v2 新增）「规则只增不减」→「规则趋于收敛」**：周期循环加入压缩合并，防止规则膨胀
