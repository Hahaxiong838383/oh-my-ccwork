# 持久控制、重启状态与预设备份复盘

2026-09-21。本轮从整夜播放后的内存增长定位，推进到 v0.14.6 持久控制、v0.14.7 首项重播/状态修复，再完成物理重启复核和全部预设备份。当前功能源码仍为 `35374e59`，已固化并推送；本次只整理文档、记忆和 skill，不改运行程序或现场参数。

## 经验与改进

| 现象或曾经的误判风险 | 实际证据 | 后续做法 |
|---|---|---|
| 播放一直正常，容易忽略内存累积 | v73 整夜增长约 149 MiB/小时；堆内大量 WebSocket/网络对象残留，实际 TCP 仅一条 | 同 PID 同场景看 footprint、堆对象和实际连接；不要用“没崩溃”或任务列表为空证明内存健康 |
| 以为 cancel 或每次独立 session 就能回收 | 生产调用独立复现仍增长，单连接复用对照显著降低增长 | 先找可重复的创建/释放路径，再修改；不能把 API 名称当回收证据，也不能断言系统内部具体持有链 |
| 只复用页面连接，仍可能随切源累积 | 自动轮播不断创建/回收页面 | 浏览器级持久通道与页面逻辑会话分层管理，校验请求/代次/页面归属，未知执行结果不重放 |
| 动画在播、计划提示“未运行”，用户以为卡住 | 启动联动仅开单来源；手动计划日志在切换；旧首项 target/timeOrigin 不变 | UI 明确单源与自动计划；新计划首项从新文档开始，普通预览仍复用；用文档身份和实际计时核验 |
| 累计 4 次连接、3 次断开容易被解释成运行掉线 | 三次拒绝均发生在 08:08:10.611–11.143 的同一回环端口；后续计数不再增加 | 先看计数递增位置，结合 boot/PID、系统错误时点和连续快照增量判断 |
| AX 返回错误后盲点第二次，可能启动额外预览 | 分段控件已切换、元素被重建但 AX 返回失效 | 先核对后置状态，结果不明时不重复发送动作；重启后 `/tmp` 探针缺失也要和 App 故障分开 |
| 单套配置文件被当作全部预设库 | UI 只解码 configuration；预设集合还有名称、UUID、日期，历史/每屏当前档独立 | 备份原始全集及独立 JSON；说明逐个导入后还要保存预设，整库无损恢复另走指定键恢复 |
| 回滚旧包时误覆盖新调参数 | 现场参数可能在构建、验收间继续变化 | App、对应源码、最新参数配对封存；恢复程序不自动恢复旧参数，必要时先确认选哪个时间点 |

## 哪些改进已落地

- v74 默认使用浏览器级持久连接，旧控制函数原样保留为兼容降级；当前实现对 pending、页面与连接尝试有上限，换页/取消清理沿用页面所有权。输入连接继续独立。
- v75 明确“单链接预览中 · 自动计划未开始”；新计划首项 fresh，普通预览的复用语义保持。新增回归在旧源码出现 2 个失败断言，修复后相关整组 124 项/617 断言通过（assertion shim，非正式 XCTest）。
- 每次安装按固定路径、版本、源码/包指纹及签名身份核对，退出后备份最新参数；原参数不随软件回滚自动倒退。
- 参数已导出为独立可导入 JSON 与无损原始集合，附 typed plist、清单、恢复说明和 SHA；ZIP 与开发机副本均核验。原参数文件不自动随代码推送。
- `display-warp-poc` 增加按场景读取的运行生命周期、预设备份迁移参考。多引擎入口原相对路径缺少 `.claude` 的点号，本次纠正并校验目标可达；仍只维护一份技能正文。
- 独立代理以跨机 ZIP 恢复、重启连接计数、缩短测试时长三个场景复核技能，未发现越界写入或自动续播诱导；据其审查，将原无条件的完整交付格式限定到实际实施/发布范围，避免简单问答被扩展成无关实验。

## 预设与配置文件的准确口径

当前 v0.14.7 的「7. 预设与版本回退」和「8. 配置文件导入导出」共享参数结构，但不是同一份备份文件。前者保存命名集合/历史，后者导出正在使用的一套 configuration。

换电脑时，可在对应显示器/分辨率下，从备份 `presets/` 选择单个 JSON，经第 8 项导入，核对画面后在第 7 项填写名称并保存，逐个迁移。导入通常立即应用，随后保存会重建 ID/日期；当前 GUI 不支持一次导入整个预设数组或 ZIP。整库保留原元数据的恢复需要退出 App 后只写回对应键，不能以局部 plist 覆盖整个偏好域。

这里的“屏幕参数”指 App 的 AA、画布、位置、镜像等，以及弧度、压缩拉伸、贝塞尔、控制点和外扩参考域；不包含操作系统屏幕排列、授权、ProtoPie 来源或鼠标设置的自动迁移。相同分辨率不等于相同光学环境，不能保证跨屏无需重标定。当前重置全部参数不会删除命名预设，这也不替代独立备份。

## 遗留与未实施项

- 未取得 CFNetwork 内部完整持有链，也未证明 App 其他路径绝无小幅内存问题。
- fresh 标记设置后极早取消可能使下一次准备额外刷新；准备期仍可能短暂存在新旧两个页面；特别慢的冷启动可能消耗连接尝试预算。这些是已记录边界，不是本轮新增已解决项。
- 自动重启/自动续播保护仍暂缓，依据是每日有人开关机的使用方式；未来需求变化可重新评估，不作为永久禁令。
- 整库 GUI 导入、无条件换屏迁移、正式 44.8 屏新一轮光学验收及完整长稳未在本轮实现。
