# ProtoPie 可见退出与鼠标恢复：v0.13.6（58）

2026-09-18：已安装到 NIO 开发机，实机连续三轮退出检查通过；用户明确确认“退出和鼠标都正常”。本轮未重做合盖／开盖周期。

## 问题与根因

用户遇到预览退出不了、鼠标看不见。现场实际 Chrome 窗口和网页视口仍为 7680×2800 全屏；ProtoPie 工具栏切换给 `MAIN` 增加 56 px 顶部留白，内容根节点变为 `[0,56,7680,2800]`。原检查把内部布局未就绪与全屏未就绪合并处理，触发了无必要的恢复尝试。

恢复失败时旧画面仍可保留，但鼠标映射已停止，普通 Esc 随之失去退出入口。虚拟内容屏又属于扩展桌面，系统指针可落到这块用户看不见的屏幕上；仅恢复箭头样式不足以找回指针。

## 修复后的行为

- 普通 Esc 的演示退出入口独立于鼠标映射。只在 NIO 输出窗口取得焦点，或专用播放器处于演示范围时接管；已消费的按下、重复和释放成对处理，系统组合键保持原行为。
- 返回工作台会取消进行中的输入启动，停止映射，将工作台与箭头定位到可见物理屏。后台检查发现指针进入内容虚拟屏时也能恢复，失败后的退出不再依赖映射仍在运行。
- 工作台、离线界面及手动打开播放器均排除内容虚拟屏和睡眠屏，优先使用内屏。失败回调不再反向触发暂停通知，避免递归回调。
- 横向铺满布局抵消工具栏造成的正常排版偏移，保留现有比例、裁切位置及 Warp 参数；重复执行不会累加位移。
- 全屏尺寸和内部布局分别记录到本地 `nioWarpProtoPie.presentationDiagnostic.v1`。日志只保留阶段、尺寸和状态，不保存私有链接；几何已稳定但布局失败时，提示明确指向内部布局。
