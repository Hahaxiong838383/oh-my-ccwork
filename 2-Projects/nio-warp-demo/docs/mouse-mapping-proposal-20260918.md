# 鼠标映射方案（已批准实施）

目标：用户看着玻璃反射画面操作鼠标时，指针方向自然、可见落点与 ProtoPie 的实际响应一致，支持点击和拖动。本文记录最初方案与预览；用户后续批准并补充“可点击边缘尽可能贴近可用极限”。现已实现和部署v0.12.0，实际交付、测试范围和限制以[发布记录](mouse-mapping-v0120.md)为准。以下原方案中的靶标/方向校准等设计设想不等于已交付控件。

## 推荐体验

默认 **玻璃观察模式**：鼠标向右，反射观察中的指针也向右；鼠标向下，指针向下。指针置于独立的源内容逻辑坐标，点击发送到同一源点；其在物理外屏上的绘制位置通过完整显示映射计算，随画面一起水平镜像和曲面变形。物理屏上的水平运动会反向，这是抵消玻璃反射所需的效果，不能再在源点击上额外翻一次。

备用 **直看外屏模式**：指针跟随物理屏的方向，在输出空间累计移动，再反查当前可见内容对应的源位置。它适合调试时直接看显示器，不作为玻璃演示默认。

镜像设置说明画面怎样采样，不能独自证明玻璃实际光学方向。默认玻璃观察基于当前单次水平反射的布置；首次启用显示非对称“左／右／上”靶标并现场验证，必要时单独调整操作方向。位移精确到观察面的光学比例仍需要实拍标定。

### 指针和退出

- 演示控制开启后只显示一个高对比虚拟指针，默认圆点加十字，避免镜像后箭头方向混淆；大小和移动速度可调。
- 普通移动、左键单击/双击、拖动、滚轮列入首版。网页右键可发送；浏览器原生菜单及其他桌面应用暂不算首版验收范围。
- 内屏控制台仍使用正常系统鼠标。进入演示控制采用显式按钮/快捷键；返回工作台时恢复系统光标与正常输入。
- 保留 `⌃⌥⌘Esc`：立即结束输入接管并隐藏覆盖层。尽力释放原目标上已按下的按钮，清理事件队列，再恢复系统光标；异常、失焦、停止预览、目标丢失也走同一恢复入口。
- 初次启用先进入“仅显示落点”，不发送业务点击；确认左右方向和八个可见靶点后再开启交互。

## 可见区域规则

**鼠标映射不能恢复已经被物理屏幕裁掉的内容。** fit 只确保源图按比例装入逻辑画布；曲面可能仍把部分内容映射到显示器之外。

本轮用生产 `WarpMath.makeMesh`、`renderedPhysicalPoint`、`sourceUV`，结合实际 Shader 的 fit 和镜像顺序，检查源内容左中右×上中下九点（x=15%/50%/85%，y=20%/50%/80%）：

- 9 点正反向数学往返均可计算，最大源像素误差约 **0.000236 px**；这只是离线坐标链路检查，不是实机鼠标输入验收。
- 其中 8 点位于物理屏幕内。
- 中下点 `(源 x=3840, y=748.8)` 映射为物理 `(3880.826, 1020.815)`，超出 936 px 屏高，当前不可显示。预览将它明确标成不可点击，不伪造“九点全可用”。

新按下仅允许发生在有效可见内容上；AA 外、曲面外、fit 留黑、源 UV 越界区域不转发业务点击，不能强行夹到边缘误点。可见源区域可能非凸，按整段移动轨迹的首次越界位置限制指针，不能只检查终点而跨过不可见中下区。虚拟指针在可见内容边界停止，不进入不可见目标；已按下的拖动离开有效区时保留会话归属并确保 release，不能留下持续按住状态。玻璃遮挡/观察视野与软件物理屏边界不同，首轮现场再检查一次，必要时另设观察可见区域，不改现有曲线参数。

## 三层实现

### 1. 映射数学：复用真正正在显示的网格

已有 `GeneratedMesh.sourceUV` 可在实际三角形中用重心插值反查画布 UV；`renderedPhysicalPoint` 是配对正向函数。网格已包含 Warp、弧度、垂直比例、贝塞尔、局部点、对齐、扩展画布，不能另做一个只抵消水平镜像的近似模型。

绝对物理点链路：

```text
输出窗口局部点 → drawable 物理像素 → AA/可见区检查
→ 正在显示的网格反查画布 UV
→ contentUVScale → fit/fill/stretch → 镜像
→ 实际捕获纹理位置 → 捕获有效内容矩形 / 网页视口原点和范围 → 网页 CSS viewport 坐标
```

玻璃观察的相对鼠标链路：

```text
鼠标相对位移 → 独立的源内容虚拟指针
├─ 对应的网页 CSS viewport 坐标 → ProtoPie 事件
└─ 镜像逆变换 → 内容适配逆变换 → contentUVScale 逆变换
   → 正在显示的网格正向映射 → 外屏虚拟指针
```

鼠标逻辑位置不从已经注入的系统指针反读，避免反馈和跳动。共享 CPU 内容映射函数及 Shader 一致性测试，涵盖四种镜像、三种内容适配、非居中裁切和扩展画布。高频反查为真实网格建立空间索引，不每次扫描约55,200个三角形，也不换成另一套低精度网格。

### 2. 捕获与输入：绑定同一演示会话

首版只控制当前专用 Chrome/ProtoPie 页面，用现有 target ID 建立专用 CDP 长连接，按序发送 move/down/up/wheel，坐标换算到 CSS viewport。CDP 官方输入坐标就是网页 CSS 像素，不能把物理 7680×936 直接当作所有缩放状态下的网页尺寸。[CDP Input 文档](https://chromedevtools.github.io/devtools-protocol/1-3/Input/)

每帧映射快照需绑定：当前 mesh revision、Shader 参数、真实纹理尺寸、捕获 contentRect/缩放、generation、window ID/PID、page target、CSS viewport 及其在捕获纹理内的原点/范围。捕获 contentRect 不自动等于网页视口；首版仅在已验证无边框全屏且来源/视口稳定时启用，无法可靠排除浏览器工具栏等区域时拒绝发送。当前帧存储只有 CVPixelBuffer，尚不足以安全支持输入。事件连接复用、请求 ID 递增，只合并多余 move，不能丢失或重排按下/抬起。

按下时锁定来源与映射版本；切页面、切源、变化缩放/参数时先结束当前手势再切换，不能把旧 up 投到新目标。全屏尺寸不稳定或没有有效首帧时暂停发送。

后续如需原生 ProtoPie Studio/其他桌面应用，再接系统级事件后端；其窗口焦点、权限、注入回流和菜单交互需单独验收，不直接套用本次 Cloud 的成功结果。

### 3. 真实鼠标接管：先做前台兼容探针

当前输出窗口为非 key/main、应用采用 accessory 策略。Apple 的鼠标位移解耦/隐藏光标 API 通常要求应用在前台；不能假定现有穿透覆盖层直接调用就能可靠生效。[Apple 鼠标与光标解耦](https://developer.apple.com/documentation/coregraphics/cgassociatemouseandmousecursorposition(_:))、[隐藏光标](https://developer.apple.com/documentation/coregraphics/cgdisplayhidecursor(_:))

批准实施后先在可退出的小探针中验证：让 NIO 接收输入，Chrome 原生全屏及跨应用 Warp 覆盖是否仍保持；相对位移是否不受屏幕边界限制；恢复焦点时系统指针是否正常。若该入口不可靠，再评估限定演示控制期间的事件 tap，需要相应输入权限，并验证原事件被消费及失效自动退出；后台光标隐藏、边缘增量是否仍有效都要另测，不能假定 tap 自动解决。若两个输入后端都不可靠，保留工作台平面预览控制区通过源坐标操作 ProtoPie，明确只是替代操作入口，暂不承诺玻璃相对鼠标。普通全局 NSEvent monitor 不能阻止原事件下传，不能用它做“双发一次”的输入接管。[Apple 事件监视说明](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/MonitoringEvents/MonitoringEvents.html)

不将“CGEvent 发给某 PID”视为已验证可行的备用实现。首次权限缺失只提示启用，不允许部分接管后留下失控鼠标。

## 界面安排

建议新增 **鼠标映射** Tab，位于“ProtoPie 联动”左侧，仍保持 ProtoPie 是最右侧 Tab。

| 区域 | 控件 |
|---|---|
| 演示控制 | 进入/退出、当前输入目标、映射就绪状态 |
| 操作方向 | 默认“玻璃观察”；备用“直看外屏”；方向检测 |
| 指针 | 速度、大小；默认单一高对比十字圆点 |
| 落点校验 | 左中右/上中下靶点、仅显示落点/允许点击、无效区域提示 |
| 恢复 | 返回工作台；持续显示紧急退出快捷键 |

校正参数、镜像和内容适配仍在原有模块；鼠标模块读取相同状态，不新增另一套容易失步的 Warp 参数。

## 分步验收与回滚

1. 保留 `nio-warp-v0.11.7-accepted-20260918` 和当前活动参数；开发安装使用新版本号、固定路径和原签名身份。
2. 完成相对输入/前台/全屏探针，再做数学闭环与仅显示光标。目标：全链路离线有效点误差≤0.5源像素，三角形边界连续，无黑边误命中。
3. 接入当前 ProtoPie 专用页面；验八个可见靶点、单/双击、拖动松手、滚轮、暂停/退出恢复。实际原型控件的行为以其定义为准。
4. 实际开盖→合盖→开盖验证：外屏身份/像素不变时保持演示与指针；桌面原点变化不能打乱坐标，变化期间结束未完成手势。真实断屏/休眠先恢复普通输入，来源再次稳定后按用户启用意图恢复。
5. 测不同缩放/负屏幕坐标、四种镜像、窗口替换/页面重载、失去连接、退出与异常；没有悬挂按键、双光标、重复点击或输入锁死。
6. 用户现场确认“朝哪个方向移动”和可见点击位置，再固化新版本。不能用离线往返误差代替玻璃实测，也不把映射成功等同于被裁内容恢复。

交互预览使用当前参数的实际网格采样；上部观察方向为示意，下部为屏幕预畸变。它不模拟未知的真实玻璃光学，不代表已对开发机开启鼠标控制。
