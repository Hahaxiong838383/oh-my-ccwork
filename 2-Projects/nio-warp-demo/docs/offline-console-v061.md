# v0.6.1 无外接屏待机

## 修复内容

v0.6.0 在创建控制台之前就检查外屏，没有外屏时直接返回并重试，因此进程可能运行着但没有窗口。

v0.6.1 将控制台与 Metal 输出解耦：无外屏、显示信息尚未就绪或图形输出初始化暂时失败，都显示完整的待机控制台，而不是弹出致命错误或无窗口循环。

## 用户操作

- 不接外屏也能双击打开唯一安装版 `~/Applications/NIOWarpApp.app`。
- 待机时可以查看保存参数、切换几何预览以及导出配置；修改参数与画面处理控件暂时禁用。
- 没有保存参数时用默认模板预览，不新建或覆盖任何显示器配置。
- 连接可用外屏后自动建立输出，并恢复该显示器自己的配置；不把内屏尺寸写入外屏档案。
- 拔掉外屏时先隐藏覆盖层，再停止捕获；控制台在可用操作屏幕上保持可见。
- 后台重试复用同一待机窗口，不每两秒创建窗口或抢焦点；再次双击 App 可把现有控制台带回前台。
- 仅一块外接屏且没有可用内屏时保持待机，避免接管唯一的操作屏幕。

## 安全边界

待机路径不创建 WarpRenderer/输出覆盖窗口，不申请屏幕录制权限，不启动性能定时器；只读加载已保存外屏配置。真实外屏加载时记住所用档案，离线再打开优先展示该档案。

显示状态变化时使旧启动任务失效，取消捕获启动与旧任务的 UI 回调；先停止旧会话再启动新会话。休眠期间不自动重启捕获。新的控制台先创建，再关闭旧控制台，避免重建期间误触发“最后窗口关闭即退出”。

屏幕选择、只读配置、无 renderer 控制台构造和控件启用状态均有自动化测试。真实外屏重连仍需连接硬件验证，不能用单屏测试替代。
