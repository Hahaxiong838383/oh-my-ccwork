- 用户现场要求恢复横向顶满：当前内容适配为“保持比例·铺满裁切”，垂直取景为 1（靠底）。原型上方黑区承担取景裁切，保留道路及底部 UI；这不意味着原型内部越出设计画布的元素也能显示。
- `画布与输入 → AA 下方 → 整幅画面上下位置（物理 px）`：负值向上、正值向下，当前范围 ±936，支持滑块、数值、±1 px 和归零，实时保存。整幅曲面与内容一起平移，不改变弧度、比例、镜像或 AA。超出实体屏幕/AA 的部分仍会裁切。

## 根因与实现

普通 Chrome 窗口受实体屏幕高度限制，DOM 或捕获配置改到 2800 不会自动补回被窗口裁掉的行。实机测试普通窗口实际最大只有 906 高；改用 App 自有、只供内容使用的 CGVirtualDisplay，原生全屏后由既有 SCK 捕获。

该接口属于 macOS 私有运行时接口，运行时检查可用性并验证实际模式；后续系统升级需要复验。`applySettings` 后系统先选了 1920×700，必须枚举并显式选择 logical/pixel 均为 7680×2800 的模式。创建后 WindowServer 登记存在延迟，未知 display ID 的 `CGDisplayIsOnline` 可返回 -1，必须等待在线列表和身份信息，不能把非零误当就绪。

物理 Warp 输出排除自有显示器；session 分开记录来源显示器与实体输出。捕获只接受真实尺寸一致、metadata 覆盖完整纹理的首帧。改变高度串行等待旧任务结束，保留正在捕获及取消交接中的旧显示器，直到新捕获确认才清理；退出程序先停捕获再释放虚拟源。仅改画布宽度不重建播放器。

整幅平移在基础、贝塞尔、局部网格、外扩和自动对齐全部完成后追加到物理 Y，纹理 UV 不变。AA 仍是固定输出裁切范围，不承担曲面平移。
