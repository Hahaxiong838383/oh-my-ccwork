# v0.11.6 (33)：开盖后全屏恢复与完整显示

用户反馈合盖再打开后，ProtoPie 演示退出全屏，并要求 UI 尽可能留在显示范围内。

## 原因与修复

- 系统重建显示/睡眠恢复时，临时隐藏输出误走了用户暂停通知，将协调器的 `outputPaused` 置为 true。现在只有明确的用户暂停/紧急隐藏动作改变用户意图，系统临时隐藏不再污染暂停状态。
- 已绑定的专用预览此前只检查进程/窗口存活。窗口仍存活但退出全屏、移动到内屏或网页尺寸变化时不会修复。现在每 3 秒核对目标屏、原生全屏状态、捕获窗口框和网页物理尺寸；连续两次异常后复用来源恢复全屏，稳定后重绑捕获。短暂单次异常不重启，连续失败最多自动尝试 3 次，健康检查通过或用户重试后重置计数。
- 异步结果返回后再次核对任务代次、来源窗口、目标屏及用户意图。停止、关闭自动恢复或手动打开播放器后，过期检查不能重启来源。
- Chrome 退出原生全屏可能先返回原来的最大化状态。连续三次确认最大化尺寸稳定后，最多补发一次恢复普通窗口请求，避免等满 10 秒；普通窗口也须连续三次稳定才继续移动。
- 「打开播放器 / 登录」进入人工操作模式，显示重接或捕获中断也不会抢回全屏；点击启动/应用或重新加载才恢复自动展示。
- 控制台每次显示时重新选当前内屏，按 `visibleFrame` 留 8pt 边距，窗口超界时平移/缩小；小可见区动态放宽最小尺寸，大屏恢复原最小尺寸。保留现有 Tab 和可滚动参数区。

## 内容可见性

开发机实际源 7680×936、内容画布 12500×2800。原 `fill` 模式等比铺满会裁切约 3501px 横向源内容。通过现有工作台将当前内容适配改为 `fit`（保持比例·完整显示），真实 UI 显示裁切 X/Y 均为 0。此设置自动保存；未修改预设、曲率、贝塞尔、局部网格、垂直倍率、镜像、AA、画布、裁切锚点或常亮策略。其他用户配置及默认模式不强制迁移。

完整显示可能在上下留黑；这里消除的是源内容适配阶段的裁切，不能据此宣称曲面反射和 AA 边界内每个 UI 元素已通过光学验收。固定玻璃/物理遮挡的最终可见范围仍需现场观察。
