## 更正前版验收口径

用户指出，要求修正的是按 Esc 退出新增预览后仍然存在的原圆形指针，而不是 NIO Warp 新画的圆圈十字。此前 v0.12.2 的“向右，正常”发生在新增落点预览中，只证明那个覆盖指针的方向；它没有证明原指针已经修复。前版“任务已解决”的结论不成立，本页取代该结论，不把先前反馈扩张为本版验收。

现场检查确认，原圆圈来自 ProtoPie 的 `webplayer-root` CSS cursor：正常态为 `TouchPoint_Default.png`，按下态为 `TouchPoint_Active.png`。它是 Chrome 交给系统显示的光标，不是网页 DOM 圆圈，也不是 NIO Warp 覆盖层。

- CDP 页面截图没有该圆圈，生产捕获保持 `SCStreamConfiguration.showsCursor = false`。
- `NSCursor.currentSystem` 读到正常态为 53×53、热点 26,26；图像 SHA256 为 `a38b6a1c705839989fcc89318934d10b29d5574c5d847eb8dd568017be2fff46`，与现场原 CSS 光标一致。
- 按下态仍由 Chrome 切换，实测为 50×50、热点 25,25。
- 旧实现按 Esc 后停止映射并恢复普通系统输入，因此只修改新增覆盖指针无法改变原圆圈的反向移动。

## 本次实现

新增 `NativeMouseInputCapture`，通过 session event tap 接收并消费专用播放器外屏上的原鼠标事件。相对位移经现有曲面、镜像、可见区域映射得到同一个 `sourceUV`：一条路径通过 CDP 向 ProtoPie 发送事件，另一条路径计算对应外屏热点并用 `CGWarpMouseCursorPosition` 移动原系统指针。

不绘制替代指针，不隐藏或替换原指针，不断开鼠标与系统光标的关联，不改写 ProtoPie 的 CSS。Chrome 保持指针形状及按下状态的所有权；Warp 窗口保持鼠标穿透，不抢占 key window。CSS 热点由系统处理，不额外减去 26,26。指针大小控件已从鼠标模块移除，避免将旧覆盖指针设置误认为能够改变 ProtoPie 原光标。

输入限制于当前专用 Chrome 进程、播放窗口、目标外屏和已验证的页面会话。进入时从原指针位置建立映射；只有移动允许约束到可见区域，黑边首次按下不会被转换成边缘业务点击。已消费的按下、拖动、抬起保持配对；Esc 或异常退出时释放旧页面的手势，并吞掉该手势尚未发生的物理抬起。系统禁用 event tap 时销毁失效监听并恢复普通输入，避免残留状态阻止再次启用。

“仅检查移动”仍发送 move，让原页面维护 hover 和光标状态，但不发送业务按下、抬起或滚轮。映射后的指针使用原有全部可见区域，不新增内接矩形或指针半径留边。画面校正、镜像、裁切和 ProtoPie 链接未为此次修复改写。

## 权限与操作

本版需要系统设置 → 隐私与安全性 → 辅助功能允许 NIO Warp。开发机已由用户开启；权限不足时不接管鼠标，并在模块中提示。屏幕捕获仍使用已有权限。

1. 保持 ProtoPie 联动与 Warp 输出接通，打开“鼠标映射”模块。
2. 首轮使用“玻璃观察”，“鼠标左右反向”关闭，勾选“仅检查移动，暂不发送点击”。点击“启用原有鼠标校正”。此时观察的应为 ProtoPie 原圆圈，不出现新增圆圈十字。
3. 现场确认移动方向后，按 Esc 返回工作台，取消“仅检查移动，暂不发送点击”，再启用以操作原型。
4. 接管期间指针限定在演示外屏的可见区域；需要操作内屏时先按 Esc。切到其他应用后恢复普通输入。`⌃⌥⌘Esc` 仍用于紧急隐藏演示。
5. 若确需切换左右方向，先 Esc，再调整“鼠标左右反向”。不要通过修改画面镜像来补偿鼠标方向。

当前“左右反向关闭”是本轮软件验收配置，真实玻璃方向仍以本版原圆圈的现场确认结果为准。软件检查结束后已取消“仅检查移动”，曾以原圆形指针、点击接通状态交给用户现场体验；随后运行记录收到1302个移动事件，用户按Esc暂停校正，当前保持普通输入，鼠标偏好保留为可点击。原圆圈的现场方向与点击体验仍待用户文字反馈。
