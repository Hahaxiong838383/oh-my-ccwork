# v0.13.4：独立播放器鼠标与键盘交互

## 原因

完整高度播放器迁入自有虚拟内容屏后，实体 Warp 输出与 Chrome 不再同屏。实体鼠标不会自然命中 Chrome；仅激活页面不能恢复原来的圆形鼠标和键盘演示。原输入范围判断又要求实体位置下方是 Chrome 窗口，因此旧路径不适用。

实机另确认 `CGEvent(source:nil).timestamp` 为 0。旧定位逻辑把该值写入位移补偿器，每次定位都触发重新初始化，下一次真实硬件移动被当作首帧丢弃；自动注入的鼠标事件走另一分支，此前没有暴露这个问题。

## 修复

- 独立内容屏由实体输出窗口接收输入，通过当前已验证的同一三角网格反算源坐标，发送到绑定的专用 ProtoPie 页面。第一次点击获取焦点，后续点击操作原型；Esc 释放并返回工作台。
- 读取原页面 CSS 光标的原始图像与热点，作为系统 NSCursor 显示；没有另画十字或替代指针。支持 normal/active 与 image-set，网页跨域读取失败时仅从已验证的原静态资源域读取，不携带登录凭据。
- 定位时间使用与真实事件同基准的开机纳秒单调时钟，补偿后零位移不再重复定位或发送。
- 仅演示输出持有焦点时转发普通键盘输入，包含数字键盘、按下/松开、重复和修饰键状态。失焦、退出时释放已持有按键，后续物理松开不泄漏到工作台；系统快捷键保留。
- 同屏 Chrome 路径保持原生键盘处理。当前 Warp 参数、页面、内容屏尺寸与实际输出尺寸不因本修复改变。
