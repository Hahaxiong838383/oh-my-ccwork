# v0.13.14（66）：演示指针静止自动隐藏

## 目标与交互

用户希望 ProtoPie 演示在鼠标静止约 3 秒后隐藏圆圈，避免遮挡画面，同时继续使用原有圆形指针和演示交互。当前实现控制 NIO Warp 持有的原 CSS 光标对应的系统 `NSCursor`，不修改在线原型，不另画一个圆圈，也不改原圆圈图案、尺寸或热点。

| 状态 | 行为 |
|---|---|
| 演示输入已接管，鼠标静止达到等待时间 | 隐藏圆圈；默认 3 秒 |
| 移动、点击或滚轮 | 立即取消空闲隐藏，操作继续发送；首次点击不能仅用于唤醒 |
| 左／右／中键按住，或正在拖动 | 不触发空闲隐藏；松开后重新计时 |
| 仅使用键盘演示 | 不重置鼠标计时，也不唤醒已隐藏的圆圈；原按键转发继续工作 |
| AA 边缘持续外推 | 即使热点已被限制在边缘，实际鼠标输入仍算活动 |
| Esc 返回、失去输入作用域、暂停或停止映射 | 解除本功能持有的隐藏状态，恢复正常鼠标显示 |

原型页面主动请求隐藏光标时，仍尊重页面状态。表中“恢复”指取消空闲隐藏，不强行覆盖页面自己的 `cursor: none`。

「鼠标映射」新增“鼠标静止时自动隐藏圆圈”开关和等待秒数输入，默认开启、3 秒，可设 1～30 秒，支持小数。演示正在启动或接管期间不可修改，按 Esc 返回工作台后再调节；关闭功能后等待秒数暂时禁用，但保留原值。

## 实现边界

- `CursorIdleVisibilityPolicy` 将“页面要求隐藏”和“空闲隐藏”分别保存，再统一决定系统光标的有效隐藏状态。定期查询原型 CSS 样式不会把已经空闲隐藏的指针唤醒，`hide`／`unhide` 只在有效状态切换时成对调用。
- 计时使用单调运行时间。程序自身的指针移动补偿、纯 Warp 回馈、零位移、非有限输入及 CSS 轮询不算用户活动；有效鼠标活动在 AA 几何限制之前计入。
- 鼠标设置新增 `cursorAutoHideEnabled` 与 `cursorAutoHideDelay`。旧 JSON 缺字段时分别补默认值，不重置原有方向、模式、预览、速度等选择，读取旧配置不会隐式回写。等待时间越界时限制到 1～30，非有限值回退 3 秒。
- 本功能只调整光标可见性，不改变 AA 几何、源坐标转换、镜像、曲面、画面位置、播放器尺寸或 ProtoPie 来源。安装应保留现场参数；本轮没有升级 Air。
- 输入仍由原通用转发链路承接，不添加演示数字键白名单。既有边界不变：Esc 为宿主退出；Cmd／Ctrl 组合键留系统处理；其他系统保留键、输入法组合、多点触控等能力仍遵循既有兼容性审计，不因本次隐藏功能而宣称全部支持。

## 实机发现与修订

首轮 v0.13.12（64）已经部署测试，但实机自动验证发现：指针空闲隐藏后，首次按下鼠标会被输入作用域检查误判为受到其他窗口遮挡，随后过早释放按键。这违反“首次操作直接生效”的要求，因此 64 不作为最终验收基线。

观察到 WindowServer 的既有系统指针窗口在隐藏、恢复或按下图案更新期间，`sharing` 可能由 0 变为 1。此前仅将 `sharing == 0` 的 WindowServer 指针窗口排除在遮挡窗口列表之外，状态变化后它可能被当作外部遮挡窗口，导致输入接管被释放。

中间候选 65 尝试仅记住已见过不可共享状态的系统指针窗口 ID，但实机仍失败：应用进程中该窗口始终报可共享，已确认 ID 集合为空；外部诊断工具对同一窗口却读到不可共享。不能依赖调用者相关的共享状态完成身份识别。是否发生过临时状态切换并不影响此结论。

最终 66 使用控制器已验证的原 CSS 光标图像尺寸和热点核对 WindowServer 窗口。共享窗口还须同时满足 Window Server 所有者、系统指针层级、只读共享、buffered 图像类型、有限正尺寸，并且窗口尺寸及其相对实际鼠标热点的原点都与已登记图像一致，最多容许 1 逻辑点取整误差。明确标记 StatusIndicator 的窗口仍排除在光标候选之外。

登记当前和上一张原图，允许悬停/按下样式过渡；重复样式不会挤掉上一张，捕获会话结束清空。共享状态本身不再是唯一身份依据，未匹配的窗口继续参与遮挡判断。没有使用已废弃的系统光标图像读取接口，也没有放宽前台应用、输出焦点或 AA 检查。
