# NIO 全屏 Warp Demo 经验复盘

## 结论

这次 Demo 最重要的结论不是“把矩形拉弯”，而是把问题拆成三个独立层级：

1. **内容空间**：先扩大虚拟画布短边，确保完整内容有地方布局。
2. **光学空间**：用逆映射生成预畸变画面，使反射后的目标区域恢复方正。
3. **系统空间**：捕获外屏完整桌面，排除自身覆盖层，再将 Warp 结果回显到同一外屏。

只有三层同时成立，才算“完整利用反射屏幕且内容仍然方正”。最大内接矩形只能保证安全显示，不等于完整利用。

## 关键决策

| 决策 | 选择 | 原因 |
|---|---|---|
| 内容利用目标 | 全 Footprint，而非最大内接矩形 | 用户明确要求使用完整反射区域 |
| 画布模型 | 输入源短边可扩展的虚拟画布 | 将“内容容量”和“物理屏分辨率”解耦 |
| 算法验证 | 先做离线双变换闭环 | 可量化覆盖率、误差和越界，避免直接陷入系统工程 |
| 交互验证 | 浏览器双窗口 | 最快验证参数调节、外屏全屏和画布高度变化 |
| 整屏接管 | ScreenCaptureKit + Metal | 浏览器无法处理其他应用窗口，原生链路才能覆盖完整桌面 |
| 同屏回显 | 捕获外屏并排除当前应用 | 保留原有外屏内容，同时避免无限递归回采 |
| 控制台 | MacBook 内屏普通 `NSWindow` | `NSPanel` 在多 Space 和失焦场景下可能不可见 |

## 做对了什么

### 1. 先校准验收口径

最初容易把“校正后方正”理解为在畸变区域内找最大安全矩形。用户真正目标是：

- 反射后完整屏幕区域都被使用；
- 内容依然方正、可读；
- 允许输入源短边扩展，而不是裁掉边缘。

因此验收指标必须同时包含：有效内容覆盖率、像素误差、UV 越界比例和完整边界可见性。

### 2. 用三阶段 Demo 降低风险

- **离线 Python**：证明扩展画布与逆映射数学闭环。
- **浏览器双窗口**：证明 MacBook 控制、外屏输出和参数实时同步。
- **原生 Swift**：证明完整桌面捕获、同屏 Warp 和 60 FPS 链路。

每一阶段只引入一类新风险，问题定位明显快于一步到位开发原生应用。

### 3. 同屏捕获必须排除自身

如果直接捕获外屏并把结果显示回外屏，覆盖层会被下一帧再次捕获，形成递归画中画。正确做法是：

- 使用 `SCContentFilter(display:excludingApplications:exceptingWindows:)`；
- 将当前应用加入排除列表；
- 覆盖窗口保持全屏、无边框、鼠标穿透。

### 4. TCC 权限依赖稳定代码身份

临时构建每次产生不同 designated requirement 时，macOS 可能把它识别成新应用，导致屏幕录制权限反复失效。构建脚本应固定：

- `CFBundleIdentifier`；
- designated requirement；
- 应用路径和可执行文件名。

Ad-hoc 签名仍适合本机 Demo，但正式交付应改为 Developer ID 签名和公证。

### 5. 多屏坐标存在 points/pixels 双口径

MacBook 和 5K 外屏都可能启用 Retina 缩放：

- `NSScreen.frame` 是 points；
- ScreenCaptureKit 配置和纹理通常使用 pixels；
- 窗口位置可能出现负坐标；
- 不能用“第一个屏幕”假定内屏或外屏。

应通过 `CGDisplayIsBuiltin` 识别内屏，并从其余屏幕中选择目标外屏。

## 踩坑与修正

| 踩坑 | 表现 | 修正 |
|---|---|---|
| 只做最大内接矩形 | 边缘被浪费，违背完整利用目标 | 增加虚拟画布短边并按全 Footprint 验收 |
| 只做浏览器全屏 | 只能 Warp 浏览器内容，无法处理其他应用 | 增加 ScreenCaptureKit 原生整屏链路 |
| 捕获和输出同屏未排除自身 | 递归画中画或反馈闪烁 | 从捕获过滤器排除当前应用 |
| 每次构建身份变化 | 屏幕录制权限反复申请 | 固定 bundle ID 与 designated requirement |
| 使用 `NSPanel` 做控制台 | 多 Space 或失焦后窗口不在屏幕上 | 使用普通 `NSWindow` + `orderFrontRegardless()` |
| 用 `open` 启动命令行构建 App | 某些终端上下文中应用启动后立即退出 | `.command` 直接 `exec` App 可执行文件 |
| 只看截图判断成功 | 可能漏掉递归回采、窗口不可见和性能问题 | 同时检查窗口列表、帧稳定性、CPU/RSS 和日志 |
| 把视觉接管等同于可交互接管 | Warp 后看到的位置与真实点击坐标不同 | 明确输入逆映射是独立阶段 |

## 验收方法

### 算法层

- 全 Footprint 有效内容覆盖率不低于 99%。
- 平均灰度误差不高于 4。
- P95 灰度误差不高于 12。
- UV 越界比例接近 0%。
- 手动增加画布高度后仍通过同一组门槛。

### 系统层

- 外屏原有桌面、菜单栏及应用窗口均被整体 Warp。
- 内屏控制台可见并能实时调参。
- 连续截图不出现递归回采或逐帧放大。
- 输出窗口覆盖目标外屏，控制窗口位于内屏。
- 目标刷新率下无持续错误日志，CPU 和内存可接受。
- 重建后屏幕录制权限保持稳定。

### 用户层

- “完整显示”模式下，四周内容均可见，没有被最大内接矩形裁掉。
- 直线、文字、网格在模拟或真实反射观察面上保持可接受的水平与垂直关系。
- 明确标注鼠标坐标尚未逆映射，避免把视觉 Demo 误当生产交互方案。
