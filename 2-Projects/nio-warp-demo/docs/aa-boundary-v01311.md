# v0.13.11（63）：AA 边缘移动与系统指针限制

## 根因

用户在 ProtoPie 预览两侧和上角外推鼠标时，演示像按 Esc 一样返回内屏。v0.13.9 首因历史中，20:38:36、20:38:54、20:39:11、20:39:17、20:39:45 五次均记录“无法同步原型鼠标样式”，画面七项绑定和输入连接仍有效，原图缓存命中。它们不是 Esc 操作，也不是此前原图下载失败的复发。

可见网格的源 UV 包含闭端点 0／1，浮点反算还会产生极小负值。鼠标事件发送已限制到网页合法半开区间，光标样式查询却直接使用 UV × 视口尺寸；例如合法 AA 热点的 UV.x=1 生成 x=1920，被严格校验拒绝，再触发退出。当前家中参数离线轨迹复现了 312 次这种无效查询：280 次端点 1、32 次微负值，物理热点仍在 AA 内。

首轮修复 v0.13.10（62）实机 28 个样本的映射、拖动和退出重入通过；同时观察到另一项边缘问题：Retina 外屏的目标 y=-800.24997 逻辑点，被系统指针快照取整为 -800，对应物理 y=800，越过 AA 的末像素中心 799.5。四个样本出现此现象，因此追加系统落点约束后形成 63，62 不作为最终验收版本。

## 修复

- `MouseInputViewport.point(forVisibleSourceUV:)` 为鼠标事件与 CSS 光标查询提供同一网页坐标；处理端点与浮点误差，保留传输层对无效输入、页面变化及断连的严格检查。
- 可操作几何继续使用实际渲染网格与 AA scissor 的交集，移动、拖动均先约束热点，再发送输入；不修改曲面、镜像或用户校正参数。
- 最后将系统指针限制在 AA 像素中心换算到桌面后的可表示整数边界。内部小数位置保留，正常边缘请求每轴只向内移动不足一个逻辑点，避免系统取整把热点推到 AA 外。无可表示落点时恢复普通输入。
- 约束对象是鼠标热点／落点。原 ProtoPie 圆圈资产、大小和热点保持；没有按圆圈半径整体缩小画面可操作区。
- Esc 仍用于返回工作台；本轮不改变快捷键政策，也未修复先前审计记录的双侧 Shift／Option 缺陷。
