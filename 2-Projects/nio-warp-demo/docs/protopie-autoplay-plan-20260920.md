# ProtoPie 多链接与自动演示执行方案

日期：2026-09-20。本文保留经用户确认的开发前方案。随后已按方案实施 v0.14.0；实际完成范围、验证结果及待验收项见 [实施记录](protopie-autoplay-v0140.md)。以下“本次只读”等描述为方案制定时状态。

## 目标与保护基线

在现有最右侧「ProtoPie 联动」Tab 内增加多云链接管理、轮播、每链接自动操作、时长控制和长期诊断日志。继续使用专用 Chrome 中的官方 ProtoPie Cloud 播放器。

本次只读核对的本地固化基线为 v0.13.15（67），应用代码提交 `cbe5d7fd`，最新运维/审计提交 `c6eed3ee`。此次未连接开发机，不把9月18日的安装记录当作9月20日运行状态。实现前须重新核对实际包、进程、源码与当前参数。

新增配置独立存储、功能默认关闭；关闭自动演示时保持原有手动使用路径。复用已有播放器、全屏、捕获、输入通道；按接入需要做小范围接口调整，不借机重构校正算法、显示器配置或退出策略。保持单链接、本地 `.pie`、镜像/AA、原圆圈、用户现有空闲隐藏设置、Esc及普通鼠标恢复。

开发前建立独立 `codex/` 分支与回滚标签，备份固定安装包、对应源码、**当时最新**偏好及摘要。升级、降级配置均须演练；降级不能用旧参数覆盖用户后续手调。旧版本忽略新的播放计划数据，原单链接保存键保留。

## 操作界面

同一Tab内使用「来源列表」「自动演示」「播放计划」「运行与日志」四个页内分区，不新增独立窗口。保留整体上下位置及原有播放布局选项。

| 分区 | 控件与行为 |
|---|---|
| 来源列表 | 添加、命名、编辑、复制、删除、排序、启用；选中项与正在播放项分别标记；手动“预览所选” |
| 自动演示 | 编辑所选链接的动作步骤；启停、单步、试播、循环次数/循环间隔；每链接独立保存 |
| 播放计划 | 单链接/顺序轮播；各链接驻留时长；整场时长输入小时、分钟、秒，或明确选择持续播放 |
| 运行与日志 | 开始、暂停、继续、停止、上一项/下一项；当前链接、步骤、轮次、剩余时间、故障提示；查看/导出日志 |

编辑列表不立即打断正在运行的演示，开始时生成一份不可变运行快照；应用修改时先完成受控暂停与重新绑定。选中、保存、开始播放是不同动作。

默认沿用当前显示布局；可为不同链接增加独立的内容取景设置（等比适配/按宽铺满、内部取景），未设置时继承原选项。实体屏幕的 Warp、镜像、AA 和整幅上下位置仍由当前屏幕配置管理，不跟随链接重置。

## 自动操作脚本

第一版采用可视化步骤列表，不要求用户编写代码：

- 等待指定时间。
- 按一下键、按住指定时长、释放；区分主键盘与数字小键盘。
- 鼠标移动、单/双击、长按、拖动、横纵滚动。
- 步骤组有限循环、整段循环及循环间隔。
- 每链接可配置进入后的初始化步骤；每轮可选择继续当前状态或重新加载后初始化。

提供数字小键盘 `2 → 0 → 1 → 2 → 3 → 4` 模板，步骤间隔可编辑。其他普通按键使用同一机制，不写成固定序列白名单。

示例：等待2秒 → 小键盘2 → 等待5秒 → 小键盘0 → 等待3秒 → 后续按键 → 等待10秒 → 下一轮。具体时长和原型复位方式由该链接的演示流程决定；不能假设重复按键会自动回到初始场景。

点击通过“选取位置”保存播放器源视口归一化坐标及布局标识，不存玻璃或桌面绝对像素。执行前检查当前可见范围，目标不可见则提示而非偷偷吸附到别的控件。归一化只适应兼容的尺寸变化，在线原型改版、按钮换位后仍需重新试播。

首版不纳入通用操作录制、任意JS/Shell执行和复杂条件脚本。当前手动输入仍有Esc、Cmd/Ctrl、IME、高级手势和双侧Shift/Option边界，脚本编辑器应明确支持范围，不能将其宣传为所有系统输入通用自动化。

## 调度与计时规则

```text
开始计划 → 准备当前链接 → 全屏/布局/捕获确认 → 输入绑定确认
       → 初始化/执行脚本 → 单项到时 → 释放输入 → 下一项
```

- **单项驻留时长**：从该链接全屏、捕获及必要输入绑定全部就绪后开始；加载、暂停、故障恢复不算有效演示时间。
- **整场总时长**：从按“开始”起计算实际经过时间，含加载、暂停和恢复，是硬性上限；界面同时显示预计结束时间，避免被重试无限延长。
- 用适合跨休眠计时的单调时钟/可注入时钟实现，不用反复减秒或系统日历改时驱动调度。若睡眠期间越过截止，唤醒后先结束计划，不补发积压动作。
- 单项到时取消该项未执行步骤，释放持键和鼠标按钮后切换；总时长到期停止全部自动任务、释放输入。结束动作可选“保留当前预览”或“停止联动、返回工作台”，默认保留预览；界面说明保留预览时原型自身动画可能继续，这不等于冻结原型。没有有效画面时明确显示失败状态。
- 无时限必须显式选择，不能用模糊的“0分钟”兼作无限。

例如：A播放10分钟、B播放5分钟、C播放5分钟，依序循环；整场2小时到期结束自动演示。

## 输入所有权与切换保护

新增输入所有权协调层，手动和自动互斥，共用现有 `MouseInputTransport`，不再打开一条独立输入连接抢同一页面。

真人接管演示时暂停脚本和轮播，清理自动持键后交回手动控制；自动合成事件不能被当作真人活动。用户点“继续”才恢复。**Esc继续返回内屏工作台并恢复普通鼠标，同时停止自动任务；自动恢复不得自行重入。** 停止、退出App、打开播放器登录均优先于自动任务。

切换时：取消旧步骤 → 释放旧页面输入 → 准备候选链接 → 确认全屏/布局/首帧 → 绑定新session、target和文档代际 → 再开始新脚本。保留staleViewport等既有守卫，不跨页面续发旧任务。

`send/sendKey`成功仅表示入队。脚本应等待此前事件确认完成再开始后续等待；日志区分“已入队”“已发送”“步骤完成”。CDP成功仍不等于原型业务场景已完成；业务效果如需自动验收，需给该原型增加可观测检查点。

## 模块划分与恢复职责

| 模块 | 职责 |
|---|---|
| PlaybackLibrary / PlaybackPlan | 稳定链接ID、排序、脚本、每项时长、整场计划、版本化本地保存与旧单链接迁移 |
| PlaybackScheduler | 当前项、运行快照、倒计时、循环、跳过、暂停/停止；不自行重开窗口 |
| ScriptRunner / InputArbiter | 顺序动作、确认发送、输入所有权、取消与释放 |
| 现有ProtoPieCoordinator | 唯一播放器/全屏/捕获恢复负责人，保留有限重试、取消与代际检查 |
| PlaybackLog / HealthMonitor | 轮转日志、低频健康摘要、异常现场、运行标记及诊断包 |

源码已发现一个必需处理的集成点：Coordinator候选切换失败时可能已保留旧画面，但 `main.swift` 当前收到任何 `.failed` 都返回工作台。新增自动模式需区分“候选失败、当前画面仍可用”和“当前演示失效”，不能直接循环调用原启动按钮。原手动故障退出策略仍保留。

恢复建议：暂时故障先按有限预算恢复；候选链接失败时保留仍有效的旧画面并跳过故障项，不能把旧画面算成新项播放成功。权限/登录问题标记需要人工处理。连续所有链接失败则暂停并明确报错；设置每项及整场恢复预算/退避，防止列表循环绕过3次重试上限。

恢复成功后从该链接配置的初始化起点执行，不盲目接续未知业务状态的半截脚本。仅保持当前项与候选项的有界资源，不同时预开所有链接。

## 长期日志与故障定位

现有defaults中播放器诊断最近24条、输入停止最近16条继续保留，另增本地异步JSONL轮转文件，避免长时间运行时关键信息被覆盖。

记录内容：

- 运行ID、版本、启动会话、链接ID、脚本版本、步骤序号、轮次和剩余时间。
- 链接切换、加载/全屏/首帧/输入就绪、暂停、停止、退出及对应原因。
- 动作类型、发送耗时、超时、输入队列深度；不采集完整用户键盘内容。
- 页面响应、视口/捕获绑定、捕获状态、渲染完成/FPS、GPU耗时、内存趋势、Chrome目标数量。
- 异常首因、前后上下文、恢复次数/结果；二次清理不能覆盖首次错误。

建议默认每10秒汇总健康指标，关键状态即时记录；按日期/文件大小轮转，保留7天且总量不超过200MB，先到的上限生效。异常调试数据也须有容量上限。链接仅记录本地ID/脱敏指纹，不记录私有查询参数、Cookie或页面正文。日志/截图不自动提交代码仓。

“画面没变化”不能直接判卡死，SCK的idle帧对静态页面是正常情况。综合页面命令响应、捕获/渲染状态、动作超时判断；有视频且能可靠观测时再检查进度。检查器不与输入争抢连接、不过度轮询，不因一个瞬态样本重启播放器。

运行开始写持久标记，主动停止、到时和正常退出写结束原因；下次启动遇到未闭合记录提示“上次未正常结束”，结合系统崩溃报告排查，不武断认定崩溃或自动重新打开用户已退出的App。App完全退出时自身不能继续写日志，此边界在诊断界面说明。

## 分阶段执行与验收

1. **基线与迁移**：核对67版源码/包/配置，创建回滚点；测试旧单链接迁移、新数据损坏处理和降级兼容。
2. **多链接与手动切换**：来源列表、运行快照、候选失败处理；先验证原单链接和本地 `.pie` 路径不退化。
3. **轮播与时长**：单项/总时长、取消/暂停、顺序循环、有限恢复；用可控时钟验证截止和竞态。
4. **脚本与输入仲裁**：步骤编辑、试播、主键盘/小键盘、鼠标位置、持键清理、人工接管与Esc。
5. **诊断与长稳**：日志基础从第2阶段起接入，最后完成容量控制、导出、故障注入和长期运行。

回归门槛：原校正参数保持；全屏/按宽铺满/画布高度/上下位置实时生效；镜像与AA边缘、原圆圈和当前隐藏时间、鼠标键盘、Esc、关闭重开、冷启动、换屏及合盖翻盖均按实际硬件覆盖。新开机禁休眠任务尚待验证的历史项单独复核，不能沿用旧通过结论。

自动化覆盖：重复启动、列表编辑不干扰运行快照、单项/总时长截止、长按中暂停/到时、切源时退出、旧回调晚到、刷新换文档、重试耗尽、人工退出后不复活。

实机故障覆盖：坏链接、慢加载、断网、登录失效、Chrome退出、捕获失败、外屏断开；验证无旧动作串页、无无限重试、无残留持键，错误能够从日志定位。

长稳先做多轮短测，再8小时实机轮播；若目标是全天展演，再做24小时。与同一硬件/内容的67版比较性能和内存趋势，确认无持续无界增长、窗口/目标数受控、日志不爆盘。静态页也纳入测试以检查误报。短测不能替代长稳验收。

完成各阶段后再交付安装体验，报告区分软件测试、实机链路、实际演示效果和8/24小时结果。实际执行结果以实施记录为准。
