# v0.13.7（59）：AU16O 全屏校正输出可见性

## 原因与现场证据

换到家中 AU16O（3840×2400 物理像素，1920×1200 points）后，参数保存及网格校验均成功，但在播放器直接进入外屏原生全屏空间时，用户看到的是未校正画面。实测 NIO 输出窗口位于正确屏幕、layer=1000、`isVisible=true`，却不在 WindowServer 的 onscreen 列表；Chrome 原始窗口在 onscreen 列表。

应用实际激活策略为 regular（0），虽然源码只在启动时请求一次 accessory。包未声明 LSUIElement，且原启动调用不检查返回结果。具体哪次操作导致策略成为 regular 尚未证明，不归因于某次外部 activate。仅检查源码常量或“窗口存在”不能验收跨应用全屏覆盖。

用户把画布高度调到另一个值，播放器回到独立内容屏后，输出窗口重新可见，用户反馈“现在调节已经有变化”。这解释了为什么故障会随画布和全屏路径切换出现；不能把暂时恢复当成永久修复。

## 修复

- App 包声明 `LSUIElement=true`，从启动阶段使用 accessory。
- 启动、创建/恢复输出和应用重新激活时，幂等核对实际策略；仅不符时请求切换，检查返回值和读回结果。最近12次实际切换尝试记录到本地诊断。
- 切换 macOS Space 时，仅重排原本处于显示状态的输出；不激活工作台、不抢输入焦点，也不恢复用户暂停的输出。
- 诊断分别记录请求显示、当前 Space、遮挡可见性与实际策略。校正数学、Retina drawable 像素路径及公司屏幕配置均未修改。
