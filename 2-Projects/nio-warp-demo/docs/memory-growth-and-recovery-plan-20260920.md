## 3. 分级保护建议（暂定，未启用）

统一使用 **NIO Warp App 自身 `phys_footprint`** 作为以下阈值口径。Chrome 进程树、系统内存压力、swap 单独记录，不能将它们混入 App 阈值。采样失效必须明确标记未知，不能记作 0 或据此判健康。

| 建议条件 | 建议动作 |
|---|---|
| 有效连续 60 分钟净增长超过 100 MiB，且趋势持续向上 | 提前告警并保存诊断；仅增长速度超限不直接重启 |
| 超过 1 GiB，持续 3 分钟 | 保存内存摘要、进程、页面、播放及捕获状态 |
| 超过 2 GiB，持续 5 分钟 | 仅在恢复机制验收通过、明确开启无人值守轮播保护时，执行受控重启 |

阈值是依据当前三星屏基线提出的项目建议，不是 macOS 通用内存上限。应排除单次切换峰值，记录暖机基线；明日正式 44.8 寸屏按真实来源/输出分辨率重新测量，确定是否调整阈值。系统出现持续内存压力时的提前保护条件，留待实施时一并定义和验证。

## 4. 自动重启之前必须补齐的恢复能力

当前版本仅保存播放列表配置，没有自动续播检查点：`ProtoPiePlaybackLog.swift` 的 `active-run.json` 只有 runID 和开始时间；启动时只记录上次未正常结束。`ProtoPiePlaybackController.start()` 会创建新计划，从首项及新的总时长开始；旧单链接 `saved.autoStart` 也不是播放列表续播。因此不能直接增加“kill + open”并宣称恢复成功。

建议恢复流程如下，全部待实现、待验证：

1. **保存检查点**：保存实际运行的计划快照、当前链接、单项剩余时长、整场原截止时间、目标屏身份与配置版本、维护重启原因、一次性恢复凭据及次数。不读取尚未生效的编辑草稿，不以旧参数快照覆盖现场手调。
2. **区分用户意图**：只对明确开启保护的无人值守轮播生效。用户暂停、停止、Esc、主动退出或计划结束立即取消恢复资格。维护重启使用独立原因，不能与普通 `shutdown` 混用；退出与恢复之间再次核验用户取消状态。
3. **保存证据并有界退出**：记录重启前内存及故障信息，释放持键、鼠标控制和指针隐藏，等待在途准备与清理、停止捕获、处理自有虚拟屏、刷新日志。优先正常退出；超时升级终止仅针对精确核验的本 App 进程，需在后续实施中测试。
4. **处理专用预览页面**：当前正常退出会保留预览页面。维护恢复必须明确复用一个已验证页面，或精确回收本轮拥有的 target，防止重复声音。不能关闭用户普通 Chrome 或其他项目页面。
5. **恢复与验证**：通过固定安装路径启动 App，重新验证屏幕、全屏、Chrome 来源、捕获与输出一致性，再恢复当前链接和原计划时长。链接会重新加载，不能承诺原型业务状态无缝续接；若未来启用脚本，从确定的初始化边界恢复，不跳入未知的脚本中间步骤。
6. **防止循环重启**：建议间隔至少 30 分钟、24 小时最多 2 次，次数跨进程保存；恢复失败停止自动重试，显示状态并保留日志。由可见、可停用的外部守护检查 App，以覆盖 App 自身无响应；不启用无条件拉起。当前没有后台聊天通知通道，不能承诺自动发消息。

总时长不得因为维护重启重新计满；恢复完成前若原截止时间已到，按原结束行为收尾。换屏或身份不匹配时停止恢复，等待核对，禁止把三星参数套到正式屏。维护重启可能短暂中断显示，必须实测恢复耗时，不能称为无缝。
