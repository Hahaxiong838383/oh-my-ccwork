## 使用

1. 确认「ProtoPie 联动」显示预览与 Warp 捕获已接通，标定网格关闭。
2. 打开最右侧 ProtoPie 左边的「鼠标映射」（工作台快捷键 ⌘6）。默认「玻璃观察」和「仅显示落点，不发送点击」。
3. 点击「进入演示鼠标控制」，看着玻璃移动鼠标确认方向。外屏显示高对比十字圆点，普通鼠标暂时隐藏。
4. 按 Esc 返回工作台；取消「仅显示落点」，再次进入即可点击、双击、拖动和滚动。速度和指针大小均可调。
5. Esc 恢复普通鼠标；⌃⌥⌘Esc 同时紧急隐藏演示。返回单外屏工作台时暂停演示，恢复按钮继续播放。

当前仅支持专用 Chrome 中的 ProtoPie Cloud 页面。原生 Studio、桌面 App、Chrome 原生菜单不在输入接管范围；网页自身弹层仍正常捕获。失焦不抢回前台；暂停、页面重载、换原型、捕获/参数失效先释放原手势并恢复普通鼠标，稳定后由用户重新进入。

## 映射与边界

- 复用实际完成渲染的三角网格、Shader 内容适配、镜像、裁切及纹理尺寸。默认在源内容空间累计相对位移，再映射到物理屏；当前单次水平反射下，物理屏水平运动与源方向相反。备用「直看外屏」在物理屏空间移动并反查源点。
- 按每个三角形和 AA scissor 裁切，保留凹形完整区域及左右下方可用部分；采用整段首次出界和切向滑动，不能跳过中下方不可见区域。
- 热点仅留 **0.5 个物理像素**，可抵达最后一行像素中心 **y=935.5**。光标图形允许被屏边截断，其半径不侵占点击面积。采样抗锯齿和真实玻璃遮挡仍可能影响人眼可见边界。
- 事件绑定专用页面、窗口/PID、文档 timeOrigin、视口和捕获 generation。单 WebSocket 串行传输，仅合并 move。旧连接释放结束后才允许新会话发送，停止先同步恢复系统鼠标，再异步补发原页面 mouseup。
- 合盖只改变桌面原点时保留局部坐标，结束正在进行的手势；忽略捕获 screenRect 的全局原点变化，实际内容尺寸、缩放或来源变化仍会退出输入。开盖时工作台不抢正在演示的焦点。

## 实机发现的捕获问题

旧捕获启用 `includeChildWindows`，把 Chrome 全屏窗口上方的隐藏工具栏纳入范围：7680×936 的网页和纹理，实际 `contentScale=936/968≈0.966942`，有效内容仅约7426×936。首次接管因此被拒绝，没有发送错误点击。

仅专用 Chrome 预览捕获改为排除附属窗口，原生 ProtoPie 捕获保留原行为。修复后 contentRect、boundingRect、纹理和网页视口均为7680×936，contentScale=1。**没有修改 Warp 校正参数；原捕获约3.3%的额外缩小被消除，视觉内容尺寸可能略有变化。** 不靠猜32px偏移或裁切滑块掩盖该问题。
