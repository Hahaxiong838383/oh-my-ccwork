## Connect 主服务与显示链路

```text
外设 / 业务输入程序 → 插件或独立 Bridge → 本机 Connect 服务
                                            ↓
                       原型 Receive → Connect 原生浏览器播放器
                                            ↓
                                 NIO Warp 捕获和现有校正 → 目标屏
```

- 客户自行在 NIO 电脑的 Connect 登录、加载合法原型并配置外设；本机主服务的播放器链接优先用 localhost。
- App 填完整 `/pie?pieid=...` 链接；SDK 填服务 origin，如 `http://localhost:9981`，用途不同。
- 外设已能控制同一 Connect **浏览器播放器**时，App 接入该链接沿用现有消息交互，现场仍需确认。若尚未调通，须先完成插件/硬件适配和原型 Receive；粘贴链接不自动生成驱动或交互。
- SDK 为独立 Node Bridge，不随 App 粘贴链接自动启动，不含任意硬件驱动；当前只接受 `demo.level`、`demo.toggle`、`demo.action` 演示白名单，客户业务消息要独立扩展契约和测试。
- 同一 Connect 服务可作为多原型互动中心；一个链接指向一个 pieid，其他屏须自行运行相应原型、约定 Send/Receive。不能自动合并全部原型。
- 当前 App 只有一个活动来源及一个目标 Warp 输出，多链接是顺序轮播。多物理屏独立校正、Stage View 合成链接没有当前实现或验收证据。

## 保留功能与未验边界

- Warp 几何、AA、镜像、渲染、捕获及虚拟屏核心对照为零核心改动；Cloud 既有铺满与输出物理 Y 机制保留，使用/调试模式门禁保留。
- Connect 仅支持原生等比适应/原始尺寸，横向铺满及内部取景禁用；原生 auto/none 光标不承诺 Cloud 圆圈和闲置隐藏规则。
- SDK `connected` 不等于原型就绪，`submitted` 不等于收到确认。核对顺序为 Connect 消息面板 → Receive → 浏览器 → Warp 输出。
- 历史本地验证：新增 Connect 39、生产 JS 13、SDK loopback 13 项通过；Native 771 方法中 766 通过、3 跳过、2 方法失败（20 条断言，与 V1 布局基线相同），legacy cancellation 两版均超时。本次不重跑、不扩大旧结论。
- 真实 Connect 协议/Enterprise 权限、硬件、客户玻璃、键鼠、合盖/重启及长测待验。RC 为 arm64/macOS 14+/ad-hoc、未公证；没有真实演示 `.pie`，只有制作步骤。
