# NIO Warp V2.0：Connect 同机主服务与二次开发交付规划

状态：已在独立分支实现首个候选版，正在完成最终测试、构建和文件交付；客户设备未部署。以下路线保留为原始规划，实际完成范围与验证缺口以 [实施回执](v2.0.0-implementation-20261010.md) 为准。

## 1. 目标与版本

NIO Warp 电脑运行用户授权的 ProtoPie Connect 主服务，外接输入通过 Connect 驱动原型；NIO Warp 管理本机浏览器播放器，并沿用现有捕获、输出、校畸变与输入控制。

- 目标正式版本：`2.0.0`。
- 首次外部验证包：`2.0.0-rc.1`；build 必须高于固化版 77，并在构建前查验后续发布记录再分配，不能重复。
- 只建立规划版本，不把尚未实现的功能写成正式发布，也不在当前早期源码上直接更改 App 版本。
- 开发基线：`nio-warp-v1.0.0-frozen-20260921`，解析后的提交 `e010f964a50a52f36e9afca8df211bdc63ffe3f9`；功能源码提交 `0a13eac59f5472e306c222511ef790d1bb1d31f0`，V1.0.0（77）。
- 当前主目录是早期源码。执行开发时从上述标签建立 `codex/nio-warp-v2-connect` 独立 worktree；不切换或重置当前共享工作区。
- 用户设备已交付，现场显示器、玻璃与硬件不在开发者手中。不能把旧 V1 的验收结果或模拟测试冒充 V2 的现场验收。

## 2. 推荐交付方式

首版交付 **可安装 App + 输入扩展源码 + 示例原型与消息约定 + 操作、开发、验收和回退文档**。用户开发输入逻辑，无需编译或修改校畸变程序。

| 方式 | 用户获得的内容 | 代价与建议 |
|---|---|---|
| 推荐：App + 输入扩展源码 | 完整运行版、独立 Bridge/插件源码、消息协议和开发示例 | 改动范围小，能独立更新输入模块，适合当前无法现场测试的条件 |
| 可选：再提供脱敏 App 源码 | 上述交付物加对应版本源码、依赖与构建说明 | 支持客户接管维护；客户修改后的构建须独立版本化与验收，不与我方发布包混同 |
| 后续：将 Warp 核心提取成独立库 | 框架/库、配置接口与调用示例，必要时开放源码 | 现有 App 不是已经封装好的 SDK；提取会改变模块和资源生命周期，首个 V2 不同时推进此重构 |

这里的“封装”首先是责任和接口边界，不意味着必须重构成二进制 framework。二进制交付和界面调试锁能减少误改，但不能阻止拥有系统管理员权限的人替换程序或修改文件。

若用户需要完整源码，使用单独的客户源码包/分支，移除历史账号、密码、私有链接、个人网络地址、现场标定原件、内部记忆、日志和设备管理配置。客户设置自己的调试口令；不能把原项目硬编码口令当作公开 SDK 示例。每个交付物都对应明确提交和 SHA-256。

## 3. 同机部署与边界

```text
本机 USB/串口/其他输入，或远端控制程序
  → 用户插件或 Bridge
  → 本机 ProtoPie Connect 消息服务
  → 原型 Receive/Send 交互
  → Connect 本机浏览器播放器
  → NIO Warp 捕获与校畸变
  → 实体屏/反射玻璃
```

本机播放器使用用户从 Connect 复制的完整 `http://localhost:9981/pie?...` 链接；端口允许修改，保留 pieid、名称和其他参数。更换 Wi-Fi 不需要改变同机播放器地址。来自其他电脑的控制程序连接 Connect 实际可达的网络地址；播放器 URL 与外部消息服务地址分别配置。保留 IP/域名、HTTP/HTTPS 和非默认端口能力，但首批验收以本机播放为主。

- 用户在 Connect 内登录并管理订阅、加载或替换原型、配置输入插件；App 不保存用户订阅密码，不绕过授权。
- Connect Core 订阅不自动等于 Enterprise 权限。自定义插件/Bridge 的可用性按用户实际套餐及官方功能表确认；需要时提供已授权内置插件方案，不保证任意订阅均能运行自定义 Bridge。
- App 可以检测服务，提供“打开 Connect”入口并等待就绪；不依赖未经验证的私有 CLI 自动上传原型或自动登录。
- 重试或切换只管理 App 自己的浏览器页面。退出 NIO Warp 不终止用户 Connect 或输入程序；不关闭用户其他 Chrome 页面。
- 页加载、播放器尺寸、捕获首帧、校正输出、消息连接分别判定。页面能访问不能代替消息测试；无法读取真实消息状态时显示“未验证”，不能显示“已连接”。
- 云端、本地文件原有来源保留；Connect 是第三种独立来源，不把 Cloud 的域名保护放宽成任意 URL。
- 几何、AA、镜像、鼠标方向、校正预设与历史结构保持。Connect 配置不写入这些参数，也不复制旧屏幕参数到新屏幕。
- 普通模式开放 Connect 链接和播放操作、输入连通性查看；调试功能继续使用现有锁定机制。

## 4. 分阶段实施路线

以下文件均指执行时从固化标签建立的独立工作区，不是当前主目录中的早期同名文件。此文件是交付路线，不是已经执行的代码变更清单。

### 阶段 A：冻结与可复现基线

- [ ] 查验固化标签、源码提交、已有 App 与参数备份校验值；单独保存用户当前配置的操作说明，不能将九月备份当作用户今日设置。
- [ ] 从标签建立独立工作区，复现 V1 构建和现有测试；记录本地 OS、架构、Swift 和 Chrome 版本。
- [ ] 建立受保护文件清单与差异审查：WarpMath、WarpConfiguration、BezierWarp、LocalWarp、CaptureSupport、虚拟屏实现和鼠标几何核心不作计划性改动。
- [ ] 记录 V1 仍存在的已知问题，尤其开始计划/切链的内屏 Chrome 闪窗；Connect 接入不夹带修复此项。

完成物：可复现 V1 和可校验的回退点。基线构建或测试失败时先解决环境问题，不据早期主目录继续开发。

### 阶段 B：Connect 来源与配置兼容

- [ ] 修改 `native/Sources/NIOWarpApp/ProtoPieConfiguration.swift`，新增 `.connect` 和 Connect 专用配置；旧配置缺少新字段时仍按原含义解码，Cloud 验证逻辑保持。
- [ ] 新建 `ProtoPieConnectSource.swift`：用 URLComponents 解析 HTTP/HTTPS、host、port、path 和 pieid，保留未知查询参数，不使用字符串拼接或任意执行 URL 协议。
- [ ] 新建 `ProtoPieConnectServiceProbe.swift`：提供有界超时、有限重试、取消和人工操作提示。将登录页、空服务首页、失效原型与可播放页区分。
- [ ] 修改 `ProtoPiePanel.swift` 和播放列表配置/界面，支持独立 Connect 来源名称、完整链接、测试、应用与多个原型选择。
- [ ] 明确页面身份包含 origin、播放器路径和 pieid；同 host/path 下不同 pieid 不能误判为同一原型。
- [ ] 添加 `ProtoPieConnectSourceTests.swift`、`ProtoPieConnectMigrationTests.swift` 和 `ProtoPieConnectServiceProbeTests.swift`，覆盖 localhost/IPv4/IPv6/域名、自定义端口、查询参数、无效协议、旧配置、断线和取消。

完成物：可保存、验证和选择的 Connect 来源；仅用模拟 HTTP 服务通过的测试须明确标记，不能声称实测了 Connect。

### 阶段 C：播放器接入与现有交互回归

- [ ] 在 `ProtoPieSystemDriver.swift` 新增 Connect 分支，复用现有持久浏览器控制、页面资源租约、取消和单一页面回收机制；不重写 Cloud 与 Studio 分支。
- [ ] 新建 `ProtoPieConnectLayout.swift`，以实际 Connect 页面结构和原生缩放状态为依据验证尺寸；未知结构报告不支持，不盲用 Cloud 的 DOM 路径或 URL 参数。
- [ ] 保持既有等比 fit/按宽铺满及位置调节语义，核对页面内容尺寸、浏览器 viewport、完整捕获高度和实际输出，避免截顶、滑块无效及刷新后缩小。
- [ ] 对 Connect 原生圆圈、焦点、键盘和鼠标注入入口做来源适配，继续使用现有输入控制器与映射数学；不另造圆圈，不把外部消息伪装成固定键盘顺序。
- [ ] 校验切链前释放按住的按键/鼠标，Enter/Esc/普通数字/数字小键盘/方向键/拖动/滚轮；AA 边缘限制、三秒闲置隐藏、Esc 回工作台、合盖与开盖保持原有语义。
- [ ] 添加 `ProtoPieConnectLifecycleTests.swift`、`ProtoPieConnectLayoutTests.swift`；复跑现有播放、控制连接、原生输入、闲置隐藏、鼠标边界、窗口和模式锁测试。

完成物：本地真实 Connect 演示闭环。没有可用开发账号或对应套餐时，只完成模拟测试并标记真实 Connect 验证缺口，不将候选包称为已经验收的正式版。

### 阶段 D：独立输入扩展与诊断

- [ ] 在 `connect-sdk/` 提供 README、可锁定依赖的 Bridge 示例、配置模板、消息协议和原型制作说明。具体语言与 Socket.IO 客户端版本由实际 Connect 协议兼容测试确定，不直接搬用过期 Node/pkg 示例。
- [ ] 消息约定至少包含消息名、值类型/单位、范围、频率、去抖规则、初始状态、断线状态和复连后的状态同步；使用通用演示消息，不绑定原先数字按键。
- [ ] 首版 Bridge 独立运行，无 Warp 配置写入接口；高频输入限速，不对未知消息自行映射成系统快捷键。
- [ ] 以一个 Receive 驱动画面变化的最小原型验证输入闭环，并提供制作步骤；只在合法可用的 Studio/Connect 环境生成真实 `.pie`，不能用伪文件替代。
- [ ] 记录 App/Connect/Chrome/Bridge 版本、会话、原型标识、准备阶段、切换原因、断线与重连、首帧、FPS 和各进程资源采样；日志轮转并脱敏，不保存口令或默认记录所有输入载荷。
- [ ] 诊断导出包含各子链路状态和配置哈希，不包含完整现场标定参数。需要用户日志时由用户主动导出，不暗中上传。

完成物：输入扩展可独立开发、停止和重启；其故障不写坏校正参数。首版不加入杀掉全部浏览器或自动重启 Connect 的全局守护。

### 阶段 E：本地验证与候选包

## 5. 最终交付目录约定

```text
NIO-Warp-2.0-delivery/
  app/                    # 唯一正式 App 包、版本清单和校验值
  connect-sdk/            # 输入插件/Bridge 源码、依赖锁与配置模板
  examples/               # 已验证原型、消息约定与运行示例
  docs/                   # 安装、Connect 配置、二开、验收、日志、回退
  skill/                  # 客户 AI agent 使用说明，仅指向扩展接口
  rollback/               # V1 软件包及保护当前参数的恢复步骤
  manifest.json           # 来源提交、包哈希、平台、依赖、验收状态
```

客户现场预设保存在客户自己的备份中，不夹入通用 SDK 或公开仓库。上述目录是计划，不代表包已经生成。

## 6. 回退与兼容要求

1. 升级前备份用户当刻配置与预设。V2 新配置采用独立存储或明确的版本化迁移，不原地把旧文件改成 V1 无法读取的格式。
2. 默认软件回退只替换 App 并停用 Connect 新来源，不恢复旧校正参数；继续使用用户最新的几何设置。
3. 如 V2 改写过 V1 共享来源配置，必须使用升级前对应来源备份恢复；禁止用旧整份偏好覆盖新标定。
4. Connect 和用户插件属于独立程序，回退 NIO Warp 不卸载或终止它们。
5. 如果无法同时满足来源配置回退和参数保护，禁止把该迁移作为默认升级路径。

## 7. 用户侧交付前收集项

由用户提供版本和设备信息即可，不索取其订阅密码：macOS/芯片、Chrome 与 Connect 版本、订阅功能等级、目标显示器与分辨率、输入硬件/协议，以及脱敏示例原型或消息约定。开发者没有真实环境或授权时，文档必须准确记录验证缺口。
