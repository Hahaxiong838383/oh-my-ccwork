# V2.0 Agent / Codex 操作入口分析

结果：现有输入 SDK 可被 Agent 通过 CLI/Node 库调用；App 来源与计划仍由 GUI 操作，没有公开控制 API/MCP。建议复用 SDK 和 Skill；稳定管理 App 时再增加有限接口及 CLI，MCP 为可选包装。本文件是审计和建议，不授权新实现或部署。

## 已有能力

| 目标 | 入口 | 边界 |
|---|---|---|
| 原型输入消息 | `connect-sdk/src/cli.js`，JSON-lines stdin/stdout | 演示白名单，不是任意硬件驱动 |
| 输入程序复用 | `createBridge()` 的 start/stop/send/status、state 事件 | 相对路径导入，包无 bin/exports；不控制 App |
| Bridge 状态 | `{"type":"status"}`、stderr、可选日志文件 | 不证明消息收到或画面响应 |
| 来源、链接、列表、计划 | AppKit GUI，有 AX 标识 | 需要 Agent 的本机桌面工具和权限，客户实机待验 |
| FPS、捕获及错误取证 | `~/Library/Logs/NIOWarp/Playback`、GUI 导出日志 | 只读解析，无统一实时状态 API |
| 输入二开规程 | 随包 `nio-connect-input/SKILL.md` | 手动加载，未自动安装；不覆盖 App 操作 |
| App URL scheme、专用 AppleScript、CLI 参数、HTTP/JSON-RPC/MCP 控制服务 | 未实现 | 内部 Swift 方法/Chrome CDP 不是 App 对外接口 |
| 多物理屏独立校正、Stage View 合成输出 | 未实现/未验收 | MCP 包装不会自动增加这些能力 |

## Agent 调用现有 SDK

在客户解压的 SDK 可写副本内，按 README 配置 Node 22+、依赖及 Connect 服务；本次不执行安装或连接。

```sh
node src/cli.js --config config.local.json
```

Agent 保持子进程 stdin 开启，等待 stderr 的 `connected` 后，以至少 100ms 间隔逐行写入：

```jsonl
{"type":"status"}
{"messageId":"demo.level","value":25}
{"messageId":"demo.toggle","value":1}
{"messageId":"demo.action","value":"next"}
```

白名单为：level 有限数值 0–100，toggle 数字 0/1，action 字符串 next/reset；其他消息被拒绝。启动时直接管道灌入整份 JSONL，可能在未连接前丢输入，EOF 会停止 Bridge，不能作为可靠的一次调用方式。

`submitted` 仅本地传输提交，无 ACK；`connected` 仅连接层状态，`stateSyncRequired` 不是业务确认。断线/忙/限速时不排队，不重放旧动作；复连由生产者重读当前硬件状态。

新增消息须规定名称、类型/单位、范围、状态/动作属性、频率、去抖、初始值和复连行为，并制作同名 Receive。新增动作不能只改验证器：Bridge 当前把 `demo.action` 写死为动作，其余按状态同值去重，必须同步扩展分类、契约和测试。需要业务确认时另定义 ACK/超时，不能盲补非幂等动作。

已有 CLI/库无需为 Codex 重写成 MCP。SDK/Skill 已随包交付；实际调用仍要求 Agent 能启动进程、访问本机服务，且客户已授权相关操作。

## App 与权限的源码证据

- [播放面板](../native/Sources/NIOWarpApp/ProtoPiePlaybackPanel.swift) 有 `nio-playback-*` AX 标识，包括 source-kind、source-url、preview-selected、start-pause、next、save；[单来源面板](../native/Sources/NIOWarpApp/ProtoPiePanel.swift) 也有标识。
- [main.swift](../native/Sources/NIOWarpApp/main.swift)、[构建脚本](../native/scripts/build-app.sh) 仅有 GUI 启动，无 URL scheme/脚本术语、参数分派或控制服务 listener。
- [WorkbenchAccess.swift](../native/Sources/NIOWarpApp/WorkbenchAccess.swift) 和 main 保留使用模式与动作门禁，调试授权仅当前会话。
- [播放库](../native/Sources/NIOWarpApp/ProtoPiePlaybackConfiguration.swift) 由 UserDefaults 读入内存。直接 `defaults write` 不会调用控制器或同步内存，还可能旁路保护，不能当正常接口。
- [CLI](../connect-sdk/src/cli.js)、[Bridge](../connect-sdk/src/bridge.js)、[验证器](../connect-sdk/src/protocol.js)、[输入 Skill](../connect-sdk/skill/nio-connect-input/SKILL.md) 是现有机器入口。

本次没有原生桌面实测，不能将 AX 自动化的一般可行性说成客户验收。尚无 NIO Warp GUI 专用 Skill，已有输入 Skill 不能代替它。

## 建议路线（未实现，待用户决定）

1. **输入与二开**：现有 SDK CLI/Node API + 输入 Skill，先按消息面板 → Receive → 浏览器 → Warp 做完整闭环。
2. **稳定管理 App**：有限本机控制接口直接调用现有 Coordinator/PlaybackController，再配 JSON 输出 CLI。先只读 status/list-sources/export-logs，再来源选择、预览、计划开始/暂停/停止、下一项；不另造播放状态机。
3. **统一 Agent 工具发现**：同一接口外加 MCP 薄包装和操作 Skill。可优先 stdio，让 Agent 启动本地进程，无需为本机能力开放网络端口。本次不注册 MCP、不改全局配置。

上述 CLI 命令是拟议名称，不是现存命令。未来请求应含请求 ID、会话/来源身份、有效状态及错误，并复用 GUI 权限和并发检查；分开保存配置、启动和就绪回执，避免 saved/submitted 被误认 playing/ready。

未来范围保持使用模式，不暴露调试解锁、Warp/AA/镜像/鼠标方向写入、任意 JS、系统快捷键注入或全局进程清理。SDK 本身无参数写接口，包装不得扩大它的能力；日志本机脱敏读取，不自动上传。

**接口提供能力，CLI 提供调用方式，MCP 提供工具发现和协议，Skill 提供规程。** Skill 不会生成接口，将普通 JSON-lines CLI 填入 MCP 配置也不会使它实现 MCP 协议。[OpenAI 官方 Skill 说明](https://developers.openai.com/plugins/concepts/skills)、[Codex MCP 支持](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。本机只读核对 codex-cli 0.161.0 的 mcp help，未执行 add/login。

## ProtoPie 官方 MCP

- **Studio MCP**：Studio 内本地服务，供 Codex 等读取/编辑当前原型、创建层与交互；当前官方要求 Studio 10.3.0+ 和 MCP Core。适合制作 Receive/原型，不是 NIO Warp 计划接口。[官方说明](https://www.protopie.io/learn/docs/mcp-studio-mcp-introduction)
- **Code MCP**：本地只读服务，用 Cloud 链接读取原型结构/交互以生成代码，当前为 MCP Enterprise；不是实时外设消息桥。[官方说明](https://www.protopie.io/learn/docs/mcp-code-mcp-introduction)

这些官方能力不证明客户版本/订阅已启用，也不代表本 V2 包安装或集成了它们。是否接入按客户制作需求、版本和权限另评估。
