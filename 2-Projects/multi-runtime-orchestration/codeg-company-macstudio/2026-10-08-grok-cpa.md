## 原因与证据边界

目标是公司 `fu-121deMac-Studio.local`，Codeg 0.34.0 / Grok 1.0.46，不是家里 Ubuntu home-studio。修复前官方 `acp_list_agents` 仅见 `GROK_AUTH_MODE=custom`，所有 custom 模型字段为空。真实 TOML 解析和只读数据库检查一致：没有 `[models]` / `[model.<id>]`，没有 CPA 地址、模型或 Key 落盘。

v0.34.0 源码（tag 对应 `592131c7`）的自定义保存条件是非空的模型 ID；灰色 `grok-4.5` 只是 placeholder。`acp-agent-settings.tsx:3220` 与 `3235` 起将空 ID 对应的地址、Key、backend、context 全部发送 null，保存按钮不会报缺字段，单测 `:442` 明确预期此行为。后端 `commands/acp.rs:4606` 起把空 ID 解释为移除受管模型段并成功返回。

生产保存结果与该分支吻合；本轮没有读取用户原表单输入，因此历史上是否具体由“模型 ID 留空”触发，仍是依据源码与运行态的判断，不能写成已取证的用户操作。没有发现环境变量、model provider 或 GROK_HOME 覆盖。Air 的真实 WKWebView 持久化存储没有 Grok selector 偏好；未读取正在运行的 WebView 内存。
