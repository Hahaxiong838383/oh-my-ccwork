# P003 启动阶段同身份重连修复

目标设备：BJP00326081002000038。依据 Air Downloads 的 `P003_SN02000038_WAKE_FLASH_DIAGNOSIS_20261031.md`。实现由 codex 完成，独立只读评审已完成。

## 问题与范围

2026-10-31 14:08—14:11 的 7 个短房，在尚无输入轨时出现同 identity、新 participant SID；旧 Worker 收到旧连接退出即删房，新连接被误踢。该路径早于 P1 搜索执行。本次修复这种建连阶段恢复，并清理被废弃的 ASR 预热。

已经开始流水线的会话沿用现有终止、退出重连语义。不能调用 `SearchSession.close()` 后在同房重建流水线：Brain 会将该 room 标为终局关闭，迟到的 close 还会关闭新实例。若后续需要活动通话无缝重连，应独立设计输入轨切换与字幕、搜索进度和输出门恢复，不能混入本次热修复。

## 实现

- 由可信房名绑定设备 identity；从 SDK 当前参与者表初始化，音轨和数据按当前 SID 校验。
- 尚未启动输入时，当前连接离开进入 3 秒恢复窗口；同身份替换被接受后给麦轨 10 秒，整个启动过程最多 60 秒。
- 旧 SID 迟到退出、无关参与者退出不关闭设备房。已启动流水线的当前参与者真正退出继续原有清理。
- 替换时丢弃旧预热和尚未消费的 control / device result / ordered PCM 队列，重新开始输入、输出就绪门。
- 每个替换连接重新发布全新 LocalAudioTrack，保留音源、获得新 publication SID；只接受当前输出轨的订阅事件。重发最多 3 秒，失败统一关闭清理。
- ASR 与预热句柄采用 OwnedTask：丢弃所有者即取消任务，包括已完成但未接管的预热结果。输入关闭或事件消费者退出后不再无效重试。

## 两个真实回归陷阱

1. Python RTC 客户端会自动重试，旧版删房后能重建同名房。只看最终 connected 会假通过；必须核原 room SID、唯一 job、输入输出通道。
2. SDK 0.8.3 的 LocalTrackSubscribed 是 publication 首次订阅事件，没有新订阅者 identity。第一次补丁只重置门，真实测试出现 input_ready=1、output_ready=0，已拦住发布。最终方案使用全新 track 对象和 SID；复用旧对象会使其 SID 被修改，旧排队事件也可能被错误放行。

## 验收与发布纪律

单元回归覆盖事件顺序、过期、无关参与者、旧队列、任务取消、关闭后的 ASR socket。独立验证进程使用合成设备身份，真实 SFU/ASR/TTS，固定本地 LLM 输出，核音频、字幕、metrics、就绪信号、room SID、job 数及退出后 ASR。此验证不能代替目标设备扬声器实听或长稳。

普通 Worker 基线保留当天天气补丁；P2 基线保留会话 24 的三设备名单校验、两路并发及已有 R26 改动。分别构建、分别留当前运行二进制回滚点。发布只换 Worker 二进制，保留实时名单、窗口和数据库。线上空闲才 stop/start，核实际运行 SHA、注册和相邻进程状态。
