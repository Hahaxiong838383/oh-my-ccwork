## 关键发现

1. 首页默认显示“朝阳公园”，不是用户所在城市。REA 点击北京后显示“北京市”，点击上海后显示“上海市”。禁止使用首页默认坐标作为用户位置。
2. 浏览器实际使用 `wwwapi.moji.com` 的公开 GET 数据：`/app-api/system/new/area/getHotCity`、`/app-api/cms/official-website/getCityData`、`/app-api/cms/official-website/getCityWeatherAndIndex`。这是官网内部协议，不是官方承诺稳定的开放 API。
3. 热门城市记录中的 `id`、`mid` 不是同一个值；北京查询实际使用 `cityId=2`，上海 `cityId=39`。不能用拼音猜 ID 或混用 `mid`。
4. 天气响应不携带城市对象，需先以 `getCityData` 校验 ID、完整城市名、时区，再读取相同 ID 的天气。响应按固定请求关联，不能宣称天气载荷本身回显验证了城市。
5. 数据具备 `current.obs_time`、`daily.update_time` 和 `daily.predict_date`，适合严格区分观测、更新和预报日期。它们比搜索结果的网页发布时间更适合天气验收。

## 冻结的接入选择

采用固定天气适配器：只读已观察到的官网端点，城市 ID/名称精确映射；首版城市限定北京、上海及经身份核验的官网热门城市。总预算 6 秒、单请求 3 秒、响应 128KiB 上限、缓存 5 分钟、失败短暂冷却、并发单飞。拒绝跨域重定向、HTML 验证页、401/403/429、超大响应、城市不符、缺失/过期日期。

观测数据默认最多 2 小时；日预报更新最多 24 小时，且目标日期必须等于用户要求的北京时间日期。缓存命中仍复核数据时效，不把缓存抓取时间替代数据更新时间。首版支持当前、今天、明天、后天及当前 AQI；超范围问题交给通用查询或明确说明尚不能确认。

输出采用经过验证的短模板及来源元数据，不用模型补造天气数值。固定天气读取为 P1 的新增专用来源，单独开关和标识；通用网页抓取和 Tool Calls 的 P2 开关继续关闭。
