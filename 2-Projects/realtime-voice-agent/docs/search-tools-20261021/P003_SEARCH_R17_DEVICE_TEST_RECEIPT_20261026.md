## 明天可直接照读的用例

| 编号 | 操作/话术 | 预期与检查点 |
|---|---|---|
| 01 普通聊天 | “我今天画了一只小猫。”“给小猫取个名字吧。”“不要查天气，我们聊小猫。” | 正常聊天，不误启动搜索；尤其比较正文开口速度，等待词不能替代正文。 |
| 02 非天气查询 | “帮我查一下中国第一颗人造卫星叫什么。” | 先有简短搜索衔接语，随后给出有根据的答案；不应只说“去查了”却一直没有结果。 |
| 03 搜索中继续聊天 | “帮我查一下火星为什么是红色的。”随后接“我今天画了一只小猫。”再说“给它画一顶帽子怎么样？” | 能接着聊小猫；不要求用户一直等待查询，不用搜索结果抢断用户正在说的话。记录是否卡住、串话。 |
| 04 空闲补播 | 重做03后停止说话，等待结果。 | 空闲时播搜索结果，一次任务不重复完整播报；长时间没结果需记录。 |
| 05 正文插话 | 查询恐龙灭绝原因，**听到结果正文后**说“先停一下，我们聊小猫。” | 正文应停止并转入聊天。只在“我查查”之后插话，不能算正文插话通过。 |
| 06 同房续讲 | 05之后说“继续刚才的搜索结果。” | 继续尚未讲完的原结果；最多重讲被中断的一句，不应重查或接不相关旧话题。 |
| 07 退出重连（重点） | 新查“恐龙为什么会灭绝”，正文未讲完时直接退出；1分钟内重新进入，先安静10秒，再说“继续刚才的搜索结果。” | 重进后不自动旧播；明确续讲后恢复这一条未完结果，不回答“没有结果”，不接更早任务。 |
| 08 变体续讲（重点） | 独立重做07，每轮择一句：“请继续刚才的搜索结果。”或“从继续刚才的搜索结果。” | 明确续讲仍能识别。每轮重新查并在正文未播完时退出，防止把已播完误当恢复失败。 |
| 09 取消及重连 | “帮我查一下潮汐是怎么形成的。”随后“不用查了，我们聊别的。”退出重进后说“继续刚才的搜索结果。” | 取消有反馈，不再补播被取消的答案；重连后不恢复已取消任务。 |
| 10 改查 | “帮我查一下火星为什么是红色的。”随后“改查中国第一颗人造卫星的名字。” | 只返回新目标；留意字幕是否把“改查”听成别的词。 |
| 11 分段与附和 | “帮我查一下。”停顿后“三角龙。”再“主要吃什么。”；另起完整查询，在结果正文中分别试“对”“嗯嗯”“哦”。 | 分段应查询或合理澄清，不答两次不同问题；附和不应突然重启旧聊天。这两类仍有识别边界，必须分别记录，不沿用历史通过。 |
| 12 城市/天气 | “帮我查一下成都明天的天气。”另试“辽宁朝阳市明天的天气。”；再试“今天天气怎么样。” | 指定城市要区分同名地名；无城市时以设备网络定位的可用信息回答，不把服务器所在地当设备位置。位置不准请记录城市，不必提供公网IP。 |
| 13 新闻/时效 | “帮我查央视今天的国内新闻。”“帮我查中国国家博物馆最新预约方式。” | 内容应相关且有明确时效；查不到要说明，不能编造实时结论。当天页面变化不等同功能一定失败。 |
| 14 非搜索与设备控制 | “继续刚才的故事。”“我想喝奶茶。”；另试“声音小一点”“把灯关掉”。 | 不因近音词误查。设备指令分别记录物理动作和是否听到确认声；动作成功不代表确认声成功。 |

普通聊天无明显变慢仍是首要验收目标。如果聊天明显卡顿、不断串旧话题或设备异常退出，先停连续重试，记录时间和现象。短词漏识别、安卓退出/确认音、同版长期延迟及全量历史训练/回归仍未全部完成，本次不将它们标记为已解决。
