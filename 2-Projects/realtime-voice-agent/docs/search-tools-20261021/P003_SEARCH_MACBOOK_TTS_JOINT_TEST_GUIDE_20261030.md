## 3. 固定播放装置和时间轴

每轮开始填表并拍一张摆位照片，后续不偷偷调音量、换音色或挪位置。若需调整，结束该run，新建“装置校准run”，保留原失败。

| 必填项 | 记录内容 |
|---|---|
| Mac | 机型、macOS版本；TTS引擎版本、准确音色ID/语言、语速；生成工具命令 |
| 播放 | 实际输出设备/扬声器名称、系统输出音量、播放器增益/音效、有无蓝牙；逐句使用固定音频文件，不临时重新合成 |
| 摆位 | 扬声器到设备麦克风距离（厘米）、高度/朝向；房间与背景噪声；其他声源有无 |
| 设备 | 初始音量、可见麦克风/采集状态、应用前后台；第9项音量变化是用例动作，单独记录前后，不作为装置调参 |
| 源文件 | 每句文件名、SHA256、采样率/声道、时长；标注真实语音起止，文件尾静音不当停说时刻 |
| 独立录音 | 录音设备/位置/格式、开始/结束时间、SHA256；与Mac播放和设备日志用同一时钟锚，保留偏差及校正依据 |

Mac可使用系统现有TTS先生成文件。先查看可用音色，再选择并固定；以下占位符须换成实际值，不提供不存在的音色默认值：

```bash
say -v '?'
say -v '<实际音色ID>' -r '<固定每分钟字数>' -o 's01-u01.aiff' '我今天有点开心'
shasum -a 256 s01-u01.aiff
```

生成所有用例的固定话术文件后一次性保存manifest。播放脚本只调用现有文件，不改系统/设备音量。每句至少写以下日志；`afplay`返回只代表播放器结束，不代表设备听清或答复：

```python
# mac_play.py：Mac上运行，python3 mac_play.py s01-u01.aiff
import datetime, hashlib, json, pathlib, subprocess, sys, time
p = pathlib.Path(sys.argv[1])
def mark(event, **extra):
    print(json.dumps(dict(event=event, at=datetime.datetime.now().astimezone().isoformat(),
                         mono_ns=time.monotonic_ns(), file=p.name,
                         sha256=hashlib.sha256(p.read_bytes()).hexdigest(), **extra)), flush=True)
mark('play_start')
r = subprocess.run(['/usr/bin/afplay', str(p)])
mark('play_end', returncode=r.returncode)
raise SystemExit(r.returncode)
```

播放开始/结束调用时间存在进程及声卡缓冲偏差，实际声学起止以独立录音对齐。录音ASR不给预期答案、话术或答案关键词做提示；分清Mac输入和小可回复。近音错字、说话人不确定保留原转写并加“不确定”，不得改成预期句后当识别成功。

## 4. 三层验证分别出结果

1. **语义/隔离RTC重放**：同段固定音频或经核验的设备上行片段，经现有隔离链路验证取消、改查、退出和任务终态。合成身份、隔离账本；服务端执行，不让现场同事改生产开关。只能证明对应输入条件下的控制语义/传输结果。
2. **真实设备＋Mac外放**：同一源文件穿过实际扬声器、设备麦克风和上行，本文件10场景的主要结果。独立麦克风完整录音不等于设备采集/上行完整。
3. **少量同话术真人对照（条件允许时）**：重点首句、取消、改查、退出；保持摆位和初始音量。人员未参与写“未做”，不能用前两层代替真人验收。

三层使用独立run ID、各自版本和结果，不互相补齐成“通过”。装置校准通过也不等于产品通过。

## 5. 每个场景的入场与停止规则

**标准云端聊天路径**：待机→播放单独唤醒文件→记录连接attempt_id/trace/room→记录招呼、提示、端侧实际收到的input_ready及真实“可以说话”节点→按该APK、该首句模式的真实合同触发第一句。若该模式要求招呼播完和端侧input_ready，则到齐后立即播；若有序首句合同允许在RTC就绪前采集/上传第一句，则按其首句许可节点播放，不能再额外叠加“必须先等云端input_ready”的门。首句合同未核清记阻塞，不猜测。另做招呼重叠边界子例，不能把延后播放当首句问题已修。

- 建议自动控制器直接订阅已有端侧真实许可/就绪事件，并记录实际选择的首句模式。只有服务端`published(scheduled)`、字幕或Mac录到招呼，均不算端侧ready；也不要把RTC模式的ready条件套到有序首句模式。
- 若现有控制器拿不到就绪事件，使用端侧原UI认可的节点人工触发并标记“人工触发”；缺合同证据记阻塞，不用固定sleep代替。
- **本地硬件控制走端侧既有授权路径**，第9项不以云端input_ready作统一前置。不得为了过连接门，擅自改它的运行方式。
- 每场景首轮仅一次。失败后最多允许**一次注明目的的诊断重试**，新建run并关联原run；改变摆位/网络/音色属于新实验，不能覆盖首轮。第二次仍失败则停止该场景。
- 连接失败、超时或未就绪时，立即停止后续查询/取消/改查文件播放。保存时间、错误、attempt/trace及画面；最多一次仅唤醒诊断，仍失败则结束云端场景，不连发唤醒。
- 每项动作有状态触发点，不用“反复说直到成功”。查询结果/取消确认超过客户端或服务端既有超时，按原超时记失败；无可查超时合同则最多观察30秒记超时待查，不加长等待制造通过。
- 退出、崩溃、意外硬件动作、持续迟到播报或普通聊天明显异常：停止整轮，保留证据并通知川哥。不要自行恢复工厂、换包、切网络或提音量。

## 6. 原10场景逐项执行

### 1）普通聊天基线

- 前置：本run云连接就绪、无历史搜索在播。
- 播放“我今天有点开心”；**本轮正文实际播完**后，播放“课间能玩什么小游戏”。
- 通过：两句输入完整、均有对应实际正文声音，能自然接话；逐句记“真实停说→实际正文首声”。等待词、招呼、字幕不能代替正文。
- 失败/阻塞：截句、无声、只等待词、连接失败或正文归属不确定。其他设备可作体验基线，但设备/模型不同不能冒充严格配对性能证明。

### 2）搜索中继续聊天＋空闲补播

- 播放“帮我查我的世界基岩版最新正式更新”。记录搜索已接收及首个可听等待词。
- 在等待词**首声后200毫秒**触发“我今天打球赢了一次”，记录实际声学重叠。若自动控制器只能人工触发，写实际偏移，不声称精确200毫秒。
- 然后不追加问题，让小可先回应聊天、在空闲时补播搜索。
- 通过：同run内两个输入完整；聊天得到正文，之后搜索有实际结果或明确的无法核实反馈；不能只输出版本号就判“最新”已验证。
- 若搜索正文已先开始，等待中聊天前置未满足，标“前置不符”；另立正文插话子例，不拼成原场景通过。

### 3）取消搜索后继续聊天

- 播放“帮我查恐龙为什么会灭绝”；等待词首声后200毫秒播放“不用了”。
- 取消句播放结束即播放“我们聊聊小猫吧”，保留真实句间间隔，不能故意等数秒回避边界。
- 服务端对账：源音频→设备采集/上行→ASR→Worker收到的控制→**同一任务取消终态**；随后观察迟到结果和聊天正文。
- 通过：不退出聊天、能聊小猫、旧搜索取消且不迟到播恐龙。服务端未收到取消或取消词截断仍记失败链路，不替服务端推断“收到但未执行”。只有无迟到声音、缺任务终态仍不算完整通过。

### 4）等待中改查

- 前置：天气修复正式发布且版本已登记。
- 播放“查北京今天的天气”；等待词首声后200毫秒播放“改查成都今天的天气”。
- 对账新旧任务ID/代次、实际城市、供应商/错误码及终态。
- 通过：完整改查被接收，旧任务被替换/停止，最终实际回答成都；不把北京迟到结果或泛泛“今天的天气”当改查成功。
- 若供应商失败、超时、无数据，分别记录，不能判天气成功。可验证正确失败反馈及无乱报，但本项完整成功仍待验。

### 5）成功结果播完后改查

- 前置：**本run北京天气有可信结果且实际播完**，不是等待词、失败提示或字幕完成。
- 再播放“改查成都今天的天气”。
- 通过：新任务和实际成都结果完成；不能只说“我去查一下”就结束。
- 北京失败则本项“前置阻塞”，后面即使成都单独查成功也不能补算本项。首次失败保留，最多一次诊断重试另run。

### 6）正文插话＋明确续讲

- 播放“帮我查篮球为什么要运球”。实际搜索正文进入第一句后200毫秒播放“等一下，聊聊今天的学校”。
- 聊天正文实际播完，再播放“继续刚才的搜索结果”。
- 通过：能插话、接普通聊天、明确续讲后回到本次同一搜索结果；记插话声音起点、正文停点、实际续讲首声及任务ID/游标。
- 未完成句允许按原合同从句首重说。少量缓存尾音需如实记录，不能声称零尾音。只有服务端sent/completed不能证明扬声器听到。

### 7）退出聊天→重连静默→明确续讲

- 新run先取得篮球搜索正文，播放中使用既有退出操作，记录旧room断开及实际声音停止。
- 重新唤醒，建立**新room**；按真实就绪合同入场。就绪后保持静默**1.5秒**，确认未自动突播旧结果，再播放“继续刚才的搜索结果”。这1.5秒只验证重连后的静默，不作为首句就绪补偿。
- 通过：旧会话确实结束、新房静默不突播、明确续讲后返回同一有效搜索；记录旧/新room与任务/游标。过期应明确提示重查。
- 重连失败即停止播放续讲，记“重连失败、续讲未测”；不能用第6项同房续讲替代。

### 8）明确语音退出

- 搜索等待时播放“算了，退出聊天”，仍在等待词首声后200毫秒触发，保存实际偏移。
- 观察端侧退出终态、room断开、实际声音停止；随后重新唤醒并播放第1项第一句。
- 通过：本次完整退出指令被接收并退出，旧结果不迟到；重进能正常聊天。
- 若仅识别残句、不退出或重连失败，分别记失败。ADB/返回键只作异常清理，不代替语音退出通过。

### 9）既有本地硬件功能

- 单独记录本地控制模式及所需状态；不因为云端连接失败就统一不让播本地硬件话术。
- 逐句“把灯打开”“亮度低一点”“声音小一点”，每句完成实体观察和前后读数后再下一句。初始灯已开时，不能以仍亮证明开灯动作；改前置状态须先得到现场同意并记录。
- 通过必须同时注明命令/事件、读数、实体灯/声音变化和观察者；字幕或边界提示不等于实体变化。音量变化是测试动作，不能偷偷复位或改Mac音量。
- **“升高一点”：上一轮用户要求跳过，本轮仍标“用户跳过”**；未另获现场明确授权不执行。

### 10）一般兴趣检索与失败兜底

- 两个独立子run：“帮我查最近有什么适合初中生的科普展”；“帮我查一条最新的中国航天消息”。
- 前置：每次云连接真实就绪；确认查询真的进入检索链，再观察实际答案。
- 资料足够：简短、有可查来源及合适日期，不编造“最新”；资料不足/真实供应商错误/超时/无数据：分别记录，须有诚实、可听的失败反馈，不长期沉默。
- 不做故障注入、改开关或临时断网。自然未出现失败，只能记成功路径已测、失败兜底待受控验证。
- 若被入房挡住，记“连接阻塞、检索/兜底未测”，不能算兜底已验证。

## 7. 首句与短句边界补测，不替代10场景

使用相同固定文件：首句在端侧承诺可说话的最早节点播放；取消/改查/退出分别在等待词中、等待词结束节点、正文中触发，各记录实际相对偏移。每种时序单独run；不以改变语速、放大音量或多说一遍覆盖失败。若有真人配合，选同样三句做少量对照。

短句缺字时先看设备实际上行/ASR和Worker收到什么。只有独立录音完整而设备缺首字时，设备采集、AEC/NS、上行、ASR均是待查因素；不得直接归因Mac TTS，也不得直接声称服务端任务状态机有错。设备上行片段缺失时标缺证据，现有录音不删。

## 8. 如何停止和恢复普通使用

出现异常先停止Mac后续文件播放；能操作时退出聊天，不能操作时保留画面并联系川哥。重进仍可能派到原P2候选，**不等于回到正常版本**。需要恢复现役链路时由服务端移出该完整SN或按既有灰度回滚程序处理，确认后再重进；现场同事不自行改范围/截止。窗口到期停止测试，原会话退出后再进现役；如未自动退出，记录为到期关闭异常并上报。

不发送凭据、完整令牌、原始儿童自由对话或音频到公开文档/代码仓。固定测试音频和受控日志用原私有证据渠道保存；本文可填写脱敏现象、ID、时间和必要截图。
