## 根因与验收缺口

现实现有三层边界：

1. Worker的续讲内容保存在当前语音会话内，新会话初始为空。
2. 退出时取消旧会话任务，Brain删除可播结果。
3. 任务读取同时校验设备身份与会话，不能直接拿旧会话任务到新会话播报。

原协议明确“退出销毁待播与可续讲内容”。R12用例10验同会话续讲，用例13验重连后不自动串入旧结果，**没有独立验“新会话里主动要求恢复旧搜索”**。这是产品期望与验收定义之间的缺口；不能拿用例13通过，推导用户主动续讲也已支持。R13本轮只改提示音，保留了原生命周期规则，所以问题仍在。主要改动应落在Worker与Brain；当前安卓已能把续讲请求完整送到云端，暂无必须先升级安卓的证据。

## 建议的下一步方案（尚未实施）

建议增加“同设备、同授权归属、原有效期内，用户明确要求时恢复最近一条搜索”，同时保留重连后不自动播旧结果：

| 边界 | 建议首版行为 |
|---|---|
| 什么可以保留 | 已得到且可播放的最近一条搜索结果及播放进度；退出只结束会话，不立即销毁这条短期恢复记录 |
| 保留多久 | 沿用原结果ready后5分钟的绝对期限，重连/续讲不刷新；超过期限明确提示过期并让用户重新查 |
| 何时恢复 | 只在新会话明确说“继续刚才的搜索结果”等时后台查询；连接建立和普通聊天均不增加等待 |
| 谁能恢复 | 经设备认证的完整SN、当前账号/绑定关系及当前灰度资格都匹配；沿用已有隔离，单独设计受控恢复入口，不删除旧会话所有权校验 |
| 不恢复什么 | 明确取消、被改查替代、过期、关闸/撤销资格的任务；退出时还没完成的查询首版仍取消，不在后台无限运行 |
| 如何播报 | 恢复后仍走空闲门、插话和续讲进度；中断结果继续余文，已播完的结果可明确重播，不把重连当自动播放授权 |
| 部署 | 两条原分支、独立候选、新回滚点；先做合同与边界测试，再Linux构建和RTC，不影响现役链路 |

需要补的验收：同会话续讲；5分钟内退出重进后主动续讲；重连不主动续讲不播旧结果；取消后重连不恢复；改查只恢复新任务；超过5分钟不恢复；换设备/换绑定归属不恢复；关闸/到期不恢复；连续重连不重复领取；恢复期间普通聊天不变慢。

如果希望跨几十分钟甚至隔天恢复，应另做“历史搜索”能力和时效说明，不能靠不断延长当前临时任务期限实现。TTS长尾另行取证和优化，不与这次跨会话状态修改混成一次大改。
