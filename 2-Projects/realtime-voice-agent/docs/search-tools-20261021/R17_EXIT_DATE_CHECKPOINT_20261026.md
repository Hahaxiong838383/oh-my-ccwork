## 探针退出问题

最小复现不建房、不调用模型：真实SDK `livekit 1.1.9` 创建AudioSource、await关闭，asyncio.run返回后进程仍可能native abort。预设最多300次且首次失败停止，第118次exit=-6；不能报成运行了300次或据此估稳定失败率。堆栈缺native符号，只定位到解释器/FFI退出阶段，未找到SDK内部精确指令。上游有[同类退出问题报告](https://github.com/livekit/python-sdks/issues/833)，其版本不同，不能代替本机复现或称维护者确认本项目根因。

新增入口要求显式一次性探针范围；业务断言和房间/流/音源的await关闭完成后，校验计数、独占创建并fsync回执、flush输出，最后以对应状态os._exit，避免再次进入有问题的Python/native终结阶段。断言失败、缺少清理、SystemExit(0)、回执已存在均不能变为成功。外部仍核退出码、回执、任务和实际房间。固定300次真实SDK控制实验通过；该控制对应整理import顺序前的相同行为版本，最终文件另跑Linux6项且保留两版摘要。禁止将此策略用作生产服务的粗暴退出或跳过应用清理。

## 答案误拒：事实错误和表达建议分开

只针对已观察到的两类公开知识问题做固定2×2诊断，没有导出所有设备聊天记录。两次卫星问题失败，捕获的初稿及复核都提供正确名称和有引用依据的发射日期，唯一拒绝类别是unasked_date；同批两次恐龙问题成功。真实设备原失败没有详细模型答复，不能倒推它们全部同源。

修复将未问年份作为现有复核轮的简洁性建议；有依据的补充日期不再使正确答案整体失败。数字仍须在对应引用原句中，虚构年份仍被拒绝；错误引用、部位/范围、闭馆例外、长度和安全文本约束保留。仍一次检索、最多两次生成、20秒总预算，不改普通聊天路径。代价是有依据的额外年份偶尔仍会被念出，后续继续改表达质量，不用整体无结果惩罚它。

两条RTC尝试使用不同公开话术，固定总预算2，未失败后追加凑绿。第一条服务端任务确已完成，但新探针30秒后错误调用待处理列表，返回空后断言失败；源码已有测试明确delivered不再主动返回。改为按准确room的结果发布日志取得task ID，再用带同房认证的详情接口核结果；第二条完成。第一次客户端字幕正文未在失败前保存，只有计数和服务端证据，不能把第二条的收音证据挪过去；探针已补失败字幕私有落盘。
