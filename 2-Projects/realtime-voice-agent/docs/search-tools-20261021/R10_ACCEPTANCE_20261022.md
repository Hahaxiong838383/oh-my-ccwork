## 部署中拦截的问题

最初部署清单漏了共享管理后台的`search-routing-config.ts`。候选新代码虽已通过测试，生产后台仍用旧严格Schema，首轮预览返回400 `invalid_request`，配置没有发布。根因是同一配置合同有候选和共享后台两个运行消费者，部署清单漏了后者；不是百度取数失败。

当时新派单始终关闭。补做原生产Schema单文件备份，核旧SHA及RTC房间0后部署，再次预览/发布/回滚/发布通过，最后才恢复派单。新备份文件独立放在R10原备份目录，未改写原tar及SHA。此遗漏导致共享后台额外一次重启，完整列入记录。

经验：共享模块不能只按当前候选入口生成部署清单，必须逐一列出实际进程消费者；本地合同单测通过不能替代线上管理API的预览、发布和回滚检查。测试装置失败（未开总闸、误用resume路由轮询）与产品失败分开记录；不能改产品语义来迁就装置。
