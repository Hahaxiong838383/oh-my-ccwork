# 停话与关房：本轮经验

- 用户裁决优先于旧语料标签。保留原始语料、原分数及历史失败，用逐项有依据的对照记录产品变化；不能为了追绿抹去原结果。
- 同一说法的最终动作必须贯穿字幕出口、投机保护、最终提交、搜索取消与倾听模式。interim 只停音/抑制投机，不能提前关房；最终整句才裁决。
- 测试必须使用真实部署词表。本轮保持原 9 项打断配置、把退出表从 72 加到 94；不能在验收输入偷偷换一张理想配置表。
- 文本测试与真实 ASR 音频是两层。本轮音频实际发现“今天先聊到这儿吧”被识别成不带“儿”的完整句，先保留失败与复现，再补齐两种同义表达。
- 各池保留既有差异。混合搜索续聊只取消任务并留房，与完整关房不同；该池基线能力不因追求整齐分数被删。
- 确认固定 SHA、CLI 与正式程序各自哈希。调研、源码审阅、离线文本、隔离 RTC、生产合成验证与真人/Android 验收分别记账。
- 只用有界整句规则，不增加逐句语义 LLM。四小时静音等新能力未做就明确不支持，不把结束当前房间写成系统定时功能。
- 分池备份和逐池发布，保护现役凭据、原名单和功能窗口。词表走现有管理 API，程序回退与词表、倾听批准 build 一起核对，不整库回灌。
