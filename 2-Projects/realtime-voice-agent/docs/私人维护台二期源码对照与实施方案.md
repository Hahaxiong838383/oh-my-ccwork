## 两个优先级高于改版的实际问题

把“我的暗号是青松”当作合成事实，换一通问“给我讲一个海浪的故事”。记住之前，模型输入里没有“青松”；记住之后，故事请求带上了“青松”；独立诊断房没有带上；显式忘记后，新房里的故事请求也没有带上。这证明普通聊天选入了无关事实。实验观察的是请求内容，没有观察到助手向用户说出暗号，也不能据此归因真实通话的延迟。

原因在私人版 PersonalRecall.chatPrompt。它先取有原话依据的事实，按当轮是否命中分两组，再把两组连起来取前八条。有依据可以解决“事实是真的吗”，选取时还要回答“这轮用得着吗”。当前可编辑记录的页面 ID 部分由内容、原话等生成，编辑后可能变化；跨版本追踪同一事实需要稳定标识。明确问“你还记得我的……吗”已有单独的据证回答路径，改普通聊天选取时应保留。

**忘记一件事还会影响另一件事。** Google Antigravity 指出了私人版的全局记忆修改时间。随后在同一份隔离大脑上实测：先让小可记住合成事实“我的书签是月牙”，再讲故事并评价“这种讲法我喜欢”。普通聊天请求确实带有这个获认可的讲法样例。只忘记书签后，发出完全相同的聊天请求，样例不再进入提示词；原反馈仍能从成长记录里读到。现有 latestConfirmed 要求样例创建时间晚于主人的最近一次记忆修改。主人在后台看到的成长记录仍在，通话却已经用不到它。

修复时要把两个用途拆开。防止过时抽取任务回写，仍用修订检查；判断某条事实、某段回答、某个讲法样例是否失效，按其来源消息和关联条目处理。先用“忘记书签、保留讲法”和“忘掉该讲法依据、样例停止使用”做一正一反的回归，再缩小全局截断范围。Worker 带回的历史缺少消息 ID 时，按服务器已记录的轮次重新构造可用历史，避免把旧事实从原话带回来。[修改边界](../ops/personal-brain/memory-actions.ts#L135) · [讲法样例的筛选](../ops/personal-brain/stage.py#L94)

## H 的记忆机制怎样用在实时语音里

| H 源码中的机制 | 私人版建议 |
|---|---|
| captureExchange 区分主人原话与助手完成的事；隐私判断前置，短而明确的“以后……”能进入判断。模型不可用和模型判定无内容返回不同结果，并做输入和产出两侧去重。 | 继续使用现有异步抽取。给每一轮留下“未触发／无需记／待确认／已写入／服务失败”的结果与原因，后台能定位到原话。只对失败任务提供重试，按同一消息与当时的修订去重，忘记之后到达的旧任务作废。 |
| recallForTask 可结合上一句补短追问，限条目和字符数，过滤脚手架、去重、重排。默认短模式 2 条/300 字，长模式 5 条/1200 字，有独立超时与启用条件。 | SQLite 先取证据有效、未撤回的相关候选。普通聊天建议起步最多 2 条/约 300 字，零相关则零条；明问私人事实仍走据证回答。上一句只取同一通，且要属于同一话题。无需为语音引入 H 的常驻向量模型或把它的 3500 毫秒超时放到首句前。 |
| lifecycle 将有效期、种类、时间尺度和分类来源拆开；人工分类有优先级。resolveConflict 让人选保留哪边、自定义或忽略；原文已变，旧裁决失效。 | 把长期事实、临时情境、承诺和讲法反馈分开。“这次简短”随本次结束，“以后都简短”修改长期风格，两者可以同时存在。只有同一主题、同一适用范围且真的互斥才进入待确认；默认保留现有已确认事实。 |
| H 在执行端与控制面之间维护镜像和待执行操作，执行后回报；源文件编辑和删除也要回写，避免下一次同步带回旧内容。被动健康采样不会通过真实检索制造一次使用记录。 | 个人 Brain 与后台已可直接通信，保留单一事实库。管理修改后由 Brain 回读，再在真实通话用到它时记下修订。看后台、打开条目、模拟召回均不增加使用次数。异步手机命令才需要区分已提交、设备执行、回读确认。 |

**把能做的操作放到条目旁边。** 第一屏分为“已确认、待核验、已失效”，支持按类别与关键词找条目。右侧显示当前值、来源、有效期与关联通话；手机点进去看同一份详情。对待核验条目提供「看原话、确认、改写、忽略」，没有原话但主人亲自录入时，标为“主人在后台确认”。对约定另设「已兑现」，免去手动删除；对推测偏好提供「以后别再推断这条」，与普通忘记区分。保留自然语言录入，同时给“长期规则、个人事实、带期限的约定”结构化表单，避免主人必须猜中口令句式。主人说过的偏好与小可作出的承诺，界面应分别标出说话者。

**更正、遗忘与审计。** 建议把长期事实的稳定 ID、修订和证据消息 ID 分开。记录的最小单位是某轮选入了哪个事实的哪个版本；引用可脱敏回看。显式忘记后，当前事实、普通对话注入、直接问答及后续重提取都要遵循同一失效标记。审计表不另存一份被忘记的正文。历史通话原文现在单独保留，按钮应把这一点说明白。诊断试问沿用现有隔离；需要预览主人记忆时，在本机做只读选择预览即可。

## 交付顺序与验收

1. **第一版就解决“为什么”。** 在现有记忆页用分组列表和侧栏，加上状态、来源、最近实际带入时间。通话详情按轮次反查。在私人 Brain 选取与组装真实提示词的位置记录少量事实 ID、修订与原因；同时修复无关事实填充和无关讲法样例失效，再加只读预览。用海浪故事、明问暗号、忘记后换房、临时试问四组对照验收。对外只称“带入了模型输入”；模型是否采纳不能从该记录得知。
2. **第二版让主人能够纠错。** 新增待确认的冲突、适用范围、失败抽取重试，以及成长每日快照。两条近似偏好做模糊更正时必须先澄清；过期页提交返回冲突并刷新；回放一条被忘记前的任务不能复活旧值。两台手机分别说“最近很高兴”和“这种讲法我喜欢”，只有能指向原回答的评价进入风格学习。无历史快照的日期显示无样本。
3. **第三版补齐配置与设备。** 选一个识别词，保留旧通话，新开一通，比较两个房间回读的修订，再用包含该词的真实语音测识别、打断和退出。搜索与设备联合验收用“北京今天 → 那明天呢 → 换上海呢”，核对目标、来源和手机呈现。小可的首段音频分别在快答、有搜索、插话三种场景测量；先有同机同网基线再判断优化。
4. **全程保持单人部署。** 延用现有 Brain、管理后台、SQLite 和手机上报。首版只改飞牛两项服务即可；需要新的热词消费者或安装进度时，再分别发布私人 Worker 或 APK。公司和 H 平台不参与私人通话的运行。
