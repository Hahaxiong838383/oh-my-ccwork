# 真实 RTC 中发现的反馈口令分段缺口

结论：同一合成 WAV、同一软件设备/独立 Brain/现役提供商配置下，旧 5b3 和新 de090 均进入倾听并连续讲述成功，但请求反馈时失败。两者 ASR 都交付三个 final：“小可”→“我讲完了”→“请说说你的看法”。没有反馈调用及 TTS 接通。这不是已证实的 TTS 连接失败，也不是本补丁新增；三套生产服务未改变。

现有 `listening_voice::parse` 要求反馈完整句落在一次输入中；Adapter 的 recent wake 只处理 Normal 状态下的进入倾听。Listening 状态下三个片段依次进入故事收集，不跨 final 组合为反馈。parser/adapter 与基线逐字节相同。

直接证据的 trace 与原始日志 SHA 见 RTC_FEEDBACK_SPLIT_FINDING.json。原始日志仅使用合成故事，保留在私有状态目录。测试初始超时与旧版 A/B 失败都保留，不能以后续控制消息测试覆盖。

后续对连接链路单独做正向验证：软件设备以现有 listening.feedback 控制合同申请一次反馈，验证真实 ASR/TTS/RTC 和三种退出、恢复普通聊天。该用例明确不代表“语音反馈口令已修好”，也不修改原失败用例。

待办：独立修复并测试倾听态的分段明确反馈口令，覆盖期限/模式切换/引用/否定/唱歌误触发及已有故事内容保留。不能只把任意故事尾句解释为控制命令。没有用户真人/安卓端复现证据时不扩大推断范围。
