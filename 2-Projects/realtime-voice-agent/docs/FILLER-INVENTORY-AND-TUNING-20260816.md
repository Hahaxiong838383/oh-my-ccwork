## 一、机制一页看懂

```
用户说完一轮话（turn 提交）
  → 按用户文本关键词选桶（§三优先级）
  → 概率门控：全局 0.9；greet/thanks 桶 0.5；打断后 5s 窗内必播(1.0)
  → 滑窗防重复：最近 3 条文案不选（排空则回退整桶随机）
  → 预解码 PCM 直接入播放轨（零合成延迟）—— 同轨串行，正文 TTS 跟在后面
  → 同时 LLM 已在流式生成，正文首句合成完即接上
  → 正文开头的承接词被流式剥掉（§五）——防止"嗯"完又"嗯"
```

关键性质：
- **filler 文本不进对话历史、不发字幕**（端上那 1–3 秒有声无字幕是设计）
- filler 与正文**同轨零间隔串行**——正文若没备好，filler 播完会出现**静音空窗**（见 §六-d）
- 实现：`rust-worker/src/filler.rs`（与 Python `engines/fillers.py` C1 v2 逐行对齐）

## 三、选桶逻辑（顺序即优先级，先命中先返回）

| 序 | 桶 | 触发条件 |
|---|---|---|
| 1 | `greet` | 文本 **≤10 字** 且含：你好 您好 哈喽 嗨 早上好 中午好 下午好 晚上好 在吗 在不在 早啊 早呀 |
| 2 | `thanks` | 文本 **≤10 字** 且含：谢谢 感谢 多谢 辛苦 谢啦 谢了 |
| 3 | `emo_neg` | 难过 伤心 想哭 哭了 委屈 郁闷 烦死 好烦 太烦 气死 生气 好累 累死 太累 害怕 焦虑 压力好大 不开心 心情不好 无聊 |
| 4 | `emo_pos` | 开心 高兴 兴奋 太棒 太好了 太好啦 好爽 哈哈 |
| 5 | `story`(强) | 跟你说 告诉你 你猜 |
| 6 | `task` | 讲个 讲一 讲讲 说个 说一 给我讲 给我说 给我来 给我放 帮我 来个 来一 唱个 唱首 唱一 背个 背一 背首 念个 念一 念首 推荐 介绍 教我 陪我 翻译 写个 写一 |
| 7 | `story` | 我今天 我昨天 我刚才 我上次 我们老师 我们班 我妈 我爸 我朋友 |
| 8 | `ask` | 怎么 为什么 什么 哪 几 多少 是不是 吗 呢 好不好 行不行 对不对 谁 难道 ? ？ |
| 9 | `opinion` | 我觉得 我认为 我感觉 |
| 10 | `gen` | 兜底 |

顺序是刻意的：greet/thanks 的 ≤10 字门槛让「你好我想问天气」落 ask；强叙述先于 task（「跟你说个事儿」含"说个"）；task 先于 ask（「给我讲个故事**好不好**」走 task）。

## 五、防结巴配套：正文开头承接词剥除（`llm.rs`）

承接音"嗯"过之后，LLM 回复开头再"嗯"就是结巴——所以正文流式剥掉这些开头：

| 类别 | 内容 |
|---|---|
| 词表 | 让我想一想 / 让我想想 / 我想想 / 这个嘛 / 好的 / 好嘞 / 好呀 / 好啊 |
| 单字 | 哈 唔 好 行 |
| 贪婪连跑 | 嗯 哦（"嗯嗯嗯"整段剥） |
| 随后标点 | ，。、…～!！?？ 一并吃掉 |

另有 system prompt 层禁令（`config.py`）："绝不要再用'好问题''让我想想''嗯''这个嘛'这类承接词或语气词开头"。**两层都跟随承接音开关**——承接音关掉时不剥（那时正文自己"嗯"一下反而自然）。

## 六、「生硬」的机制成因候选（按嫌疑排序，优化时对症）

| # | 嫌疑 | 机制 | 对应的改法 |
|---|---|---|---|
| **a** | **静音空窗**——filler 播完了，正文还没备好 | filler 均值 **1864ms**，而 LLM 首句+TTS 首包在慢轮可到 2.5s+：填空音播完→**突然安静→正文才来**，比不填还生硬。快轮反过来：正文早就绪，被 filler 拖着 | 最难也最值：①文案加长尾气口（"嗯——让我想想哈……"拖尾自然）②按 LLM 首包速度动态选长短条（要改逻辑）③投机命中轮跳过 filler（正文已就绪时 filler 纯属拖延） |
| **b** | **概率 0.9 过高** | 几乎每轮都有承接音 → 模式感、"套路化"，孩子听三轮就腻 | env 一行：`FILLER_PROBABILITY=0.5~0.6` 即时生效（stop/start），**成本最低先试这个** |
| **c** | **task 桶只有 3 条** | "给我讲个故事"是最高频句式，池最浅+滑窗 3 排空回退随机 → **最常用的场景重复感最强** | 补文案到 7–8 条（走 §七流程） |
| **d** | **文案「接得住」但「递不出」** | 现文案全是应答型（"嗯，我看看哈"），播完直接跳正题——中间缺一拍过渡。且正文开头的承接词又被剥掉，衔接点更秃 | 文案改造方向：尾部带**引导**（"嗯，我看看哈——这样……" / "哎，你说到这个——"），让尾音把正文"递"出来 |
| **e** | **打断轮必播悠闲文案** | 用户刚不耐烦地打断，5s 窗内 boost 必播——若抽中"哎，你说，我听着呢"这类慢悠悠的，火上浇油 | 打断轮单独一个短促桶（"嗯！" "好！"，<800ms），或打断轮降为 0.5 非必播 |
| **f** | **预合成韵律与正文不接** | filler 是一次性批量合成的固定语调；正文逐句实时合成，语速/情绪随上下文变——同音色也能听出"换了口气" | 重合成时给 filler 加讯飞语速/语调参数对齐正文常用值；或每条文案合成 2–3 个韵律变体随机选 |
| **g** | **误选桶** | 关键词法有误伤（如"你说什么"是反问却落 ask）| 文案往"桶间通用"靠（越具体越容易穿帮），或补关键词 |

## 七、优化操作路径（三条路，改哪层走哪条）

**① 只调参数（零合成，分钟级）**
`64.90:/root/rust-worker/rust-worker.env` 加/改 `FILLER_PROBABILITY=0.6` → `systemctl stop voice-worker-rust && sleep 3 && systemctl start voice-worker-rust`（禁 restart）。

**② 改文案/补条目（要重新合成）**
1. 改 `scripts/gen_fillers.py` 里的桶文案表（文案原则注释在文件头：语气词承载情绪、只承接不给立场、别全用"好/行"开头）
2. 在 64.90 上跑（讯飞凭据在服务器 env，不出机）：脚本已支持 xfyun provider（聆小璇）
3. 产物落 `/opt/voice-agent/fillers-colleague/`（**线上真源目录**；⚠️ 脚本默认输出仓内 `assets/fillers`，跑前确认输出路径指到 colleague 目录，别把火山版目录覆盖了）
4. worker 重启加载（启动日志锚：`filler bank loaded: N clips`）
5. 改完同步给 codex 一份新 `fillers.tsv`（他端侧可能复刻）

**③ 改选桶/播放逻辑（要发版）**
`rust-worker/src/filler.rs`（选桶/概率/滑窗）或 `pipeline.rs`（播放时序）→ 走正常构建部署（GHA → 64.90 直拉 → 灰度探针 → stop/start）。
