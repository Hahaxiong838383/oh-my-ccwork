# GEO 文章发布质量管控研究报告

> 主题:发布 GEO 文章时被平台审核为"不符合创作规范"如何处理
> 研究方法:调研 GitHub 上主流 GEO/SEO 内容生成开源项目的处理方案
> 调研时间:2026-09-02

---

## 一、核心结论

**主流开源 GEO 项目没有一个是靠"写完硬发、被拒再申诉"来解决问题的。**

它们几乎一致的做法是:**在发布前设置多层质量关卡 —— 先过合规红线,再过质量打分,全部通过才放行。** 把"被平台/搜索引擎判为低质"当成一个**可以在发布前用规则拦截的事件**,而不是事后烂摊子。

三个最具代表性的实现,各代表一种范式:

| 项目 | 范式 | 特点 |
|------|------|------|
| sinianchu9/laozhou-site-update | **多层流水线** | 法规→标准→创作→验收→发布,最系统最全 |
| weipanux/seo-geo-blog-writer | **自动评分门槛** | 打分+自动修复循环,及格(≥80)才放行 |
| liangdabiao/GEO-Content-Optimizer-Skill | **AI味专项检测** | 营销空话词表屏蔽 + 可读性评分 |

## 二、项目一:laozhou-site-update(最系统,层级流水线)

**仓库:** https://github.com/sinianchu9/laozhou-site-update
**项目描述:** "AI content generation skill system for SEO/GEO optimized site — 5-layer architecture: compliance, standards, persona, creation, verification"

它的 **创作流程 = 过法规(14)→ 达标准(13)→ 创作 → 验收(09)→ 发布**,含 14 个 references 文档。

### 2.1 法规层(合规硬性红线,命中即不可发布)

以下任一命中 = 内容**不可发布**,不讨论权重:

- 标题与内容不符(标题党)
- 关键信息缺失(读者看完仍不知道怎么做)
- 信息过时且未标注(已失效的价格/政策/功能)
- 有采集痕迹(大段复制竞品内容)
- 风险故意隐瞒(只说好处不说坑)
- AI 味模板结构(连续多篇结构一模一样)
- 信息增量为零(纯同义词替换/段落重组)
- **语义相似度超过 30%**(与采集源高度重复)

### 2.2 反作弊三道防线(防全站被判"批量生成")

| 防线 | 规则 |
|------|------|
| 规模化内容滥用 | 同一意图不拆多页;**日新增≤3篇, 周≤15篇**, 模拟自然增长;**连续3篇相同 section 结构必须打破** |
| 声誉滥用 | 新主题与站点已有主题语义重叠度 **≥40%** 才可写;YMYL(金融/安全/法律)需作者署名+来源+风险声明齐备 |
| 过期域名黑帽 | 不买过期域名跳转、不藏文字、不做 doorpage、不堆关键词(实验中堆词反而-10%) |

### 2.3 质量层(A-E 五维度 25 项指标带评分)

| 维度 | 权重 | 检查项 |
|------|------|--------|
| A 信息实质 | 30% | 理解覆盖、深度vs表面、原创增量、判断明确、关联前置、信息增益(语义广度/视角换/受众细分/数据合成) |
| B 数据引用 | 25% | 具体数字、来源标注、密度(长文≥3个可验证来源)、直接引用、新鲜度、格式 |
| C 可提取性 | 20% | 核心结论词首、H层级、可独立引用段落(30-60)词)、表格清单、视觉中断点 |
| D 信任信号 | 15% | 作者署名、作者Person实体+sameAs、资质、局限性、更新日期、来源归属 |
| E 体验质量 | 10% | 排版可读、图文相关、移动适配、性能、无干扰弹窗 |

### 2.4 验收层:50 项发布前检查清单

覆盖法规/信息增益/质量/数据/提取/信任/SEO/CWV/风格/**Anti-AI 味**,清单要点如:
- 模板感:读者会不会一眼看出"按模板填写"?
- 节奏:句子长短是否有变化,会不会短一样?
- 口语感:有没有自然的表达?
- 通用感:有没有一句话放在任何网站都能用?改了更具体
- 经验感:有没有至少一处第一手经验描述?

### 2.5 去重执行路径(核心迭代)

根据 Google 信息增益专利 + Helpful Content 思想,二次创作必须 `分析→解构→扩展` 而不是 `阅读→改写`:
1. **叙事逆向工程** — 原文从理论推到案例,改写从极端案例反推理论
2. **升降维** — 过度句提取原理/细化,彻底改变向量位置
3. **核心事实隔离** — 数据/时间/政策配入表格,分析文本全重写
4. **结构重建** — 不保留原段顺序,按搜索意图重组

## 三、项目二:seo-geo-blog-writer(自动评分门槛)

** 仓库:** https://github.com/weipanux/seo-geo-blog-writer
** 范式:** 跑分不讨好就自动修,及格才放行。

四阶段工作流:**Research → Outline → Draft(E-E-A-T) → Optimize(自动验证)**

### 3.1 评分逻辑(validate_structure.py)

对文章打 0-100 分,12 项硬检查:

| # | 检查项 | 目标 |
|---|--------|------|
| 1 | 标题长度 | 50-60 字符 |
| 2 | H2 数量 | 4-8 个 |
| 3 | 字数 | 1500-3000 |
| 4 | FAQ | ≥4 个问题 |
| 5 | 内链 | 3-5 个 |
| 6 | 外链 | 2-4 个 |
| 7 | 图片 | ≥5 张 |
| 8 | 作者署名 bio | 必须存在 |
| 9 | 目录(TOC) | 长文(>1500 词)需有 |
| 10 | Schema 校验 | JSON-LD 合法有效 |
| 11 | Meta 描述 | 145-155 字符 |
| 12 | 可读性 | Flesch 60-70 |

### 3.2 自动修复循环(iterative_validation.py)

`AutoFixer` 类会**自动补齐不合格项**, 循环迭代直到 `score >= 80` 或达最大次数, 才放行：
- 没 FAQ → 自动把 H2 标题转成问题生成 FAQ 段
- 没作者 bio → 自动补作者简介模板
- 补内链、修 Schema、加 Meta 描述 等

** 这一点很关键:它把"质量门槛"变成了可执行的脚本 + 自动修复,不是靠人肉一条条审。**

## 四、项目三:GEO-Content-Optimizer-Skill(去营销味)

** 仓库:** https://github.com/liangdabiao/GEO-Content-Optimizer-Skill

### 4.1 可读性评分(readability_checker.py)

核心是**扫描中文营销空话词表**,这是 AI 搜索眼中明显的低质信号:

** 禁用词:** 创新、领先、独特、一站式、极致、颠覆、最佳、最顶级、唯一维懂、标杆、龙头...

** 检查项:**
- 平均句长(理想 15-25 字,>35 分提醒)
- 是否有直接问句(它建议加 1-2 个如"如何...?""...有什么区别?"必)
- 是否有具体数字(≥3个最高分)

评分高/中/低三档,不合格给出具体改进建议:
- "营销词替换为具体事实: 创新、领先..."
- "拆分长句 (当前均长 X 字, 建议 15-25 字)"
- "加入具体数据 (百分比、金额、案例数量等)"

### 4.2 E-E-A-T 四支柱(写文章底线)

| 支柱 | 作用 | 落地 |
|------|------|------|
| Experience 经验 | 第一手经验 | 多用 "我实测过/我踩过坑" + 具体数字日期,禁编造 |
| Expertise 专业 | 深度与资质 | 作者 bio 写清从业年限、认证、专业领域 |
| Authoritativeness 权威 | 被认可 | 持续在领域内专注,不跨界 |
| Trustworthiness 可信 | 透明可验证 | 作者署名+来源标注+局限性声明 |

** 特别强调:**"AI 引擎对 '知乎'/本站编辑 这类无主内容降权" → 发布前先跑 readability_checker。

## 五、跨项目共通:平台判"低质/规范不合"的信号清单

汇总以上项目规范化,平台主要在扫描这些信号:

### 5.1 结构 & AI 模板感
- [ ] 连续多篇文章 section 标题模式雷同
- [ ] 开头方式每篇一样
- [ ] 句子/段落长短无变化,像填空
- [ ] 有"首先/其次/最后""我们需要/你必须"等模板腔

### 5.2 内容实质
- [ ] 读完仍不知道"到底选哪个/怎么做"(无判断)
- [ ] 全文章公开信息的排列组合,**零增量信息**
- [ ] 语义相似度过高(>30%同一来源高度重复)
- [ ] 与竞品相比无独有内容/实测/案例

### 5.3 营销空话
- [ ] 出现创新/领先/卓越/一站式/极致/颠覆/最佳等空洞词

### 5.4 权威 & 信誉
- [ ] 无作者署名/知乎空泛作者
- [ ] 无作者资质/局限声明
- [ ] 无更新日期、无来源标注

### 5.5 数据 & 引用
- [ ] 全文假设断言无来源
- [ ] 无任何具体数字支撑
- [ ] 数据过时未标注

### 5.6 高规模化
- [ ] 同意图拆多篇
- [ ] 高频批量发布(日均 >3 篇 / 周 >15 篇)
- [ ] 短期多篇结构相同

## 六、给你的实操清单(4 层检查)

无论你的 GEO 栏目发在哪个平台,发布前建议套这套:

**第一层:别被当临凑的**
✅ 有真实作者署名+简介 ✅ 至少保留一个具体数据 ✅ 有竞品/他人没有的增量信息

**第二层:别被当 AI 模板**
✅ 每篇开头方式不同 ✅ 句子长短有变化 ✅ 有态度句 / "我踩过坑"经验 ✅ 不用营销词

**第三层:别被当搬运**
✅ 和源素材语义深度重构 ✅ 围绕搜索意图重组结构 ✅ 事实数据入表格+标注来源 ✅ 相似度 <30%

**第四层:别被当批量群发**
✅ 同意图不拆多篇 ✅ 控制日期频率 ✅ 连续几篇不用同一标题结构
