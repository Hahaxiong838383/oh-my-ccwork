## 5. 经验沉淀（写到 memory 的核心范式）

### ★★ 真理原则

1. **信事实不信状态** — `feedback_sidecar_self_heal_pattern.md` + `feedback_async_polling_watch_fact_not_exit.md`
   - 状态 API 不假设流程完美执行
   - 子进程 exit code 不一定反映业务结果
   - 用真实可观测事实 (文件存在 / 文件大小 / token 落地 / HTTP 200) 做判定

2. **零侵入 LLM-driven 集成范式** — `feedback_multica_llm_skill_integration_pattern.md`
   - 闭源 daemon 不让 hook → 用 skill 教 LLM 调外部 sidecar
   - issue.metadata 是天然 task-level 上下文注入点
   - sidecar HTTP API + bash wrapper 是与 LLM 安全交互的最佳接口

3. **HOME 目录隔离** — `feedback_lark_cli_home_isolation.md`
   - 当工具硬约束阻碍多租户时 (unique app-id),用 OS 级隔离 (HOME / XDG / chroot) 绕过
   - 不要跟工具的安全模型对抗,用更底层的隔离层 cover

### ★ 操作教训

4. **codex 派单契约** — `feedback_codex_sandbox_no_network.md`
   - prompt 必明示"依赖你只写 import 不实现,失败就报错出来不要 silent 用 shim"
   - review 必查 go.mod / package.json 是否有 replace / file: 引用

5. **launchd plist 占位符** — `feedback_launchd_plist_user_home_placeholder.md`
   - plist 不展开 $HOME / ~,必须绝对路径
   - 用 `__USER_HOME__` 占位符 + deploy ssh $HOME 替换,避免 cross-machine 硬编码

6. **macOS keychain-downgrade** — `feedback_keychain_downgrade_workflow.md`
   - 任何 daemon/automation 跑前必须本机 Terminal 一次 keychain-downgrade
   - SSH/sandbox 自己跑会失败 by design

## 9. 我没解决的（留给未来）

1. **04 V3 lock_dir 不死锁的保证** — 当前 30s timeout 拿不到锁会报错，但 lock_dir 残留要靠 cleanup trap。如果 sidecar 进程被 kill -9 残留 lock_dir → 下次启动卡 30s 才释放。建议加启动时清理 stale lock。
2. **token refresh 自动通知** — token 7 天 refresh，过期会触发 user 重新扫码，但目前**不主动通知**。需加 cron 检测距 refreshExpiresAt < 24h 的 user 自动发飞书提醒。
3. **多 user 高并发授权竞态** — 当前 mkdir lock 足够 10 人，但 50+ 需要 sharded lock（per-user lock dir）。
4. **sidecar 容器化** — 当前 launchd 跑裸 binary，docker 化后跟 multica 部署同构。
