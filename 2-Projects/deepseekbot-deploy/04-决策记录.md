### 现象与根因

用户要求 Mac mini 运行 DeepSeekBot，并从公网浏览器使用。附件研究涉及同名项目，必须先确定为 BotHarness/DeepSeekBot；Mini 本机服务不能直接解决公网 HTTPS 与持久运行问题。

### 候选方案与决策

| 方案 | 优点 | 约束或风险 |
|---|---|---|
| 现有 cli4 HTTPS 子路径 + 受限 SSH 反向隧道 | 复用证书、域名和服务器，固定入口可立即交付 | 需验证路径重写、Cookie、WebSocket |
| 新建 deepseekbot 独立域名 | 域名清楚，路径配置简单 | 当时可用 Cloudflare 凭据无目标 Zone 管理权限 |
| 临时公网隧道 | 开通快 | 地址不适合作为长期日常入口 |

选择现有 `/deepseekbot/` 子路径；Mini/HK 两端只监听回环地址，保留 DSH 原生认证。独立项目依赖、DSH_HOME、workspace 与两个 LaunchAgent，复用现有 Node，不迁移其他服务。未选独立域名是权限条件不满足；临时地址不作为最终交付。

### 改动与验证

项目启动脚本和 LaunchAgent 已归档，部署真值与回滚见 [README](README.md)。线上 Nginx 仅新增本任务 location；反向隧道账号只允许指定回环端口。保留原站 Basic Auth；本路径使用 DSH 启动令牌换签名 Cookie，支持 WebSocket。

未认证首页/API 为 401；私密启动链接授权后 200；认证 WebSocket 101；Cookie 为 HttpOnly/Secure 且限定子路径。进程重启后旧有效 Cookie、Bot、模型目录和历史消息均保留。详细证据见 [验收记录](ACCEPTANCE.md)。

### 什么条件下该翻这个决策

- 获得目标 Zone 权限且用户需要独立域名时，再迁移并重新验证 Cookie 与 WebSocket。
- 多人使用、需要更强隔离或登录前自启时，重新设计权限边界及运行方式；当前用户级 LaunchAgent 与 workspace-write 不等于独立虚拟机。
- DSH/插件升级时先验证配置兼容性；当前固定 DSH 0.2.1-rc.2、Bot 1.4.0，不直接跟随最新版。

### 现象、排查与根因

用户打开日常网址，收到 `dsh web authentication required; reopen the URL printed by dsh web`。服务与认证链路已通，但首次登录文件只交付在 Studio，实际使用的 Air 浏览器没有签名 Cookie；干净网址本身不携带授权能力。

### 候选方案与决策

| 方案 | 结果与风险 |
|---|---|
| 将私密首次入口交付到 Air，再收藏干净网址 | 保留认证，用户可直接完成首次授权；采用 |
| 在公开入口嵌入启动令牌 | 泄露访问能力；放弃 |
| 关闭认证或改动 API Key | 前者暴露服务，后者不能解决浏览器 Cookie 缺失；放弃 |

Air 新增权限 0600 的 `~/Documents/DeepSeekBot/首次登录.webloc`，系统 open 打开。维护脚本增加 `--air` 同步，启动令牌仅在进程内读取和私有文件保存，不进入 Git 或终端输出。Host 重启后需重新生成新浏览器的首次入口，已有有效 Cookie 可继续使用。

### 验证与用户反馈

Air 独立 HTTP 检查：私密链接换 Cookie 后 200，携 Cookie 打开日常网址 200，测试 Cookie 清理。未读取用户浏览器 Cookie。修正后用户回复“OK”，要求总结经验、更新记忆、commit + push；不补造未知的反馈时分。

### 什么条件下该翻这个决策

如果需要多用户分权或无需私密链接的常规登录，评估独立身份认证；如果已授权浏览器仍出现 401，进一步检查 Cookie 过期、域名/Path、签名记录与代理，不一概归因于未首登。

### 可复用经验

1. 公网地址可达、首次授权入口可用、真实模型回复是不同验收层次；必须把首次入口送到用户实际设备，并说明新浏览器的登录方式。
2. 凭据按用户指定文件取用：RTF 在 Air 转文本，SSH stdin 写 Mini 原生凭据，保留已有 browser-session 记录、权限 0600；不回显 Key、不把源文件或私密 URL 纳入代码仓。
3. Air 的旧 DHCP 地址和 SSH 用户大小写可能失效；mDNS 发现当前地址后，用已有可信主机密钥严格验证。单次发现的地址不固化成长期真值。
4. 模型目录有 Flash/Pro 不代表实际调用成功。本次另验了真实消息 handled 和完整回复；应用 usage 原值不等于官方账单，不能直接折算费用。
5. 浏览器超时先对照代理和直连。首次弹窗、隐藏同名元素与等待不足属于自动化定位问题，应与服务错误分开记录；会话摘要可见不冒充全部工具或多 Bot 流程通过。
6. 本次仅验证进程重启与手机尺寸首屏；整机断电重启、完整手机聊天、工具执行、派工与 IM 接入未验。关闭额外遥测不代表模型请求不发送上下文。
7. 主仓有其他任务改动且 main 与远端分叉时，从最新 origin/main 建独立工作区，只提交本任务文件。共享 `0-System` 是仓外符号链接，须单独备份，不能把代码 push 当成共享记忆已上传。

## 2026-10-19 · 密码入口复用 DSH 原生 Cookie

用户希望通过 Air 指定 RTF 设置密码并记住登录。DSH 当前包只有启动 token 换原生签名 Cookie；在 Mini 增加独立回环密码网关，服务端验证 scrypt 后代换原生 Cookie，保留 API/WS 鉴权与签名持久化。比修改 DSH 认证源码更易回滚，升级依赖时仍需验证 token 输出格式和 Cookie 协议。真实 WebKit 验证 30 天属性及浏览器重开通过；浏览器密码管理器保存由用户确认。

排障经验：no-referrer 可能令浏览器表单 POST 的 Origin 变成 null；只用 curl 带 Origin 会遗漏此问题。密码页设置 same-origin meta/Header 后，保留严格 Origin 校验，真实浏览器通过。记录：[密码登录验收与回滚](PASSWORD-LOGIN-20261019.md)。

## 2026-10-19 · Mesh 直达与服务出站直连

Mini 已在 chuan-mesh，先查现网而非重复安装。保留公网备用，新增只绑定固定 mesh IP 的密码网关；外部 Host/Origin 严格校验后，才转换为 DSH 原有 authority，复用原生鉴权，避免修改运行中的 Host 或签名密钥。模型/API 出站直连与网页入站反向代理是不同链路，前者通过实际 socket、环境和 DSH 代理模块核验。

只验证首页200会漏掉 HTTP 私网地址不提供 crypto.randomUUID 的前端崩溃。真实浏览器定位后，仅在 mesh 页面注入基于 getRandomValues 的 UUIDv4 兼容脚本；公网 HTML 不注入，不使用 Math.random，也不假装已有 HTTPS 安全上下文。密码管理器、麦克风与剪贴板等仍有浏览器限制。详见 [直连与 Mesh 实测](MESH-DIRECT-20261019.md)。
