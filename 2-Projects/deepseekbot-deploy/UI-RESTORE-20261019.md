# Bot 聊天界面恢复记录

2026-10-19，codex（OpenAI）。

## 用户反馈与根因

用户看到的是 Harness 执行会话，左侧工作区只投影有执行会话的 Bot；这不是完整 Bot 名单。13 个迁入 Bot、原有 2 个 Bot、2 个群都在原生数据库里。

浏览器复现了 @botharness/ui 1.4.0 的另一处问题：新工作台首次默认打开 Home，消息面板隐藏；点击频道会更新选中状态和数据，但没有展开消息面板，因此中央继续显示 Home。手动点击控制列「消息」后，同一条真实回复立即可见。上轮仅核对名单、没有通过频道展开验收，不能据此宣称完整 UI 已恢复。

## 修复方式

`ops/patch-classic-ui.py` 只接受已核对 SHA256 的 1.4.0 前端文件，启用包内已有的经典组件：

- 保留 Harness 品牌导航与可滚动的完整消息列表。
- 使用原生聊天气泡、输入框和 ChannelSidebar，避免新 Dock Home 遮挡消息。
- 群右侧复用原生分栏组件，同时显示成员与会话；私聊保留记忆、会话等切换。
- Bot 名称允许换行，避免长名称被省略。
- 空 hash 的日常入口默认进入幕僚长 DM；已有明确 Bot 深链接仍优先。
- `refresh-access.py` 生成的私有首次登录链接也附带原生 Bot DM 定位 hash。

这是本实例的兼容补丁，不是上游发布，也不是整体降级。保留 1.4.0 后端、数据、权限与认证；插件升级可能覆盖补丁，不能未经核对自动重打。

## 应用与回滚

Mini 上：

```bash
python3 ~/local/deepseekbot/patch-classic-ui.py \
  ~/local/deepseekbot/data/profiles/deepseekbot/node_modules/@botharness/ui/lib/client.js
```

原件保存在目标真实目录的 `client.js.mycc-original-1.4.0`（0600）。回滚同一命令增加 `--restore`。修改后仅重启 `com.mycc.deepseekbot`，不重启其他服务，随后在 Studio 运行 `ops/refresh-access.py --air` 刷新私有首次登录文件。

## 验收

验收脚本 `ops/verify-ui.cjs` 不发送新消息，不输出 URL、Cookie 或响应正文。截图与回执在忽略的 `output/ui/`；预览通过 Playwright 路由替换，生产验收不带路由替换。

预期覆盖：日常地址自动进入 Bot 模式、15 个 Bot 逐一切换、2 个群的 3/6 名成员及会话栏、真实幕僚长历史回复可见、日常链接重开与刷新、1280/2048 宽度输入框完整。

## 仍然存在的还原边界

官网截图是示例团队及对话效果，不是用户 Grok 备份的数据。原备份缺少聊天数据库、原长期记忆和部分完整配置，群历史为空属源资料缺失；没有伪造示例对话、审批任务或成员。业务凭据、登录态、macOS 依赖与禁用的 3 条定时计划仍按迁移记录处理。
