## 根因与经验

1. **衔接太密不是一个 env 数字的问题。** 语义桶、boost强制概率和ordered最短选句各有分支；零概率及重复窗口必须覆盖整个策略。
2. **小池最能暴露重复错误。** 去重回退比较最近一次使用，不比较首次出现；二条池长于窗口的序列能抓住A→B→A→A。
3. **体验策略应在会话签发时携带。** 主Brain知道真实账号与风格，候选不复制生产人格库；热路径无配置网络请求。可选字段独立解析，坏值不能破坏旧metadata或阻断入房。
4. **知识召回与全局规则需一起核对。** 只加金币条目，基础prompt仍一概让孩子问父母，无法稳定修复。正式产品定义、实际资产和模型回答三层对账。
5. **内容旁路不能抢控制命令。** 取消/换查优先使用已有classifier；天文与别的游戏负例要在Worker和Brain对齐。
6. **相同仓库不代表相同上线基线。** 普通R18与灰度R26分别测试和构建，禁止为一个小修复把候选其他改动带到全部设备。
7. **UI要真的可操作。** 异步加载后组件的aria-disabled曾残留，换原生数字输入并验证0/100、失败反馈；不靠强制点击通过测试。
8. **运输成功、CI成功和上线成功各有证据。** SSH断续后通过可信中转及分片/整包SHA恢复；备用CI两次失败保留，临时workflow变更撤回，部署使用原已测Ubuntu24.04产物。稀疏检出需包含Rust外部合同fixture。
9. **回滚保新数据。** 留SQLite一致性快照，但只恢复触及源码/二进制/配置键，不整库回灌或整env覆盖。新配置键回退先核无人后改。
10. **下一步倾听是独立能力。** 降低衔接音只改善普通聊天密度，无法禁止完整LLM回复、后台结果或端侧自发音频；另设计模式状态和全出口许可。
