# v375实施经验

- 合同必须对固定客户端Git对象取证；交接摘要中的“先单开tiering看桶”与实际双开关代码不符。
- 按需采样与即时HTTP是两回事；v375仍日批，短期授权窗口必须覆盖日批和重试。
- 客户端inflight无年龄退出上限；payload TTL不能带走seen和额度账本。
- 独立审查抓到未闭合周期被收下、占用稳定ID的问题；校验服务端接收时刻，拒收不占ID，闭合后最终内容才首次接受。
- 聚合与诊断独立payload表，可保留Ark有界raw扫描及资产语义，不用聚合count推余额。
- gzip异步与两槽限制仍需真实HTTP/SQLite writer验收；最终ACK之后才算持久化成功。
- 当前部署可能比Git新；先固化17个BLE/微信现役差异，精确SHA包不能替代上线前现查。annotated tag要核peel后的commit。
- 回滚先显式false、保留新信封兼容；若退旧接收端，先JSON503暂停上传保队列，不能用400/415/未知事件让历史积压死信。
- 主实现、独立审查和唯一发布者职责分开；阶段测试、完整业务复核、真机、7天效果分别记录，不能用包SHA通过冒充业务通过。
