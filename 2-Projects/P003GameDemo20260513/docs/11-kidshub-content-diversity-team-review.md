## 产品背景
儿童读写台「小可」语音 AI 陪伴产品（6-13 岁）。世界观：方舟飞船，孩子白天专注=充能，合盖后方舟夜航离线收集，带回宝箱/资源建设生态缸。
小可有 8 张场景卡（登舰破冰/夜航呼唤/回归承接/记忆复现/KidsHub情绪回应/关机预告/坐姿吐槽/设备查询）。
KidsHub-AI 是给产品经理 + 工程师的 prompt 调试工作台：选一张卡 → LLM（gemini-2.5-flash-lite via 代理，温度已调 1.0）基于该卡 scene prompt 实时生成小可的开场白。

## 川哥（产品负责人）提的问题
夜航呼唤卡连点 3 次，开场白措辞每次不同，但内容**永远在讲「小鱼长尾巴/新花纹」**：
1. 「朵朵指挥官，你回来啦！方舟刚才 10 小时航行带回 30 颗星尘，快去看生态缸吧，小鱼长出新花纹呢！」
2. 「朵朵指挥官，昨晚方舟航行 10 小时，带回 30 颗闪亮星尘！生态缸里小鱼有新变化，长出漂亮花纹！」
3. 「朵朵指挥官，方舟刚结束 10 小时夜航，收集 30 颗星尘。生态缸里小鱼身上长出漂亮新花纹！」

川哥原话：「比如夜航呼唤，为什么每次都讲小鱼长尾巴的事？全局排查一下优化。」

## 关键机制（为什么会这样）

### 全局 prompt 的【真实性铁律】（强约束，来自产品定义，不可破）
> 涉及收益、进度、变化、承诺时，只能引用【当前状态】device_state，状态里没有的数字和变化绝不编造。查不到就说「小可还查不到呢」。
> 记忆只能用【已确认记忆】confirmed_memories。

这是儿童产品红线：留存钩子全靠「昨天说的今天对得上」，幻觉=信用事故。绝不能为了多样性让小可编造不存在的收益/变化。

### device_state mock（当前唯一事实源，前端 variables.ts）

## gemini（产品/UX 视角）
你好老板。作为资深产品经理和 UX 设计师，我理解目前的痛点：**LLM 的“好文笔”被“穷事实”给困住了**。

为了在 KidsHub-AI 工作台中展现“小可”的生命力，同时死守“真实性铁律”，我给出以下三方面的落地优化方案：

### 1. Mock 数据设计：构建“事实原子池”

目前的 `device_state` 是单点事实，我们需要将其扩展为**事实原子池**。每个字段不应该只有一个 String，而是一个包含多个“可选事实”的 Array。

以下是符合 6-13 岁受众、贴合方舟世界观的 mock 示例：

```typescript
// apps/web/src/kidshub/prompts/variables.ts 建议修改方向

export const FACT_POOLS = {
  // 生态缸变化：侧重视觉细节、生命感
  ecosystem_variants: [
    "发光水草悄悄开了三朵蓝色的花，在水里一闪一闪的",
    "小鱼身上长出了淡紫色的新花纹，像极了星云",
    "生态缸的底部多了一块像红宝石一样的矿石",
    "透明水母学会了跟着方舟的动力节奏跳舞",
    "珊瑚城堡的顶端多了一个发光的哨塔"
  ],
  
  // 夜航奇遇/收益：侧重资源感、神秘感
  voyage_discoveries: [
    { hours: 10, stardust: 35, loot: "一罐稀有的极光气体" },

  ],
```

### 2. 机制选择：前端“随机原子注入” (Atomic Injection)

**我的建议：方案 B（前端每次点击随机抽取事实子集注入）最符合 PM 调试体验。**

*   **理由**：
    1.  **防“话痨”**：如果把 10 条事实全塞给 LLM，它为了体现“聪明”会把所有事一次性说完，导致话术冗长且下次没话讲。
    2.  **受控感**：单次注入 1 条事实，能最清晰地验证 LLM 对该事实的转化能力。
    3.  **真实模拟**：在真实设备上，传感器/后端在某一时刻也只会推回一条确定的状态更新。Demo 模拟“点击一次 = 模拟时间流转到下一个随机状态”最直观。

*   **工程逻辑**：
    在 `compose.ts` 组装前，增加一个 `getDynamicState()` 函数，从上述池子里随机 pick 一个元素塞入 `device_state` 发给 server。

### 3. 工作台交互：增加“变量透明度”与“时轴感”

要让 PM 一眼看懂多样性来自事实，而非 AI 瞎编，UI 需要做以下增强：

1.  **“当前事实真相”面板（Reality Snippet）**：
    在对话框上方或 LLM 输出结果的旁边，高亮显示本次生成**真正参考的那条事实原文**。
    *   *UI 提示*：“小可本次参考的事实：`{生态缸：发光水草开了蓝色的花}`”
    *   *心理暗示*：让 PM 看到 AI 是如何把这句干巴巴的 JSON 变成暖心的话术。

2.  **“变量随机/锁定”切换器**：
    在右侧变量面板，给每个字段加个“🎲 随机生成”的小图标。
    *   当 PM 连点“夜航呼唤”卡时，这个图标闪烁，表示事实已更新。

3.  **“验证铁律”红色标记**：
    如果 LLM 输出了事实池之外的关键词（比如池子里没说“螃蟹”，它说了“螃蟹”），工作台通过关键词对比（或简单的语义 check）在后台给出一个“疑似幻觉”警告，方便 PM 压制 Prompt 里的发散度。

### 总结建议
我们要给 LLM 提供一个**“富饶的真相池”**，并在 Demo 中模拟**“时间碎片化的注入”**。这样既能展示小可“见人说人话”的灵动，又能守住“不骗孩子”的底线。

## grok（第一性原理视角）
**1. 本质拆解（信息论 + 认知角度）**

“像录音、像提前录好的”的本质是：**生成过程的条件熵接近于零**。

小可的每一次输出，本质是 LLM 在一个被强约束的条件分布上采样：
P(utterance | global_prompt + scene_prompt + device_state + confirmed_memories + iron_law + temperature)

当前 device_state 对夜航呼唤/回归承接/关机预告来说，只注入了一个标量事实（“小鱼长出了新花纹”或“明日预告：小鱼长尾巴”）。这个事实就是条件分布里**唯一高权重的语义锚点**。温度只能在表层（句式、语气词、词序、长度）增加方差，无法在语义 payload 层增加方差。听者大脑会自动把“内容母题完全一致 + 表面形式小扰动”归类为“脚本在换着法子背”，因为这正是录音/提前写好台词的统计特征。

“鲜活、像真人临场”的本质是：**说话者拥有独立于“要报告的事实”之外的生成自由度**。

真人说话时，输出分布的熵来自多个正交源：
- 世界状态（device_state）
- 说话者内部状态（注意力焦点、上次怎么说的、今天想强调哪一面、情绪微调）
- 听者模型 + 交互历史
- 可合法应用在同一事实上的不同“话语行为”（speech act）：现象报告、归因、邀请行动、情感共振、前景化后果、轻连其他已知元素等。

当内部状态 + 话语行为选择器有独立熵时，即使世界只给了一个 delta，说话者也能把同一个原子事实映射到不同认知/情感槽位，孩子听起来就像“它今天刚想到这件事的这个侧面”。这不是表面多样，而是**生成模型里有结构**。

当前小可的角色定义是“忠实事实转述者 + 世界观朗读者”，内部几乎没有可独立采样的维度，所以无论温度调多高，都会像录音。

**2. 多样性的根本来源**

内容多样性的根本来源是**输入联合分布的熵**，具体是：
世界状态熵 + 说话者策略/内部状态熵 + 选择算子熵。

“堆更多 mock 数据”是典型的治标（甚至是反治本）：
- 它把 demo 里的固定包从“1 个 delta”变成“预先写死的 N 个 delta”。LLM 学到的是“这 N 个就是全部合法内容”，仍会在每次生成时优先挑最匹配当前 scene goal 的那一个或几个，产生新的“轮换背诵感”。
- 真实产品上线后，某天世界真的只有 1 条已锁定变化（这是常态，不是异常），堆的那些“备用事实”不存在，强行用就直接违反真实性铁律，制造幻觉信用事故。
- 即使在 demo 里，它展示的是“假的丰富世界”，而不是“对同一个贫信息世界依然能多角度活说的能力”。PM 连点三次后，很快会觉得“它在切换不同剧本”，而不是“它今天有不同感受”。

治本必须做到：**即使事实输入熵为 1（真实单一状态），输出语义仍有多条不造假的路径**。这要求把多样性来源从“事实集合的基数”转移到“对事实的生成性使用策略”上。

**3. 真实上线后的难题 + 必须同时满足两者的机制设计**

真实难题的核心是：**真实世界会经常出现“合法事实只有 1 条”的日子**。任何靠“多准备几条假事实来切换”的方案，在那一天就会被迫编造 = 直接撞真实性铁律（儿童产品最不能撞的红线）。

好的机制必须同时满足：
- 铁律零破：LLM 永远只能引用当前注入的 device_state + confirmed_memories，查不到就认怂。
- Demo 能展示鲜活不重复：即使 mock 永远只有那一条小鱼花纹/恐龙，也能连点 N 次听起来像不同的人在不同时刻说。
- 真实产品同一条机制自然成立：当天只有一条真实变化时，依然能用不同方式说，且明天孩子回来对得上账。

**正确机制设计（表达层与事实层严格解耦）**：

把小可的角色从“事实播报器”升级为“用已知事实做不同话语行为的伙伴”。话语行为（framing operator）是封闭集合、事实无关、可正交采样。

对“生态缸变化：小鱼长出了新花纹”这类单一事实，合法 operator 可以是（示例，非穷举，从产品定义 goal/must 提炼）：
- 归因式（这是你充能换来的）
- 现象+邀请式（看，它多漂亮，来一起看）
- 生态意义式（我们的家又多了一点活气）
- 前瞻钩子式（这说明它在往更好方向长）
- 情感共振式（哇，我们一起守着它变）
- 轻连记忆式（像你喜欢的恐龙皮肤一样神奇呢）——仅当 confirmed_memories 存在且自然

每次生成时，系统必须注入一个**本次 framing 选择器**（新变量或动态 addendum 片段）。这个选择器不声称任何新世界事实，只声称“我这次决定用这个角度呈现已知事实”。

- Demo 模式：变量注入面板增加“表达角度 / framing”可编辑区 + “换一个角度”按钮。PM 点生成前系统自动换一个不同 operator（可记录本次用过哪些）。
- 真实运行：轻量 last-used 追踪 + 规则（避免连续同 operator）+ 真实可观测上下文（专注时长、时间、一天里小可的“种子”）来决定本次用哪个。仍只作用于已有事实。

这个设计在“真实只有 1 条”时完全合法，因为 operator 改变的是**信息在孩子脑中的激活路径**，不是信息本身。孩子明天回来，事实没变，但小可“今天选了另一个侧面说给你听”，信用依然成立。

**4. 最优根本解 + 推理链**

推理链（第一性）：
- 问题根源不在采样温度、不在措辞禁令、不在 mock 条数，而在“说话者被定义为无内部生成自由度的事实奴隶”。
- 任何增加事实基数的方案，都把 demo 优化和真实世界约束放在了对立面，迟早要二选一。
- 唯一能同时 hold 铁律 + 提供持续新鲜感的，是给小可一个**正交、可控、不生产事实的内部自由度**：话语策略层。
- 录音感 vs 活人感的终极区别，从来不是“知道的事多不多”，而是“对已知的事，能不能每次都像带着新意图、新角度在说”。

**最优根本解**：**在架构里把 Framing Layer（话语行为选择层）做成第一等公民，与 Fact Layer（device_state + confirmed_memories）严格分离**。

落地最小但直击根源的改动方向（工程约束友好）：
- variables.ts 里增加 framing 相关注入能力（可以是结构化 JSON 或简单字符串种子）。
- 全局 prompt + addendum 里明确写入“operator 字典 + 强制本次必须与上 N 次不同 + 禁止发明事实”的规则。
- 高风险卡（card2、3、4、6）的 scenePrompt 里显式列出该卡允许的封闭 operator 列表（从产品定义四件套提炼）。
- 变量注入面板（PromptPanel）增加 framing 控制区，demo 时 PM 可直接操作或“一键换角度”；真实产品可不暴露或只做后台策略。
- 触发时把“本次建议 framing”（或“避开列表”）作为额外信号注入（不改 triggerInstruction 语义）。
- Store 里对关键事实做极轻的 per-session / per-day 去重追踪（纯客户端，不上链）。

这样改动极小（主要是 prompt 资产 + 变量面板 + 少量 store 逻辑），但把“内容重复”的根（单一事实 + 无选择策略）一次性拔掉。

堆数据只能让 demo 暂时好看；引入 framing layer 才能让**无论世界当天给不给新 delta，小可都能像个有自己想法的伙伴**。这才是儿童产品该有的“留存钩子”底层逻辑——信用建立在“它说的都对得上”，新鲜感建立在“它每次说的方式都像刚想起来”。

对其他卡的快速确认：card1、7、8、5 重复风险显著低于上面四张，因为它们要么依赖孩子输入，要么依赖通用人设/仪式，要么查询走事实本身。但全局都应该把 framing 思维植入，避免未来单一记忆或单一设备状态把它们也锁死。

这就是从根上解。打补丁只会让系统越来越像一个越来越复杂的录音机。
