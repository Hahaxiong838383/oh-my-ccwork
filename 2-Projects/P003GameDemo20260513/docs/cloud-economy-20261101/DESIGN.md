# P003 云端规则与收益迁移方案

状态：2026-11-01 用户批准执行；当前交付 P0 只读试算，正式经济接管分阶段验收。

## 决策与经验

1. 目标改为云端统一管理规则、配表与最终收益账本。原方案的端侧快照是当前实现适配，不能继续当目标架构；设备负责在场与使用事实采集、离线缓存、显示云端确认结果。
2. 规则计算是确定性业务代码，LLM 只解释查询结果。配置调整在已支持字段范围内不需 OTA；新采集能力或新 UI 仍可能需一次客户端升级。
3. 诊断日志与业务时长分离；23 点夜批不能支撑当前即时到账。关闭 Analytics 不能停止孩子的业务收益。优先复用现有 telemetry 传输，但不能直接把其统计聚合当经济账本。
4. presence 变化不证明持续在场；focus_segment 墙钟区间要去重叠；progress_checkpoint 的累计域/重启持续性尚未冻结。两路分别展示，禁止相加。
5. 本地 reward_granted 是已发生结果，不能再作为云端发奖输入。首次接管须冻结余额和结算边界、唯一发奖方；回滚保留已发生交易，不整库恢复。
6. 旧本地 9 月配表不等于当前 APK 的有效规则；只有版本号不等于拿到该版本内容。缺数值、不完整、GM、身份/存档未知都要显式标注，不能用 0 或猜测补齐。

## 分阶段实施

### P0：本轮执行

- 在已有隔离工作树 codex/p003-analytics-control-20261031 中增加独立工具；基线 39594625debe3a0be5600a9f15fca2725aae6ce7。
- 两个只读适配器读取 analytics/telemetry 原始事实；不导入会初始化生产库的 Store 单例。
- 每次固定 SN、北京时间日期、接收截止；单日最多 10000 条/来源、查询时限、JSON 字节限制，截断不冒充完整。
- 生成观测时长、区间去重、检查点回退、GM/版本/时钟/覆盖缺口及端侧发奖观测。默认不提供规则时只输出事实审计；提供显式候选规则时输出条件试算，永远不是正式应发收益。
- 独立 shadow SQLite 只保存输入摘要/报告，不复制原始正文。重复同输入/规则只留一条；同运行ID不同内容拒绝。
- CLI + 可分享 Markdown 报告；在 HK 独立版本目录部署并执行真实只读回放，保留来源与校验。无主服务重启、无设备回写、无发奖接口、无对话注入、无 cron 自动放量。
- 不修改既有 Analytics 开关、TTL、seen 去重语义或主/P2/倾听业务代码。

### P1：统一规则与输入契约

- 冻结当前游戏规则正式配表、在场/有效使用定义、逻辑日、累计域、断电/换档行为。
- 最小端侧适配：持久单调累计/区间、boot/save/归属作用域、序号和覆盖界限；优先复用现有通道。GM 单独域。
- 规则不可变版本和生效边界，默认次日生效；迟到数据依据发生时规则，不按接收时最新表重算旧收益。
- 后台配表发布/预览/回滚及按 SN 试算对账。

### P2：单机经济接管

- 独立业务库：规则、使用输入与水位、奖励/消费账本、当前状态；单事务去重与记账，稳定业务交易ID。
- 期初余额和接管水位验证后切换一个 SN，端侧停用对应本地发奖，消费/领取同样统一归属。
- 云端回执幂等应用与确认；离线继续记录，收益待同步，不与云端同时确权。
- 小可与设备读同一已确认状态；缺失、过期和待同步有不同口径，不能把试算写进长期记忆。

## P0 接受标准与回滚

- 合成测试覆盖时长并集、重复/冲突ID、跨日裁剪、倒退累计、GM、版本混合、无数据、阈值边界、顺序稳定、时钟异常、查询截断、生产只读与报告幂等。
- 真实回放与合成测试分别报告；无真实覆盖/配表时写明缺口，不将代码通过等同真机经济验收。
- 全局 ready_for_settlement=false、certified_eligible_ms=null。P0 没有可打开的正式发奖开关。
- 回滚只停止调用独立试算工具、保留审计目录；不触碰生产数据库、开关或钱包。新代码删除/回退对应提交即可。
