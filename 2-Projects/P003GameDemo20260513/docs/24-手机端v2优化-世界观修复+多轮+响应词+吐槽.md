## 问题1（最严重）：小可世界观被学习知识库「覆盖」

### 真根因（Explore 读源码确认，非猜测）
**不是覆盖，是移动端 `/m` 从来没下发过世界观 prompt：**
- 体验台 web：卡切换 → `sendSessionConfig`(完整世界观) → server 存用 ✅
- 移动端 `/m`：`useMobileVoice` 只发 `sendSessionMeta`，**从不 `sendSessionConfig`** → server 回退 `DEFAULT_SYSTEM_PROMPT`(最小兜底、无世界观) → 孩子只听到 server 按对话内容匹配注入的「课程护栏」`curriculumGuardrail`。
- 3 层根因：① 前后端 prompt 架构分离 ② **移动端缺口（核心）** ③ 课程护栏追加 prompt 末尾、长上下文 LLM recency bias 压制靠前的世界观。

### team 三家共识 + cc 决策
**核心：server 内置世界观基座 = 单一真相源**（三家一致，否决「只靠移动端补发」；合记忆 `feedback_memory_multi_end_single_source_of_truth`）。

**prompt 顺序**（破 recency bias）：
```
安全底线 → L1世界观/人设 → 儿童记忆 → L2场景素材 → 课程/启蒙护栏 → 尾部锚点复述(~100字人设强约束)
```
- 课程护栏**绝不放最后**；尾部锚点 = "始终保持小可身份、童话陪伴口吻、不变老师说教"（省 token，对抗末尾偏置）。
- 课程护栏 **soft 化**："作为小可，倾向用生动比喻" 而非 "必须教导"。

### 实施点（demo）
1. `apps/server/src/pipeline.ts` `DEFAULT_SYSTEM_PROMPT`(line 58-61) 升级为完整世界观基座
2. `apps/server/src/prompt-orchestrator.ts`(line 15-36) prompt 顺序调整 + 尾部锚点 + 护栏 soft 化
3. `apps/web/src/mobile/useMobileVoice.ts` `beginTurn` 补发 `sendSessionConfig`（兜底）
4. 日志 `promptSource=default/client/orchestrated` 防双真相源
- ⚠️ **server 两端生产**（gemini-flash 公司 / DeepSeek 个人站）同步改；建议先个人站验证再上公司侧。

## 问题2：唤醒响应词换预存人声随机
- 现状：`voice-client.playCue()` 是 AudioContext 合成「叮咚」提示音
- 方案：生成一批小可音色短语（"我在呢"/"在呢"/"怎么啦"/"我在听"/"哎"），预存 `apps/web/public/`，唤醒**随机播 1 条**（不连续重复上一条）
- 实现：`playCue` 改成随机播预存音频；音频用 server TTS / minimax 生成小可音色

## 问题3：多轮对话等待期（连续多轮）— 等手机验证

### team 三家共识 + cc 决策
**状态机（新增 `WaitForFollowup`）**：
```
idle/KWS → Listening → Thinking → Speaking → WaitForFollowup(开录音等接话) → ┐
   ↑                                                                          │
   └── 静音超时退出 ←──────────────────────────  检测人声 → Listening(下一轮)
```
- 小可说完 → **不立即 idle** → `WaitForFollowup`（自动开 Web 录音 + N 秒静音超时）→ 检测人声进下一轮 / 超时退 idle 恢复 KWS。
- **童声静音阈值**：1500-2000ms（传统 500ms 太短），检测未完句（"因为/然后"）动态 +1000ms。
- **等待期原生 KWS 关闭**：Web 录音接管，避免抢麦+回声，超时退 idle 才重启 KWS。
- **退出条件**：最大 3-5 轮 / 等待静音 6-8s / 退出词。
- VAD 落点：demo server 复用 `asr.final`；正式 + 端侧 silero-vad + semantic endpointing + backchannel("嗯""然后呢")。

### 实施点
- server：TTS 结束事件加 `allow_followup` 字段 + endpoint 调参
- 前端：`useMobileVoice` 加 `WaitForFollowup` 状态机
- ⚠️ 强依赖手机语音真机验证，川哥回来实施。

## 问题4：右下角吐槽入口 — 95% 复用
- 方案（Explore）：`useMobileVoice` 加 `feedbackMode` 参数(`captureMode:'feedback'`) + `onFeedbackDown/Up`；`MobileMain` 右下角加「按住吐槽」按钮（琥珀色，对标 kidshub `CanvasHost`）。
- kidshub 吐槽链路已全（`sendSessionMeta captureMode:feedback` → server 落反馈库 + 吐槽人格回应），移动端差个按钮，~20 行。
