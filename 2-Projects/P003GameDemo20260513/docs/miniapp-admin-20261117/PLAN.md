# Worker 小程序 Dashboard：实施方案与预览

2026-11-17｜状态：方案待评审，交互预览已制作；本轮未改产品代码、未部署、未操作真实绑定。

## 推荐方案

在现有 **Worker 管理** 左侧标签中新增 **小程序 Dashboard**，与“设备接入”“Worker Brain”同级。采用“设备列表 → 设备详情”布局，详情全宽显示，保留返回时的列表筛选条件。当前 admin 为单 HTML + Vue 3 / Element Plus，沿用现有页面与管理登录。

数据由现有小程序查询逻辑供给，增加薄管理接口；不另建数据副本、不新增服务、不让浏览器冒用家长 token。此页显示的是**当前绑定家长在小程序可见的数据**，区别于后台已有的、以设备 Brain 为入口的管理数据。

| 方案 | 取舍 |
|---|---|
| **推荐：Worker 新标签 + 共享服务端查询** | 满足独立查设备入口；和小程序同口径，后续新增字段只维护一处计算 |
| 在 Brain 详情中再加子标签 | 更少布局改动，但入口藏得深，且现容器受 Brain 开通状态限制；不符合本次独立 Dashboard 入口诉求 |
| 嵌入整个小程序 / 重做一份查询与汇总 | 前者需要处理家长登录身份，后者会产生口径漂移；两者都增加维护负担 |

## 页面范围

### 设备列表

- 搜索：完整 SN、设备 public_id、家长账号 ID、家长手机号；筛选已绑定 / 未绑定，默认每页 20 条。
- 每行：设备名称/备注、SN、小程序设备 ID、家长账号 ID、手机号、绑定状态、详情入口、解绑入口。手机号默认脱敏，在管理员详情中按需查看，搜索时不把手机号写入 URL 或日志。
- 顶部统计仅用设备台账可直接计算的设备数、已绑定、未绑定、已开通 Brain 数。没有上报不等于离线，不为列表逐台拉全部历史和流水；数据概况可在选中设备后读取。预览列表的概况来自固定夹具，正式版不以 N+1 详情请求实现。
- 未绑定、未开通 Brain 的设备也可查身份与明确不可用原因，不因 Brain 开通门限整页消失。返回列表保留筛选，解绑成功同步更新数量与当前行。

**“小程序 ID”拆开命名，避免混淆：**

| 名称 | 当前字段与显示 |
|---|---|
| 小程序设备 ID | `device_registry.public_id`，与小程序设备 API 路径一致 |
| 家长账号 ID（小程序账号） | `parent_account_id`，当前小程序手机号登录使用的统一账号 |
| 微信 OpenID / UnionID | 当前微信手机号登录没有持久化；显示“未接入 / 当前未保存”，不伪造，不把 account_id 改名为 OpenID |
| 小程序 AppID | 全应用共同的标识，不是逐设备、逐用户 ID；无需在每行重复 |

### 设备详情

固定头部显示 SN、public_id、家长账号、脱敏手机号、绑定状态和数据时间；右上角提供刷新与低强调的“解除小程序绑定”。

| 标签 | 内容 |
|---|---|
| 数据总览 | 今日/近 7 日有效使用、对话统计、流水入口、设备最近状态、昨日收益、最新获得、数据覆盖提示 |
| 使用时长 | `usage.today/daily` 的日期、available、focus_minutes、更新时间、来源和时区；7 日趋势与日明细；缺测为“暂无数据”，有效观测的 0 正常显示 |
| 资产与收益 | 家族币、星尘、补勤卡**当前快照**，来源/采样与接收时间；昨日已上报家族币/星尘收益；最新获得的**整组**物品、类别、数量、激活状态、相关 ID；当前库存和最近获得不混同 |
| 业务流水 | 默认 20、最多 50 条；北京时间日期/存档/资源筛选，原记录 ID、序号、发生与接收时间、来源、资源变化、获得/激活、兼容库存状态变化；baseline、normal、GM、unknown 和原归属未验证分别标识 |
| 历史对话 | 总消息数、孩子/小可各自条数、首末时间、覆盖说明；按需读取正文，日期筛选、游标翻页、刷新首屏；不是按会话或对话轮次数展示 |
| 身份与接入 | 当前账号/手机号、public_id、绑定版本、上传配置、最近**自报**版本、历史授权状态；数据域来源/缺失原因。已有设备配置与 Brain 档案提供对应入口，避免复制编辑表单 |

所有域保留 `available/reason/source/time` 等解释信息，常规阅读用中文；排障时折叠显示许可字段与来源，不输出凭据、私有授权串或完整原始账号记录。

**已审计的真实版边界：** 当前小程序 live 页真实接入的是绑定设备、设备状态、使用时长、Ark 当前资产、两摘要、流水和对话。五 Tab 原型中的任务、亲子约定、兑换操作、周报、孩子/视光报告、反馈、消息、偏好设置等仍是 DemoIndex 本机演示；蓝牙配网演示也未完成云端激活接线。新 Dashboard 列出这些“未接入”项，不生成假的线上数字。服务端旧 weekly 路由和 Brain 画像虽存在，也不冒称当前 live 小程序已消费；后续正式接入时再加入同源视图。

**关键口径：**

1. `usage.today/daily` 为用时真值；旧 `today/week` 存在缺测补 0 的兼容字段，禁止回退使用。
2. online 是最近 10 分钟内收到快照的判断，文案使用“近期有上报/近期无上报”；不是实时网络探活。
3. 当前 Ark 快照不是实时钱包；只展示合格 normal 快照，其他沿用 `non_normal` 不可用状态及 null 值；流水中的 normal、GM、unknown 分别标明。昨日收益只含已同步正常奖励，baseline 不算收入或新获得；昨日收益目前是家族币/星尘，不另造补勤卡收益摘要。
4. 记录和对话都有覆盖边界，`complete=false/history_complete=false` 不改写成“全部历史”。C 的 186 条是 11 月 16 日快照，不写死为线上总数。
5. 当前 telemetry 使用时长按 SN 汇总，尚无家长绑定代次维度。新后台保持与小程序相同并明确这一点；不宣称所有数据都已实现跨家长历史隔离。对话与 Ark 继续执行现有完整授权范围。
6. 流水 DTO 只有当前页 items、has_more 和 coverage，没有总 count。首版显示入口/查询状态或“本次已加载 N 条”，不推定总量、不为一张统计卡扫全表。

## 解绑：两次点击，一次受校验的写入

1. 点击设备的“解绑” → 弹出确认框，列出 SN、设备 ID、当前家长账号与手机号，说明作用范围；取消不写入。
2. 点击“确认解绑”才提交；提交时禁用重复点击。备注选填，不增加口令输入、审批流或第三次确认。
3. 服务端核 admin 权限，并把弹窗打开时的 `expected_public_id / expected_parent_account_id / expected_binding_version` 用作条件。设备已换绑则 **409**，展示“绑定已变化，请刷新后重新确认”，不得解绑新家长。
4. 复用设备注册表的绑定更新与现有 Ark 代次触发器；仅解除家长关联，保留设备、public_id、Brain 账号、存档、对话、原始流水及未 ACK 队列。家长会话不全局登出，但该设备访问立即失效；不要调用删除设备或恢复出厂。
5. 失效旧预授权、未 claim 的绑定会话；自动确认及 claim 必须校验创建时绑定版本。现 legacy 自动确认可能把旧预授权重新绑定回来，**只取消当前条目不足以抵抗并发，需要提交时再核代次**。复用 BLE 已有条件更新模式：预授权创建时存 owner/version，传递到会话，最终 `performSnBinding` 事务按该条件提交。旧预授权不能在解绑后用新版本重新盖章；既有 null-version 旧绑定意图明确失效，不默认补当前版本。
6. 不承诺所有旧设备凭据均撤销：带绑定版本的凭据会失效，无版本 legacy 有兼容路径。此功能不是“停用设备”或“全量撤销凭据”；如以后需要该操作，另用现撤销水位能力，不暗中改变本次解绑语义。
7. 成功后清除当前详情/分页/迟到响应，回到未绑定状态；旧对话与 Ark 授权失效，重新绑定同一人也不自动恢复。用时依旧按 SN 聚合，确认说明明确这一差异。
8. 记录管理员、SN、前后绑定版本、操作时间、结果和备注（不含令牌/手机号全文）。先沿用现操作日志扩展结构化字段，不新增通用审计平台。

**最小接线建议：**增强现 `PATCH /api/admin/devices/:sn/parent` 的解绑分支，要求上述 expected 字段；当前旧“解除家长关联”入口一起补传字段，共用同一服务方法。绑定到非空账号的现行为不借机重构。新 tab 不暴露 Brain 的“解绑”按钮，避免两种解绑混淆。分文件实现时先上线兼容读取能力，再同步发布要求 expected 条件的服务端和两个后台入口；旧缓存提交缺字段必须明确拒绝并提示刷新，不能无条件继续。

跨库的预授权/配对会话清理若不能同事务，绑定版本是权威防线：所有旧自动确认与 claim 最终条件提交失败；清理负责释放旧意图，不以清理完成代替并发校验。用可控双连接测试这条路径，不引入分布式事务框架。

## 接口与代码落点

以下为拟定接口，不表示当前已经存在。

| 接口 | 用途 |
|---|---|
| 复用 `GET /api/admin/devices` | 列表所需 SN、public_id、parent_account_id、parent_phone、binding_version，管理员字段白名单；不取对话正文 |
| 新 `GET /api/admin/devices/:sn/miniapp/dashboard` | `{binding, observed_at_ms, data}`，data 与当前家长 dashboard 同源；未绑定返回明确空态，不读取前家长详情 |
| 新 `GET /api/admin/devices/:sn/miniapp/records` | 复用原流水 query/cursor/DTO，保留原历史授权和错误语义 |
| 新 `GET /api/admin/devices/:sn/miniapp/conversations` | 复用原对话 query/cursor/DTO，按当前家长可见范围读取 |
| 增强 `PATCH /api/admin/devices/:sn/parent` | 解绑分支要求旧 public_id/owner/version；冲突409，重复旧请求不推进绑定版本 |

- 在 `apps/web/public/admin/index.html` 的 `WORKER_NAVS`（当前约4882行）、`visibleWorkerNavs`、`khSelectNav` 中增加 `miniapp`；页面仅 admin 可见，并使用独立状态对象。不要仅在 Brain 的 `subTab` 内添加，也不要受 Brain `bound` 布局门限控制。
- 复用 `deviceApi` 与管理员认证；后端 admin 路由强制校验，不能只隐藏前端。详情接口 `Cache-Control: no-store`，数据不进 localStorage 或共享缓存。
- 从 `apps/server/src/routes/telemetry.ts` 抽出当前 dashboard 读取函数，家长路由保持字段与状态码兼容，admin 路由解析当前家长身份后调用同源逻辑；流水/对话复用现 stores。只抽一个业务查询模块，不造通用服务框架。
- 整个聚合查询前后核完整身份元组（SN/public_id/owner/device account/binding_version/Ark epoch/当前 grant_id/启用与授权状态），保留对话/流水已存在的独立授权检查。管理员身份不意味着给当前家长追认所有旧历史。账号对应的真实 role 仍需核实，不伪造 parent JWT 或绕过 scope。
- 摘要、流水、对话各自加载/错误/空态。400/410 清旧 cursor，首屏503不得复活旧 cursor；切设备/筛选/退出/解绑使旧请求失效。页签进入和手动刷新请求即可，首版不轮询完整对话。

## 实施顺序与验收

| 批次 | 交付 | 通过条件 |
|---|---|---|
| 1. 共享读取与后台页 | 列表、六标签、三个 admin GET；小程序读取改调用同一个函数 | 固定时钟和相同数据夹具下，admin data 与家长 API 逐字段相同；原小程序回归无变化；C 缺测不显示0 |
| 2. 解绑补齐 | 条件解绑、旧绑定意图失效、两个后台入口共用 | 取消无写入；确认成功；双击/重放不重复推进；旧确认409；A→B→A拒绝；旧预授权/claim不能自动复绑；原始数据/队列不删除 |
| 3. 页面及联调 | 桌面/窄屏、浏览器交互、单设备线上读取对账 | 搜索/筛选/返回保留；两域分页/失效恢复；快速切设备/账号/退出无串数据；无权用户401/403；未知/缺测/合法0/基线/GM各自展示 |

读取对账用同一查询时点、同一当前绑定：后台、家长 API、小程序界面三方核状态、时长、资产、收益、获得、记录 ID、对话 ID/计数。解绑的写入验证用隔离数据或专用测试绑定；不为了看弹窗就解除 C 的现场绑定。正式发布前核在线源码漂移与空房时段，只发布本次文件；保留源码回滚，不回灌旧数据库。

按这三批实施即可，不需要改 Worker 音频链、设备固件、小程序合同或另做大规模统计平台。预览为独立 HTML，正式页面再接入现 Vue/Element Plus；不直接把预览内联示例数据带入生产。
