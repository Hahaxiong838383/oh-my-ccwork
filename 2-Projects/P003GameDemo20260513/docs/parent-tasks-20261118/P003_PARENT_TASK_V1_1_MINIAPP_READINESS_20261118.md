## 4. V1.1覆盖旧草案的重点

| 旧草案 | 统一按V1.1执行 |
|---|---|
| 时长1–300分钟 | 1–120整分钟；奖励1–500整枚；默认值按联调包 |
| 描述必填 | 选填，最多200个Unicode码点；空/省略/null归一；设备侧固定description=null |
| 从创建时刻开始计时 | 从创建当日/当周起点核算归属明确的真实历史；历史已足够可创建即待确认 |
| 编辑下一期才生效 | 进行中编辑立即重算本期与后续规则；达标锁定后该期不可改删 |
| 同步开关固定开 | `sync_to_xiaoke`仅控制两种主动提醒；false不关闭任务、家长确认、入账或状态查看 |
| 旧设备GET及ark前缀草案 | `POST /v1/device/parent-tasks/sync`和`POST /v1/device/parent-tasks/receipts:batch` |
| 旧后台tasks草案 | `GET /api/admin/devices/{sn}/miniapp/parent-tasks` |
| 按任务定义一行 | 按occurrence_id逐期一行，上期待确认与本期进行中可并存 |

家长6个接口沿`/v1/parent/devices/{publicId}/tasks`：POST/GET列表、GET详情带occurrence_id、PATCH带周期和expected_definition_version、DELETE查询参数带两者、POST指定周期confirm且正文`{}`。创建、修改、删除、确认全部带Idempotency-Key；操作权限以服务器actions为准。

计时沿用现网已接收focus，同event去重，后到重叠段沿用现网整条拒收，跨午夜拆日；不用首页估算，不把周累计除门槛冒充达标天数。进度截断一位小数，59秒显示0.9分钟；是否达标由服务端原始毫秒核算。没有证据显示“暂无已同步记录”。

## 5. 收到研发回执后的小程序工作顺序

1. 核现役源码与实际接入版本，核家长任务接口环境/可用项及缺口；缺少源码或真实接口的模块保持“待接入”。
2. 接入按周期任务列表、创建/编辑/删除、家长按周期确认；处理幂等、409刷新、分页及迟到响应，保留当前登录/设备归属。
3. 分开渲染任务状态与钱包状态：awaiting_confirmation待家长确认；pending_payment已确认待到账；paid已到账。钱包synced/syncing/unknown独立显示，可信余额null不补0，不本地加币。
4. 复用逐笔收益历史，按服务端回执的结算映射验证同一笔收入；与Worker后台共同核对，不把任务列表或昨日汇总代替收益历史。
5. 真实环境与方舟包就绪后先跑下列主流程，通过后再测上期待确认与本期并存、删除后补传等边界。
