# 18 · 小可用户记忆系统 · 实施计划（v1.1 · demo 阶段版）

> 2026-06-18 · cc · 配套 [docs/17 选型方案](./17-用户记忆系统选型方案.md)
> **v1.1 变更（川哥指示）：纯 demo 阶段，隐私合规先不考虑** → 隐私相关全部移到「附录 A · 正式版上线前必补」，主路线只保留让小可「记得住、懂孩子」的功能。记忆质量机制（时效/矛盾/幻觉防线，属功能非合规）保留。
> 原则：**分阶段、每阶段独立可上线可回退、不破坏现有单轮链路**。
> 文件路径均为 `apps/server/src/`（后端）/ `apps/web/src/kidshub/`（前端），行号基于 2026-06-18 现状。

## 0. 路线总览（demo 版）

| Phase | 目标 | 工期 | 上线即收益 | 可独立回退 |
|---|---|---|---|---|
| **P0.1** | 会话内多轮 history | 0.5–1 天 | 小可记得上一句（"再讲一个"接得上） | ✅ |
| **P0.2** | 已有 profile 注入（后端 Orchestrator 雏形） | 0.5–1 天 | 小可知道孩子名字/年龄，口气适配 | ✅ |
| **P1** | 结构化画像 + 异步抽取 + 预加载 | ~3–5 天 | 跨会话"上次你说喜欢恐龙" | ✅ |
| **P2** | L2 情节记忆（FTS5 结构化事件表） | 按需 | 长期陪伴感（情感事件召回） | ✅ |
| **P3** | 向量/时序图（数据驱动才上） | 远期 | 多跳/事实演变 | — |
| 附录 A | 隐私合规闭环 | **demo 不做** | 正式版上线前必补 | — |

> demo 阶段去掉了原 P1.5（隐私闭环），P1 工期从 ~1 周降到 ~3–5 天。**demo 核心 = P0 + P1**：让小可既记得住对话、又懂这个孩子。P2/P3 远期按需。

**关键架构决策（来自 v0.2，demo 仍遵守）**：
- 注入点 = **后端 Prompt Orchestrator**。后端物理分区组装 `[人格] + [lore] + [user_memory 后端独占] + [实时context]`。
- L2 = **结构化事件表 + SQLite FTS5**（非纯关键词、非直接向量）。
- 记忆写 = **Buffer-Flush + pending→active**（demo 可先用内存队列轻量版，正式版升持久 outbox）。
- 延迟铁律 = **connect 阶段禁调 LLM**；ASR final→LLM start 之间禁同步检索；注入做 token 预算 + 摘要化。
- 存储 = 本地 `node:sqlite`（工程默认，加密/审计等合规手段见附录 A）。

> **demo 提速说明**：P1 的记忆质量机制（outbox / pending→active / 矛盾检测）可先用轻量版（内存队列 + 抽取直接写 + 简单覆盖），完整版在正式化时升级。设计保留在下文，实施时按 demo 取轻量档。

## P0 · 最快见效（1–2 天，拆两步，先 history 后 profile）

### P0.1 会话内多轮 history

**现状**（已验证，Explore 读源码）：`gemini-llm.ts` / `deepseek-llm.ts` 只收 `systemPrompt`+`userText`，LLM 调用永远是 `[{system},{user}]`，无历史；`pipeline.ts` 的 VoicePipeline 不存多轮。

**改动**：
1. `providers/gemini-llm.ts` + `deepseek-llm.ts`：`streamChat` 签名加可选 `history: {role,content}[]`，messages 拼成 `[system, ...history, user]`。**向后兼容**（history 缺省=现状单轮，不破坏现有调用）。
2. `pipeline.ts`：VoicePipeline 加 `private history: Turn[]`（成员变量，随实例/TTL）；每轮 user+assistant 入队；滑动窗口**严格 8 轮**（16 条），超出丢最旧。
3. 注入前做 **token 预算检查**：history+systemPrompt 超阈值则截断最旧（防 Prefill 膨胀拖 TTFT）。

**验收**：① 孩子"给我讲个恐龙故事"→"再讲一个"，第二轮 LLM 能看到第一轮（日志打 messages 条数 >2）② 8 轮后内存不无限增长 ③ 单轮老链路不回归（现有 E2E 通过）④ 实测 TTFT 不显著退化。

**风险/回退**：改 LLM client 接口 → 全程 history 可选，出问题前端不传即退回单轮。

### P0.2 已有 profile 注入（后端 Orchestrator 雏形）

**现状**：`profile-store.ts` 存 nickname/birthday/gender 但 `pipeline.ts` 组装 prompt 时**完全不读**；systemPrompt 由前端下发、后端只存（`sessionSystemPrompt`）。

**改动**：
1. 新增 `prompt-orchestrator.ts`：`assembleSystemPrompt(frontendPrompt, memberId)` = 前端下发的 prompt（人格+lore）**+ 后端追加 `【关于这个孩子】` 块**（从 profile-store 读 nickname/age/gender 拼成自然语言）。这是后端注入(Y)的最小落地，**不改前端组装逻辑**，只在后端尾部加一个 user_memory 区块（物理分区 + 声明边界）。
2. `pipeline.ts`：`startLlmAndTts` 里 `systemPrompt = orchestrator.assembleSystemPrompt(this.sessionSystemPrompt ?? DEFAULT, this.sessionMeta?.memberId)`。
3. session.meta 已带 memberId/nickname/age（前端下发），后端据此查 profile。

**验收**：① 小可主动用孩子名字、按年龄调整用词（5 岁 vs 12 岁）② profile 为空时退回 DEFAULT 不报错 ③ E2E：建连→对话，日志确认 systemPrompt 含 `【关于这个孩子】` 块。

**风险**：与前端 framing/死活分离协调——user_memory 块要带边界声明（"以下是这个孩子的长期信息，实时状态以 device_state 为准"），**需在 docs/13 补一条"user_memory 区块由 server 注入"变更记录**。

## P1 · 结构化画像 + 异步抽取 + 预加载（~3–5 天）

### P1.1 画像 schema 扩展（L1）
`profile-store.ts` 的 FamilyMember 扩展（含**时效性字段**，治发育漂移）：
```
interests: {value, confidence, last_updated, source}[]   // 兴趣[恐龙,奥特曼]
preferred_address: string        // 喜欢被叫什么
personality_notes: string        // 性格观察
recent_emotion_anchor: {emotion, topic, ts}   // 近期情绪锚点（短时效）
```
- L1 = **稳定、家长可编辑、低争议**事实；瞬时情绪不进 L1（进 L2）。
- migrate 老库（PRAGMA table_info + ALTER，幂等，复用 P003 已验范式）。

### P1.2 异步抽取（Buffer-Flush + pending→active；demo 轻量版）
1. 新增 `memory-extractor.ts`：累积 **3–5 轮** → 一次微总结 LLM 调用，按固定 schema 抽"画像增量"。
2. 抽取**独立于 WS 主链路**（主链路只入队不等待）。demo 用内存队列即可；正式版升持久 outbox + 幂等 + 重试（见附录 A 不含此项，此为可靠性非合规——正式版工程化）。
3. **矛盾检测**（记忆质量，保留）：新增量与现有 L1 冲突（"讨厌→喜欢番茄"）→ 触发**更新**（更 last_updated/confidence）而非追加。
4. **幻觉防线**（记忆质量，保留）：每条记忆留 `source_quote + model_version + confidence`；demo 可先抽取直接进 active，正式版加"对话中自然确认 / 家长确认才进稳定画像"。

### P1.3 预加载注入（延迟解耦）
1. connect 时**只读预先算好的 memory digest**（profile 摘要，不调 LLM）→ 缓存。
2. orchestrator 注入 digest，做 **token 预算 + 动态层级缩减**（记忆多时只注入 Top-K 摘要，不注入全部原文）。
3. ASR final → LLM start 之间**禁任何同步检索**。

### P1.4 家长端可编辑画像（产品功能，保留）
- 家长端/admin 加画像 CRUD，**家长编辑优先级 > 模型抽取**（家长改的 source=parent，抽取不覆盖）。

**验收**：① 跨会话："上次你说喜欢恐龙" 成立 ② 矛盾自愈：改偏好后小可不再用旧偏好 ③ 异步写不阻塞主链路，**E2E P99 延迟不退化** ④ 家长编辑生效且不被抽取覆盖。

## P2 · 情节记忆 L2（按需，FTS5 结构化事件表）

- 新增 `episodic_memory` 表：`who/topic/entities/emotion/valence/time/source_quote/importance/confidence/expiry`。
- 检索：**SQLite FTS5**（内置零依赖，分词+BM25）+ 规则扩展（指代/同义）+ 小型 rerank。
- 读：仅话题相关时，**ASR 流式期并行预取**，未完成跳过本轮（不插在 final→LLM 之间）。
- 写：同 P1.2 异步管线，标 importance/emotion/expiry。

**验收**：情感事件召回（"上次考试难过""布偶猫团子"）；隐喻/指代场景 FTS5+规则召回率达标。

## P3 · 向量 / 时序图（数据驱动才上）

- **升级扳机（多信号 AND，实测校准非预设）**：先埋观测指标（见下），用**连续 2 周真实数据 + A/B** 判定。
- FTS5 召回失败率持续高 → 加 `sqlite-vss` 向量列 + bge-small-zh（KidsBench 已有经验，92MB）。
- "事实会变"成高频需求 → 引 Graphiti 式时序 KG。

## 贯穿事项

### 可观测埋点（P1 起，demo 也建议）
首 token 延迟 / 记忆命中率 / 误提率 / 孩子纠正率 / 跨孩子串记率。这些是 P3 升级扳机的输入。

### 离线基线对照（按需，非 demo 阻塞项）
正式化前，用 KidsBench（已在跑 mem0/Zep 等）对照自建的召回/误记/延迟，用数据证明自建 ≥ 重型系统。demo 阶段可跳过。

### 多孩子 / speaker（demo 用现状，多孩子时再做）
demo 现状一账号一孩子，记忆 key=(account_id, member_id) 已够。**一台读书台多个孩子共用**（兄弟姐妹串记）= 功能正确性问题，等真要支持多孩子时再做「会话开始显式选孩子 + 低置信不写长期」。

## 风险与回退总表（demo 版）

| 风险 | 缓解 | 回退 |
|---|---|---|
| 改 LLM client 破单轮链路 | history 可选向后兼容 | 前端不传 history |
| 注入太长拖 TTFT | token 预算 + 摘要化 + Top-K | 缩减注入条数 |
| 异步写丢/乱序 | demo 内存队列够用；正式版升 outbox | 关抽取，只保 P0 |
| 记忆毒化（瞬时情绪固化） | L1/L2 分层 + 矛盾检测 | 家长一键清画像 |

**P0.1 → P0.2 先上**（1–2 天，最快见效、风险最低、独立可回退），跑几天看真实效果 + 埋点数据，再决定 P1 节奏。demo 阶段不做隐私（见附录 A），**正式版上线前必须回头补齐附录 A 再接真实用户**。

## 附录 A · 正式版上线前必补（demo 阶段按川哥指示不做，但接真实儿童用户前必做）

> 这些是 team 三发挖出的儿童合规硬约束，demo 阶段不实施，**但接真实儿童用户前必须补齐——写进去的儿童敏感数据再删很麻烦，所以"开始写真实用户记忆"之前这一段要先就位**。

1. **第三方 LLM 链路受控**（codex 致命）：主 LLM + 异步抽取 LLM 本身在处理儿童对话 → 核实聚合网关/模型方零留存 + 禁训练 + 数据地域；抽取只发最小字段 + 脱敏。
2. **记忆准入策略 admission policy**：默认不存精确地址/联系方式/学校班级/第三方儿童身份/健康心理/家庭冲突；自伤等安全风险只存最小 safety flag + 短 TTL + 高权限。
3. **at-rest 加密**（SQLCipher/字段级）+ **访问审计日志**（谁何时读了哪条 profile）。
4. **家长同意闭环**：consent 版本持久化 + 撤回即停 + 按字段删除 + 数据导出 + 保留期 + **删除证明**。
5. **一键遗忘即时剔除**：家长删记忆 → 即时从 LLM context 剔除（依赖后端注入 Y，已具备）。
6. **持久化可靠性工程化**：异步写从内存队列升级为持久 outbox + 幂等 + 重试 + 死信（属可靠性，与上线稳定性相关）。
7. **合规提示**：加州要求对未成年人每 3h 提醒休息 + 提醒是 AI（产品层，非记忆模块，但同属上线合规）。
8. **敏感误存率埋点**：上线后监控记忆准入是否漏网。

> 触发点：**任何"开始持久化真实儿童用户的记忆"的动作之前**，附录 A 的 1–5 必须先落地。demo 用内测假数据/可控样本不受此限。
