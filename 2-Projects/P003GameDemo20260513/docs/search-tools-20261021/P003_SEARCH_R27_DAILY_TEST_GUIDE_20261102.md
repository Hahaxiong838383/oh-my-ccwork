# P003 R27 日常搜索：现场短回归

**当前为待安排测试文档，不是“窗口已开”回执。** 三台原P2窗口已于2026-11-02 11:19（北京时间）到期。服务器修改、发布门结果以技术回执为准；搜索等待保护还需端侧在当前APK接入。测试开始前由服务端确认有效版本和新窗口，不能拿本文件当派单凭证。

本轮只判断常规使用是否可收口，不要求精准200毫秒插话，不扩展硬件控制和复杂异常场景。真实设备＋MacBook TTS外放自动化，或者同话术真人发声，须分别记录，不能混成完整真人验收。

## 开始前记录一次

- 完整 MCU SN、APK版本/哈希、服务端确认的有效候选版本与窗口。ADB编号或Mac账号不是云端身份。
- Mac的TTS引擎/音色/语速、扬声器/输出音量、与设备距离/朝向、设备音量、环境噪声；同轮保持不变。不要为得到通过而偷偷改音量。
- 各输入音频文件的SHA-256、播放起止时间、独立录音时间；电脑与设备时钟对齐。真人对照另标。
- 退出旧聊天，再唤起新会话。按设备真实“可以说话”提示开始，记录招呼、提示和播放时间。连接未就绪就停止后续话术，最多一次独立诊断；保留第一次失败。

## 按顺序测一轮

每段正常说完，等实际声音结束再进行下一段。不要仅凭字幕出现、等待词或0.35秒静音判断正文结束。后台结果不是一定成功；明确说暂时查不到可以接受，静默、乱答或只承诺后无后续不接受。

| 顺序 | 话术与触发点 | 应观察到什么 |
|---|---|---|
| 1 普通聊天 | 就绪后分别说：“我今天打球赢了一次。”“小猫为什么喜欢晒太阳？”“给我的小猫取个名字吧。” | 三轮都正常回应。记录每句输入结束到**正文实际声音**的延迟，不能用等待音或字幕计时；与其他正常内测设备同条件对比。 |
| 2 日常天气 | 说“今天天气怎么样？” | 按网络大致位置查询；有天气结果或明确的位置/供应商失败说明。等待词之后不能因原5秒空闲退出。 |
| 3 搜索中聊天 | 说“帮我查一下羽毛球双打发球应该站在哪里。”听到等待词后说“我今天和同学打球很开心。” | 聊天正常接住，搜索在空闲时补播；不能因为继续聊天把搜索永久卡住。 |
| 4 取消后换话题 | 新查询“帮我查一下恐龙为什么灭绝。”听到等待词后说“不用了，我们聊聊小猫吧。” | 停掉本次查询并继续聊天；观察30秒，不得迟到插播恐龙结果。再单独做一次“不用了”取消，失败不能被另一次成功覆盖。 |
| 5 等待中换城市 | 查“北京今天的天气”，等待时直接说“成都今天的天气”，不刻意加“改查”。另一次从“今天天气怎么样”换到成都。 | 新城市成为目标，不继续报旧城市；有新结果或对应失败说明。若第一条已播完，标成第6项，不能冒充等待中改查。 |
| 6 成功播完再改查 | 只有天气确实成功播完后，才说“改查上海明天的天气”。 | 新查询正常完成；前置天气失败则本项记“阻塞”，不能算通过。 |
| 7 读网页＋普通网页聊天 | 说“帮我读一下央视网国内新闻页面，挑一条能核实日期的新闻，讲两句重点告诉我来源。”完成后问“网站是什么？” | 第一条创建查询并给结果或明确失败，不能只说在后台查却没有任务；第二条直接解释网站，不要求再说搜索口令。 |
| 8 插话、续讲、退出重连 | 一条搜索结果开始说话后，正常插话“我想先聊聊别的”，再明确说“继续刚才的搜索结果”。随后结束聊天、重新进入，先保持安静，再明确续讲。 | 插话被接住；同房续讲和新房续讲分别记录。新房明确续讲前应保持静默；不能用同房成功代替重连成功。语音“退出聊天”与手动退出分别标明。 |

天气之外至少一条查询必须得到有用结果；页面请求允许诚实失败，但须有同轮任务/工具证据与可听反馈。单次第三方无资料无需扩成大改造；常规取消不兑现、换了城市仍报旧城市、仅等待词后静默退房，仍不能收口。

## 异常怎么处理

连接失败就停止后续输入。发生静默、错城市、旧结果迟到、退出失败时，记录北京时间到秒、现象、截图/录音，结束当前聊天。若语音退出无效，使用设备正常结束入口。服务端负责按同一run、room、trace补查，持有人不必查内部部署。

首轮失败保留；最多再做一次相同话术的诊断对照，明确写改变了什么。不要盲重试到成功，不把两轮各通过一半拼成整轮通过。新窗口关闭后重新进入正常聊天；若派单未确认恢复，先停止本轮搜索测试。
