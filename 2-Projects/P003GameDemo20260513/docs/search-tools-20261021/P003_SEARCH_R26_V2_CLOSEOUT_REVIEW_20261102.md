## 可以后续优化，不作为本轮致命卡点

精确200ms插话、所有近音字、已接住意图时的个别漏字、极端重连、S09灯和升高等用户跳过项，不扩进本轮收口。B/S01有执行器0.35秒静音误判答复结束的证据，不能全算产品故障。设备两批之间重启原因待核，暂不据此断言应用崩溃。声音断续保留观察；若自然聊天稳定复现到听不清，再提升优先级。

普通聊天“不明显变慢”仍是底线。影响语音路径的修复沿用既有性能门，不以扩大盲等、放宽阈值或只测等待音来通过；无需为了本轮决策新建大型测试平台。

## 最小收口安排

1. 修复上面三组问题，保留现有搜索与聊天架构。
2. 同一最终版本完成一次连续短回归：普通聊天3—5轮；查天气；搜索中继续聊并等结果；取消后换话题；等待中换城市；明确读取新闻页面。取消、改查各重复一次，旧结果不得迟到插播。
3. 天气之外至少有一个普通问题得到有用结果；没有可靠结果时明确说明，不能只承诺或静默退出。至少一个页面请求有任务/工具证据与可听结果或明确失败说明，不必要求每个网站每次都成功。
4. 既有退出重连续讲只做一次保留回归。记录首轮失败；调整播放时机的诊断另列，不用反复重试成功替代原结果。
