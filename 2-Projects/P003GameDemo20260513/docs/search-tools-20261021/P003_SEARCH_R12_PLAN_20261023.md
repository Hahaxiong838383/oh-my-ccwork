# R12：上午真机反馈核对与聊天延迟优先优化

状态：实施计划；通过项以同目录后续 R12 验收记录为准。历史 R11 的功能通过不代表本轮通过。

## 目标与取舍

最高优先级是普通聊天响应不明显回退、尽早说到实质答案。搜索在后台执行，搜索结果继续让路于用户说话。承接音先响、任务 ready、服务端发出音频均不等于设备听到了答案。

- 普通聊天不增加模型路由调用、网络等待或统一防抖。
- 安全输出按 Worker 已支持的句界放行；逗号跨片段的虚假执行承诺仍拦截。
- 不缩短 ASR 判停、不改变首句协议与退出权威来制造表面提速。
- 不用更长的承接音遮掩慢回答。普通灰度轮选语义桶中最短完整承接音；插话轮保留原策略。
- 慢 TTS 连接只增加一次有上限、可取消的备用握手。全候选进程最多两个并行备用；没有容量时不排队。

## 实现范围

1. Brain `search-chat-policy.ts`：安全分号、波浪号、省略号边界与既有 Worker 对齐；跨token误承诺继续测试。
2. Worker `search_tasks.rs`：澄清后的限定裸主题续句；完整问题、超时、取消、新查询、热配置天气和无关闲聊分开处理。确认话术缩短为“好，我查一下。”，澄清为“想查什么？”。
3. Worker `tts.rs`：记录预连接等待、提供商首包、完整首PCM时间；等待预连接被取消时终止子任务；`P003_TTS_LATENCY_V1=1` 下，首连接650ms未完成才启动一次备用，健康连接不增加等待。
4. Worker `pipeline.rs`：同开关仅在灰度搜索会话启用最短完整承接音，保留插话行为。

裸主题续句是有限规则，并非任意 ASR 分片重组。超过1200ms或已经提交的查询不自动无限合并；仍需真机复测停顿差异。
