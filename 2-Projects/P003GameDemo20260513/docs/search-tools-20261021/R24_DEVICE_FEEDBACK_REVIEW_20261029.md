### 1. 取消搜索误变成退出聊天

房间尾段 `1793239598`，任务 `356bee74-8492-4a4f-8f0c-5878a3a69d23`：

2. 10:06:55.054，ASR final 为“不用了”。
3. 10:06:56.216，Worker 记录 `session_exit utterance swallowed`，path=exact。
4. 10:06:56.217 发出 session_exit 信令；10:06:56.352 才出现后半句“我们聊别的”。
5. 10:06:56.434 设备断开，房间清理。没有该天气结果的正文发布。

源码依据：Worker `src/textproc.rs` 默认退出词含“不用了”；`src/pipeline.rs` 约 3150—3210 行先处理退出吞句、关闭搜索会话，再进入后续搜索路由。因此本轮不是“取消搜索后聊天继续”，也不是自然闲置关房。任务最终 expired 不能倒推为当时查询失败或取消成功。

建议只在有活动搜索上下文时处理这一冲突：把含明确搜索对象的取消以及该上下文中的模糊“不用了”优先作为停止搜索处理；明确“退出聊天／不聊了”仍走既有退出合同。没有活动搜索时保持原语义。不要给所有普通聊天增加拼句等待，避免响应变慢。

## 延迟结论与最小收口条件

两次天气伴随小猫聊天，提交至正文首帧约 1.47 / 1.40 秒；附件复测估算物理问句结束到相关回复约 2.6 秒。两种计时起点不同，不能相加、互换或称为跨机性能对比。且两次聊天提交时天气已经 ready，不能写作正在远程取数的压力样本。

下一轮只验以下必需项：

1. **取消保留聊天**：查询后说“不要查了，我们聊别的”“不用了，聊小猫吧”，不退出、不补播旧结果、能够继续聊；明确“退出聊天”仍退出。覆盖分段输入，关键路径至少各 3 次。
