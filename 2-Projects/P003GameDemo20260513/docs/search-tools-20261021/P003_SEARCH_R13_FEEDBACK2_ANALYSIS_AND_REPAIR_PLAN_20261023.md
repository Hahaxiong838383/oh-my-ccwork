源码核实的三个缺口：

1. **附和保护没覆盖这条路径。** 线上BACKCHANNEL_MODE未配置，解析为observe；默认仅对至少120个LLM字的长回复观察。BackgroundSay的`llm_chars`初始化为0，只有Reply流分支递增；搜索结果走BackgroundSay，33字内容也低于120。只把模式改为enforce，或只把搜索字数填进去，都不足以解决。
2. **搜索阶段与聊天上下文脱节。** 搜索任务和BackgroundSay刻意不进入普通聊天历史；短输入转成chat时，模型仍能看到之前的取名问答，却不知道刚刚转到搜索。隔离网页正文是正确边界，但需要补“当前正在搜索/播报”的临时状态。当前Brain会丢弃Worker messages里的system角色，因此只给Worker加system提示也不会生效。
3. **中断执行先于任务语义处理。** 普通commit会先hard_abort_current，再走search.interpret。附和保护必须在硬打断前做本地判断，不能等远端路由或模型返回后补救。

附带一次capture_frame短暂失败发生在abort之后，并在约22ms后重试成功；它不是本次转回旧话题的起因。不能据此先改网络或播放器重试。

Worker新SearchSession的remainder为空；Drop调用`/session/cancel`；Brain取消旧session任务并删除result；原接口还要求subject和session同时相同。必须新增受控恢复协议，而不能删除session校验或只按SN开放旧任务。

**进度问题必须先补：** BackgroundSay在整段synthesize完成后才登记文本/音频映射。流式PCM已发出而合成还没结束时被打断，会把“已播5秒”记成“0字”。单纯保存remainder会造成恢复后从头重播。首版应采用保守句级游标：确认完整发布的句子才推进，未完成句可从句首重播，不承诺字级精确续讲，也不把服务端发布当成设备实听。

## 3. 延迟必须分层，不能统一归因TTS

- 用例5本次搜索提示50ms、正文2.85秒，快提示和取数均起效，但功能仍因后续误打断失败。
- 上轮补测的搜索正文8.20秒长尾仍有效，主要等待在预连接阶段，不因本次样本较快而删掉。
- **本次17:54:24的普通聊天还有约6.70秒正文首帧慢样本。** 同轮LLM TTFT=6257ms，TTS实际预连接等待=0ms、provider TTFB=277ms；虽有慢预连接备用日志，握手已与LLM并行完成。该轮主要等在LLM请求首字阶段，不能归成TTS预连接阻塞。LLM TTFT包含Brain路径及上游等待，现有日志不足以再细分为哪一方。

这说明不能宣称普通聊天已全面无长尾；也没有同音频现役对照证明这6.70秒由搜索引入。方案保持普通聊天零新增远程等待，把LLM、TTS、排队、承接音分开记录；不通过全局延长判停来拼句。

## 4. 方案取舍

| 方案 | 收益 | 问题 | 结论 |
|---|---|---|---|
| 只开全局附和开关/降阈值 | 改动少 | 搜索计数仍为0；改变所有普通聊天的打断语义；不能修续讲 | 不采用 |
| 搜索播报专用附和处理＋临时阶段上下文＋受控短期恢复 | 对准两项失败，普通聊天不加网络等待，边界可测 | 需要Worker/Brain协议和进度配合 | **推荐** |
| 搜索结果全部写入聊天长期记忆 | 看起来上下文连续 | 网页内容污染人格/记忆，恢复范围难控，回滚复杂 | 不采用 |

推荐分开交付：

1. **R14-A，先修用例5。** 仅在真实搜索结果正在播报时，将严格命中的短附和当作继续听；停止、退出、取消、改查、完整新话题照常立即处理。新聊天请求可带经过认证的枚举型搜索阶段提示，Brain只在本轮生成使用，不放进conversation/history/画像抽取。原普通聊天附和策略不变。
2. **R14-B，补进度与跨会话。** 保留同设备、同授权归属最近一条ready结果，绝对期限为ready后5分钟且不超过灰度截止。退出只关闭会话与在途查询；已就绪结果可短期恢复。新会话不自动播，明确续讲才异步领取新播放授权。取消、改查替代、撤权、期限到达立即不可恢复。Brain重启或进度证据不完整应明确降级，不冒称无缝恢复。
3. **R14-C，延迟与混合对话验收。** 为被打断轮保留阶段计时，分别验证LLM与TTS慢样本；不先加更多竞速请求。按相同音频验证普通聊天，功能正确和速度单独判定。

授权隔离还发现一个需要补入设计的现实约束：候选和现役devices.db是不同文件，当前映射也存在差异。不能把候选的旧绑定快照当当前归属。恢复验证应读取现役台账的最小授权字段（只读连接），同时保留候选账号隔离；快照、account或parent映射变化时使旧恢复记录失效。此读取仅发生在后台搜索接单/恢复/验证，不进入普通聊天主循环。
