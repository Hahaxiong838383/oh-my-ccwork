# 小可AI：叠加后台搜索后的真机体验用例

设备：BJP00326070803800006（末8位03800006）。软件：353 / 1.2.2-canary.339，已由川哥确认。测试日期：2026年10月22日，北京时间。

**是否已开窗、实际起止时间，以配套最新开窗回执为准；本文件本身不是开窗成功通知。** 当前范围为P1网页搜索，P2工具调用和受控网页抓取需P1通过后另行开放。

## 开始前

设备保持联网、有足够音量。结束之前的对话，回到主界面等待约10秒，再通过平时使用的入口进入小可对话；无需换包或重新安装。不要把另一台的对话操作在本机上同时进行。测试人记录设备显示时间与手机北京时间是否一致。

目标是实际体验“搜索在后台跑、前台继续聊天、合适时机补充结果”。**听到了什么、什么时候听到，才算体验证据**；屏幕有字幕或服务器显示发送成功不能替代实听。

## 先用5分钟跑通

1. 说“帮我查一下今天北京的天气”。紧接着说“我今天画了一只小猫”，再聊“我给它画了蓝色眼睛”“你觉得它该叫什么名字”。
2. 停止说话，等结果补充。听是否说清城市、日期和结论，是否有字幕，是否打断了刚才的聊天。
3. 再搜索“帮我查一下今天上海的天气”，播报中说“先停一下”，接着聊一句其他话题，再说“继续刚才的搜索结果”。
4. 新开一轮搜索后说“取消搜索”；等一会儿，确认不会迟到补播已取消的结果。
5. 退出对话、重新进入，说一句普通问候，再发一次明确搜索。

任一步出现卡死、持续无声或错误串台，先记录时间，不必强行做完全部用例。一次失败不反复连喊十次，避免排队与重复识别混在一起。

## 完整用例表

| 编号 | 直接照着说/操作 | 预期表现与观察点 |
|---|---|---|
| S01 普通聊天 | “你好小可，我今天画了一只猫。”再聊两轮 | 正常回应，风格基本延续；不因未发搜索而主动声称正在联网查询。 |
| S02 明确搜索 | “帮我查一下今天北京的天气。”随后安静等待 | 确实完成检索后给结果或明确失败；城市/日期正确；不能把“我去查查”当已经查到。 |
| S03 搜索中连聊 | 发S02，紧接着聊小猫，连续聊三轮 | 普通对话能继续，不要求用户等搜索结束；记录每轮是否有正常回答，是否丢句或明显拖慢。 |
| S04 空闲补播 | 搜索期间保持聊天，最后停止说话 | 结果应等用户和小可当前回复结束后补充，不抢正在说的话；无重复完整播报。若一直没有结果，30秒记一次异常，继续观察到60秒，保留时间。 |
| S05 初段插话 | 搜索结果刚开始播时说“先停一下，我想问别的” | 及时停播或暂停并接住新话题；观察尾音、明显拖延、字幕与实际声音差异。极早打断短段重复属于待验问题，要记录。 |
| S06 中段插话 | 结果播到一半时说“先停一下，我们聊小猫吧” | 能打断并聊新话题；之后不自行整段重播旧结果。 |
| S07 显式续讲 | S06后说“继续刚才的搜索结果” | 在结果有效期内尽量接着剩余内容讲；不倒退整段。每次结果只保留有限时间（约5分钟），过期应说明并可重新搜索。 |
| S08 连续打断 | 续讲后再次插话，再请求续讲 | 不死锁、不突然无声、不越讲越往前退；记录每次接续位置。 |
| S09 查询中取消 | 发搜索后立刻说“取消搜索”或“别查了” | 确认取消后不再开始旧结果播报；若原结果已在播，少量缓冲尾音单独记录，不当新结果。 |
| S10 播报中取消 | 结果播报时说“取消搜索”，再聊普通话题 | 不再续播该结果；正常聊天可继续；不能只口头答应取消而后继续完整播报。 |
| S11 改查 | “帮我查一下今天北京的天气”，紧接“改查上海的天气” | 最终对应上海；原北京结果不应迟到盖过新查询。若识别错城市，记录字幕与实听。 |
| S12 搜索中退出 | 发搜索后返回主界面；过几秒重新进入，普通聊天 | 旧会话的结果不串入新会话；新发搜索仍可用。关闭窗口后重进应恢复普通小可链路。 |
| S13 断网重连 | 仅测试设备短暂断开Wi-Fi，再恢复；不要改服务器或其他设备 | 能按客户端既有机制重新连上；旧任务不突然跨会话补播。记录断网和恢复时间。 |
| S14 长会话 | 上午/下午/晚间各做几次搜索与普通聊天，间隔正常使用 | 无越来越慢、持续无声、反复断开或跨会话串结果。低样本仅算体验，不等于压力验收。 |
| S15 内容质量 | “帮我查一下故宫周一开放吗”“帮我查一下大熊猫为什么被叫作活化石”“帮我查一下中国下一次可见的月食是什么时候” | 关注地点/日期/适用条件、可靠来源、儿童能否理解；不确定就明确说，不编造查到。时效答案人工与官方来源核对。 |
| S16 搜索未成功 | 自然遇到超时、无结果时继续聊一句普通话题 | 能明确表达未查到/暂不可用，普通聊天不跟着卡死；不要把失败的查询内容包装成查到的事实。无需持有人做故障注入。 |
| S17 到期回切 | 回执截止时间到达后结束旧会话、返回主界面重进 | 测试会话到期会结束；重新进入继续普通对话，搜索灰度不再生效。不是在原会话内无缝换服务。 |

建议先把S01～S12各跑一遍，有问题就反馈；其他时间自由体验。P1问题定位后再增加重复样本，不要求先完成整套普通聊天基线才能体验搜索。

当前单设备按北京时间每日最多100条搜索任务（取消和改查也会消耗名额）；到限时记录提示并反馈，不会因此关闭普通聊天。请按正常交互节奏测试，不连续刷请求。

## 对照设备怎么用

另一台维持现役普通聊天，不开搜索。尽量使用相同网络、相同地点与音量、相近的软件版本、同一测试人和相同话题；分别记录设备、版本、时间、首声体感、是否漏答。设备硬件/网络/人格不同会影响结果，所以只作为辅助对照，不把差异直接归因于搜索，也不宣称严格同机性能验收通过。

## 出现异常时

记录北京时间（精确到秒）、用例编号、当时说的话、字幕/画面、实际听到的内容和等待时长。方便时截屏或录屏，避免拍到无关个人信息。反馈给川哥后由服务端按同一时段对账。

轻微问题：结束对话后重新进入重测一次，记录是否恢复。严重无声/卡死/串台：停止连续搜索，退出对话并反馈，服务端关闭这台的灰度；收到关闭确认后重进即可恢复正常链路。**窗口仍开时重进不等于退出灰度**，不要把“重连成功”当作已恢复现役。无需清数据或卸载APK。
