对应两间会话的设备网络定位记录都为 `ready / 北京市`，在请求发生前已就绪且未过期。它只能证明IP服务返回了北京，不能证明设备物理位置一定在北京。

实际错误链条：

1. Worker `search_routing.rs` 的 `weather_place_words` 依次删掉天气词、时间词与语气词，把剩余汉字当地点。
2. “下不下雨”删掉“下雨”和“不”后残留“下”；复合问句还残留“放学适合打球”。
3. `expanded_weather` 只检查剩余文字长度及汉字范围，未确认它是否为有效地点，就生成 `place_weather`。自动IP定位只在 `auto_weather` 分支生效，因此被绕开。
4. “改查成都”被ASR识别为“该插成都”，未命中改查控制词；天气规则仍启动普通搜索，整个“该插成都”被当成城市。这同时影响地点和 replace 语义。
5. Brain `FixedWeather.run` 先执行 `resolveWeatherPlace`，找不到上述地点即报错，尚未调用百度或墨迹。这是三次失败与限流无关的直接依据。

本轮日志未检出明确HTTP 429、天气限流或配额耗尽错误；这个范围结论不外推成“上游永不限流”。已有百度适配器设有5分钟缓存、同查询请求合并、30秒失败冷却、每分钟最多30次新请求；这些是本地限制，不是上游承诺的配额。

**换天气源无法单独修复：向任何API提交“下放学适合打球”，仍然查不到正确城市。主修在云端 Worker；Brain 配套加强参数和错误分类。无需为这个根因先发布安卓APK。** ASR严重漏字/没提交语音属于另一层，不能靠天气API恢复。

### 官方接口、费用与能力边界

- **高德**：官方天气API提供实况、按日预报和reporttime；没有在该基础接口中提供分钟降雨/AQI字段。不能凭按日数据承诺“17:30学校操场不会下雨”。[接口文档](https://lbs.amap.com/api/webservice/guide/api/weatherinfo)
- **高德额度**：当前官方计费表列个人认证天气 **5,000次/月、3QPS**，不是5,000次/天；天气价格列30元/万次，配额内减免，最终以账号控制台权益为准。两台设备每台每天20次、每次1个接口约1,200次/月；若每次同时查实况和预报约2,400次/月，均未计其他应用共享用量，缓存可降低实际请求。[官方计费表](https://lbs.amap.com/pages/base_service_price)
- **高德IP定位**：可返回城市/adcode，基础接口仅支持国内IPv4。若后续采用，必须显式传可信入口提取的设备IP，不能省略IP后定位到云服务器。当前IP9已经返回有效城市，本次不必顺手替换定位服务。[IP文档](https://lbs.amap.com/api/webservice/guide/api/ipconfig)
- **彩云**：官方支持按经纬度调用和分钟级降水，但具体API权限、有效期、QPS及价格取决于套餐。最新计费文档要求在控制台查价，公开旧价目表/旧免费额度存在不同口径，本报告不承诺固定免费额度或用旧价格代替当前报价。[计费](https://docs.caiyunapp.com/weather-api/billing.html) · [速率](https://docs.caiyunapp.com/weather-api/ratelimit.html) · [数据覆盖](https://docs.caiyunapp.com/weather-api/v2/v2.6/tables/coverage.html)
- **公开网页源**：无需Key不等于无限流量或稳定API。Get_Weather与weather-zh都主要依赖中国天气网，不构成两家独立数据源。保留百度作为已有备用比同时接两套同源爬虫更简单。

## 6. 建议的最小实施顺序

### A. 先修本次常规表达，继续使用现有天气源

1. Worker解析改为有效地名实体识别与天气意图分离；仅有“这里/本地”时使用当前设备IP，附加“放学适合打球”保留为回答需求，不当城市。显式未知城市要澄清，不能静默改成本地；同名市区结合明确省份或当前省份消歧。
2. 把“下不下雨”等正常表达作为整组处理。不要无休止扩大删除词表，也不要把所有“打球/出门”自动当成搜索。
3. “该插成都”仅在天气/已有搜索及唯一有效地名上下文做有限容错，并保留replace语义；无ASR文本不能补造控制指令，不做全局同音替换。
4. Brain再核地点、时间范围及能力，错误分成地点、定位、上游超时/限流、数据过期。后台保留具体原因码，语音提示说明真实原因。
5. 如果只有日级预报，回答覆盖今天总体天气，并说明不足以确定放学那个时段；运动建议要区分有依据的天气信息和一般建议。

改动位置：Worker `src/search_routing.rs`、必要时 `src/search_policy.rs` 及相应测试；Brain `src/tools/search-runtime.ts`、`weather-places.ts` 与适配器错误处理/测试。路由预览与Worker共用实现，需一同构建、核SHA。

### B. 一个正式源加一个已有备用

建议拓扑：**可信设备IP/显式地点 → 规范行政区 → 高德天气（主候选） → 现有百度备用**。当前墨迹保留既有受支持范围，避免再一次接入四套实现。

- 高德需准备Web服务Key和控制台权限；本轮没有读取或创建该Key。Key仅服务器保存，不入前端、Git或日志。
- Brain新增 `amap-weather.ts` 和按行政区编码的映射；现有天气站号不能直接拿来作adcode。
- 按需查实况或预报，复用连接、城市/指标缓存、同请求合并、取消传播；遇到配额不足/429不循环重试，以总预算限制主备等待。
- 沿用现有后台任务，不在正常聊天前新增网络请求、LLM分类或MCP往返。候选源可按两台设备配置回切，普通聊天优先。
- **时效规则不能照抄**：高德预报每天约8/11/18点更新，实况每小时多次；现有百度2小时校验不能直接套到高德日预报，否则会制造新的误拒。按数据类型、reporttime和目标日期分别校验。[官方更新说明](https://lbs.amap.com/api/webservice/guide/api/weatherinfo)
- 如果重点是“放学几时下雨、多久停雨”，再选彩云逐小时能力；IP定位到城市中心只能报城市级参考，不能假装获得学校操场的精确坐标。

粗略工作量判断：A为小范围云端修复和回归；B为中等量适配器、城市编码与额度/时效验证；彩云额外增加地点精度、小时范围及权限处理。具体工期需以Key可用和隔离联调结果为准，不把研究结论写成已集成。
