## 开始测试

1. 完全退出当前语音会话，回到小可入口，再进入一轮新会话；仅静音/亮灭屏不算重新进入。
2. 先说“你好，给我讲一句关于小猫的话”，确认能听到普通回答。
3. 一次只做一个用例，记北京时间到秒。可录屏/录像帮助对齐声音，但不要发送凭据、私人正文或不必要的个人信息。
4. 查询使用明确话术“帮我查一下……”或“查找……”。搜索结果没有当前可靠资料时，明确说不能确认是正确行为，不能编造天气/日期。

## 核心体验用例

| 编号 | 可以照着说/操作 | 预期与记录重点 |
|---|---|---|
| S01 搜索与日常聊天 | “帮我查一下今天北京的天气。”听到承接语后马上说“我今天画了一只小猫。” | 正常回应小猫话题；查询在后台继续，不因等待搜索而长时间卡住。记录承接语、普通回答与搜索答案是否都实际听到。 |
| S02 空闲补播 | 完成S01后保持安静，暂时不要退出。 | 在普通回答结束后空闲时补充搜索结果。结果已准备好时，补播首音目标≤3秒；如果尚未返回可更久，应记录实际时间。当前可靠证据不足可明确兜底。不能只凭字幕判定听到。 |
| S04 极早插话后补播（重点，重复10轮） | 发起查询后继续聊；若结果刚开口、尚未听清完整一句，就说“我还想给小猫画一顶帽子。”随后安静等待。 | 先回应聊天；符合极早打断条件的结果，应在空闲后自动补播一次。服务端判据是播放进度不足1秒且未完整播完一段，人工不必掐毫秒；记录实际起声和插话时刻，服务端后续判定是否命中。不可把较晚插话误判为漏补播。 |
| S05 再次插话 | S04补播刚开始，再说“小猫还可以画成什么颜色？”随后安静。 | 先回应普通聊天；同一搜索不应第三次自动抢播。需要时主动续讲。 |
| S06 已听清后的插话 | 听搜索结果说了约2～3秒后说“先说说小猫吧。” | 停止搜索播报，继续普通聊天；已明显播出的结果不应不断自动重播。 |
| S07 显式续讲 | 在S06后5分钟内说“继续刚才的搜索结果。” | 接着剩余内容讲；极短语段可能少量重读，记录范围。超过原5分钟、已取消或退出重连后，旧结果不得复活。 |
| S08 停止与取消 | 结果起播时说“停一下。”安静观察；再说“不用查了，取消刚才的搜索。” | 识别到“停一下”后应阻止本轮自动补播；明确取消后，不应迟到播出旧搜索结果。收到取消确认再继续聊天。 |
| S09 改查 | “帮我查一下今天北京的天气。”随后说“改查今天上海的天气。” | 按新主题查询，之后不能把旧北京结果当上海答案。记录是否听到更换确认、是否有旧结果迟到。 |
| S10 自然表达 | “查找今天北京天气。”另开一轮说“帮我查一下”，短暂停顿后3秒内补“今天上海的天气”。 | 完整“查找”能接单；短时补全明确公共主题可衔接。无关聊天不应被拼接成查询。连续完整一句仍是最稳定测试方法。 |
| S11 无可靠资料 | “帮我查一下北京2000年1月1日的天气。” | 查不到对应历史资料时明确不能确认；不能拿今天的天气回答历史日期。 |
| S12 退出与重连 | 发起查询后主动退出，再重新进入，先普通聊天。 | 不补播上一个会话的旧结果；新查询需重新明确发起。窗口内重连仍进入搜索灰度，不代表退回普通版本。 |
| S13 普通聊天基线 | 用本机和另一台非灰度内测设备分别说同一句小猫话题。 | 比较回应速度、声音连续性、是否误触发查询/反复询问姓名年龄。跨设备比较仅作体验参考，不能写成同机性能统计通过。 |

S04每轮建议换一轮新会话或不同明确查询。区分三种情况：①确实命中极早打断后成功补播；②实际打断较晚，按合同等待显式续讲；③过早退出，无法继续观察。三类分别统计，不把所有情况都写“通过”。

## 尚待核实的边界

- **v319曾在普通回答结束约5～6秒后退出会话。** 本次云端未改Android退出逻辑，仍需复验；若复现，请记录最后回答结束、画面退出和取消/断开时刻。端侧同事补退出reason、静默计时器启动/重置/触发及RTC断开原因，无需提供用户原始正文。
- 单字“停”曾在一次合成语音中没有被识别为有效文字；优先使用“停一下”或明确的取消整句。如果没停住，记录识别文字与声音，不把它当作已经取消。
- 搜索来源受审核范围与时效约束；带来源不保证答案完整，发现知识简化、日期不对或内容不完整也应反馈。
- 服务端完成播报不代表设备扬声器确实发声。请分别填写“屏幕文字”“实际听到的声音”“是否被截断”。
