## 本轮经验与已沉淀方法

- 独立端口、健康200、普通聊天成功不足以验证搜索。先跑一次接单→来源→播报→回执的功能链，才启动大矩阵。
- 派单名称必须与实际SDK/runtime注册方式一致，不能认为目录隔离就等于派单隔离。本项目使用固定agent名称；模型、SDK推荐能力需先核实际runtime支持。
- 复制环境时检索所有固定agent、URL路径、socket、数据路径及权限读取点。只搜agent字符串会漏掉任务客户端白名单。
- 阶段部署串行：传输成功→目标文件真实存在且哈希一致→服务健康→运行PID的exe哈希→功能探针。初次文件重命名遗漏和过早启动探针都留作失败记录。
- 单字附和无ASR时不能用“播报继续了”冒称识别通过；错误说明有音频时也不能用“首声到了”冒称搜索结果通过。
- 原性能失败与预算继续保留；新增完整合成档案、独立identity的实验单列，不能与旧空档案样本拼接或重置原同轮预算。
