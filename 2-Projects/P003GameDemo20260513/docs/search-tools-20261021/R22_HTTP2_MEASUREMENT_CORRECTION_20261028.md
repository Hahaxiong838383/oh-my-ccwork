# R22 HTTP/2 计时归属纠正

2026-10-28 13:00，北京时间。**正式批次仍在运行，本记录不构成发布通过。**

原统计以“开始发送聊天音频到下一步骤”的时间段统计全部提交和正文。实际记录证明，查询尾句的迟到转写、以及在当前输入前已开始的查询尾句回复，可能落入该时间段。于是当前聊天已经正常回答，却被记成两次输入或两次正文而排除。普通聊天组没有此前查询，仍沿用原结果。

具体例：mixed 第0对，查询尾句在聊天音频开始后307ms才收到字幕；真正的当前聊天在2607ms收到字幕。第7对查询尾句的回复先开始，当前聊天的正文属于另一个turn_id。两个回复不能用同一时间段粗略计数。本记录不将查询尾句误识别或额外回答认定为已修复。

纠正方法：

1. 用A侧单一实际聊天转写，匹配B侧完全一致的目标转写及唯一提交。保留真正的聊天转写不同、拆句、缺失和版本/画像不同的排除记录。
2. 通过正文事件的turn_id及since_turn_ms反算该轮开始时刻，只关联目标提交区间内开始的唯一普通正文。单独排除有明确任务日志的后台播报，以及在目标提交前已经开始的旧轮正文。
3. 不限制提交到开始或到正文的耗时。14秒慢回复夹具仍计入14秒；只有1ms整数时钟精度容差。多条无法唯一归属的正文按缺失/歧义计入失败，不能选择其中较快的一条。
4. 原始日志、全部尝试、原safe.json、失败任务和原门判定都保留。纠正输出另存corrected-safe.json，不覆盖原结果；不加入pilot、旧版本或补跑样本。

仍使用固定120房、三组各30对尝试、每组至少20有效配对、中位增量≤100ms、经验P90≤300ms、无新增缺正文。生产者的源码、配置、音频、顺序、间隔和计时事件均未修改。普通聊天完整60房/27对原结果保持。

纠正协议在完成93房时落盘，已有样本用于发现测量问题，**不能称为在全部采样前预注册**。剩余原预算继续完成，以验证实际搜索/续讲负载；不因为旧时间段方法的有效数量不足而丢弃剩余有用证据。原统计不能通过的事实仍需在最终验收中列出。纠正后的统计也必须完整结算后达到原门槛，当前小样本结果不是发布依据。

[协议、分析器及夹具](validation/r22-http2/http2-measurement-correction-protocol.json)已落盘。7项夹具检查通过：旧查询回复混入、慢启动/慢正文、缺正文、多个候选正文、后台播报、下一输入回复混入、整数时钟精度。夹具验证统计归属，不替代产品功能或真人实听。
