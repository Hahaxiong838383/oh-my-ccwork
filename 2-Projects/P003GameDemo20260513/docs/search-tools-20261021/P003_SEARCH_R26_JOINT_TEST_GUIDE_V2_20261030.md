## 4. 入房、首句和停止规则

**每次需要新会话时：**按设备既有操作结束旧会话→单独唤醒→记录招呼/提示、端侧实际许可说话节点以及可查的 attempt/trace/room→按当前APK的真实首句合同播放第一句。

- 若当前模式要求招呼结束及端侧收到 `input_ready`，条件到齐后立即播放；若有序首句模式允许更早采集，按该模式已有许可节点播放。不能统一额外等几秒，也不能把云端“已发ready”当端侧已收到。
- 现场拿不到内部事件时，使用该APK原UI认可的说话节点人工触发，保存画面和声音；事件证据标缺失。连UI许可节点都不能确认时记“就绪合同不清、前置阻塞”，不要乱猜播放时机。
- 唤醒后连接超时、提示失败或一直没有就绪：**停止后续文件**，保留原错误。最多一次另run仅唤醒诊断；仍失败则结束云端场景。不要连续唤醒到成功后删除前面的失败。
- 每场景首轮一次。确需诊断最多另run一次，写清只改变哪个因素和目的；首轮与诊断分别计数，不覆盖。连接诊断仍失败时，不继续剩余云端场景。
- 按现有客户端/工具超时判断；无可查超时合同时，单项最多观察30秒后停止并记“30秒观察截止、产品超时合同待核”。这是本轮观察上限，不能当产品允许沉默30秒或验收阈值。
- 新场景开始前确认上个任务已取消/结束或确实退出旧会话；旧结果是否还有效由服务端补查。没有清楚前置状态时标阻塞，禁止清数据库、重装或恢复出厂来凑前置。
- 意外硬件动作、崩溃、连续迟到播报或持续无法退出：停止整轮并留证。Mac停止播放后用既有返回操作结束会话，不反复加指令。

**等待词重叠触发：**第2/3/4/8项沿用“实际可听等待词首声后约200毫秒”的诊断时序；自动化可精确触发则记录实际偏移，人工不能精确时如实填写。若没有等待词或结果已开始，不等一个不存在的词，也不硬算等待场景通过；保留现象，标“等待词缺失”或“前置时序不符”，由服务端对账。该等待词本身也是测试对象。

## 5. 原10场景：话术、触发点和预期

### S01 普通聊天与首句

**前置：**本run已按第4节取得说话许可，无搜索在播。

1. 在最早承诺可说话的节点播放：“我今天有点开心”。
2. 小可本轮正文实际播完后播放：“课间能玩什么小游戏”。

**预期：**两句都能完整接住，有可听、相关的普通聊天正文，接话自然。分别记录源音频真实停说到小可**正文首声**的时间及主观“正常/明显变慢/无声”；招呼、等待词、字幕不算正文。

**失败/阻塞：**首句缺字、漏答、只有等待词、连接失败或答复归属不清。其他设备可做体验参考，单独写版本与条件，不能据此声明严格性能配对通过。

### S02 搜索期间继续聊天，随后空闲补播

1. 播放：“帮我查我的世界基岩版最新正式更新”。
2. 等待词首声后约200毫秒播放：“我今天打球赢了一次”。
3. 不追加问题，听完聊天和之后的搜索反馈。

**预期：**搜索在后台继续，能先接打球话题，空闲后给搜索结果或明确说明暂时查不到；不重复等待、不抢断普通聊天。涉及“最新”时要能核日期/来源，不能仅听见一个版本号就认定正确。

**记录：**两个输入是否完整、聊天正文首声、搜索实际补播时刻、结果有没有来源/时间限制。若搜索正文已开始才插话，标“等待中前置不符”，可记录为正文插话现象，不能替本项通过。

### S03 取消后继续聊天（重点）

1. 播放：“帮我查恐龙为什么会灭绝”。
2. 等待词首声后约200毫秒播放短句：“不用了”。
3. 短句文件结束后紧接播放：“我们聊聊小猫吧”，记录真实句间间隔及是否被识别成同一回合，不人为插入数秒盲等。

**预期：**仍留在聊天，能聊小猫，旧搜索取消，之后不迟到播恐龙结果。

**异常时：**保留“不用了”源音频、设备识别/字幕原样及实际声音。不要因后一句正常就忽略取消失败。若首轮失败，最多另run一次诊断：同样时序只播放“不用了”，不紧接下一句，以区分短句本身和连续输入边界；其成功不能覆盖原连续场景失败。

**服务端补核：**Worker实际收到什么、同一旧任务是否取消、是否有迟到播放。只凭现场没听到旧结果，任务终态仍标“待对账”。

### S04 等待中改查天气（重点）

1. 播放：“查北京今天的天气”。
2. 等待词首声后约200毫秒播放：“改查成都今天的天气”。
3. 听到本轮最终结果或明确失败反馈。

**预期：**改查完整被接住，旧北京任务被替换/停止，实际回答成都的**大致天气**，不播回北京。无需追求街道级位置或分钟级精度。

**失败分开写：**城市错/残句/旧结果迟到/工具真实失败/超时/无数据/长期无声；不要先猜是额度或频控。供应商失败时有诚实可听的反馈可记“失败反馈正常”，本项“天气改查成功”仍未通过。

### S05 成功结果播完后改查

**前置必须在本run成立：**播放“查北京今天的天气”，已经听到可信北京结果并实际播完。

再播放：“改查成都今天的天气”。

**预期：**开始新查询并实际回答成都，不停在“我去查查”，不复述旧北京结果。北京失败或只播等待词时，本项记“前置阻塞”；之后成都单独成功也不能补算本项。

### S06 搜索正文插话，再明确续讲

1. 播放：“帮我查篮球为什么要运球”。
2. 实际搜索正文第一句开始后约200毫秒播放：“等一下，聊聊今天的学校”。
3. 普通聊天正文实际播完后播放：“继续刚才的搜索结果”。

**预期：**正文能被插话打断，能接学校话题，明确续讲后回到这次篮球搜索。未完成句可按既有合同从句首重说，实际缓存尾音照实记。

**记录：**插话起点/正文停点、聊天及续讲首声；服务端补核同任务和播放游标。不能拿字幕完成代替听到完整续讲。

### S07 退出重连，先静默再续讲（重点回归）

1. 新run播放：“帮我查篮球为什么要运球”；等到搜索正文实际开始。
2. 使用设备已有退出操作结束聊天，确认声音停止，记录旧会话结束。
3. 重新唤醒，按真实合同进入新会话；就绪后静默1.5秒，观察是否自动突播旧结果。
4. 再播放：“继续刚才的搜索结果”。

**预期：**旧会话已结束、新会话静默不突播，明确续讲后返回同一有效搜索；若结果已过期，应明确提示重查，不凭空继续。1.5秒只测重连静默，不作为补偿首句就绪的盲等。

**阻塞：**重新入房失败就停止播放续讲，写“重连失败、续讲未测”。现场不知room时记待查，由服务端按时刻核新旧room；第6项同房续讲成功不能替本项通过。

### S08 语音退出并恢复聊天（重点）

1. 播放：“帮我查恐龙为什么会灭绝”。
2. 等待词首声后约200毫秒播放：“算了，退出聊天”。
3. 确认实际退出和声音停止后，重新唤醒，按真实说话许可播放：“我今天有点开心”。

**预期：**完整退出指令被执行，旧结果不迟到，重进可正常聊天。记录完整/残句/没识别、退出动作、停声、重连四个阶段。

返回键/ADB退出仅作失败清理，不能替代语音退出成功。重连失败单独记，不能因退出做到了就把整项通过。

### S09 既有本地硬件控制

按本APK原本地控制模式执行，不统一套云端input_ready；云端入房失败时，该项仍可按本地既有合同单独测。

逐句播放：“把灯打开”→“亮度低一点”→“声音小一点”；每次完成实体观察和前后读数后再下一句。

**预期：**对应灯、亮度、声音确实变化；命令/ACK/读数/实体变化和观察者分栏记录。初始灯已亮不能凭“仍亮着”证明开灯；需改前置状态时现场先确认并记录，不偷偷操作。

设备音量下降是用例动作，记录前后；不改Mac音量。**“升高一点”沿用用户要求跳过，标“用户跳过”，本轮不执行。**

### S10 学生兴趣检索及诚实兜底

分别开独立子run，每次先确认真实连接和说话许可：

- **S10-a：**“帮我查最近有什么适合初中生的科普展”。若缺城市应合理澄清；如追问地点，统一答“成都”，记录澄清回合，不能随便换城市凑结果。
- **S10-b：**“帮我查一条最新的中国航天消息，说一下来源和日期”。
- **S10-c（P2工具观察）：**“帮我读一下央视网国内新闻页面，挑一条能核实日期的新闻，讲两句重点，告诉我来源”。

**预期：**能得到简短、相关、年龄合适且可核来源/日期的答案；证据不足时明确说明暂时无法核实，不编“最新”、不长期沉默。对S10-c，回答正常与实际是否执行Tool Calls/网页抓取分开记录；后者由服务端核实，不能仅凭“我看了网页”判已调用。

真实错误、超时、无数据和未进入工具分别记。没有自然出现失败时，只写“成功路径已测，失败兜底未触发”，不主动断网或改开关制造故障。被入房挡住则“连接阻塞、检索未测”，不能当兜底已验证。

## 6. 短句失败时，如何留下有用证据

不要现场直接归因Mac TTS、声学算法、服务器或频控。保留同一run的以下链路，有哪段记哪段：

**源文件/播放时轴 → 设备采集或发布前证据 → 实际上行/ASR → Worker收到的控制 → 任务终态 → 字幕与实际声音。**

最小现场材料是：完整SN、当前版本、场景/run、准确起止时间、播放文件及哈希、实际听到什么、画面/录音。attempt/trace/room拿不到就写未取到，由服务端按时间/SN反查，不因为缺ID拒绝提交。

有ADB且现场同事具备取证条件时，可用上一交接包内的只读取证工具采集before/after；这是可选诊断手段，不要求为了体验先开放远程、安装新包、清日志或启用额外PCM开关。已有原始日志/WAV/失败一律保留。独立ASR不喂预期答案，近音、说话人不确定保留原样。

正常时序与等待词/正文重叠必须分开run。首轮短句失败后的**一次**诊断可选安静节点播放同一文件，写清变化；若安静成功、重叠失败，两条均保留，原失败仍在。不要再换长句、大音量或反复播放到成功。

## 7. 反馈与收口口径

结果统一使用：**体验符合预期（服务端待对账）/同轮证据通过/失败/前置阻塞/未测/用户跳过/证据不确定**。

- 现场只凭声音和画面能先给体验结果；涉及身份、任务取消/替换、实际工具调用、新旧room的完整技术通过，待同run服务端证据补齐。
- 每次run完整判断，不把上午成功一半、下午成功另一半拼成整场通过；两台设备也不混算。
- 分别统计唯一连接attempt、成功建房/就绪、有效输入和场景完成。多个错误日志可能属于同一attempt，不按日志条数算连接失败率。
