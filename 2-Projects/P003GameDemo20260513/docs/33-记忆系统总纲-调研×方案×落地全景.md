**两代的关系(关键)**:
- docs/17 的**四层心智模型(L0 working / L1 画像 / L2 情节 / L3 图谱)依然成立**,是理解「记忆有哪几种」的最好框架。

## 1. 北极星 vs demo(一张图看清降维)

| 层 | 北极星 PRD V2.0(理想态) | demo P0 落地(docs/29 定稿) |

| 双时间 | bitemporal 区间查询 | 只留 `valid_from/to`+`revision_of` 字段,不做区间查询 |

> **四家共识(最高置信)**:PRD 方向(北极星)对,但 demo 阶段几乎全部降维。不建 Redis/Qdrant/EventStore/Graphiti 任何一个。两周可落。

### 调研的核心结论(三条独立证据链收敛到同一答案)
1. **KidsBench 反推**:K12 没有全局冠军;真实 workload=写极多、读稀但深、高情感连续性(写读比 ~18:1)→ 指向**混合早晚绑定 + 画像为主**,而非纯向量库。
2. **2026 语音工程**:sub-200ms 才自然;检索是主链路延迟瓶颈 → **session 预加载 + 每轮异步写 + 写操作移出关键路径**。
3. **儿童隐私**:COPPA 数据最小化 + 加州 AI 陪伴提醒 + Maryland 拟禁用儿童数据训练 → **本地化、可删除、不训练**。
> → 语音 + 儿童 = 必须轻量、预加载注入、异步写、本地化、可删除、不训练。**结论是「自研」不是「背一个重型系统」。**

## 4. 记忆有哪几种(四层心智模型,源自 docs/17,理解用)

| 层 | 是什么 | 范式 | demo 落地形态(docs/29) |
|---|---|---|---|
| **L0 Working** | 会话内多轮滑动窗口(最近 6-10 轮) | episodic、内存、零延迟 | LLM client 支持 history[];存会话实例,TTL 随连接 |
| **L1 Profile** ★ | 这个孩子的稳定画像(昵称/兴趣/口味/性格/情绪锚点) | semantic、早绑定、结构化可审计 | `profile-store` 投影(热路径只读),由 `memory_events` 同事务重建 |
| **L2 Episodic** ☆ | 重要情感事件片段(带时间戳原文) | episodic、晚绑定、按需检索 | `memory_events` type=episodic;检索 P1 起步用 SQLite FTS5 |
| **L3 图谱** | 事实演变(搬家/换学校)的时序 KG | temporal KG | 远期,数据驱动才上;现有 curriculum-kg 是只读护栏不是这个 |

> **最痛点排序(白纸现状【已验证】)**:① 多轮无上下文 ② 画像存了不用 ③ 零跨会话。L0+L1 解决前两痛、见效最快。

## 5. 当前权威方案(docs/29 工程定稿)

### 5.1 合一架构(turn envelope 为枢纽)

```
[Android 薄壳+WebView]  React FSM(fsmEpoch,UI) / voice-client(playbackGeneration,音频)
        │ WS 带 envelope:{session_id, turn_id, response_id, playback_generation}
        ▼
[Server]  pipeline(activeTurn 守卫)
  ├─ 热路径(只读<50ms,★严禁LLM抽取):profile-store 投影 + curriculum-kg 护栏
  └─ 冷路径(turn后异步):memory-extractor→内存DRAFT→双轴仲裁→commit gate
        commit 前校验 turn_id==activeTurn,不匹配→丢弃(=打断回滚)
        ▼
[SQLite]  append-only memory_events ──同事务──► profile-store 投影
```
> **交汇枢纽**:`turn_id` 是交互轮次与记忆 provenance 的唯一纽带。打断时 `activeTurn++`,旧 turn 的 extractor 写库前发现不匹配→丢弃→数据库零污染。**同一守卫,既治丝滑打断,又治记忆不脏写。**

### 5.2 现状已有(均【已验证】读过源码,别重建)
- `profile-store.ts` = 当前画像投影雏形(L1)
- `memory-extractor.ts` = turn 后异步抽取 + prompt 注入防护 + 并发 lost-update 防护(冷路径雏形)
- `pipeline.ts` `activeTurn` = interrupt 守卫雏形
- `curriculum-kg.ts` = 纯内存只读 10685 节点 match<10ms(热路径只读投影 + 延迟铁律)

### 5.3 P0 只补 5 项
| # | 补什么 |
|---|---|
| P0-1 | SQLite 新增 `memory_events` append-only 表(schema 见 §6) |
| P0-2 | extractor 改双步:先 `INSERT event` → **同事务**重建 profile 投影 |
| P0-3 | **commit gate**:ASR partial 永不写;只有 `definite` final 且 `turn_id==activeTurn` 才进抽取;被 `tts.turn_discard` 的轮次不写 |
| P0-4 | **双轴仲裁**:authority(user_explicit/correction/parent/tool/llm)× observation(asr_final/uncertain/repeated) |
| P0-5 | correction 抢占 supersede + LLM 推断默认 pending(复现 ≥2 次才进画像) |

### 5.4 五个关键修正(team 揪出的「金子」,这些最值钱)
1. **双轴仲裁**(修 PRD):P003 所有儿童输入都过 ASR,若 ASR 一概低优则几乎没事实能 commit → 必须拆 authority×observation。
2. **assistant 文本默认禁写长期记忆**:最隐蔽脏写是「小可说一半被打断」(「下一关去火星——」「不要!」→ 不能写 `已进火星`)。game_progress 只由游戏状态机/tool 写。
3. **冲突变「主动反问」体验亮点**(最妙产品洞察):发现冲突别后台默默纠错,让小可主动问「你昨天不是说最喜欢苹果吗?」→ 工程难题转护城河。
4. **伪纠错防护**:ASR 把「我想看」听成「不要看」会篡改画像 → 纠错需强否定句式(「不是…是…」/「我没有…」)才认,否则降级 pending。
5. **node:sqlite 别卡首 token**:`DatabaseSync` 是同步 API,event append/投影重建绝不能在 ASR-final→LLM first token 之间,放 turn 后冷路径。

## 6. 数据模型 `memory_events`(P0 落地版)

```sql
CREATE TABLE memory_events (
  event_id      TEXT PRIMARY KEY,
  session_id    TEXT,
  child_id      TEXT,
  turn_id       INTEGER,                 -- 与交互轮次同纽带,commit gate 校验用
  response_id   TEXT,                    -- 区分同 user turn 下不同 assistant 输出
  type          TEXT,                    -- fact|preference|skill_state|episodic|correction|invalidation|game_progress
  subject       TEXT,
  predicate     TEXT,
  object_json   TEXT,
  source_authority    TEXT,              -- user_explicit|user_correction|parent_edit|tool|game_state|llm_inference
  observation_quality TEXT,              -- asr_final|asr_uncertain|repeated|manual
  stability     TEXT,                    -- ephemeral|stable|persistent
  sensitivity   TEXT,                    -- low|medium|high (K12)
  confidence    REAL,                    -- 辅助信号,不作主仲裁
  valid_from    TEXT,
  valid_to      TEXT,                    -- null=当前真值;有值=已关闭历史版本
  tx_time       TEXT,                    -- 不可改
  utterance_ref TEXT,
  revision_of   TEXT,                    -- 版本链;supersede/correction 必填(纠错回溯)
  metadata_json TEXT
);
```
**契约规则(冷路径强制)**:必须有 type + SPO 三元组;只有 COMMITTED 进表;`valid_to==null` 的最高 authority 最新事件 → 投影进 profile(热路径只读);LLM inference 默认 pending 不进 profile,复现 ≥2 升 stable;assistant-derived 默认禁写。
