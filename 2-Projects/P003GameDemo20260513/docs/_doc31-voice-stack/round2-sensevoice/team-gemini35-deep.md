### 架构评审报告：小可端侧 ASR 深度评估与选型决策

#### 【结论先行】
**彻底放弃 SenseVoice-Small，全量采用 Zipformer-zh（Small）作为唯一端侧 ASR 模型。**
cc 的“Zipformer 主力 + SenseVoice 旁路情绪增强”方案在工程落地和儿童真实场景下属于**低 ROI 的过度设计**。实时对话系统的命门在“低延迟判停”和“流畅的字级流式反馈”，Zipformer 在这两点上具备压倒性优势。而 SenseVoice 的端侧模拟流式体验较差（无 Partial 字幕）、判停严重依赖外挂 VAD 延迟高、且其儿童情绪识别在真实场景下准确率较低，不具备生产价值。

---

#### 【焦点问题深度解析】

##### 1. SenseVoice 情绪与事件检测对儿童陪伴的真实价值
- **【推断】情绪标签在中文儿童场景下准确率极低**：SenseVoice-Small 的情绪/事件分类主要在大规模成人普通话及多语言 ASR 语料上训练。5-10 岁儿童的语音声学特征（基频 F0 极高、共振峰偏移、高频喊叫或哭腔）与成人差异巨大，模型极易产生误判（例如：儿童激动的笑声被误判为 ANG/生气，或哭腔被误判为 NEU/中性）。
- **【建议】LLM 消费不可靠信号的风险极大**：如果将高误判率的情绪标签（如 `<SAD>`、`<ANG>`）作为 Prompt 强行喂给云端 LLM，会导致 LLM 产生“莫名其妙的过度安慰或防御反应”，严重破坏对话连续性。相比之下，云端 LLM 直接通过文本中的语气词（如“呜呜”、“哼”、“哇”）来判断情绪，其鲁棒性远超端侧声学情绪模型。
- **【验证】音频事件检测（AED）实用性受限**：`LAUGH`（笑声）在安静环境下较准，但在嘈杂的儿童使用场景（玩具碰撞声、背景电视、TTS 回声泄漏）中误报率较高。

##### 2. 模拟流式 vs 真流式：实时对话与逐字字幕的代价
- **【验证】字幕体验是硬伤（无 Partial）**：SenseVoice 在 `sherpa-onnx` 中是“模拟流式”，其本质是块处理（Non-autoregressive）。这意味着在孩子说话过程中，屏幕**完全无法逐字吐字（没有 Partial 结果）**，必须等待整句说完、VAD 切断后，整句字幕才突然显示。对于注意力集中的儿童，这种视觉“零反馈”会让他们以为系统死机，从而导致重复说话或打断。
- **【验证】判停延迟显著增加**：Zipformer 是真流式 Transducer，能结合 Blank 状态和内部 Decoder 实现较低延迟的自然判停（通常 500-600ms 静音即可确认）。而 SenseVoice 必须完全依赖外挂的 Silero VAD。为了防止儿童说话时正常的停顿、喘息被粗暴切断，VAD 静音阈值通常必须设在 800ms - 1.2s 以上。这直接导致小可的整体交互首包延迟（RTT）增加至少 400ms，对话显得迟钝。

##### 3. 双模型结合（主+旁路）在端侧的工程可行性
- **【推断】内存与能耗超标（中端机硬伤）**：
  - **内存**：Zipformer-zh (small) 仅需约 14MB 权重，运行时内存占用约 30-50MB；SenseVoice-Small（int8 量化）权重近 100MB，运行时内存占用约 120-150MB。双模型并存仅 ASR 运行时就将吞噬近 200MB 内存。在 Android 中端机上，这会显著增加被系统 OOM 杀后台的概率。
  - **算力与发热**：若采用并行旁路，两个 Encoder 同时在 CPU/GPU/NPU 上运行，会导致手机迅速发热并降频，电池消耗极快。
- **【推断】旁路“异步后处理”逻辑上自我矛盾**：若为了省电，在 Zipformer 完成判停后，再异步将音频流送给 SenseVoice 做一次性情绪推理。虽然单次推理仅需约 100ms，但：
  1. 如果 LLM 必须等待这 100ms 的情绪标签，则对话延迟被强行拉长。
  2. 如果 LLM 不等，直接发送 ASR 文本，则得到的情绪标签无法用于当前回复，只能用于下一轮对话，其实时性价值归零。
  因此，无论是“并行流式”还是“串行后处理”，双模型方案均不可行。

---

#### 【最终推荐与落地路径】

**明确推荐**：**单模型方案，仅保留 Zipformer-zh（Small）**。

##### 落地路径：
1. **ASR 选型与精简**：集成 `sherpa-onnx` 中的 `zipformer-zh-small`。确保模型尺寸控制在 15MB 左右，保障冷启动速度和超低内存占用。
2. **端侧判停优化**：弃用火山云的云端判停，完全切换为本地 Zipformer 的 Transducer Endpointing + 辅以轻量级局部 VAD，将判停延迟控制在 500-800ms 的动态区间（根据儿童发音特点微调静音阈值）。
3. **情绪分析平替**：将情绪感知能力完全交由**云端 LLM 进行文本级语义分析**。在 LLM System Prompt 中加入儿童口语化语气词识别规则。
4. **声学事件回退**：若后续产品强烈要求“检测孩子哭声/笑声”，应引入专门的、参数量在 1-2MB 级别的极轻量 AED 专项模型，而不是背负 100MB 的 SenseVoice。

---

#### 【关键风险与应对策略】

1. **AEC（回声消除）失效导致 ASR 自激**
   - **风险**：端侧播放小可的云 TTS 声音时，麦克风会录回小可自己的声音，导致 Zipformer 误识别并触发 LLM 再次回复（陷入无限死循环）。
   - **应对【建议】**：在 WebView/原生播放器播放 TTS 音频时，向本地 ASR 发送“压制/静音”信号，或者在底层开启硬 AEC（Hardware AEC）。如果硬件 AEC 不佳，在播放期间必须对 ASR 进行软屏蔽（Software Muting/Gating）。
2. **童声退化与方言适应性**
   - **风险**：Zipformer-zh-small 在面对儿童普通话不标准、前后鼻音不分、甚至夹杂方言口音时，识别率会有所下降。
   - **应对【建议】**：利用端侧 Web 端的打字机字幕动效，容忍部分错别字（儿童对错别字的敏感度远低于成人），重点优化“语义理解”阶段的模糊匹配（云端 LLM 对错别字有较强的纠错能力）。
