## 0. TL;DR

- 川哥问"给小可接教育知识库"，但真正的问题不是"接哪个数据集"，而是 **"小可要不要、以什么身份懂课程知识"**。
- **核心结论（team 对抗最大收获）**：
  - ❌ **不为"补知识"接 KG**——大模型(gemini/deepseek)已懂 K12 常识，为知识能力接 KG = 过度工程。
  - ✅ **若接，只为"课程安全护栏 + 兴趣→知识点桥接"**：不越级、不乱编教材顺序、把鼓励落到孩子在学的主题。
- **架构**：K12-KGraph 当**条件 context capsule**（intent 门控注入，**绝不常驻、绝不进主链路检索**），SQLite+FTS5 轻量存，复用记忆系统延迟解耦范式。教材 RAG / TQA 只做异步 / 离线，不进实时。
- **前置决策**：做不做 L_curriculum 取决于"小可 demo 要不要学习陪伴场景"。cc 推荐 **先离线用数据验证"裸大模型 vs 加 KG"差距，再决定值不值得做**（呼应 docs/18 数据驱动哲学）。

## 2. 核心结论：KG 价值的重定位

cc 初始主张"接 KG 让小可懂课程"，被 team 两家**共识否定**，重定位为：

**否定**：大模型已覆盖 K12 常识，"讲个分数 / 光合作用"不需要 KG。为"知识能力"接 KG 是过度工程，徒增延迟 / license / 维护三重成本。

**重定位**：KG 真正且**不可被大模型替代**的价值 = **结构**（人教版课程顺序 / 先修关系 / 年级边界），服务于陪伴产品真需要的三件事：

1. **不越级**——不顺口跟一年级孩子讲微积分（年龄/年级边界）。
2. **不乱编教材顺序**——先修关系（"分数前置是除法"）LLM 不一定准，KG 是 ground truth，防幻觉。
3. **兴趣→知识点桥接**——把"孩子喜欢恐龙"自然接到"在学的生物分类"，这是陪伴的高光时刻。

→ **接 KG 的理由从"补知识"改成"课程护栏 + 锚定"。这个重定位决定后面所有架构选择。**

## 3. 架构方案（team 对抗修正后）

### 3.1 致命修正：L_curriculum 是条件 capsule，不是常驻第 4 层

- **cc 原错**：把课程 digest 当第 4 个 block 与【关于这个孩子】**并列常驻**注入 systemPrompt。
- **team 否定**：grok——常驻会稀释人格陪伴 prompt 权重、把陪伴做成半教学；codex——L_world/L_user 是高频人格/关系上下文，L_curriculum 是**条件上下文**，常驻 = 低相关信息长期污染对话 + 浪费 token + 诱导模型主动说教。
- **修正方案**：`assembleSystemPrompt` 里 L_curriculum 走**门控注入**——只有满足以下任一才注入，默认会话不注入：
  - intent gate：孩子主动提到作业 / 知识点 / 学校学习；
  - session flag：家长设置的"学习陪伴模式"；
  - profile confidence：年级 / 章节字段可靠时。
- **门控用后端规则，不用 function-calling**（codex）：低龄语音对话 LLM 工具触发稳定性差，且工具调用回到主链路破坏 TTFT。function-calling 只用于后台 Slow Thinker / 非实时场景。

### 3.2 存储：SQLite + FTS5（不上 NetworkX / LightRAG）

- K12-KGraph < 100MB、节点/边类型固定 → 用项目已有 `node:sqlite` 最省运维。NetworkX 是 Python 生态（引入跨语言服务），LightRAG 对 demo 过重。
- 表设计（codex）：`concepts` / `sections` / `edges` / `aliases` / `text_index`（FTS5）。
- 查询约束：**1 跳 taxonomy + 1 跳 prerequisite**；digest 默认 200–400 中文字，**硬上限 ≤800 token**（防膨胀拖 TTFT）。

### 3.3 字段脆弱性：grade/subject/chapter 必须带 confidence

- **风险（codex，cc 漏点）**：profile 加 grade/subject/current_chapter 看似简单，但来源脆弱——孩子不知教材版本、家长未配置、模型抽取误判、跨地区教材差异。**错误课程锚定比没有锚定更糟**（把小可带偏到错的章节）。
- **方案**：字段带 `provenance / confidence / updated_at`；低置信只用**宽泛年级段**（如"小学中段"）不注入具体章节；教材版本 + 当前进度由**家长端 onboarding 明确选择**，不靠模型猜。

### 3.4 陪伴优先，答疑异步 / 离线

- **路线 A（陪伴锚定，主链）**：顺着在学内容自然聊 / 鼓励 / 引导，只用 KG 结构做轻量锚定。
- **路线 B（答疑讲题）不进实时主链路**：教材 RAG 撞延迟铁律（向量检索 50–300ms 吃光 sub-200ms 预算，arXiv 2603.02206），只能 Slow Thinker 后台预取下一轮注入，或离线。
- **TQA**：不进产品/检索，**保留为离线回归 benchmark**——测"裸 LLM vs KG 注入 vs RAG 增强"三方案的幻觉 / 拒答 / 解释质量（修正 cc 原"完全不接"）。

## 7. 推荐路径 + 待川哥决策

**做不做 L_curriculum 是产品意图问题，cc 不替川哥拍**。三条路：

1. **纯情感陪伴**（grok）：先不做 KG，小可只聊天/鼓励/世界观，课程知识交给大模型自带，资源全投 profile + L_world 迭代。
2. **加轻量课程护栏**（codex + cc）：接 K12-KGraph 当门控 capsule，服务不越级/不乱编/兴趣桥接，陪伴时"懂行"但不变家教。
3. **先离线验证再定**（cc 最推荐）：先用 K12-Bench / TQA 离线测"裸 gemini vs gemini+KG 注入"在课程对齐 / 越级 / 先修上的差距——**差距显著就走 2，差距小就走 1**。最诚实最省，避免拍脑袋（呼应 docs/18 P3"数据驱动才上"）。

> cc 推荐 **3 → (2 或 1)**：用数据证明 KG 有没有真价值，再投工程。若川哥已笃定要"学习陪伴"场景，直接走 2 的轻量门控版即可（~2-3 天，复用记忆系统框架）。

> **2026-06-19 川哥选「先离线验证再定」→ 已执行，见 §8。结果：KG 增益实锤，方案2 技术前提成立。**

## 8. 离线验证实证（2026-06-19 · 川哥选「先验证再定」后执行）

**方法**：从 K12-Bench 抽最吃 KG 的 **Prereq(先修)+Neighbor(邻域)** 两类、覆盖数理化生各 5 题共 **40 题**，对比 arm1 裸模型 vs arm2 KG 子图注入的 multi-select exact-match。题目 id 直接编码目标概念节点 → 1-hop 子图零检索注入。脚本 `experiments/kg-value-verify/run_verify.py`，数据 `/tmp/k12-verify/`（不进 git）。

> ⚠️ **模型 caveat（保真度）**：小可生产用的 gemini 网关 key 当日失效（已知坑），转已验证可用的 codex-api2 网关 **gpt-5.5**。gpt-5.5 比小可的 gemini-3-flash **强** → 增益是**保守下界**：连强模型都从 KG 获显著增益，弱 gemini 只会更需要。

**结果**：

| 指标 | arm1 裸 gpt-5.5 | arm2 +KG | 增益 |
|---|---|---|---|
| **总体 exact-match** | 37.5% | **75.0%** | **+37.5pp** |
| prereq (n=20) | 45% | 85% | +40pp |
| neighbor (n=20) | 30% | 65% | +35pp |
| biology / physics / chem / math | 60 / 30 / 30 / 30% | 100 / 80 / 60 / 60% | 全科显著 |

**净增益分解**：KG 救活 **17** 题、带偏 **2** 题、两者都错 8 题 → **净 +15/40**。

**结论（数据裁决 §6 与 §7 分歧）**：
- ✅ **KG 价值实锤**：救活 17 ≫ 带偏 2，准确率翻倍。**grok「KG 没价值 / 什么都不接」被证伪**；**codex「有条件接」被证实**。方案2（轻量门控护栏）技术前提成立。
- ⚠️ **风险真实但小(5%)**：2 个反例是 KG 1-hop 子图不全 → 模型**过度收窄**（本该多选只选 KG 突出的那个）。neighbor 仍错 6/8 多因子图覆盖不足回退「全选」。**工程含义**：prereq 1-hop 已很好(85%)，neighbor 需 2-hop / 更多关系类型把子图做厚。
- 🎯 **精确表述（防过度解读）**：验证证明的是「**一旦小可进入课程相关对话，KG 能把准确率翻倍**」；**没**证明「孩子日常陪伴高频触发课程需求」（那是产品运营问题，需真实用户数据）。故架构必须 **门控注入**——课程相关才挂 KG，闲聊不挂，与 §3.1 一致。

### 8.1 小可真实模型复测（gemini-3.1-flash-lite-preview，生产有效 key，同批 40 题）

首轮 gpt-5.5 是本地 gemini key 失效时的代推；川哥指出体验台生产 gemini 网关有效 → 用生产 key 复测小可真实模型：

| 模型 | 总体 arm1→arm2 | prereq | neighbor | 净增益 |
|---|---|---|---|---|
| gpt-5.5（强/参考） | 38%→75% (+38pp) | 45→85 (+40) | 30→65 (+35) | 救 17 带 2 |
| **gemini-flash-lite（小可真实）** | **20%→45% (+25pp)** | **35→75 (+40)** | 5→15 (+10) | 救 10 **带 0** |

- ① 裸 gemini(20%) < 裸 gpt-5.5(38%) → **小可真实模型更不懂课程结构、更需要 KG**。
- ② **prereq(先修) 上 gemini 增益 +40pp = 与强模型同等**（35→75 翻倍）——KG 对小可「不越级 / 不乱讲教学顺序」价值实锤。
- ③ neighbor 上 gemini 即使 +KG 也只 15%（flash-lite 天花板，消化不动复杂多选）——这类场景 KG 帮助有限，需更强模型或降优先级。
- ④ **gemini 带偏 0** → KG 对小可纯增益、零带偏风险（裸答太差，KG 只会救不会把对的带错）。

**对决策的影响**：方案2 的技术前提已被数据证明（小可真实模型 prereq 翻倍）。是否现在做取决于川哥对「小可要不要学习陪伴场景」的产品判断；若做，~2-3 天复用记忆框架落地，**neighbor 子图要做厚**（当前 1-hop 不足）。
