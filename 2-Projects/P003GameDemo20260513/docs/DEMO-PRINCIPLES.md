## 一、4 个绝对目标（不可变更）

### 1. 形态：手机横版 800×480 模拟器

- 用户在**手机上**通过 Web 浏览器体验
- **横版**（手机横置或自动横屏）
- 屏幕区域**严格模拟真实硬件 800×480 像素**（aspect ratio 5:3，对齐 1.6 主界面规格）
- 外壳可见或可隐藏，但内部画布永远是 800×480

### 2. 核心功能：小可 AI 实时语音对话

- 像**豆包式**实时语音交互（用户说话 → 小可几乎实时回应）
- 不只是命令理解，**是真正的对话陪伴**
- 这是 demo 的核心卖点 —— 没有它就不是这个 demo
- 端到端延迟目标：**理想 < 1.5s，可接受 ≤ 2.5s**

### 3. 时间：4 天交付

- 4 天 = **4 个工作日**，不是 4 周
- 不能延期，砍范围而不是砍时间
- 后端**先本地跑通**（电脑作服务器），川哥验收后**再迁云端**让手机能公网访问
- 部署链路简单，能跑就行

### 4. 第一原则：demo 优先，不考虑生产

- 跑起来 > 优雅
- 单机能用 > 集群可扩
- 直接调通 > 完美架构
- 砍配置表、砍 9 层抽象、砍 3 份存档冗余、砍状态机泛化 —— 一切为速度让路

## 三、技术选型原则（4 天内能落地的）

| 维度 | 选择 | 理由 |
|---|---|---|
| 前端 | Vite + React + TS + Tailwind | 之前已选，不变 |
| 状态 | **Zustand + 手写 transition function**（XState 砍） | 简单可控 |
| 渲染 | ~~PixiJS~~ → **纯 CSS + Tailwind animation**（V0.5 修正） | 4 天 demo 不需要 2D 引擎，CSS 够用 |
| 后端 | **Node + Hono**（本地 → 阿里云 VPS） | 单文件起服务，部署简单 |
| 实时语音通道 | **WebSocket 流式** | 比 HTTP 轮询低延迟，比 WebRTC 简单 |
| STT | **火山流式 ASR**（主线） / 备：Web Speech | 同厂三段拼装延迟最低 |
| LLM | **豆包 Chat**（主线） / 备：Gemini-3.1-flash-lite-preview（TTFT 1024ms 已实测） | 同厂三段；火山未开通时切 Gemini |
| TTS | **火山 TTS v3 双向流**（主线） / 备：讯飞超拟人 | 同厂三段；火山未开通时切讯飞 |
| 部署 | 本地 → 阿里云 VPS（已有 <阿里云VPS> 经验） | 4 天交付要求快 + 复用已有运维 |

## 四、复盘检查清单（每次开 session 前必读）

1. **手机能不能横屏看到 800×480 画布？** 不能 = 偏离目标 1
2. **能不能跟小可说话听到回应？** 不能 = 偏离目标 2
3. **从今天起到交付还剩几天？** 超出 4 天 = 偏离目标 3
4. **是不是在为"生产化"做事？**（配置表/抽象/可观测/容错）是 = 偏离目标 4
5. **写的代码是不是把模拟器/调试控件混进了游戏画布？**（V0.5 新增）是 = 违反画内/画外铁律

任一偏离 → **立即砍范围，不要继续投入**。

## 四点五、画内 / 画外铁律（V0.5 新增）

- **画内（800×480 游戏画布）**：所有游戏 UI（剧情场景、HUD、按钮、动画、字幕、Modal）
- **画外（设备外壳调试区）**：所有模拟器 / 调试控件 / 硬件按键
  - VoiceButton（模拟硬件麦克风按键）
  - 配网模拟（📵未配网 / ✅完成配网）
  - WiFi 信号 4 档下拉
  - 跳关 10 项下拉
  - 键盘快捷键 1234567890

代码审查时 hard rule：模拟器/调试控件**禁止**出现在 `<div className="screen-canvas">` 子树内。
