### 3. TTS sayDirect 通道（绕过 ASR+LLM）

新增"直接 TTS 一段固定文本"通道（用于开机欢迎语 / AskMode 引导 / 其它无 ASR 触发的场景）：

- **协议新增**：`{ type: 'tts.say'; text: string }` 客户端 → 服务端
- **server**：`pipeline.speakDirect(text)` 直接 `tts.start()` + `feed(text)` + `finish()`，复用现有 onAudio / onSentenceBreak / onSentenceEnd 转发
- **client**：`voice-client.sayDirect(text)` —— bargeIn 后发送 ws 消息
- **playback 架构改进**：voice-client 内部统一播放（`case 'tts.audio': void this.playAudioChunk(msg.mp3Base64)`），不再依赖外部监听器（VoiceButton 等）

## 4 大踩坑链（含修复）

### 坑 1：字幕条重叠（PNG 自带 vs 代码渲染）
- 现象：SetupGuide 显示两条"请保持手机接近设备"字幕
- 根因：cc 误以为代码字幕条是必要的，但 PNG 本身已经烧录了字幕
- 修法：删除代码字幕条（后川哥决定整个字幕条都不要，直接注释）

### 坑 2：动效太保守反而看不见
- 现象：6 颗星点 drift 1.4cqw + 周期 7s + scale 1.06，4s 显示窗口内肉眼几乎不可见
- 根因：第一次为了避免"焦躁"（gemini 反复警告"少即是多"），cc 矫枉过正
- 修法：drift → 4cqw（约 32px 横向位移）/ 周期 → 3s（4s 窗口完整 1 周期）/ scale 1.25 / opacity 0.25→1.0
- 教训：**4s demo 窗口下动效必须显著放大，gemini 反对的是"高频闪烁"不是"足够幅度"**

### 坑 3：codex 多文件改动遗漏 server 入口白名单
- 现象：客户端 ws 发 `tts.say`，server 完全没反应，log 也没打印
- 根因：codex 改了 `pipeline.ts` 加 `case 'tts.say'`，但漏改 `server/src/index.ts` 的 `decodeClientMessage` 白名单 switch（默认 return null → BAD_MESSAGE 静默 reject）
- 诊断路径：cc 写 node ws probe 直发 tts.say → 收到 1 个 68 字节 BINARY（BAD_MESSAGE 错误响应）→ 锁定 server 入口校验问题
- 修法：[`server/src/index.ts:91-95`](../apps/server/src/index.ts) `decodeClientMessage` switch 加 `case 'tts.say'`
- 教训：**派 codex 多文件改动时，prompt 必须列出"入口校验/路由表"等 contract gate 文件，要求一并扫描**

### 坑 4：AudioContext 用户手势栈陷阱
- 现象：sayDirect 成功送达 + server 产 mp3 chunks + 客户端收到，但听不到声音
- 第一次错误诊断：以为是 `useEffect → setTimeout(700ms) → sayDirect` 链路 break 了用户手势栈
- 实际根因：voice-client onmessage 收 tts.audio 后只 `emit` 给外部监听器，**只有 VoiceButton 监听**（且 VoiceButton 只在 focusRunning 挂载），Welcome 阶段 17 个 mp3 chunks 全部被丢弃
- 诊断路径：cc 装 playwright + Chrome instrument AudioContext.decodeAudioData 拦截 + ws frame 计数 → 发现 17 chunks 收到但 0 次 decode
- 修法：voice-client 内部直接 `void this.playAudioChunk(msg.mp3Base64)`，不再依赖外部监听器；VoiceButton 删手动播放保留 UI 状态副作用
- 教训：**音频/视频/数据流的播放应该由协议层自动处理，不应该让上层组件挂载与否决定数据是否被消费**

### 坑 5（次要）：Finder 双 .png 后缀
- 川哥两次保存图都成了 `setup-bg.png.png` / `welcome-bg.png.png`
- 原因：Finder 隐藏扩展名 + 手动加 .png
- 修法：cc `mv` 重命名
