## 4. 已部署的快照合同v1

`POST https://kidshub-ai.hahaxiong.cc/v1/device/ark/state`

请求头：`Content-Type: application/json`、`Authorization: Bearer <现有Device Bearer>`。不得提交凭据到回执或聊天；SN只从Bearer sub取，body不接收SN/account_id。公网无凭据探针已返回401 `invalid_device_credential`；合法真机上报200仍需安卓完成。

完整字段示例见 [snapshot-v1.example.json](snapshot-v1.example.json)，**仅用于结构说明，合成时间和数值禁止原样上传**。所有字段必填；不支持的额外字段会被拒绝；JSON上限16KiB。

| 字段 | 合同要求 |
|---|---|
| schema_version | 固定1 |
| snapshot_id | 采样唯一ID；1–64位`[A-Za-z0-9_.:-]` |
| captured_at_ms | 真实采样UTC毫秒；≥授权水位，不能比服务器时间快超过2秒，不能旧于24小时 |
| boot_id / boot_started_at_ms | 本次启动唯一ID／UTC毫秒；启动不晚于采样，新boot时间严格大于旧boot |
| sequence | 同boot持久递增正整数；进程重启需恢复序号或正确切换boot，不能原boot回到1 |
| logical_day | `YYYY-MM-DD`；实时进度首版要求等于当前北京时间日期；游戏逻辑日不同需明确反馈，勿静默改写 |
| config_revision / content_version | 当前实际生效版本ID，各1–64位同上述字符集；不使用未核实包内默认值 |
| source_mode | normal / gm / unknown |
| wallets.family_coin / stardust | 0–10亿整数或null；家族币映射C-FAMILY-001，星尘不可猜item_id；未知不是0 |
| inventory.M-CARD-001 | 补勤卡数量，0–10亿整数或null |
| progress.timer_state | running / paused / stopped / unknown |
| progress.claimable_count | 可领取奖励项数量，0–10亿整数或null，不是金币数量 |
| progress.next_reward.status | locked / claimable / claimed / day_complete / unknown |
| next_reward.kind | currency / chest / item / unknown |
| next_reward.item_id | currency仅C-FAMILY-001；item仅M-CARD-001；chest／unknown必须null |
| next_reward.stage_id | 1–64位同上述字符集或null |
| next_reward.remaining_seconds | 剩余**有效使用进度**秒数，0–86400整数或null；按当前端侧实际计时语义输出，不能声称已证明学习质量 |

状态约束：locked必须已知kind且剩余秒数>0；claimable必须已知kind、剩余0、可领取项数>0；claimed/day_complete/unknown的剩余秒数必须null。当前合同只支持上述资源类型，不要扩展未支持ID或把别的道具伪装成补勤卡。

上传时机建议：唤醒、钱包／奖励／计时状态变化时采样；语音活跃且计时中约10–15秒合并发送，单机最多12请求／分钟，错误和重复也占额度。上传异步执行，不阻塞语音、BLE和UI。网络恢复采样最新状态，不补发每秒旧倒计时。

只有采样时间和接收时间同时在30秒内、normal且逻辑日匹配时，才能解释当前倒计时／可领取。过期钱包可说“截至上次同步”，进度过期必须未知。精确重复返回duplicate但不刷新新鲜度；被新快照覆盖的旧seq返回stale。

| 响应 | 处理 |
|---|---|
| 200 accepted / duplicate | 保存成功／当前快照幂等；保留snapshot_id及received_at_ms |
| 400 invalid_snapshot / invalid_json / clock_invalid | 修字段或校钟，不循环重传原错包 |
| 401 invalid_device_credential | 核对现有合法凭据 |
| 403 not_enabled_or_authorized / not_authorized | 服务端核设备绑定与方舟授权，Analytics开关不能替代 |
| 408 read_timeout / 413 body_too_large | 重新发送完整小包／缩小请求 |
| 409 stale / conflict / before_grant | 丢旧快照重新采样；核boot、seq、授权水位 |
| 429 rate_limited | 遵守Retry-After=60，合并变化 |
| 503 ark_dependency_unavailable | 退避重试，主对话继续 |

历史埋点仍走原 `POST /v1/device/analytics/events:batch` 和23点持久队列，不改成高频全量上传。最多200条／2MiB、单机同时1批，批间抖动并遵守429／503退避。快照接口与夜批分开；本轮不用故障注入或打开其他设备。
