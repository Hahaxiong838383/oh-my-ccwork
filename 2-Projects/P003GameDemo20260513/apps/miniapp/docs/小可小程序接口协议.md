# 小可小程序接口协议（联调草案）

版本：0.2；日期：2026-10-29；状态：**供产品、业务后台、设备云、固件和小程序共同评审，未签署生效**。

依据：量产 PRD 的 BLE 配网方向、`页面接口对齐表.md`、`数据需求与结构草案.md`、`服务端与数据库联调交接单-2026-10-28.md`，以及当前小程序源码。**本文件中的 `/v1/...` 路径、枚举、示例 ID 和字段结构是联调提案，不代表服务端已有实现。**已有 cc 路径列于第 8 节，迁移时以服务端正式 OpenAPI 为准。产品业务规则以量产 PRD 为准；本文不把演示数据当成正式数据。

## 1. 范围与参与方

- 小程序及备用网页只请求业务后台/BFF 的 HTTPS 接口；不直连数据库、cc 或设备云。BFF 负责身份、权限、数据聚合、错误映射和脱敏日志。
- 手机与读写台通过 BLE 完成身份握手、Wi-Fi 列表读取和 Wi-Fi 配置。`NETWORK_READY` 是设备网络就绪回执，**不是云端激活或账号绑定成功**。
- 设备向设备云报到/上报；设备云将激活、在线、遥测和使用事件交给业务后台。设备云到 BFF 的推送/订阅接口属于服务间合同，不能从本文件的手机接口直接推断。固件 BLE 帧协议另见 `读写台BLE配网联调交接单-2026-10-27.md`。
- 数据库由服务端维护。表名、主键、事件去重与事务实现由服务端/DBA确认，小程序只依赖本协议的业务语义。

首轮闭环按顺序验收：微信身份 → 扫码验真/建配网会话 → BLE 配网 → 设备上云 → 业务后台确认激活与归属 → 小程序读取真实设备与首页数据。其余页面接口列于第 5 节，不能因首轮闭环通过而自动宣称全量完成。

## 2. 通用传输合同（提案，需后端确认）

| 项 | 合同 |
| --- | --- |
| Base URL | `https://<test-bff-host>`；生产地址另给。微信小程序 `request` 合法域名、上传/下载域名由运维配置；`127.0.0.1` 只用于本机开发。 |
| 内容 | JSON、UTF-8；字段名 `snake_case`，小程序 API 层转 `camelCase`。请求体大小、图片上传类型/大小另定。 |
| 身份 | 登录接口除外，`Authorization: Bearer <session>`；服务端从会话判定账号，不能信任请求体中的 `user_id`。401 清本地会话并重新登录，403 表示已登录但无该资源权限。 |
| 追踪 | 请求 `X-Request-Id`，响应原样回显；设备上报、配网会话和业务日志还需可关联的 `operation_id` / `provisioning_id`。不得在日志记录 Wi-Fi 密码、手机号授权凭据或 BLE 密钥。 |
| 写入去重 | 绑定、确认奖励、兑现、反馈等写操作使用 `Idempotency-Key`，服务端按账号+操作+键去重并返回同一业务结果；保留时长待定。设备事件用设备事件 ID 去重。 |
| 时间 | 时间戳建议 ISO 8601 带时区，业务日期 `YYYY-MM-DD`，出生月 `YYYY-MM`；统计时区和周报截点由产品/后台冻结。若现有 cc 使用 epoch 毫秒，由 BFF 统一转换。 |
| 数值/空值 | 金额为整数币数，使用时长为整数秒；`0` 是确认的零，`null` 是未知/缺失，`[]` 是确认空列表。请求失败不得返回 200 空数据。 |
| 列表 | 建议 `items`, `next_cursor`, `has_more`，请求 `cursor`, `limit`；最大 limit、排序稳定键待确认。 |
| 数据状态 | 建议 `availability`: `available` / `no_data` / `not_activated` / `unavailable`；这仅描述数据是否可用，不替代 HTTP 错误。聚合数据还需 `data_updated_at`。 |
| 缓存 | 个人数据响应 `Cache-Control: no-store`；BFF 若对上游做短缓存，必须按账号+资源隔离，写入后失效。 |

**成功示例（提案）：**

```http
GET /v1/me/devices HTTP/1.1
Authorization: Bearer <session>
X-Request-Id: miniapp-123
```

```json
{"items":[{"device_id":"dev_001","sn":"<masked-sn>","model":"MAX","name":"空间光学读写台","binding_status":"bound","activation_status":"activated","online":true,"last_seen_at":"2026-10-29T15:00:00+08:00"}],"next_cursor":null,"has_more":false,"server_time":"2026-10-29T15:00:03+08:00"}
```

**错误示例（提案）：**

```http
HTTP/1.1 409 Conflict
X-Request-Id: miniapp-123
Content-Type: application/json
```

```json
{"error":{"code":"DEVICE_BOUND_TO_OTHER","message":"设备已绑定其他账号","retryable":false},"request_id":"miniapp-123"}
```

HTTP 建议：400 输入错误，401 未登录/会话过期，403 越权，404 资源不存在或对当前账号不可见，409 状态冲突，422 业务校验，429 限流，500 服务端错误，502/503 上游不可用。`Retry-After` 用于 429/503；最终错误码、是否隐藏资源存在性、错误体由后端确认。小程序不得靠 `message` 文案分支。

## 3. 登录、扫码、绑定与激活（P0，首批必须签收）

下表的路径均为**建议路径**；`扫码内容`、设备证明和微信登录凭据格式必须由对应团队提供正式安全协议，不能用示例字符串直接量产。

| 方法与建议路径 | 请求关键字段 | 成功响应关键字段 | 失败/权限与完成条件 |
| --- | --- | --- | --- |
| `POST /v1/auth/wechat` | 微信 `login` 临时 code；手机号授权凭据（如业务需要，格式待微信/后端确认） | `session`, `expires_at`, `user {id, phone_masked, profile_status}` | 授权拒绝、code 失效、手机号冲突；不得把页面显示的掩码手机号当已认证身份。 |
| `POST /v1/auth/logout` | Bearer 会话 | `revoked: true` | 重复退出行为待确认；服务端应使旧会话失效。 |
| `GET /v1/me`、`PATCH /v1/me` | 读资料无请求体；编辑仅头像资源 ID、昵称（≤10 字） | 家长 ID、头像、昵称、脱敏手机号、权限摘要 | 手机号不可直接编辑；401/403、昵称校验；不得返回微信 AppSecret。 |
| `POST /v1/provisioning/identify` | 扫码原文或已约定的安全载荷；`Idempotency-Key` | `device_sn`, `model`, `proof_status`, `binding_status`, `challenge`/一次性票据（如协议要求）、`expires_at` | 未知设备、过期/伪造二维码、已绑他人；设备证明方法待固件/后台共同定。 |
| `POST /v1/provisioning/sessions` | `device_sn`, `purpose`（首次绑定/重新配网），设备证明及账号授权材料，`Idempotency-Key` | `provisioning_id`, `operation_id`, `device_id`（可空）, `binding_status`, `network_status`, `activation_status`, `expires_at` | 已绑、越权、票据过期、重复提交；应能表达“BLE 已绑定账号但尚未联网”这一状态；**建会话成功不等于绑定成功**。 |
| `GET /v1/provisioning/sessions/{id}` | `id` 为本账号会话 | 三个独立状态、`step`, `device_id`, `device_sn`, `error_code`, `updated_at`, `activated_at` | 404/403/会话过期；只在目标设备的云端报到与归属校验均完成后返回最终成功。轮询间隔/超时待定。 |
| `POST /v1/provisioning/sessions/{id}/cancel` | `Idempotency-Key` | 取消后的会话状态 | 已完成会话能否取消待定；不误解绑已激活设备。 |
| `GET /v1/me/devices` | `cursor`, `limit` | 设备列表、绑定/激活状态、在线状态、数据更新时间 | A 账号看不到 B 设备；换手机登录后归属一致。 |
| `PATCH /v1/me/devices/{device_id}` | 仅可编辑 `name`，版本号/并发条件待定 | 更新后的设备资料 | 越权、名称非法、并发冲突。 |
| `DELETE /v1/me/devices/{device_id}/binding` | 二次确认材料与 `Idempotency-Key`（格式待定） | `binding_status`, `retention_status` | 解绑后历史保留/删除规则须先获产品与隐私确认。 |

配网状态最小语义：`binding_status` 区分未绑定/处理中/已绑定/失败；`network_status` 区分未配置/连接中/已就绪/失败；`activation_status` 区分未激活/等待设备上云/已激活/失败。**具体枚举字符串由后台最终回传**，不可把这里的中文语义直接当 API 值。配网会话应关联同一 `device_sn`、`operation_id`、账号和设备云事件；重复轮询不得改变状态。

建议时序：小程序登录→扫码验真并建立配网会话→通过 BLE 与设备握手并发送 Wi-Fi→设备返回 `NETWORK_READY`→设备连设备云并上报身份/操作号→设备云与 BFF 关联目标设备→BFF 返回激活和归属结果→小程序进入首页。**Wi-Fi 密码只走已确认的安全 BLE 通道，不进入普通业务接口、数据库、日志或遥测。**设备报到协议、签名/验真方式、事件推送地址、重放保护由设备云与后台另签服务间合同。

## 4. 真实数据的公共读取对象（P0）

以下是客户端必须看到的业务字段，不要求数据库建立同名大表。来源、采样时间和可用性需随数据返回。

| 对象 | 必须返回或明确为空的字段 | 关键口径 |
| --- | --- | --- |
| `device` | `device_id`, `sn`, `model`, `name`, `binding_status`, `activation_status`, `firmware_version?` | BLE `deviceId` 不是云端 `device_id`，SN 也不能当数据库主键。 |
| `telemetry` | `online`, `last_seen_at`, `reported_at`, `received_at`, `presence_detected`, `led_on`, `screen_connected`, `brightness_level`, `color_temperature_mode`, `calibration_required`, `vid_meters`, `current_focused_seconds`, `availability` | 在线不等于学习中；离线参数不拿旧值冒充实时值。心跳判离线阈值待硬件定。 |
| `daily_usage` | `date`, `focused_seconds`, `posture_reminder_count`, `active`, `availability`, `updated_at` | 活跃天按连续使用至少 300 秒，不能用全天零碎累计替代；迟到数据的修正策略待定。 |
| `wallet` | `wallet_id`, `balance`, `version`, `updated_at` | 币账户真正归属待确认；余额只能从服务端读。 |
| `report` | `report_id`, `period_type`, `start_date`, `end_date`, `visible_from`, `availability`, `daily_usage`, `total_focused_seconds`, `active_days`, `posture_reminder_count`, `calculation_version` | 周报发布为周日 22:00；统计时区、迟到上报和日均分母待确认。 |

| 性能与兼容 | 4G Tab ≤2 秒、图表 ≤1 秒、BLE 近场发现 ≤5 秒、2.4GHz 配网成功率 ≥95%、≥50 FPS；微信 8.0+、iOS 14+、Android 8+、BLE 4.2+ 与屏幕矩阵 | 这些是端到端验收指标，不是新增 HTTP 接口；需要可观测性和真机测试报告。 |

## 6. 写接口、设备指令与状态一致性

- 任务确认、约定兑现、钱包变动必须由服务端在同一事务内判权、验状态、记流水并更新余额；重复请求/设备事件只生效一次。返回**提交已接收、云端已保存、设备已执行**中哪一级必须明确。
- 设置修改返回期望值和命令 ID；设备回执后才能将 `sync_status` 变为已执行。设备离线、超时、拒绝执行都需有独立错误/状态。
- 设备上报至少区分 `device_id`、设备事件 ID、设备发生时间、云端接收时间、固件版本、事件类型。签名、重放窗口、时钟漂移、离线补报和去重策略由设备云/后台签收。
- 激活、绑定、解绑及重新配网必须用同一设备唯一身份关联；旧绑定的历史数据归属不能因新绑定而自动泄露。Wi-Fi 密码不可进入上述任何业务事件。

## 7. 联调验收矩阵

| 场景 | 必须观察的结果 |
| --- | --- |
| 真机正确配网 | BLE `NETWORK_READY` → 设备云目标 SN 上线 → BFF 会话 `activated` 且归属正确 → 换手机登录可读同一设备。每步可用同一操作 ID 对账。 |
| 只有 BLE / 设备未上云 | 页面停在等待或明确超时；BFF 不返回最终激活成功。 |
| 错密码、路由器不可达、设备断电 | 明确阶段/错误码和可重试方式；不伪造已激活。 |
| 已绑他人、未知 SN、过期二维码 | 服务端拒绝且不暴露他人资料；设备云/数据库无错误归属。 |
| A/B 两账号 | B 无法读取、修改或解绑 A 的设备、儿童、钱包和报告；过期会话不能写入。 |
| 设备产生一条使用数据 | 设备云事件、业务服务记录、同一天首页/日历/周报可追溯且口径一致；迟到上报可复核修正。 |
| 重复确认/兑现、并发兑现 | 只有一笔流水；余额不重复增加或变负。 |
| 设备设置离线/失败/回执成功 | 分别显示待下发/失败/实际已生效；不能将 HTTP 200 当设备执行成功。 |
| 空数据、上游故障、限流 | 200 的 null/[] 与 5xx/429 显示不同；响应含请求 ID 便于追踪。 |

## 8. 与现有工程和候选接口的对应

- 当前小程序 `src/services/api.ts` 的默认 BFF 为 `http://127.0.0.1:4180`，已有 Bearer、`X-Request-Id` 和 401 清会话行为；真机需改为 HTTPS 测试地址。当前本地 BFF `server/app.ts` 只有 `/health` 和非生产 `/dev/probe/*`，**第 3—5 节业务路由尚未在本工程实现**。
- 旧对齐表记载候选 cc 路径：短信 `POST /api/auth/sms/send`、`POST /api/auth/sms/verify`，伙伴登录 `POST /api/auth/partner/phone-login`，档案 `GET/POST /api/profile`，首页 `GET /v1/parent/devices/{public_id}/dashbord`，周报 `GET /v1/parent/devices/{public_id}/weekly-report`。这些不等于本协议 `/v1/...` 已落地；后台需确认是否复用、代理或替换。量产 BLE 方案覆盖旧 SoftAP 流程。
