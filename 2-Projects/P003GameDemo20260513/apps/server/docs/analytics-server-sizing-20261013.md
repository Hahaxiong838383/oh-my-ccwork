## 建议顺序

1. **当前先优化与复验。** 8.4万条/晚的全天平均不到1条/秒，峰值、写放大和可靠提交延迟才是本轮关注点。保留完整原验收目标，并与端侧协调00点后10–20分钟错峰；端侧建议未实现，不计入服务端已完成项。
2. **基础设施优先评估数据盘：现机增加100GiB ESSD PL1独立数据盘。** 标称6800IOPS；先核当前盘型和目标费用，若选用则先在目标盘运行隔离库验收，通过后再安排停写迁库。独立盘便于容量、快照及备份管理，但新增盘不能突破当前实例8k IOPS/50 MB/s合计上限，也不能预先保证容量验收通过。
3. **长期将语音与埋点分离，埋点服务器选企业级通用型。** 可把`ecs.g7.large`（2核8GiB）或香港可售更新代同档规格作为压测候选；其官方基础云盘能力20k IOPS/1.5 Gbit/s。分机有助于隔离两类业务的CPU、磁盘与维护负载；具体收益仍须验收。4核16GiB是后续容量候选，不是当前已证实必需。最终确认地区库存、磁盘等级、基准吞吐、费用和迁移窗口后另行采购。[通用型官方表](https://www.alibabacloud.com/help/zh/ecs/user-guide/general-purpose-instance-families)
4. **托管PostgreSQL作为后续架构选项。** 同地域同VPC的托管PostgreSQL可减少备份、补丁及故障切换运维；待恢复目标、容量或并发需求明确后评估，需要适配和迁移验证，不在当前优化中立即强迁，也不保证替换数据库就消除低效事务。[RDS职责](https://www.alibabacloud.com/help/en/rds/product-overview/competitive-advantages-of-apsaradb-rds-instances-over-self-managed-databases)

ESSD AutoPL可分别配置容量和预配置IOPS，但仍受实例上限，且要核突发计费；目前未确认需采用。[AutoPL官方说明](https://www.alibabacloud.com/help/en/ecs/user-guide/essd-autopl-disks)

备份/经批准的冷数据可按原保留期放对象存储，不用它代替逐事件幂等事务，也不借归档延长儿童数据保留期限。现阶段不需要GPU、大数据专用机或分布式集群。
