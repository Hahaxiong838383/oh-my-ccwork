# P003 埋点服务器选型建议（2026-10-13）

状态：建议与事实核验，不是采购/迁移回执。用户授权先优化当前服务器；优化仍在隔离环境，真实采集保持关闭。96 MiB完整压测已完成，但时延仍未达标；128 MiB超过原RSS门槛，不采用。

## 当前机器

加固实例元数据实测：香港 `ecs.e-c1m2.large`。官方规格2 vCPU/4 GiB；OS可见3669209088字节内存。现机40GiB系统盘、约16.4GB可用，无swap，多项业务共用。云盘具体Category/PerformanceLevel尚未核实，`lsblk ROTA=1`不能判为机械盘。

| 项目 | 官方规格与含义 |
|---|---|
| CPU | e经济型共享调度，存在物理CPU争用的可能；不是t系列CPU积分机制 |
| 云盘基础IOPS | 实例合计8000，无突发 |
| 云盘基础吞吐 | 实例合计0.4 Gbit/s，约50 MB/s，无突发 |
| 内网网络基础/突发 | 0.2/最高2 Gbit/s，不代表已购买的公网带宽 |

依据：[经济型e官方表](https://www.alibabacloud.com/help/zh/ecs/user-guide/shared-instance-families)、[实例存储I/O合计约束](https://www.alibabacloud.com/help/en/ecs/user-guide/storage-i-or-o-performance)。实例上限不等于已被本轮压测触达，需与实测磁盘数据对齐。

## 实测瓶颈与盘型选择

旧fact布局、64 MiB缓存的慢窗口出现约2,120 IOPS平台，磁盘忙度约99%、CPU iowait约94%–98%、实际计算约1%–6%、steal为0。该窗口支持存储等待主导，但后续数据已证明，不能把2,120 IOPS当作整个磁盘的硬上限。

加入fact时间索引后，64 MiB缓存的完整84,000条事件压测记录如下：

| 指标 | P95 | 最大值 |
|---|---:|---:|
| 磁盘IOPS | 3,761 | 3,862 |
| 磁盘写带宽 | 31.63 MB/s | 38.60 MB/s |
| 磁盘忙度 | 99.5% | — |
| CPU iowait | 92.9% | — |

新结果仍显示较重的存储等待，同时IOPS明显超过旧窗口平台。两组结果对应不同的fact布局，不能用旧平台反推盘型或把后续收益全部归于硬件。**当前实际云盘Category/PerformanceLevel依旧未知**；迁移或采购前需通过控制台/DescribeDisks核实。单纯加CPU仍缺少本轮证据支持；约38.60 MB/s的实测最大写带宽也不代表已经触达实例50 MB/s的合计吞吐上限。

96 MiB缓存实验完整发送并确认84,000条事件，接口P95为1,259 ms、P99为2,782 ms，RSS峰值229,142,528字节（约218.5 MiB）。内存低于256 MiB目标，但P95≤500 ms、P99≤2,000 ms两项时延目标仍失败。128 MiB虽完整84,000条，P95665ms、P991847ms，但RSS280,072,192字节超过256MiB，故不采用；不能放行真实采集。

以下仅是官方规格计算，用于候选比较，不表示当前系统盘属于其中哪一类：

|---|---:|---:|---|
| 高效云盘 / ESSD Entry | 2120 | 2600 | 两类在这些容量下相同，不能用于唯一识别当前盘型 |

公式来自[阿里云块存储性能](https://www.alibabacloud.com/help/zh/ecs/user-guide/block-storage-performance)。不同盘型、容量的规格上限不同，不能保证业务按IOPS比例加速，且所有盘合计仍受实例上限。采购或迁移前必须核实当前盘型、目标盘型/等级、香港可用区支持、费用和迁移窗口。

## 建议顺序

1. **当前先优化与复验。** 8.4万条/晚的全天平均不到1条/秒，峰值、写放大和可靠提交延迟才是本轮关注点。保留完整原验收目标，并与端侧协调00点后10–20分钟错峰；端侧建议未实现，不计入服务端已完成项。
2. **基础设施优先评估数据盘：现机增加100GiB ESSD PL1独立数据盘。** 标称6800IOPS；先核当前盘型和目标费用，若选用则先在目标盘运行隔离库验收，通过后再安排停写迁库。独立盘便于容量、快照及备份管理，但新增盘不能突破当前实例8k IOPS/50 MB/s合计上限，也不能预先保证容量验收通过。
3. **长期将语音与埋点分离，埋点服务器选企业级通用型。** 可把`ecs.g7.large`（2核8GiB）或香港可售更新代同档规格作为压测候选；其官方基础云盘能力20k IOPS/1.5 Gbit/s。分机有助于隔离两类业务的CPU、磁盘与维护负载；具体收益仍须验收。4核16GiB是后续容量候选，不是当前已证实必需。最终确认地区库存、磁盘等级、基准吞吐、费用和迁移窗口后另行采购。[通用型官方表](https://www.alibabacloud.com/help/zh/ecs/user-guide/general-purpose-instance-families)
4. **托管PostgreSQL作为后续架构选项。** 同地域同VPC的托管PostgreSQL可减少备份、补丁及故障切换运维；待恢复目标、容量或并发需求明确后评估，需要适配和迁移验证，不在当前优化中立即强迁，也不保证替换数据库就消除低效事务。[RDS职责](https://www.alibabacloud.com/help/en/rds/product-overview/competitive-advantages-of-apsaradb-rds-instances-over-self-managed-databases)

ESSD AutoPL可分别配置容量和预配置IOPS，但仍受实例上限，且要核突发计费；目前未确认需采用。[AutoPL官方说明](https://www.alibabacloud.com/help/en/ecs/user-guide/essd-autopl-disks)

备份/经批准的冷数据可按原保留期放对象存储，不用它代替逐事件幂等事务，也不借归档延长儿童数据保留期限。现阶段不需要GPU、大数据专用机或分布式集群。
