# MediaCrawler 与固定公网入口验收

日期：2026-08-05

## 结论

MediaCrawler 小红书扫码采集、结构化导入、任务历史和结果详情页已经完成真实用户验收。川哥确认能够从公网登录系统，并查看本次采集结果。

正式入口为 `https://insight.kidshub.cn`。该入口不依赖 Cloudflare Quick Tunnel，因此不再受随机 `trycloudflare.com` 域名和 Error 1016/1033 影响。

## 已验收能力

- root 可手动启动小红书/抖音研究采集。
- 同一时间只允许一个采集任务，并发固定为 1。
- 单次最多采集 20 条，不下载图片或视频，不自动定时运行。
- 首次登录可在后台页面扫码，采集状态区分启动、等待扫码、采集、导入、完成、失败和取消。
- 采集完成后自动导入达人、内容、评论和每日互动指标。
- 历史任务提供“查看结果”入口。
- 结果页支持标题/正文/达人搜索，按点赞、收藏、评论、分享或发布时间排序。
- 结果卡片展示匿名达人、正文摘要、原文链接、互动指标和已存评论数。
- 结果页面和 API 仅 root 可访问。

## 公网架构

```text
浏览器
  → HTTPS insight.kidshub.cn
  → aliyun-hk Nginx :443
  → 127.0.0.1:13200
  → Studio 主动建立的受限反向 SSH
  → 127.0.0.1:3200 Next.js
```

安全边界：

- 香港入口只公开 443，反向转发端口只监听 `127.0.0.1`。
- Studio 使用独立受限密钥，只允许指定端口转发，不允许远程 shell。
- PostgreSQL 继续只监听 Studio 的 `127.0.0.1:5432`。
- Next.js 的 3200 端口不直接暴露公网。
- TLS 证书自动续期链已经通过 dry-run 验证。

## 经验教训

1. **Quick Tunnel 只能用于临时诊断。** 随机域名、DNS 传播和连接器状态不可控，不适合作为用户验收或长期入口。
2. **固定域名不等于固定链路。** 必须同时验证 DNS、TLS、Nginx、转发监听、Studio 应用和真实登录后的业务页面。
3. **HTTP 200 不是最终验收。** 必须完成登录、扫码、采集、导入、结果页和原文链接的真实用户闭环。
4. **单次成功不能证明稳定。** 公网入口至少从两个独立网络连续多轮检查，并确认转发进程没有反复重启。
5. **错误码要先定位所在层。** Error 1016/1033 属于 Cloudflare 域名/隧道层，不应在 Next.js 或数据库层盲目修改。
6. **停止临时进程必须精确到 PID。** 禁止用宽泛 `pkill -f cloudflared`，避免误伤其他项目或用户主动保留/清理的服务。
7. **公网用户路径和运维路径要分离。** 用户页面可用不代表管理员能够 SSH 到 Studio；远程维护入口应独立建设。
8. **Studio 不能直接暴露应用端口。** 当前公网 IPv4 的 22/80/443/3200 均不可达；若未来直连，必须先完成公网 IPv6 或路由器端口映射、防火墙和反向代理验收。

## 回滚原则

- DNS 可切回上一入口地址。
- 香港 Nginx 配置变更前保留原文件备份并先运行配置检查。
- 反向 SSH 使用独立 launchd unit，可单独停用，不影响 Studio 的 Web 与数据库服务。
- 不修改 Studio 上 Ollama、LiveKit、kidsbench、vision-daemon 和 voice-worker。
