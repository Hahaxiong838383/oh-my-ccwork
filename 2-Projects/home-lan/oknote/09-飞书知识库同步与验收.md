## 本次修正的具体问题

- User OAuth 成功不等于凭据已持久保存。最终使用密码库条目「飞书 User OAuth - oknote 源同步（只读）」的 schema2 密码字段 JSON 保存 access/refresh 等内容，写后逐字段回读；Notes 只放简短元数据。凭据值和授权链接参数不入报告、命令参数或 Git。
- 实际飞书 sheets 列表字段为 `sheets`，旧草稿按 `items` 读取会得到假空表。已依据真实响应补齐；仅 HTTP 200 不能证明导出成功。
- docx 的 `merge_info` 全为 1×1 时不是发生合并单元格信息损失；按真实数据纠正误报。真实空页需由原始块结构确认，不能把未知块或失败当空页。
- OK笔记 3.2.0 不识别若干源编辑器节点，必须先适配，并把原始结构保留为附件；多列内嵌 doc 需展开，不丢子结构或文本。
- 此版本附件上传需要原始 UTF-8 filename；仅发送 ASCII fallback 与 filename* 会丢失中文文件名。
- 原附件物理文件比逻辑内容多 28 字节存储封装。原有数据保护比较原始存储字节，新增附件完整性比较 API 解码后的载荷；不能把两者混用而误判损坏。
- 浏览器会提前 30 秒刷新会话；最初 30 秒临时验证凭证立即触发续期，导致只读探针失败。查明运行版本机制后，浏览器探针改为单次 120 秒凭证并重验；普通维护 API 仍用短期凭证。此机制只用于当次已授权维护，不发布为常规登录方法。
- Hermes 完成源盘点、导出器修复和首批导出后遇到模型额度限制，由父代理接手补齐、导入和独立验收；不把委派结束或草稿测试通过写成迁移完成。
