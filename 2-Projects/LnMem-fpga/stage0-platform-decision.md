## 1. 三个候选

| 维度 | A. KV260（FPGA，原方案） | B. NVIDIA Orin Nano/NX | C. Mac 软件版（现有设备） |
|---|---|---|---|
| 采购成本 | ~2000 元档 | ~2000 元档（Nano dev kit） | **0**（Air/Studio 现成） |
| 上手周期 | 慢：Vitis/HLS 工具链 + 定点对拍，数周 | 快：PyTorch/TensorRT，数天 | 最快：当天 |
| CfC 单步延迟 | µs 级 + **确定性**（无调度抖动） | ms 级，GPU 有调度抖动 | ms 级 |
| 全链路功耗 | 数瓦~十几瓦 | 7–25W 可配 | 不适用（插电桌面机） |
| 视觉前端 | DPU/PL，工程量大 | **GPU 生态现成，最省力** | CPU/ANE 够用（30fps 单脸可行） |
| 车载量产路径 | 强（FPGA/专用芯片是常见路线） | 强（Orin 有车规版本） | 无（仅验证用） |
| 先发成果价值 | **高**（CfC-on-FPGA 公开空白） | 无 | 无 |
| 工程风险 | 高（HLS/定点/对拍全新领域） | 低 | 最低 |

## 2. 三个可选决策

- **D1 直上 FPGA**（按原 §17 路线）：适合「确定性延迟 / 极致功耗 / 先发成果」是硬需求的情况。代价：在意图效果被证明之前，先投入最重的硬件工程。
- **D2 转 Orin，放弃 FPGA**：适合纯产品验证优先。代价：丢掉先发成果与 FPGA 车载路径，「LnMem 硬件化分支」定位弱化。
- **D3 软件版先行，FPGA 后置（cc 推荐）**：
  1. 阶段 1 + 「软件版阶段 2」在 **Mac（零采购）** 上做：全链路实时 demo（摄像头 → 特征+context → CfC 软件版 → 标签输出），先把**意图/表情效果**证明到 KPI 达标；
  2. FPGA 上板改为**阶段 2b**，启动 gate = 软件版效果过 KPI 门；届时再买 KV260、做定点金标准与硬件 IP（先发成果不丢，只是排序后置）；
  3. Orin 仅在「车载预研提前」或「Mac 算力/形态不合适」时引入，不默认采购。

## 3. 推荐理由（D3）

**LnMem 终局已经用两个月证明：这类项目当前最大的风险不在硬件，在信号与数据**（纯脸部特征 0.086 bits 到顶、数据管线 bug 报废 481 条——全部是软件层/数据层问题，没有一个是「算力不够」）。效果没站住之前投 FPGA 工程，等于花最贵的钱让不准的模型跑得更快。软件版先行把「效果」这个最大未知数用零成本平台消掉，硬件投入 gate 在其后——**风险排序对了，总成本最低，且不放弃任何长期选项**。
