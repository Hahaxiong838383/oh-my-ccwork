## 0. 这本手册怎么用

- **立项时**：产品 + 算法一起过 §1（标签定义）+ §2（输入面契约），签字后才允许开采集。
- **搭采集管线时**：工程按 §3（schema）+ §4（anchor 红线）+ §6（哨兵）实现，校验逻辑进 CI。
- **采集进行中**：标注团队按 §5 执行；采集到计划量一半时强制走 §10 中期评审。
- **训练之前**：算法先过 §9 MI 门——**裁判说无信号，就回来改 §2 输入面，不是去调模型**。
- **写评测报告时**：口径只认 §7 + §8。

## 1. 意图标签定义规范

### 1.1 三要件（缺一不立项）

| 要件 | 含义 | 反例 |
|---|---|---|
| 场景化 | 绑定具体场景（会议 / 课堂 / 车载），不做开放域 | 「通用意图识别」 |
| 可观察 | 有外显行为或客观事件可对齐 | 「用户是否喜欢产品」 |
| 可标注 | 两个标注者看同一段视频能给出一致标签（κ 可测） | 「潜意识倾向」 |

### 1.2 可观察性梯度分级（决定 v1 范围与风险）

| 级 | 类型 | 例 | 判据 | 风险与策略 |
|---|---|---|---|---|
| **A** | 动作前兆类 | 准备发言（前倾+张嘴前兆）、离开倾向（起身姿态） | 身体大动作，物理可观察 | 低风险，**v1 主攻** |
| **B** | 交互事件锚定类 | 提问前兆（以真实提问事件为时间锚，往前取窗） | 有客观事件时间戳可对齐 | 中风险，v1 可做——事件锚天然解决「标签打在哪一刻」问题 |
| **C** | 内部状态推断类 | 困惑、不耐烦、满意/不满 | 从脸推内心，无外显锚 | **高风险**。LnMem 撞墙处：纯脸部特征对此类标签互信息仅 0.086 bits（占标签熵 5.7%），F1 0.39 vs 多数类基线 0.24——统计显著、产品无用。**没有 context 输入支撑不启动** |

### 1.3 每类标签的定义模板（复制使用）

```markdown
## I<N> <标签名>
- 级别：A / B / C
- 正例描述（标注指引，写外显行为不写心理动词）：
- 反例（最易混淆的相邻情形）：
- 时间锚：事件锚（哪个 event type）/ 区间标注（t0..t1 判据）
- 排除条件（遮挡 / 侧脸 > N° / quality < x 时不标）：
- 预期占比（采集后对照 §6 R3 监控）：
```

**数量纪律**：3–8 类 + `I0 未知`。每加一类，混淆矩阵与数据需求超线性增长。

### 1.4 会议场景标签集 v1（实例化 · 2026-07-20）

> 场景已拍板：日常办公会议（主文档 v2.1 §2.1）。以下按 §1.3 模板实例化；**正例只写外显行为，不写心理动词**。context 字段定义见 [`feature_contract.md`](feature_contract.md) §4。

#### I1 专注听讲（A 级 · 基线状态）
- 正例：面部朝向屏幕/讲者方向稳定（偏转 <30°）持续 ≥5s；躯干静止或小幅调整；无 I3–I5 前兆动作
- 反例：朝向稳定但反复瞥向手机区域（→I4 候选）；闭眼 >3s（瞌睡 →I0）
- 时间锚：区间标注（稳定段起止）
- 排除：侧脸 >45° / 遮挡 >50% / quality 低于校准阈值
- 预期占比：50–70%（会议大部分时间的中性桶，给分类器一个非拒识的默认归宿）

#### I3 准备发言（A 级主攻 + B 级事件锚 · v1 北极星标签）
- 正例：躯干前倾幅度突增；张嘴吸气前兆；手部抬起/举手；（context）解除静音操作
- 反例：伸懒腰前倾（无后续发言）；咳嗽/打哈欠张嘴
- 时间锚：**事件锚 `speech_start`**（真实开口或解除静音后发言），回溯 [t−3s, t] 为正窗；无后续发言事件的前倾段不标 I3
- 排除：`self_speaking=1` 期间（发言中不算「准备」）
- 预期占比：5–10%
- 评测：提前量曲线主标签（0.5s/1s/2s F1，主文档 §10.4）

#### I5 离开倾向（A 级主攻 + B 级事件锚）
- 正例：收拾桌面物品/合电脑；躯干重心上移（起身前兆）；反复看门口方向
- 反例：弯腰捡物（重心变化无离开）；调整坐姿
- 时间锚：**事件锚 `leave_seat`**（真实起身离座），回溯 [t−5s, t]
- 排除：会议正式结束后的起身（散会正常离开不是「倾向」信号）
- 预期占比：2–5%

#### I2 困惑（C 级 · 缓启动）
- 正例：皱眉持续 ≥2s 伴歪头；视线在共享内容同一区域反复停留；（context）当前议题停留时长显著超均值
- 反例：强光眯眼（用曝光/quality 记录排除）；专注思考的皱眉（与 I2 天然混淆，κ 预期偏低——C 级风险的直接体现）
- 时间锚：区间标注；弱锚可用后续 `question_asked` 事件（困惑→提问链路）
- 排除：**context_valid=false 时不启用**（§1.2 C 级红线）
- 预期占比：5–15%
- 启用 gate：context 覆盖率 >90% + 双人 κ ≥0.6

#### I4 不耐烦（C 级 · 缓启动）
- 正例：视线频繁离开会议内容区（≥3 次/分钟）；躯干姿态高频小幅变化（坐立不安）；反复瞥向手机/时钟区域
- 反例：颈部放松活动（低频大幅度）；场外声响引起的单次转头
- 时间锚：区间标注（行为频次窗 ≥30s）
- 排除：同 C 级红线
- 预期占比：5–10%
- 启用 gate：同 I2

#### I0 未知/拒识桶
- 一切不满足上述判据、quality 不达标、或标注者无法在 10s 内决断的段
- 预期占比：10–25%

**v1 训练范围声明**：

- 进 v1 主损失：**I1 / I3 / I5 / I0**（A 级 + 基线 + 拒识）；
- I2 / I4：标注照攒（指引已就绪），**不进 v1 主损失**；正式启用 gate = context 覆盖 >90% ∧ κ ≥0.6（届时以辅助任务低权重引入）；
- 提前量评测主标签 I3，次 I5。

**车载迁移映射预留**（拍板要求可迁移；context 语义整表另立，见 feature_contract §9）：

| 会议标签 | 车载对应（预研占位） |
|---|---|
| I3 准备发言 | 乘客交互意图（欲对系统/司机说话） |
| I5 离开倾向 | 下车前兆 |
| I2 困惑 | 导航/界面困惑 |
| I4 不耐烦 | 乘车焦躁 |

机位/光照/振动差异走配置 profile（主文档 §8.7），标签模板与红线体系（§4/§6）跨场景不变。

## 2. 输入面契约：context 不是可选项

### 2.1 为什么（LnMem 终局实证）

- 纯脸部（AU）特征对意图：I = +0.086 bits（p=0.0033），**产品级到顶**——不是采样不够，是信号天花板。
- 仅加两个粗糙 context 字段（最近事件类型 + 时段），Macro-F1 0.354 → 0.418（**+18%**）。
- 结论：**意图的因果上游在场景与交互事件，不在脸**。脸是辅助模态。

### 2.2 context 的双重身份

| 身份 | 用途 | 常见错误 |
|---|---|---|
| **推理输入特征** | 进 `FeatureFrame.context`，v1 就位 | ❌ 只当训练弱标签，推理时不给（LnMem v2.0 前的做法，即主文档 v2.0 §10.2 原稿） |
| 弱标签来源 | 客观事件（提问/离座）反推意图区间标签 | ❌ 用它打标签却不让模型看到它 |

### 2.3 采集元数据清单（硬性，缺一即视为管线不完整）

每条样本 / 每个 session 必须带：

1. **交互事件流**：事件类型 + 独立时间戳（提问、离座、议程切换、系统动作等）；
2. **系统/AI 动作时间戳**（若场景中有系统参与）：动作类型 + 发出时刻；
3. **用户操作时刻**（键鼠活动率 / 点击时间戳，不采内容）；
4. **session 元信息**：日期、光照条件、机位/相机 ID、被试 ID；
5. 每个特征帧的 `ts`、每条标注的 `annotated_at`（见 §3）。

> LnMem 教训：这份清单是 codex 对抗审给出的补课项——当初没采「AI 动作时间戳 + 用户点击时间戳 + 前台应用」，导致 context 模态想接都没有原料，只能用极粗代理估计上限。**采集时少存一个时间戳，分析时就少一个模态。**

## 3. 标注 schema v1

```json
{
  "video_id": "sess_20260720_01",
  "subject_id": "S017",
  "fps": 30,
  "session_meta": {
    "date": "2026-07-20",
    "lighting": "indoor_led",
    "camera": "cam01"
  },
  "segments": [
    {
      "t0": 12.0,
      "t1": 18.5,
      "intent": "I3",
      "annotator": "A",
      "conf": 0.8,
      "anchor_mode": "event_ts",
      "anchor_event_id": "ev_0042",
      "annotated_at": 1789000000.0
    }
  ],
  "events": [
    { "id": "ev_0042", "t": 18.2, "type": "asked_question" }
  ]
}
```

字段要点：

| 字段 | 为什么必须有 |
|---|---|
| `anchor_mode` | 声明标签时间是怎么定的：`event_ts`（事件锚回溯）/ `manual_segment`（人工划区间）/ `fallback_now`（兜底，**单列统计，评测时默认剔除**）。LnMem 实测：剔除 81 条 fallback 样本后信号强度 +23%——兜底样本是稀释剂 |
| `annotated_at` | 标注**动作**发生的时刻 ≠ 被标注**内容**的时刻。两者不分是 §4 事故的根源 |
| `anchor_event_id` | B 级标签必须能追溯到锚事件 |
| `conf` | 标注者置信，供仲裁与加权 |

## 4. 时间对齐红线：anchor 校验（本手册最重要的一节）

### 4.1 事故原型（LnMem 根因 A，全手册的存在理由）

标注系统的实现是：用户在控制台看到一帧画面做出判断 → 点击提交 → 服务端收到 POST 后**从推理缓冲取「当前」最近 10s 特征窗**存为该标注的训练输入。看起来天衣无缝，实际上：

- 控制台展示的帧取自信号缓冲的**最旧端**（`data[0]` 而非 `data[-1]`），比「现在」旧约 5 分钟；
- 于是每条样本的标签对应约 5 分钟前的画面，特征窗却是点击瞬间的——**481/481 条，100% 错位（median ≈285s）**；
- 模型在学「现在的脸 → 5 分钟前某事的标签」，等价于纯噪声；
- 该 bug 存活约一个月，期间 11 轮模型层消融实验（τ、lag、窗长）全部无结论——**因为病根不在模型层**；
- 全部旧标注报废，修复前继续攒 = 攒废数据。

### 4.2 五条铁律

| # | 铁律 | 执行 |
|---|---|---|
| A1 | **标注 ts 必须落入其特征窗** | 入库前自动校验 `t0/t1 ∈ [win_start, win_end]`，不过不入库、告警。进 CI + 线上双份 |
| A2 | **展示帧与存储窗同源同刻** | 标注 UI 展示的内容必须携带其自身 `ts`，提交时按该 `ts` 回切特征窗（server 端按 anchor 切窗），而不是「提交时刻取最新」 |
| A3 | **三类时刻分立字段** | 内容时刻（`t0/t1`）/ 锚事件时刻（`events[].t`）/ 标注动作时刻（`annotated_at`）永不混用 |
| A4 | **fallback 单列** | 取不到 anchor 时允许 `anchor_mode=fallback_now` 兜底入库，但必须打标；评测默认剔除 |
| A5 | **修复后实战验收** | anchor 机制上线后，用真实标注流验收 N≥50 条：anchor 命中率必须 100%（LnMem 修复后验收 50/50） |

### 4.3 校验脚本规格（工程实现参考）

```text
validate_annotation(record) -> pass | reject(reason):
  1. record.segments[*].t0/t1 均落在其引用特征序列 [min_ts, max_ts] 内
  2. anchor_mode ∈ 枚举；event_ts 模式必须能解析 anchor_event_id
  3. annotated_at ≥ t1（不能先标后发生）
  4. session_meta 必填字段齐全
  5. 输出周报：anchor 命中率 / fallback 占比 / 时钟偏移分布（多机采集时 NTP 漂移也会制造 A1 违例）
```

## 5. 采集与标注流程 SOP

1. **伦理与告知**：录制告知、可退出；敏感场景默认只存特征不存原视频；
2. **场景脚本**：设计诱发任务（听讲解 / 做难题 / 自由离座），保证各标签类都有自然诱发路径；
3. **context 通道先行**：按 §2.3 清单把事件流采集接好，**再**开视频采集——顺序反了就是 LnMem 的「想接模态没原料」；
4. **VLM 预标注 + 人工校验**（2026 趋势，成本差 5–10×）：
   - VLM zero-shot 预标注（VQA prompt / 链式推理式），产出候选 segment + 置信度；
   - 人工只做校验与仲裁，低置信与分歧样本进人工队列；
   - **评测集例外**：仍需双人独立全标 + Cohen's κ（κ < 0.6 的标签类回炉改 §1.3 定义）；
5. **纠正信号配额**（LnMem 结构性短缺教训）：若标注流里有「模型预测 → 人确认/纠正」环节，必须监控**纠正类样本占比**——LnMem 曾出现 10 条反馈里仅 1 条纠正（其余全是自我印证），模型无从学起。触发/抽样策略要主动偏向可能出纠正的时刻，而不是模型最自信的时刻；
6. **难例集单列**：强光、侧脸、口罩、肤色多样性，单独成集不混入主训练集。

## 6. 数据健康度哨兵（与主文档 §10.7 六红线一一对应）

| # | 哨兵 | 阈值/频率 | LnMem 学费 |
|---|---|---|---|
| R1 | anchor 校验 | 每条入库时 + CI | 481 条 100% 错位报废（§4.1） |
| R2 | **per-dim 活性** | 每维特征滚动方差 / 取值分布，日报；恒常值维 = 死维告警 | 18 维里 4 维（audio/context）恒缺省值 0.5 跑了 4788 帧无人发现；另有 1 维（gaze）死。死维不但无信号，还污染诊断：kNN MI 估计器对恒 0.5 的死维测出 0.039 nats 正偏底噪 |
| R3 | 类别分布 | none/unknown 占比周报 | 旧数据 none 占 65%（灌水稀释信号）；修复采集策略后 pos 42% / neg 38% / none 20% |
| R4 | 阈值实测校准 | 任何触发/置信阈值，先扫候选信号的 P50/P75/P90 + **饱和率** | 两个信号 49% 帧饱和在 1.0，阈值设 0.6 和 0.95 触发数完全相同——饱和率 >30% 时绝对阈值失效。另：拍脑袋阈值曾造成 4 分钟 22 次弹窗过敏 |
| R5 | MI 门 | 见 §9 | 11 轮模型消融循环论证 vs 中立裁判一轮定案 |
| R6 | 中期评审 | 见 §10 | 问题在 14 天 PoC 的第 13 天才被发现，为时已晚 |

## 7. 划分与评估协议

1. **按人 ID 划分** train/val/test（防身份泄露）——必要但**不充分**；
2. **叠加按时间划分**：blocked-by-day 或 rolling-origin——同一人同一天的相邻窗口跨 train/test 就是时间泄露，随机 K-fold 在时序数据上**必然**泄露（LnMem：codex 评审增量结论）；
3. **GroupKFold 退化警示**：当数据高度集中于少数 session/被试（LnMem：91% 样本来自单一常驻 session id）时，GroupKFold 会退化出 p=1.0 之类的伪影——那是**统计功率塌了**，不是「无信号」。判读任何跨组检验前先看组分布；
4. 评测集只用 `anchor_mode ≠ fallback_now` 的样本（§3）；
5. 报告必须注明：数据集版本、每被试/每日样本分布、剔除样本数及原因。

## 8. 指标口径（写进需求基线，不许临时改）

| 规则 | 内容 | 依据 |
|---|---|---|
| **禁 accuracy 做北极星** | 重 unknown 分布下，全猜多数类即可拿 >0.5 的 accuracy。LnMem 实测：所有配置的 accuracy 都跑不赢「全猜 none」（0.548）——曾经的「65% 准确率」承诺被此口径戳穿 | LnMem 终局 |
| 北极星 = 双指标 | **Macro-F1**（建议门槛 ≥0.55）+ **非 unknown 二分 F1**（建议 ≥0.65），随场景标定但必须成对出现 | LnMem 北极星修订 |
| 多数类基线硬门 | 任何模型指标必须显著跑赢「全猜多数类」与「按先验随机猜」两条基线，否则不进报告正文 | 同上 |
| 提前量曲线 | B 级标签必报提前 0.5s / 1s / 2s 的 F1 曲线——提前量才是意图任务的产品价值 | 主文档 §10.4 |
| 拒识两条曲线 | 覆盖率–精确率曲线；conformal 模式下报名义覆盖率 vs 实测覆盖率 | 主文档 §8.6 |

## 9. MI 门：训练前的中立裁判

**规则：标注攒到第一批（建议 ≥300 条干净样本）后、训练任何时序模型之前，先跑一轮特征↔标签互信息裁判。**

- 做什么：直接计算「原始特征（0s 单帧 / 不同 lag / 不同窗长聚合）↔ 人工标签」的 MI 与 permutation p 值，**不经过任何受测模型**；
- 为什么：用受测模型自身做消融来回答「有没有时序信号」是循环论证——LnMem 在 τ 之争上烧了 11 轮 lag ablation 无结论，中立裁判一轮定案（时序增量为零，单帧最优）；
- 判读三修正（LnMem 方法学遗产，复用其 harness 时必读）：
  1. 死维先剔除再算（kNN MI 正偏底噪，见 §6 R2）；
  2. 组分布先检查再信跨组 p 值（GroupKFold 退化，见 §7.3）；
  3. 判别文案要按数据实情重写——脚本模板给出的「domain shift → 转 per-user 建模」这类结论在单人/单场景数据上语义错误；
- 出口：
  - 时序增量存在 → 放行时序模型 A/B（含模拟丢帧组，主文档 §9.4）；
  - 单帧有信号、时序无增量 → 先做单帧基线产品化，时序模型降优先级;
  - 全无信号 → **回 §2 改输入面**（加 context 维度），不是调模型。

> 可复用资产：LnMem-poc 仓 `scripts/diag_mutual_information.py` / `diag_within_session.py`（含上述三修正的上下文见其 `docs/reports/2026-07-03-phase2-verdict-final-and-pause.md` §3）。
