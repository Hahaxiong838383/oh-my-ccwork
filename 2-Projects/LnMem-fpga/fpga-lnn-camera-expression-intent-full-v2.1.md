## 1. 执行摘要

### 1.1 一句话结论

**在 FPGA 上接摄像头做「实时表情 + 短期意图趋势」是可行的工程路径**；推荐架构为：

> **轻量视觉前端（检测/对齐/空间特征）+ 场景 context 信号 + LNN/CfC 时序后端 + 任务头（表情 / 意图）**，  
> **全链路流水线 + INT8/定点 + 置信度门闩**。

**v2.1 核心修订**：意图头的输入面必须从 v1 起就包含 **context（场景/交互事件信号）**——「纯脸部特征 → 意图」的信号天花板已被独立项目 LnMem 实证为产品级不可用（详见 §10.0）。

### 1.2 三个必须分清的命题

| # | 命题 | 判断 | 依据强度 |
|---|---|---|---|
| P1 | FPGA 能否运行 LNN？ | **能**（尤其 CfC / 定点 LTC 基线） | 公开论文/课题有硬件结果 |
| P2 | 摄像头 + FPGA 能否实时做人脸后续？ | **能**（检测/ISP/轻量 CNN 已成熟） | 工业界常规 |
| P3 | 能否直接「读心」通用意图？ | **不能当作已验证**；须先定义标签、采数、评测 | 无公开端到端成品先例 |

### 1.3 推荐技术选型（默认）

| 层 | 选型 | 理由 |
|---|---|---|
| 传感器 | MIPI CSI 摄像头优先 | 带宽与延迟优于 USB UVC |
| 平台（原型） | **Kria KV260** | 有 CfC on FPGA fabric 先例；PS+PL 分工清晰 |
| 平台（低成本 demo） | Zynq XC7Z020 | 可做链路 demo，不宜当高分多人产品 |
| 空间特征 | 关键点几何 **或** 轻量 FER embedding（INT8） | 降维到 32~128d |
| 时序核 | **CfC**（部署默认）/ **双门控短卷积块**（LFM2 式，A/B 候选）/ LTC（研究对比） | CfC 避免迭代 ODE 且显式吃可变 dt；门控短卷积无超越函数、更易定点（Liquid AI 工业化路线，§19） |
| 输出 | 表情连续态/类别 + 意图 3~8 类 + 拒识 | 意图必须场景化；v1 收缩为动作前兆类（§10.1 分级） |

### 1.4 本文不承诺的内容

- 不承诺「任意 FPGA 板、任意分辨率、任意人数」都能 30 fps。
- 不承诺存在现成的「LNN + FPGA + 摄像头 → 通用意图」开源成品。
- 不把神经形态芯片（Loihi）结果直接等同 FPGA 结果。
- 不把「液体状态机 LSM（2008）」与「LTC-LNN（2020）」混为一谈。

## 2. 问题定义与边界

### 2.1 业务问题（可写成需求）

**场景钦定（2026-07-20）**：v1 = **日常办公会议**（单人主 ROI，桌面/会议室机位）；**车载为扩展目标**——不进 v1 排期，但接口契约（§6.3）、配置 profile（§8.7）与意图标签体系（§10.1）设计时须保留车载迁移空间（光照/振动/机位差异走 profile 而非改架构）。

在边缘设备上，对摄像头画面中的人脸（默认单人主 ROI）：

1. **实时估计表情状态**（离散情绪类，和/或 连续效价-唤醒 / AU 动态）；
2. **在预定义意图集合上做短期预测**（例如：困惑倾向、准备发言、离开倾向），并给出置信度；
3. **端到端时延与吞吐满足交互/告警场景**（见第 13 章 KPI）；
4. 输出仅用于 **提示 / 统计 / 人机交互策略**，不直连危险执行器。

### 2.2 非目标（Out of Scope，v1）

| 非目标 | 原因 |
|---|---|
| 通用「读心」/开放域意图 | 无标签、无因果、不可验收 |
| 端到端像素→意图纯 LNN | 高维空间特征不是 LTC/CfC 公开强项 |
| 大模型级 Transformer 实时表情 | 带宽与算力墙；与微信文结论同向 |
| 强隐私场景下的云端长视频回传 | 默认边缘本地推理 |
| 多人密集场景产品级 SOP | 需另开检测/跟踪预算 |

### 2.3 成功判据（Definition of Done）

同时满足才算「链路跑通」：

1. **功能**：离线金标准与板端输出在允许误差内（表情 + 可选意图头）；
2. **实时**：单脸端到端 P95 时延 ≤ 目标（默认 50 ms），吞吐 ≥ 30 fps 或按场景约定；
3. **稳健**：光照变化、小角度侧脸、短时遮挡有量化指标（可降级，不可 silent fail）；
4. **安全**：低置信拒识；意图不直接驱动危险动作；日志可审计；
5. **证据**：有数据集说明、评测表、资源/功耗报告，而不是 demo 截图。

## 3. 先对齐：微信文在讲什么（不是 LNN）

### 3.1 原文事实（研读对齐）

微信文《把大模型塞进 FPGA 后续》一类分享，核心是：

| 项 | 内容 |
|---|---|
| 工作主体 | 本科生将 **nanoGPT（迷你 Transformer）** 部署到 **Zynq XC7Z020** |
| 关键技术点 | 共享计算核、**KV Cache**、INT8 量化 |
| 验收结果 | 板端 vs 定点 Python：200 token **0 失配**；约 **129.5 ms/token** |
| 开源参考 | https://github.com/HanxinKING/nanogpt-zynq-backups/ |
| 相关实现 | https://github.com/zcxsince2005/My_Transformer_on_fpga |
| 原文链接 | https://mp.weixin.qq.com/s/ks59AqqyomQ0JNDl_dtTyw |

### 3.2 它证明了什么 / 没证明什么

| 证明了 | 没有证明 |
|---|---|
| 小型 Transformer **可以**上中低端 FPGA | 文中已跑过 LNN |
| INT8 + 共享核 + 缓存策略有效 | 大参数量 LLM 可实时交互 |
| **金标准对拍（0 失配）** 是正确的硬件文化 | 视觉端到端实时表情已解决 |
| 带宽/FFN 往往是瓶颈（工程上要尊重数据通路） | 「FPGA = 免费算力」 |

### 3.3 可迁移的工程文化（比模型名字更重要）

1. **定点 Python / 浮点金标准 → RTL/HLS 逐层对拍**；
2. 量化误差单独记账，不把「差不多」当「正确」；
3. 先锁 **PPA（性能/功耗/面积）与延迟预算**，再堆模块；
4. 开源可复现路径，避免「只有 demo 视频」。

**结论：** 该文是 **「小型序列模型上 FPGA」** 的旁证与方法论模板；**不能**直接写成「文中已实现 LNN 表情意图系统」。

## 4. LNN 技术底座：LTC / CfC / NCP

### 4.1 名词表（避免混用）

| 缩写 | 全称 | 含义 | 备注 |
|---|---|---|---|
| **LNN** | Liquid Neural Network | 常指 LTC 家族连续时间神经网络 | 口语总称，写方案时尽量落到 LTC/CfC |
| **LTC** | Liquid Time-Constant | 时间常数随状态变化的连续时间 RNN | 前向常需 ODE 数值求解 |
| **CfC** | Closed-form Continuous-time | 闭式/近似闭式更新的连续时间模型 | **更适合嵌入式/FPGA 部署** |
| **NCP** | Neural Circuit Policies | 稀疏线虫启发结构 + LTC 单元 | 常与 LTC 联用，参数量可极小 |
| **LSM** | Liquid State Machine | 更早的 reservoir「液态」计算 | **≠ 2020 LTC-LNN** |
| **Neural ODE** | Neural Ordinary Differential Equations | 用 ODE 描述隐状态演化 | LTC 属于更结构化的一类 |

### 4.2 LTC 直觉与形式（工程向）

LTC 的核心思想：每个隐藏单元的 **时间常数不是固定的**，而由输入与状态通过门控非线性调制，从而在时间上「液态」适应不同时间尺度。

连续时间形式可概括为（示意，细节以论文为准）：

\[
\frac{d\mathbf{h}(t)}{dt}
=
-\left[\frac{1}{\boldsymbol{\tau}} + f(\mathbf{x}(t),\mathbf{h}(t);\theta)\right]\odot \mathbf{h}(t)
+
f(\mathbf{x}(t),\mathbf{h}(t);\theta)\odot A
\]

- \(\mathbf{h}(t)\)：隐状态  
- \(\boldsymbol{\tau}\)：基础时间常数相关项  
- \(f(\cdot)\)：由网络参数 \(\theta\) 参数化的非线性（门控）  
- \(A\)：系统稳态相关偏置/边界项  

**工程含义：**

- 前向常调用 **ODE solver**（固定步 / 自适应步）；
- 表达力强、时序建模漂亮，但 **多步积分 → 硬件上串行深度大、难并行、延迟与能耗不确定**；
- 适合 **训练探索 / 小规模时序**；直接上 FPGA 原始 LTC 要额外做「固定步数 / 求解器硬化」。

**权威出处：**

- LTC 论文：https://arxiv.org/abs/2006.04439  
- 官方代码：https://github.com/raminmh/liquid_time_constant_networks  
- 现代易用库 ncps：https://github.com/mlech26l/ncps  

### 4.3 CfC：为什么部署优先

CfC（Closed-form Continuous-time）目标：在保持连续时间归纳偏置的同时，给出 **闭式或近似闭式的时间更新**，从而：

- **避免每一步迭代 ODE 求解**；
- 推理图变成 **固定算子图**（乘加、门控、指数/近似指数、插值混合等）；
- 更像「可综合的小型 RNN 核」，便于 **定点化、流水线、可预测 latency**。

**工程写法（示意）：** 给定采样间隔 \(\Delta t\)，

\[
\mathbf{h}_{t}
=
\sigma(-\mathbf{f}_t \cdot \Delta t)\odot \mathbf{h}_{t-1}
+
(1-\sigma(-\mathbf{f}_t \cdot \Delta t))\odot \mathbf{g}_t
\]

其中 \(\mathbf{f}_t,\mathbf{g}_t\) 由输入 \(\mathbf{x}_t\) 与 \(\mathbf{h}_{t-1}\) 的线性/非线性网络产生（具体参数化以 CfC 论文/实现为准）。

**出处：**

- Nature Machine Intelligence 论文：https://www.nature.com/articles/s42256-022-00556-7  
- 代码：https://github.com/raminmh/CfC  
- ncps 中亦集成 CfC 单元  

### 4.4 对「表情/意图」任务的归纳偏置匹配

| 现象 | 为何匹配 LNN/CfC |
|---|---|
| 表情是 **连续演化** 而非独立帧标签 | 连续时间/可变时间常数 |
| 不同人「假笑→真笑」时间尺度不同 | 液态时间常数 |
| 意图往往是 **短时趋势**（即将提问/离座） | 时序状态机 + 分类头 |
| 边缘算力紧 | NCP/CfC 可达 **极小参数量** 仍有表达力 |

**但不匹配：** 从原始高分辨率像素直接提取空间语义——这是 CNN/ViT 的工作。

**⚠️ v2.1 实证警示——时序增益不是免费的**：连续时间归纳偏置兑现的前提是**特征流里真的携带时序信号**。LnMem 在真实摄像头 AU 特征上实测：10s 时序窗对意图标签的互信息增量为零（四轮裁判一致，单帧反而最优）——在弱信号输入上争论 τ/时序结构接近伪命题。因此本方案定两条纪律：① 先证信号、再训模型（§9.4 MI 门 + §10.7 R5）；② CfC 的主战场明确为**可变 dt**（丢帧/降频/事件驱动，§13.3 与 §19），而非均匀 30fps 采样。

### 4.5 推荐模型拓扑（算法默认）

```
x_t = concat(f_t, c_t) ∈ R^{d+k}   # f_t: 视觉前端特征 32~128d；c_t: 场景 context 4~16d（§6.3，v2.1）
    │
    ▼
┌─────────────┐
│  CfC Cell   │  hidden h ∈ R^{H}, H=16~128
│  (或 NCP)   │
└─────────────┘
    │ h_t
    ├──────────────► Expression Head → e_t  (K类 或 2D VA / AU)
    ├──────────────► Trend Head      → Δe   (可选)
    └──────────────► Intent Head     → i_t  (C类 + reject)
```

- **多任务共享时序核**，头部分离，避免意图头污染表情主任务（可用 loss 权重与 stop-grad 技巧）。
- **context 通道 c_t 从 v1 就进输入面**（交互事件 one-hot / 距上一事件 Δt / 键鼠活动率等）：意图的因果上游在场景不在脸（§10.0），context 不能只当训练弱标签。
- 输入窗：流式单步更新（在线）；训练可用 T=8~64 的序列截断 BPTT。

## 5. FPGA 能否运行 LNN：公开证据链

> 结论先行：**可以。** 但证据多是 **小网络时序加速 / 模型恢复 / 分类**，不是「摄像头端到端产品」。

### 5.1 证据矩阵

| ID | 证据 | 平台 | 模型 | 关键数字 | 对本文的含义 | 链接 |
|---|---|---|---|---|---|---|
| **A** | MERINDA | FPGA | 讨论 LTC / ODE 硬件难点；相对 FPGA-based LTC baseline 加速 Model Recovery | 约 **6.3× 更少 cycle**（相对其 baseline 设定） | 证明 LTC 类计算 **已有人在 FPGA 上认真做**；ODE 串行是真痛点 | https://arxiv.org/abs/2512.06113 |
| **B** | OST 课题 | **Kria KV260** fabric | **CfC** | CPU ~**3.49 ms** vs FPGA ~**22.5 µs**（约 **155×**）；有 MSE 升高代价 | **最直接的「CfC→FPGA」先例**；原型板选型锚点 | https://www.ost.ch/files/daten/abstracts/pdf/0fa74ec8-23c8-40be-937d-b785254a7651.pdf |
| **C** | LNN on Loihi-2 | 神经形态 ASIC | LNN | CIFAR-10 ~**91.3%**，~**213 µJ/frame** | 证明 LNN **可硬化到硅**；**≠ FPGA 数字** | https://arxiv.org/abs/2407.20590 |
| **D** | LSM on FPGA | FPGA（2008） | Liquid State Machine | 语音等 | **名字 liquid 但模型族不同**，勿并入 LTC 证据 | 文献：Schrauwen et al. / SciDirect 相关条目 |

### 5.2 证据解读规则（写对外材料时用）

1. **能引用「FPGA 可跑 CfC/LTC 类」** —— 用 A/B。  
2. **引用能耗/精度时必须标明平台** —— Loihi 数字不要写成 FPGA。  
3. **LSM 单独脚注**，避免审稿人/老板抓混用。  
4. **任何「我们板子也能 22.5 µs」必须复现条件**：隐层大小、位宽、是否含特征提取、时钟、是否含 DMA。

### 5.3 「能跑」的边界

| 能 | 不能默认 |
|---|---|
| 低维时序核（数十~数百状态）µs~百 µs 级更新 | 720p 全图端到端 LNN 实时 |
| 与 CNN/DPU 流水线拼接 | 无视 DRAM 带宽与检测延迟 |
| 定点化后可预测 latency | 自适应 ODE 求解器任意步数仍实时 |

## 6. 摄像头链路：为何不能端到端像素 LNN

### 6.1 维度鸿沟

| 量 | 数量级 | 说明 |
|---|---|---|
| 720p 一帧像素 | \(O(10^5\sim10^6)\) | 尚未计多通道与 ISP 中间态 |
| 典型 LNN/CfC 隐状态 | \(10^1\sim10^2\) 维 | 公开高效案例多在此范围 |
| 时序步 | 10~30 Hz 视频 | 每步都要吞下「空间压缩后的向量」 |

LTC/CfC 的归纳偏置在 **时间动力学**，不在 **大规模空间层级特征**。把像素直接当 \(x_t\)：

- 参数与 MAC 爆炸；
- 对平移/光照等变化极脆；
- 没有公开「产品级」成功范式可抄。

### 6.2 正确分工（本设计的核心原则）

```
摄像头
  → 图像前端（ISP / 缩放 / ROI）          【空间 + 信号调理】
  → 人脸检测 / 跟踪 / 对齐                 【几何】
  → 空间特征（轻量 CNN 或 landmark）       【这帧是什么】
  → 低维序列 f_t ∈ R^{32~128}             【接口契约】
  →（拼接场景 context c_t：交互事件/键鼠）  【意图因果上游 · v2.1】
  → LNN/CfC 时序核                         【怎么变】
  → 表情头 / 意图头 / 后处理               【任务语义】
  → 策略层（门闩、日志、UI）               【业务与安全】
```

| 维度 | 负责模块 | 不该塞给 |
|---|---|---|
| 空间「是什么」 | CNN / landmark / 可选小 ViT | 纯 LNN |
| 时间「怎么变」 | CfC / LTC / GRU… | 单帧 CNN 硬凑 |
| 意图「下一步可能怎样」 | 时序状态 + 分类头 + 数据 | 无标签的「感觉」 |

### 6.3 接口契约（前后端解耦）

定义稳定的 **Feature Frame**（建议）：

```text
FeatureFrame {
  ts_ms: u64,              # 采集时间戳
  track_id: u32,           # 人脸轨迹 ID
  face_bbox: [x,y,w,h],    # 像素或归一化
  pose: [yaw,pitch,roll],  # 可选
  feat: float16[d],        # d=32~128 主特征
  context: float16[k],     # k=16 会议 context schema v1，意图头必需；完整定义见 feature_contract.md（v2.1）
  context_valid: bool,     # context 链路在线与否；false 时禁止灌缺省值（LnMem 死维教训）
  quality: float32,        # 模糊/遮挡/置信
  valid: bool
}
```

- 视觉前端可替换（OpenCV→DPU→纯 PL），**只要输出契约不变**，CfC 核无需重写。
- `quality` 低时：冻结状态 / 降权更新 / 输出 `unknown`。
- **每维活性纳入健康监控**（§8.7）：LnMem 实测 18 维中 4 维恒缺省值跑一个月无人发现——死维不但零信号，还会污染 MI 诊断（kNN 估计器对死维有正偏底噪）。

### 7.1 逻辑架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        Application / Safety                     │
│   UI · 日志 · 标定 · 策略门闩 · 远程配置（可选）                  │

└───────────────────────────────┬─────────────────────────────────┘
                                │ AXI / shared mem / RPMsg
┌───────────────────────────────▼─────────────────────────────────┐
│ PL (FPGA fabric)                                                │
│  ISP → Detect/Align → CNN/Landmark(INT8) → CfC(fixed) → Heads   │
│  （可部分模块暂放 PS，阶段演进，见路线图）                          │
└───────────────────────────────┬─────────────────────────────────┘
                                │ MIPI / 并行 / USB(过渡)
                          [ Camera Sensor ]
```

### 7.2 硬件平台分档

| 档 | 推荐板卡 | 适用 | 备注 |
|---|---|---|---|
| **原型首选** | **Kria KV260** | 算法+PL 协同、CfC 先例 | 生态（Ubuntu/PYNQ/Vitis）友好 |
| 扩展原型 | ZCU104 / 同类 Zynq UltraScale+ | 更高 ISP/多人预算 | 成本上升 |
| 低成本 demo | **XC7Z020**（如 PYNQ-Z2 / 各类开发板） | 教学、链路打通 | **别当高分多人产品** |
| 生产 | 自研 SoC 模组（Zynq US+ / 国产对标） | 量产 | 需另开 BOM/供货评估 |

### 7.3 部署拓扑选项

| 拓扑 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| **T1 全边缘** | 板端闭环 | 隐私好、延迟稳 | 算力上限 |
| **T2 边缘+旁路云** | 仅上传聚合统计/难例 | 可迭代模型 | 需合规 |
| **T3 仅 PC 金标准** | 阶段 1 | 快 | 非最终形态 |

默认产品路径：**T1**，开发期允许 T3→T1。

### 7.4 数据流与时钟域（概念）

1. Sensor 像素时钟域 → ISP  
2. 帧级流水（line buffer / frame buffer）  
3. 检测 ROI 后特征提取（可跳帧检测、逐帧跟踪）  
4. 每帧（或每 N 帧）产生 `FeatureFrame` → CfC 单步  
5. 结果经 AXI-Lite/Stream 到 PS → 业务  

**丢帧策略：** 超时则丢最旧帧，**保时延不保每一帧**（实时系统常规）。

## 8. 模块详细设计

### 8.1 成像与 ISP

| 项 | 建议 |
|---|---|
| 接口 | **MIPI CSI-2** 优先；USB UVC 仅作 demo |
| 分辨率 | 工作流 **640×480 或 720p**；检测可降到 320~480 边长 |
| 帧率 | 传感器 30/60 fps；处理 30 fps 目标 |
| ISP | 黑电平、AWB、gamma、缩放；可厂商 IP 或开源 |
| 触发 | 自由运行；时间戳在帧进入时打 |

**坑：** 自动曝光突变会造成特征跳变 → 建议在 `quality` 中反映，或对特征做曝光归一。

### 8.2 人脸检测 / 跟踪 / 对齐

| 子模块 | 建议方案 | 延迟预算（目标） |
|---|---|---|
| 检测 | 轻量人脸检测（SCRFD-n / YuNet / 厂商 IP） | 3–10 ms（可 5~10 帧一次） |
| 跟踪 | IoU / KCF / 简单位置预测 | <1 ms |
| 对齐 | 5 点相似变换；输出 96×96 或 112×112 | <1 ms |
| 失败处理 | `valid=false`，CfC 可选衰减更新 | — |

**多人：** v1 只保 **主脸（最大/最近/交互位）**；多人需乘算力与 ID 管理。

### 8.3 空间特征提取（二选一或融合）

#### 方案 F1：几何关键点

- 输入：对齐后人脸  
- 输出：landmark 坐标差分 / 形变特征（可 PCA 到 32~64d）  
- 优点：极轻、可解释、FPGA 友好  
- 缺点：细粒度表情上限低于深度特征  

#### 方案 F2：轻量 FER embedding

- 小 CNN（MobileNet-ish / EmotionNet Nano 量级）INT8  
- 输出 64~128d embedding  
- 优点：表情判别力更强  
- 缺点：资源与量化工作量大  

参考方向（轻量表情 CNN）：  
https://www.frontiersin.org/articles/10.3389/frai.2020.609673  

#### 方案 F3：融合（推荐中后期）

`feat = concat(geom, emb)` 再线性投影到固定 d。

### 8.4 CfC 时序核（PL 核心 IP）

#### 功能

- 输入：`x_t`（d 维）、`valid`、可选 `dt`  
- 状态：`h`（H 维），掉电可保存到 BRAM/PS  
- 输出：`h_t` 及中间门控（调试用）  

#### 参数建议（起步）

| 参数 | 起步值 | 范围 |
|---|---|---|
| d（输入维） | 64 | 32–128 |
| H（隐状态） | 32 或 64 | 16–128 |
| 位宽 | 16-bit 定点激活 / 8-bit 权 | 见量化章 |
| 并行度 | 先 4~8 MAC/cycle | 按资源加 |

#### 微架构建议

```
AXI-Stream in (x_t)
   → 输入缓存
   → 并行 MAC 阵列（W_x, W_h）
   → 非线性（LUT 近似 sigmoid/tanh/exp）
   → 状态更新混合
   → h BRAM
   → AXI-Stream out (h_t)
```

- **固定延迟流水线**，每帧/每 tick 确定性 cycle 数；  
- 非线性用 **分段线性 LUT**，与金标准同一近似；  
- 支持 `soft_reset`（换人 track_id 变化时清状态）。

### 8.5 任务头

| 头 | 输出 | 损失（训练） | 部署 |
|---|---|---|---|
| 表情分类 | K 类 logits | CE / focal | argmax + conf |
| 表情连续 | valence-arousal | CCC / MSE | 回归 |
| AU（可选） | 多标签 | BCE | 阈值 |
| 意图 | C 类 + reject | CE + 拒识 | conf 门限 |
| 趋势（可选） | \(\Delta e\) | MSE | 平滑显示 |

### 8.6 后处理与策略层

1. **时间平滑**：EMA / 中值； discrete 标签用迟滞（进入阈值 > 退出阈值）；  
2. **拒识**：起步 `max_softmax < τ` → `unknown`；v1.1 升级 **split conformal + reject option**（分布无关覆盖保证；推理时只是分数与校准分位数比较，FPGA 零额外算力）；  
3. **冷却时间**：意图告警最小间隔，防抖；  
4. **状态机**：`NO_FACE → TRACKING → DEGRADED → LOST`；  
5. **安全**：意图事件默认只写日志/UI，不驱动执行器。

### 8.7 标定与运维

- 相机内参（若做 3D 姿态）；  
- 曝光/ROI 配置 profile（会议室/车载/柜机）；  
- 模型版本号与 checksum；  
- 远程只读指标（FPS、丢帧、温度、电压）；  
- **特征健康度哨兵（v2.1）**：每维特征滚动方差/取值分布日报，死维（恒常值）与饱和维（>30% 帧贴上下界）告警——定点化 scale/zero_point 配错最易造死维（手册 §6 R2）；  
- 阈值类配置（`conf_th` 等）必须附实测分布依据（P50/P75/P90 + 饱和率），禁止拍脑袋（手册 §6 R4）。

## 9. 表情任务设计

### 9.1 标签体系选择

| 体系 | 内容 | 适用 |
|---|---|---|
| 离散 7 类 | 怒、厌、惧、喜、悲、惊、中性 | 演示友好 |
| VA 连续 | valence / arousal | **更贴 LNN 连续动力学** |
| FACS AU | 动作单元 | 可解释、标注贵 |
| 复合 | 离散 + VA | 产品常用 |

**建议：** 训练主任务用 **VA 或 AU 动态**，演示层映射到 7 类。

### 9.2 公开数据（表情，非意图）

| 数据集 | 用途 | 注意 |
|---|---|---|
| AffectNet | 大规模野外表情 | 噪声标签 |
| FER2013 | 基线 | 分辨率低 |
| RAF-DB | 质量较好 | 许可 |
| Aff-Wild / Aff-Wild2 | 视频连续标注 | 更贴时序 |
| CK+ | 实验室可控 | 不代表野外 |

**时序训练：** 优先视频集或把静态图合成短序列（弱）；评估必须在视频上报告。

### 9.3 评价指标

| 指标 | 说明 |
|---|---|
| UAR / WAR | 类别不均衡时必报 UAR |
| CCC | VA 连续一致性 |
| 时序平滑错误率 | 抖动惩罚 |
| 与单帧基线 Δ | **证明 LNN 后端有增益** |

### 9.4 LNN 后端的价值主张（怎么写进汇报）

不要写「LNN 更准（空）」；要写可证伪对比：

0. **MI 门（v2.1 前置）**：训练任何时序模型前，先用中立裁判直接计算「特征（0s 单帧 / 不同 lag / 不同窗长）↔ 标签」互信息——时序增量不存在就不要指望时序模型跑出增益。LnMem 曾用 11 轮模型层消融反复争论 τ 全是循环论证，中立裁判一轮定案（手册 §9）；  
1. 单帧 CNN；  
2. CNN + GRU/LSTM；  
3. CNN + CfC/LTC；  

在 **相同前端特征** 下比：准确率、参数量、延迟、抖动、短时遮挡恢复；  
**必须加测「模拟丢帧/降频」组**（随机 drop 10–40% 帧、检测降频+跟踪补帧）：均匀 30fps 采样下 CfC 对 GRU 的优势未必显著，**不规则 dt 才是 CfC 应该赢的战场**——这恰是 §13.3 降级策略的真实运行态。

## 10. 意图任务设计（必须自建）

> **没有标签定义与数据，就没有「意图预测」产品，只有故事。**

> **v2.1 依据**：本章修订来自 LnMem 项目实证（2026-05~07，543 条真实标注 + 信息论中立裁判四轮 + 双引擎对抗审签收）——它做的正是「摄像头脸部时序 → 意图」的单人版本。操作细节固化在配套 [`intent_annotation_handbook.md`](intent_annotation_handbook.md)（下称「手册」）。

### 10.0 输入面原则（v2.1 核心修订）

**意图的因果上游在场景与交互事件，不在脸。** LnMem 终局数字：纯脸部（AU）特征对意图互信息仅 +0.086 bits（占标签熵 5.7%），F1 0.39 vs 多数类基线 0.24——统计显著、产品级到顶；而仅两个粗糙 context 字段（最近事件类型+时段）即带来 Macro-F1 **+18%**。

| 信号 | v2.0 处理 | v2.1 处理 |
|---|---|---|
| 场景/交互事件（提问、离座、议程切换、键鼠） | 仅训练弱标签 | **推理输入特征 + 弱标签双重身份**，进 `FeatureFrame.context`（§6.3），v1 就位 |
| 脸部时序特征 | 主模态 | **降级为辅助模态**，与 context 融合 |

### 10.1 意图必须「场景化、可观察、可标注」

坏例子：

- 「用户在想什么」「是否喜欢你的产品」（不可观察/不可验收）

好例子（会议助手场景）：

| ID | 意图标签 | 可观察依据（标注指引） |
|---|---|---|
| I1 | 专注听讲 | 朝向屏幕/讲者，较少大幅度动作 |
| I2 | 困惑 | 皱眉、歪头、反复看同一区域 |
| I3 | 准备发言 | 身体前倾、张嘴前兆、举手相关动作 |
| I4 | 不耐烦 | 频繁转头、看手机区域、坐立不安 |
| I5 | 离开倾向 | 起身前姿态、看门口、收拾动作 |
| I0 | 其他/未知 | 拒识桶 |

**数量建议：3–8 类 + 未知。** 类越多，数据与混淆越爆炸。

**可观察性梯度分级（v2.1，决定 v1 范围与风险）**：

| 级 | 类型 | 上表对应 | 风险与策略 |
|---|---|---|---|
| A | 动作前兆类（身体大动作可观察） | I3 准备发言、I5 离开倾向 | 低风险，**v1 主攻** |
| B | 交互事件锚定类（客观事件可对齐） | 以真实提问/离座事件为锚回溯取窗 | 中风险，事件锚天然解决「标签打在哪一刻」 |
| C | 内部状态推断类（从脸推内心） | I2 困惑、I4 不耐烦 | **高风险——LnMem 撞墙处；无 context 支撑不启动**（手册 §1.2） |

### 10.2 数据采集团队流程

1. **伦理与告知**：录制告知、可退出、敏感场景默认不存原视频（可只存特征）；  
2. **场景脚本**：设计诱发任务（听讲解、做难题、自由离座）；  
3. **context 通道（v2.1）**：键鼠/是否提问/是否离座等交互事件**同时作为推理输入特征与弱标签**（§10.0）；每个事件必须带独立时间戳，采集元数据清单见手册 §2.3——**采集时少存一个时间戳，分析时就少一个模态**；  
4. **VLM 预标注 + 人工校验（v2.1）**：VLM zero-shot 预标注（VQA prompt / 链式推理式）产出候选 segment，人工只做校验与仲裁（成本差 5–10×）；**评测集例外**：仍需双人独立全标 + 一致性（Cohen's κ）；  
5. **划分（v2.1 加严）**：按 **人 ID × 采集日** 双重划分（blocked-by-day / rolling-origin）；随机 K-fold 在时序数据上必有泄露，同人同日相邻窗口禁止跨 train/test（手册 §7）；  
6. **难例集**：强光、侧脸、口罩、肤色多样性检查。

### 10.3 标注格式建议

```json
{
  "video_id": "sess_20260719_01",
  "subject_id": "S017",
  "fps": 30,
  "session_meta": {"date": "2026-07-19", "lighting": "indoor_led", "camera": "cam01"},
  "segments": [
    {"t0": 12.0, "t1": 18.5, "intent": "I2", "annotator": "A", "conf": 0.8,
     "anchor_mode": "event_ts", "anchor_event_id": "ev_0042", "annotated_at": 1789000000.0}
  ],
  "events": [
    {"id": "ev_0042", "t": 18.2, "type": "asked_question"}
  ]
}
```

**anchor 铁律（v2.1）**：`t0/t1` 必须落在其引用特征帧序列的时间范围内，**入库前自动校验，不过不入库**。LnMem 曾因「标注动作时刻 ≠ 被标注内容时刻」系统性错位约 5 分钟，**481 条标注 100% 报废且一个月未被发现**——完整案例与五条铁律见手册 §4。`anchor_mode=fallback_now` 的兜底样本单列统计、评测默认剔除（LnMem：剔除后信号 +23%）。

### 10.4 建模方式

| 方式 | 描述 | 难度 |
|---|---|---|
| 帧/窗分类 | 对 \(h_t\) 或最近 T 步池化后分类 | 低，起步 |
| 提前量预测 | 在事件发生前 \(\Delta\) 秒预测 | 中，**真正有价值** |
| 序列标注 | CRF/CTC 类 | 高 |

**必须报告：提前量–准确率曲线**（例如提前 0.5s/1s/2s 的 F1）。

### 10.5 训练目标

\[
\mathcal{L}
=
\lambda_e \mathcal{L}_{expr}
+
\lambda_i \mathcal{L}_{intent}
+
\lambda_r \mathcal{L}_{reject}
+
\lambda_s \mathcal{L}_{smooth}
\]

- 意图样本少时：`λ_i` 勿压过表情；可用 focal / class-balanced。  
- 拒识：训练显式 unknown 或能量分数阈值。

### 10.6 意图任务的诚实对外话术

**推荐：**  
「在预定义的 N 类场景意图上，基于表情与头部动态时序特征，做短期倾向估计，并支持低置信拒识。」

**禁止：**  
「实时读懂用户想法」「通用意图识别已量产」。

### 10.7 数据管线红线（v2.1，违反任一条 = 数据不可信）

| # | 红线 | 一句话 | LnMem 学费 |
|---|---|---|---|
| R1 | anchor 校验进 CI | 每条标注 ts 必须落在其特征窗内，不过不入库 | 481 条 100% 错位报废 |
| R2 | per-dim 活性哨兵 | 每维滚动方差监控，死维/饱和维告警 | 4/18 维恒缺省值一个月未发现 |
| R3 | 类别分布监控 | none/unknown 占比周报，重 none 灌水淹没信号 | 旧数据 none 65% → 修复后 20% |
| R4 | 阈值实测校准 | 先扫 P50/P75/P90 + 饱和率再定阈值 | 信号 49% 帧饱和时 0.6 与 0.95 阈值触发数相同 |
| R5 | MI 门前置 | 训练前先中立裁判验信号存在 | 11 轮模型消融循环论证 vs 裁判一轮定案 |
| R6 | 中期健康度评审 | 采集到一半强制复盘对齐/活性/分布 | 问题第 13/14 天才发现，为时已晚 |

执行细节、校验脚本规格与案例全文见 [`intent_annotation_handbook.md`](intent_annotation_handbook.md)。

## 11. 训练、量化与导出

### 11.1 训练流水线

```
原始视频
  → 检测对齐（离线可更强模型）
  → 特征提取（与部署同结构的 float 版）
  → 序列样本打包（长度 T，步长 s）
  → 训练 CfC + 多任务头（PyTorch + ncps）
  → 验证（按人划分）
  → 导出 float 金标准 ONNX/ TorchScript
  → PTQ / QAT → 定点金标准（Python bit-exact 模型）
  → 权重与 LUT 导出 → FPGA 加载
```

### 11.2 软件依赖（建议）

- Python 3.10+  
- PyTorch  
- **ncps**：https://github.com/mlech26l/ncps  
- CfC 参考：https://github.com/raminmh/CfC  
- 可选：onnx、onnxruntime、brevitas / pytorch-quantization  

### 11.3 量化策略

| 阶段 | 方法 | 目标 |
|---|---|---|
| 前端 CNN | INT8 PTQ→不够再 QAT | 与 float Top-1 掉点可控（如 ≤1~2pt） |
| CfC 权 | INT8 | MAC 友好 |
| CfC 激活/状态 | INT16 起步 | 时序误差累积更敏感 |
| 非线性 | LUT 与 Python 共用表 | **位级可对** |

**时序网络量化注意：**

- 误差会沿时间累积 → 必须用 **长序列** 校准与验收；  
- 关注 `h` 的动态范围与饱和；  
- `dt` 若变化，确认定点缩放。

### 11.4 导出物

```text
artifacts/
  model_float.pt
  model_quant_spec.json      # 位宽、scale、zero_point
  weights_int8.bin
  lut_sigmoid.bin
  feature_contract.md        # d, 归一化, 坐标系
  eval_report.md
  bitexact_vectors/          # 输入输出向量，供 RTL sim
```

## 12. FPGA 实现：定点、资源、流水线

### 12.1 推荐实现路径

| 路径 | 适用 | 说明 |
|---|---|---|
| **HLS（Vitis HLS / 厂商 HLS）** | CfC 核快速迭代 | 注意 II、数组 partition |
| RTL（SystemVerilog） | 最终性能/面积优化 | 成本高 |
| DPU + 自定义 RTL | CNN 走 DPU，CfC 走自定义 | KV260 常见分工 |
| 全 PS 软实现 | 仅阶段 1–2 | 验证算法，不代表最终延迟 |

### 12.2 资源粗估（数量级，需综合后以报告为准）

假设：d=64，H=64，INT8 权，INT16 状态，单 CfC 层：

| 资源 | 量级直觉 |
|---|---|
| DSP | 取决于并行 MAC；小核可数十级 |
| BRAM | 权重 + 状态 + LUT；通常远小于大 CNN |
| LUT/FF | 控制与定点路径 |

**经验：** 在「特征已压缩」前提下，**CfC 核通常不是最大资源户**；检测 CNN 与帧缓存才是。

### 12.3 流水线时延预算（默认 30 fps 单脸）

| 级 | 模块 | 目标延迟 | 可重叠 |
|---|---|---|---|
| S0 | 传感器读出 | 帧周期相关 | 与处理重叠 |
| S1 | ISP/缩放 | 1–3 ms | 是 |
| S2 | 检测（可跳帧） | 3–10 ms | 是 |
| S3 | 对齐+特征 CNN | 3–15 ms | 是 |
| S4 | CfC+Heads | **≪1 ms**（OST 量级 µs~百 µs） | 是 |
| S5 | 后处理+PS | <1 ms | 部分 |

**端到端目标：P50 ≤ 30 ms，P95 ≤ 50 ms（可按产品改）。**

### 12.4 带宽粗算（务必做）

示例：720p YUV422 30 fps ≈ 720×1280×2×30 ≈ **55 MB/s** 量级原始；  
若全帧进 DDR 再读多次，带宽倍增。策略：

1. 尽量 **线缓冲 + ROI**；  
2. 检测用降分辨率；  
3. 特征只存向量环形缓冲；  
4. 避免「每层都整帧 round-trip DDR」。

### 12.5 与微信文方法论对齐的 FPGA 验收

| 步骤 | 动作 |
|---|---|
| 1 | Python float 金标准 |
| 2 | Python 定点（与 RTL 同一 scale/LUT） |
| 3 | HLS C-sim / cosim |
| 4 | 板端读回中间层 tensor |
| 5 | 报告：最大绝对误差、Mismatch count、是否 bit-exact |

**目标：** 对 CfC 核力争 **bit-exact 或可解释的 1 ULP 级误差**；对 CNN 允许统计掉点但要上表。

## 13. 实时性与 KPI 体系

### 13.1 产品 KPI 表（建议写入需求基线）

| 指标 | 建议目标 | 测量方法 |
|---|---|---|
| 端到端时延 P95 | ≤ 30–50 ms | 帧 timestamp → 结果 timestamp |
| 吞吐 | ≥ 30 fps 单脸 | 60s 稳态计数 |
| 丢帧率 | < 1%（负载内） | 计数器 |
| 表情（主指标） | 达数据集 SOTA 差距表内可接受带 | 离线 test |
| 时序增益 | 优于单帧基线（显著） | A/B |
| 意图 **Macro-F1 + 非 unknown 二分 F1**（v2.1 双指标） | 双指标均须**跑赢多数类基线**；accuracy 禁做北极星（重 unknown 分布下全猜多数类即 >0.5，LnMem 实测 0.548 无配置能赢） | 事件对齐 + 提前量曲线（0.5s/1s/2s F1） |
| 拒识后精确率 | 提升，覆盖率可降 | PR 曲线 |
| 板级功耗 | 场景预算内（数瓦~十几瓦） | 功率计 |
| 热 | 外壳/结温限制内 | 热电偶/芯片传感器 |
| 启动时间 | 冷启动 < 15–30 s | 计时 |

### 13.2 实时性真相

> **高实时主要靠流水线并行与带宽管理，不是单靠「LNN」三个字母。**  
> CfC 前向在 FPGA 上可以很快，但 **ISP + 检测 + DRAM** 经常才是瓶颈。

### 13.3 降级策略（保实时）

1. 降输入分辨率；  
2. 检测降频（跟踪补帧）；  
3. 特征网络宽度剪枝；  
4. 关意图头，只跑表情；  
5. 超时丢帧，输出保持上一有效态并标 `stale`。

- 优先存特征与事件，不存可识别原图；

## 18. 风险矩阵与不建议清单

### 18.1 风险矩阵

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| 意图标签含糊导致不可学 | 高 | 高 | 场景化、可观察标注、先减类 |
| **特征流无时序信号，时序核白训（v2.1）** | 高 | 高 | MI 门前置（§9.4 / 手册 §9），先证信号再训模型 |
| **标注-特征窗时间错位（v2.1）** | 中 | **极高**（全量报废） | anchor 校验进 CI（§10.3 / 手册 §4）；LnMem 481 条 100% 报废前车之鉴 |
| 检测/带宽拖死实时 | 高 | 高 | ROI、降分、跳帧检测 |
| 时序量化误差累积 | 中 | 高 | INT16 状态、长序列校准、对拍 |
| 野外泛化差 | 高 | 中 | 多场景数据、拒识 |
| 平台资源不够（020） | 中 | 中 | 换 KV260/减模型 |
| 伦理合规 | 中 | 高 | 告知、本地化、用途限制 |
| 把 LSM/Loihi 数字误用 | 中 | 中 | 证据表规范 |
| 期望「读心」 | 高 | 高 | 对外话术与 DoD |

### 18.2 明确不建议

1. **端到端全 LNN 像素→意图**（无充分公开产品先例，维度不匹配）；  
2. **大 Transformer 做实时表情主干**（带宽墙；与微信文工程结论同向）；  
3. **未定义意图标签就宣传可预测意图**；  
4. **XC7Z020 硬上高分辨率多人 + 重 CNN + 大时序核当量产**；  
5. **把 Loihi 能效数字写成 FPGA 结果**；  
6. **意图直连危险执行器**；  
7. **只交 demo 视频无对拍报告**。

## 19. 方案对比：为何选 LNN/CfC 后端

| 后端 | 精度潜力 | 参数/算力 | 硬件友好 | 连续时间归纳偏置 | 建议 |
|---|---|---|---|---|---|
| 单帧 CNN | 中 | 中 | 高 | 无 | 基线必做 |
| CNN+GRU/LSTM | 中高 | 中 | 高 | 弱（离散） | 强基线 |
| CNN+TCN | 中高 | 中 | 高 | 无 | 可对比 |
| CNN+Transformer | 高（大数据） | 高 | 中低（实时难） | 无 | 边缘慎用 |
| **CNN+门控短卷积（LFM2 式，v2.1）** | 中高 | 低~中 | **最高**（纯乘加+门控，无超越函数） | 中（有限感受野+输入自适应门控） | **与 CfC A/B**（Liquid AI 工业化路线） |
| **CNN+CfC** | 中高 | **低~中** | **高** | **强** | **部署首选** |
| CNN+LTC(ODE) | 中高 | 低~中 | 中低 | 最强 | 研究/对比 |
| 纯 LNN 像素 | 未验证产品级 | 高 | 低 | 有 | **不推荐** |

**选型一句话（v2.1）：** 用成熟视觉前端解决空间，用 context 定义意图输入面，用 **CfC 吃不规则 dt**——丢帧/降频/事件驱动才是它对 GRU 的真正分水岭；均匀采样下的时序增益必须先过 MI 门实证，不预设存在。

h = zeros(H)
for frame in camera:
    f, quality, track_id = frontend(frame)
    if track_id != last_id:
        h = zeros(H)
        last_id = track_id
    if not quality.ok:
        emit_degraded(h); continue
    h = cfc_cell(x=f, h=h, dt=dt)
    e = expr_head(h)
    i, conf = intent_head(h)
    if conf < tau:
        i = UNKNOWN
    emit(smooth(e), i, conf)
