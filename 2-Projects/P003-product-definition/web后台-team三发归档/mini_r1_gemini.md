这份方案旨在整合已上线的 V1.3 现状与 PRD V2.0 新需求，核心目标是**将小程序从单纯的“台灯遥控器”转型为“家长价值交付与亲子契约中心”**。

---

### 一、 九个对账点裁决（五大吵点 + 四个补充）

#### 1. 积分 vs 家族币：彻底更名，切断“时长挂钩”
*   **裁决**：**彻底切换为“家族币”体系，停用并迁移现状积分。**
*   **理由**：时长换积分直接诱导孩子“刷时长”，与护眼定位死磕。家族币必须来自“夜航收益”或“KidsHub 任务贡献”。
*   **迁移路径**：V2.0 更新后，原积分 1:1 自动兑换为家族币。下线“使用时长换算积分”后台逻辑，改为“夜航结算”。前端文案统一为“家族币”。

#### 2. 信息架构演进：从 3 Tab 升级为 5 Tab
*   **裁决**：**采纳附录 C 建议，由 3 Tab（设备/积分/我的）演进为 5 Tab。**
*   **导航定义**：**[首页] / [周报] / [兑换] / [KidsHub] / [我的]**。
*   **理由**：周报是 ROI 交付（让家长觉得值），兑换是契约中心（让孩子有劲头），KidsHub 是二级沉没成本（让家长看到孩子成长），均具备一级入口价值。

#### 3. 现状功能归位：融入而非删除
*   **裁决**：**视光报告进入[周报]模块；智能建议 VID 进入[首页]设备详情；说明书保留在[我的]。**
*   **具体逻辑**：视光报告的手动录入数据是周报“护眼硬数字”的基准线。VID 调整作为设备属性设置，不占独立 Tab。

#### 4. 配网/建档增强：体验做轻，埋点做深
*   **裁决**：**改造现有流程，实施“异步建档”。**
*   **改造点**：允许在 Loading 间隙填昵称/年龄；点击“跳过”即由云端分配 AI 兜底昵称；T+1/3/5 挽回推送由后台定时任务下发。

#### 5. 分期切分：P0 解决“有无”，P1 解决“精细”
*   **裁决**：
    *   **P0 (6.30)**：家族币更名及夜航结算显示、兑换页（基础合同+进度）、周报（护眼硬数字）、KidsHub 家长页（时间线）。
    *   **P1 (7.30)**：消息中心、流失拦截问卷、改进定向回告、VID 智能推荐。

#### 6. 命名统一：全线更名“小可”
*   **裁决**：**统一为“小可”。** 已开发代码中的“小未”及相关语音词库在 V2.0 批量替换。

#### 7. 记录分享 vs 价值报告：弹药合一
*   **裁决**：**周报直接吸收记录模块。** 原规划的柱状图、日历作为“查看历史报告”的详情页，不再另立门户。分享渠道作为周报末尾的“晒单”触发点。

#### 8. LED 远控与约束冲突：定义为“环境预设”
*   **裁决**：**允许控制开关灯及亮度，但禁止实时语音插话或视频直播监工。**
*   **理由**：开关灯是家长下班前或睡前的基本管理需求，不属于干扰孩子 AI 互动的“监工”行为。

#### 9. 视力档案：作为周报的“硬核地基”
*   **裁决**：**视力档案数据直接接入周报。** 所谓“护眼价值”，必须由“家长录入的视力趋势”+“设备拦截的坐姿次数”共同背书。

### 三、 核心功能定义（新增/改造）

#### 1. 家族币与兑换状态机（对应 PRD 功能 10）
*   **做什么**：记录孩子通过夜航获得的虚拟币，并翻译成现实奖励。
*   **入口**：Tab 3 [兑换]。
*   **联动**：设备端达成 -> 孩子确认 -> 云端推送小程序 -> 家长在[兑换]页收到“待兑现”提醒 -> 线下完成后点击“标记已兑现”。
*   **约束**：绝不代付，不涉及资金流。

#### 2. 周报/价值报告（对应 PRD 功能 13）
*   **做什么**：每周日晚推送，交付 ROI。
*   **入口**：Tab 2 [周报] 或 微信模板消息。
*   **内容**：累计护眼守护 X 次（硬数字）、本周一个用眼问题及操作解法（如：建议调长采样间隔）。
*   **纪律**：长期不活跃家长改推“小可求助信”。

#### 3. KidsHub 家长主页（对应 PRD 功能 15）
*   **做什么**：展示孩子对产品的建设性意见及被采纳情况。
*   **入口**：Tab 4 [KidsHub]。
*   **价值**：家长看到孩子被品牌“署名致谢”，产生教育溢价感，触发朋友圈分享。

#### 4. 消息中心与定向回告（对应 PRD 功能 17）
*   **做什么**：反馈闭环的落脚点。
*   **逻辑**：家长提的建议改好了，消息中心出现红点提示：“因为你的建议，小可进化了”。
*   **纪律**：重要回告必须落库，防止微信推送被滑掉后断链。

#### 5. 坐姿采样间隔配置（对应 PRD 功能 14）
*   **做什么**：将“监工”权还给家长。
*   **入口**：[首页]-设备详情 或 [我的]-设置。
*   **组件**：时钟滚轮式，支持 5 分钟、10 分钟等，滑动至 0 为关闭。

### 四、 P0/P1 切分清单

#### **P0 交付 (6.30)：留存生死线改造**
1.  **家族币更名与口径切换**：停用时长积分，对接夜航结算。
2.  **极简配网 2.0**：异步建档，随机昵称兜底。
3.  **兑换中心基础版**：5 个现实奖励模板，支持“达成-确认-提醒家长”链路。
4.  **KidsHub 家长页雏形**：显示建议状态流（已收到/评估中/已采纳）。
5.  **基础周报**：透出“护眼守护次数”硬数字。
6.  **夜航助攻推送**：每日早晨的一条喜报推送逻辑。

#### **P1 交付 (7.30)：体验精细化与流失挽回**
1.  **消息中心完全版**：支持小改回告、公告分类。
2.  **流失拦截答题页**：针对 30 天低活家长的单选题拦截。
3.  **视力档案深度集成**：视力折线图与周报数据的交叉分析建议。
4.  **VID 智能建议**：基于视力档案数据的 VID 推荐页（静态转向动态）。
5.  **弱召回逻辑**：并入周报的“生态缸干涸”提醒话术。

### 五、 风险与遗留（未覆盖矛盾）

1.  **多孩子场景缺失**：现状一账号一孩子，PRD 提到“换号/解绑”但未定义多孩子并行切换。若二胎家庭共用一台灯，家族币账本会发生纠缠。建议 P0 暂不解决，标注为“单设备单孩子”。
2.  **实时状态的时延风险**：现状 1 分钟上报一次。若孩子在设备端刚点“确认兑换”，家长可能要 1 分钟后才收到推送，存在“即时感”落差，需在小程序端加 Loading 或提示“正在同步”。
3.  **虚拟币合规隐忧**：虽然“现实奖励不代付”，但“家族币兑换虚拟皮肤”若后续涉及交易，需关注微信小程序虚拟支付红线。目前仅限“学习行为兑换”，风险可控。

---
**结论**：方案已对齐 PRD 留存机制，利用周报和 KidsHub 强化了家长的“付费价值感”，通过家族币契约中心锁定了孩子的“使用获得感”。请产品经理裁决 Tab 5 架构的开发资源优先级。
