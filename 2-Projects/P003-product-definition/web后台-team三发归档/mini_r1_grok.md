**P003 小程序产品定义整合方案（V1.0）**

**目标**：在已上线 V1.0/V1.3 基础上，落地 PRD V2.0 留存机制（北极星：D30 孩子主动使用占比 ≥40%）。不推倒重来，能改造即改造，能复用即复用。所有新增/改造均对齐 PRD 附录 C 基线与推送纪律红线（夜航助攻 ≤1 条/天、弱召回并周报 ≤1 次/周、流失拦截 30 天频控、夜间静默、回告必落消息中心）。

**铁律执行**：现实奖励家长线下兑现（小程序只记录/提醒，不代付）；小程序不直接实时遥控设备（V2.0 远程控制规划与 PRD C.5 冲突，裁决权留 PM）；三端数据强一致。

---

### 一、五大吵点逐一裁决

**1. 积分 vs 家族币体系冲突（头号）**  
**推荐 b**：保留现有积分 UI/流程框架，**产出口径全面切换为夜航/任务产出**，名字统一为「家族币」。  
**理由**：  
- 1 分钟 = 1 积分直接诱导刷时长，与 PRD 北极星（主动使用 ≠ 时长）、护眼定位、小可 B.5「不诱导过度使用」冲突。  
- PRD 家族币永不清零、无审批流、现实奖励走预设合同 + 孩子确认 → 提醒家长 → 线下兑现 → 已兑现/待兑现状态机（24h 未接住系统安抚），与现有「时长换积分 → 自由创建奖励」完全不同。  
- 彻底切换（a）会推倒已开发奖励列表/兑换记录/创建入口，成本高；双轨（c）会让家长/孩子困惑「到底用哪个」。  
**迁移路径**：现有积分余额一次性映射为家族币余额；原有奖励按「预设合同模板」重分类（学习类等保留）；创建入口改为「新建约定」（内置 5-6 个模板一键选）；兑换记录保留但状态机升级为 PRD 10 所述三段确认。保留「1 分钟 = 1 积分」文案仅作历史说明，不再产出新积分。

**2. 信息架构演进**  
**推荐对齐 PRD 附录 C.2 五页架构**：首页 / 周报 / 兑换 / KidsHub / 我的。  
**理由**：现状三 tab（设备/积分/我的）已承载核心数据，PRD 新增周报（13）、KidsHub 家长主页（15）、消息中心（17）、反馈入口（16）、流失拦截（16）需一级可见。C.2 建议与现状可平滑对齐：设备 tab → 首页（改造）、积分 tab → 兑换（改造）、我的 tab 保留并下沉消息中心/视光报告/设备管理/设置/使用帮助。  
**具体**：  
- 首页（设备状态 + 今日概览 + 夜航收益快捷透出）  
- 周报（价值报告，新）  
- 兑换（家族币 + 预设合同 + 待兑现提醒）  
- KidsHub（家长主页，新）  
- 我的（含消息中心红点入口、视光报告、设备管理、设置、使用帮助）  
消息中心作为二级入口（我的内或顶部常驻红点）；反馈入口挂周报内 + 流失拦截为打开小程序时软弹窗；流失答题页为独立软弹窗。

**3. 现状已有但 PRD 没写的功能归位**  
**保留并融入**：  
- 视光报告 → 成为周报「护眼价值」硬数字弹药（手动录入验光单数据可直接喂入周报「守护 X 次 + 视力趋势」模块）。  
- 智能建议 VID → 保留为设置/帮助内静态页（或首页设备状态卡下入口），不冲突 PRD。  
- 使用帮助说明书、设备管理 → 保留在「我的」内（PRD 未覆盖，现有实现已稳定）。  
**理由**：这些功能不与 PRD 核心留存机制冲突，且已开发，推倒无价值。

**4. 配网/建档 PRD 增强怎么落**  
**改造**（不重做全流程）：  
- 配网 loading 间隙异步建档（已有登录/建档页，改 loading 期间弹出昵称/年龄输入，可跳过）。  
- 跳过时用 AI 随机昵称兜底（预设词库），同时支持预设称呼接设备端 AI 称呼链路。  
**新增**：未激活提醒（T+1/3/5，扣周末权重，T+3 推家长小程序卡片）；激活双闸门埋点（闸门 1/2 事件上报）。  
**理由**：已有配网全流程可跑，PRD 要求是「增强」而非重写，异步 + 跳过 + 随机兜底可最小改造实现。

**5. 分期（P0 最小改造集）**  
**P0（6.30 交付，对应 PRD D1-7 + KidsHub 15）**：  
- 家族币体系改造（产出口径切换 + 状态机）  
- 周报基础版（吸收记录&分享模块）  
- KidsHub 家长主页基础版（贡献时间线 + 等级 + 署名）  
- 消息中心（回告落点）  
- 夜航助攻推送（≤1 条/天，早晨）  
- 弱召回并入周报（≤1 次/周）  
- 流失拦截软弹窗（30 天频控）  
**P1（7.30）**：视光报告深度融入周报、VID 智能建议升级、流失拦截答题页细化、反馈定向回告完整闭环。  
**理由**：PRD P0 明确小程序角色是「夜航助攻、生态缸可见、回归弱召回、KidsHub 家长主页」，以上 7 项为最小必要改造/新增。

### 二、整合后信息架构（tab 级 + 页面级）

**一级 Tab（5 个）**：  
- **首页**（改造自设备 tab）：孩子卡 + 设备状态卡（亮度/色温/像距 + 操作指南） + 今日/本周专注时长 + 夜航收益快捷透出 + 本周总时长柱状图。未连接/未完善孩子信息引导态保留。  
- **周报**（新增）：本周高光 + 护眼硬数字（守护 X 次） + 一个问题 + 解法 + 亲子小目标 + 就地反馈入口。长线低活用户降频。  
- **兑换**（改造自积分 tab）：家族币余额 + 进度条 + 预设合同（5-6 个模板） + 待兑现提醒区 + 已兑现打卡流 + 创建约定入口。  
- **KidsHub**（新增）：孩子贡献时间线（语音建议状态：已收到→评估中→已采纳/金点子库） + 当前等级/昵称署名 + 已采纳条数 + 金点子库进度。  
- **我的**（保留）：个人中心 → 孩子管理（含积分记录改家族币记录） → 视光报告（手动录入，喂周报） → 设备管理 → 设置（坐姿采样间隔时钟组件、预设称呼、权限/隐私） → 使用帮助 + 消息中心入口（红点）。

**二级/模态**：  
- 消息中心（所有回告、夜航助攻、兑换提醒、定向改进回告落点，可重看）。  
- 反馈入口（周报内就地 + 流失拦截软弹窗）。  
- 流失答题页（30 天低活打开小程序时软弹窗，单选「没空/嫌烦/太贵/其他」，选「没空」即关）。  
- 智能建议 VID、使用帮助、设备管理保留原入口。

**标注**：首页/兑换/我的 = 改造；周报/KidsHub/消息中心/反馈/流失拦截 = 新增。

### 三、新增/改造功能定义（重点 7 项）

**1. 家族币与兑换状态机（改造，PRD 10）**  
做什么：产出从「使用时长」改为夜航/任务；现实奖励走预设合同（内置模板一键选）；状态机「达成 → 孩子确认 → 提醒家长 → 线下兑现 → 已兑现/待兑现（24h 未接住系统安抚）」。家族币永不清零。  
入口：兑换 Tab。  
联动：设备端夜航/任务产出 → 云端统一账本 → 小程序进度/提醒/兑现记录。  
对应 PRD：功能 10、6、7。

**2. 周报（价值报告，新，PRD 13）**  
做什么：报喜为主（高光 + 护眼硬数字「守护 X 次」） + 一个问题配解法 + 亲子小目标；吸收原有今日/周使用记录、视力趋势；按家长活跃度分层推送（爱看可加喜报，长期不看降频改「小可求助信」）。  
入口：首页快捷入口 + 推送卡片。  
联动：设备端数据 + 视光报告手动录入 → 云端聚合 → 小程序展示 + 就地反馈入口。  
对应 PRD：功能 13、9b、16。

**3. KidsHub 家长主页（新，PRD 15）**  
做什么：孩子贡献时间线（语音建议状态全正面） + 等级/昵称署名 + 已采纳条数 + 金点子库进度。  
入口：独立 Tab。  
联动：设备端 KidsHub 提交 → 云端状态机 → 小程序家长可见（二级沉没成本）。  
对应 PRD：功能 15。

**4. 消息中心与回告（新，PRD 17）**  
做什么：所有夜航助攻、兑换提醒、定向改进回告、反馈闭环提示落点；7 天未读周报二次兜底 + 常驻红点。  
入口：我的 Tab 顶部红点。  
联动：云端回告路由 → 小程序消息中心可重看。  
对应 PRD：功能 17、6、10、13、16。

**5. 夜航助攻推送（新，PRD 6）**  
做什么：早晨微信模板消息「昨晚孩子的小可夜航带回了 X 家族币，提醒开盖领取」（≤1 条/天）。  
入口：微信推送 → 点击进小程序首页/兑换。  
联动：设备端夜航结算 → 云端 → 小程序/微信助攻。  
对应 PRD：功能 6。

**6. 弱召回（并入周报，PRD 9b）**  
做什么：设备断档 7 天不在周报末尾插入「生态缸快干涸了，今晚一起来看看」。不单独推送。  
对应 PRD：功能 9b。

**7. 流失拦截（新，PRD 16）**  
做什么：云端判断 30 天低活，打开小程序时软性单选弹窗「最近用得少了，是因为？[没空/嫌烦/太贵/其他]」。选「没空」即关，不纠缠。  
入口：小程序打开时。  
对应 PRD：功能 16。

**其他改造/保留**：配网异步建档 + 跳过 + 随机昵称兜底 + 未激活提醒（改造+新增，PRD 1-3）；视光报告喂周报（改造，PRD 13）；LED 远程控制（V2.0 规划）与 PRD「不直接控设备」冲突，建议「参数预设下发、设备端执行确认」，裁决留 PM。

### 四、P0/P1 切分

**P0（6.30，最小改造集）**：家族币体系改造（产出口径+状态机）、周报基础版（吸收记录&分享）、KidsHub 家长主页基础版、消息中心基础版、夜航助攻推送、弱召回并周报、流失拦截软弹窗。均为对已开发功能的改造或 PRD 必须新增。  
**P1（7.30）**：视光报告深度融入、流失拦截答题页细化、反馈定向回告完整闭环、VID 智能建议升级等。

### 五、九个对账点结论

1. 家族币体系：推荐 b（产出口径切换，名字统一）。  
2. 信息架构：对齐 C.2 五页（首页/周报/兑换/KidsHub/我的）。  
3. 已有功能归位：视光报告融入周报，其余保留在我的。  
4. 配网/建档增强：异步建档 + 跳过 + 随机兜底（改造），未激活提醒（新增）。  
5. 分期：P0 上述 7 项最小集。  
6. 小未 vs 小可：统一「小可」，唤醒词与角色名同步改，CSV「小未」视为旧名。  
7. 记录&分享 vs 周报：周报直接吸收该模块，避免两套报告；分享渠道即 PRD 家长晒单/转介绍落点。  
8. LED 远程控制冲突：指出 V2.0 规划与 PRD C.5「不直接控设备实时交互」冲突，推荐「参数预设下发、设备端执行确认」，裁决留 PM。  
9. 视力档案：接周报护眼价值硬数字（坐姿提醒次数 + 用眼时长 + 视力档案趋势）。

### 六、风险与遗留

- **远程控制冲突**：V2.0 规划「开关灯+三档亮度/色温」与 PRD「小程序不直接控设备实时交互」直接冲突，需 PM 终裁。  
- **多设备支持**：PRD 未覆盖一账号多设备/多孩子，现状 V1.0 一账号一设备/一孩子，V2.0 规划多设备切换，需确认是否 P1 纳入。  
- **视光报告手动录入 vs 自动**：PRD 价值报告护眼硬数字来源未明确是否包含手动验光单，需确认数据线。  
- **KidsHub 孩子端与家长端状态机一致性**：三端强一致要求高，需云端统一状态机。  
- **推送频控红线执行**：夜航助攻 ≤1 条/天、弱召回并周报等需云端严格频控，否则易违反微信限制或家长反感。  
- **未覆盖矛盾**：学期/寒暑假模式（PRD 横切约束）、一户多设备数据分层展示、离线补传 ≤3 天过期策略，PRD 已提但小程序侧未细化。

**以上方案已完整覆盖 PRD 附录 C 11 个功能交互定义与已开发 27 条功能，无遗漏。**
