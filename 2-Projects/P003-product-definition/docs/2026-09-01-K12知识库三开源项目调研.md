## 一、结论

三个项目里**只有 AI_Tutor_Release 值得整合**，且不是整体搬运，是拆四块资产移植；EduRAG-Tutor 是教科书级 demo 无可移植代码；edu-knowlege 是盗版网盘资源导航，**商用产品禁用**。小可的知识库应建在**云端 server 的 brain 注入层**（与人设/记忆注入同点位），worker 与 Android 端零改动。

## 三、AI_Tutor 四块可移植资产（含实现位置）

1. **Ingest 管线**：`scripts/ingest_2_0.py` + `chunk_utils.py` + `ocr_scanned_pdfs.py` + `keypool.py`
   - pymupdf4llm 版面感知抽取 → 扫描页双模 OCR（Gemini Vision 管 STEM / EasyOCR 离线兜底）→ 800 字块/150 重叠、保表格公式 → key 池轮换限速 embedding → LanceDB v2 表 → FTS 索引 → **原子 rename 切换**（带中断恢复+孤儿行救援）。生产级，直接移植。
2. **Hybrid 检索**：`server/services/search.js`（155 行）
   - 向量检索 + Tantivy FTS（内置 CJK 分词）并行 → RRF 融合（k=60）→ 年级/学科过滤 → 空则全局回退 → embedding 挂了 fail-open 到无 KB。node 实现与 p003 server 同构。
   - ⚠️ 抄作业避坑：它的年级/学科过滤靠 `source LIKE '%数学%'` 匹配文件路径（`server/prompts/guidelines.js` buildLanceDBWhereClause）——我们建库改显式 metadata 列（grade/subject/edition/doc_type）。
3. **分龄 prompt 体系**：`server/prompts/templates/system_guidelines.txt` + `guidelines.js`
   - 1-3 童趣档 / 4-6 启发档 / 7-9 逻辑档三套语体 + 苏格拉底三档（strict 不给答案 / guided 逐步提示 / direct 直给+思考题）+ 强制引用来源页码。理念可进小可人设注入层，**文本须全部重写为语音口语版**。
4. **chapters.json**：`server/prompts/chapters.json` —— 人教版 1-9 年级全学科单元大纲（id/单元名/趣味描述/难度星级），现成数据资产，可作知识组织骨架 + 知识卡生成目录。
5. （附）`server/trie.js`：敏感词最长匹配 trie，chat 前置拦截转安全话术——儿童产品刚需，与 p003 现有内容门对比后决定是否吸收。

## 四、建议架构（管端云）

核心判断：**知识库放云端 server，插在 custom-llm.ts 组 prompt 处——人设、记忆已在此注入，课本依据是同一点位的第三路素材。**

```
端 Android          零改动
管 worker(rust)     零改动
云 server ┬─ 离线管线（Python 独立进程，移植 AI_Tutor scripts/）
          │    语料 → 抽取/OCR → 分块 800/150 → embedding
          │    → LanceDB（向量+FTS，显式 grade/subject/doc_type 列）
          │    → 原子表切换（热更新不停服）
          ├─ 在线检索（node 进 server，移植 search.js 思路）
          │    LLM 调用前：意图门 → 向量+FTS 并行 → RRF → top-3 带来源注入
          │    降级链：embedding 超时/失败 → FTS only → 无 KB（=现状）
          │    fail-open 铁律同 echo gate，KB 永不阻塞主链路
          └─ 语音适配层（三仓皆无，小可独有新写）
               查询侧：ASR 碎句/错转 → 检索 query
               输出侧：口语化/短句/不念符号（借分龄语体理念）
               逐字层：古诗/口诀 exact 命中直接注入原文防幻觉
```

要点：
- **意图门控**：闲聊/情感轮不查（白加延迟+稀释人设）。可复用设备命令三层漏斗的意图基建思路；首版可全查+300ms 超时 fail-open，拿命中率再定门。
- **延迟预算**：LanceDB 本地 <20ms；大头是 query embedding API（100-300ms）→ 高频缓存（AI_Tutor 有 EMBED_CACHE 设计），中期换本地中文 embedding（bge-small-zh 级）零 API 依赖（语音场景本地 embedding 是标准解，见 memory `agent_mem_landscape`）。
- **逐字层单独建**：古诗/口诀/公式念法不走「分块+相似检索+LLM 改写」——改写即幻觉通道。单独 exact 表，命中即原文注入并要求逐字输出。

## 五、数据源策略（比代码更重要；版权判断为推断级，最终口径川哥拍板）

| 层 | 内容 | 来源 | 版权 |
|---|---|---|---|
| 骨架 | 单元大纲、知识点目录 | chapters.json 复用 + 课标（公开文件） | 干净 |
| 主体 | 分龄知识卡（概念/例子/常见误区，口语化） | **LLM 按大纲批量生成 → 人工抽验 → 入库** | 干净（自有） |
| 逐字层 | 古诗文（公版）、口诀、常识 | 公版语料 | 干净 |
| 参考 | 教材 PDF 原文 | 智慧教育平台等 | **只做内部生成对齐参考，不对外输出原文**；AI_Tutor「引用课本原话+页码」不学 |

edu-knowlege 机构资料任何一层都不出现。

分阶段：
- **P0（一周量级）**：逐字层+骨架层。古诗+口诀+大纲千条级，SQLite/FTS 即够（先不上向量库），server 加注入点+意图门。先做到「背床前明月光一个字不错」——家长可感知的确定性收益。
- **P1**：移植 ingest 管线 + hybrid 检索上 LanceDB，知识卡批量生成灌入，分龄语体并入人设注入。
- **P2**：「学到哪个单元」进设备记忆做进度个性化；KidsBench 跑上线前后学科问答对照。

风险两条：①KB 注入与人格 prompt 配比——课本腔压过小可人设是真实风险，注入走「小可转述」不走「播报资料」；②embedding 供应商依赖——P1 起抽象 embedding 接口，为本地模型留门。
