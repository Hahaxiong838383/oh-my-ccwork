# 小可语音调档落地方案（孩子说一句，小可自己切说话风格）

- 日期：2026-09-03 10:19 CST · 作者：cc（Claude）
- 前置：[2026-09-01 说话风格系统方案](./2026-09-01-小可说话风格系统方案调研.md)（P0/P2 在产）、设备命令三层漏斗（2b，在产）
- 定位：P1 中「语音指令调风格」这一项的落地设计；**只分析不实施**，等川哥拍板三个决策点

## 〇、结论

1. **不新建系统**：语音调档 = 给在产的风格模板（`trait_template` 基线机制）加**第二个写者（孩子语音）**，写的是同一张表、同一条注入链、同一本账；worker 与 Android **零改动**，全部在大脑（server）内完成。
2. **照搬 2b 的三层漏斗与纪律**：S1 关键词快路（LLM 前、同轮生效）→ S2 LLM 标记慢路（`[[STYLE:key]]`，下轮生效）→ 先观察后执行（`STYLE_VOICE_MODE=off|observe|execute`），canary = persona allowlist 三台。
3. **切「模板」不切「维度」**：孩子的话映射到四档模板（默认/话痨/安静/搞笑），与 admin 同一真源、白盒同一色系；「再温柔一点」这类维度级微调留 P1.5。
4. 三个要川哥定的点（§三）：孩子语音与家长设定**同权还是家长锁**（推荐同权 + 可选家长锁）、**防抖参数**（推荐 10 分钟 1 次、每日 3 次）、**先跑 observe 几天**（推荐 2 天）。

## 一、复盘：现有方案与接口（真值，读的是生产源码）

| 层 | 在产实现 | 可复用度 |
|---|---|---|
| 模板 | `style-template.ts`：`chatty/quiet/funny` 三档 + `default`；每档 = 五维值 + 一段固定 `styleRule` 文本（代码常量，无注入面） | 直接复用四档 |
| 存储 | `trait_template(account_id, template, updated_at)` 只存 key；`traitStore.setTemplate(acct, key)` 立即把五维置到模板值并作为弹簧回拉锚（`baselineFor`） | 加一个 `source`（parent/voice）参数即可 |
| 注入 | `prompt-orchestrator.ts:163` 每轮读 `getTemplate(acct)` → `styleRule` 拼进 policy 指令区（不吃 persona allowlist 门） | 切了下一轮自动生效，零改动 |
| 记账/白盒 | `resetDimsTo` 每维写 ledger `rule=parent_style_template`；admin 风格卡时间线 🟠家长设定 / 🟢互动 / ⚪自然回落 | 新 rule `child_voice_style` + 一个新色 |
| 接口 | `GET/PUT /api/admin/devices/:sn/style-template`；probe `style_template` + `injection_live.style_template_line` | 增 `source/locked` 字段 |
| 本地音频 | `buildSystemPrompt` 读 `baselineFor + styleRule`；模板切换 → 特质偏移 → 次日 3 点档重生成（今日已加 2 条/槽预算 + 3 天保底） | 无需处理 |
| 大脑入口 | `custom-llm.ts:79` 在 LLM 调用前已拿到 `userText`；`:123` 有设备意图协议注入先例；SSE 转发处有 paren-filter 等流过滤先例；`persistTurn` 有每轮抽取钩子 | S1 挂 `:79` 之后、S2 协议挂 `:123` 同位、标记剥离挂流过滤同位 |

**今天孩子说「你话太多了」会发生什么**：只会命中 `mirror_lsm_short`（短句 → talkativeness −0.01/轮），十几轮才勉强可感 —— 等于没反应。隐式适应（镜像/强化五条规则）是设计给「潜移默化」的，显式要求需要显式通道。

**9-01 方案对这条路的原设想**（L2 双写入口第二行）：「意图漏斗加 style_adjust 一路 → 改维度 → 小可口头确认」。本方案的修正：改**模板**不改维度（可解释、可回滚、与家长端一致），确认话术由本轮回复本身承担（不另起一轮）。

## 二、落地思路：三层漏斗

### S1 · 关键词快路（server，LLM 调用前，同轮生效）

- 挂点：`custom-llm.ts` 拿到 `userText` 之后、`assembleSystemPrompt` 之前。
- 词表 → 模板（只收「对小可说、关于她说话方式」的形态；否定形态显式列出）：
  - quiet：话太多 / 说少点 / 少说点 / 简短点 / 简单点 / 安静点 / 别说那么多 / 别那么啰嗦
  - chatty：多说点 / 多聊点 / 多讲点 / 别那么闷 / 话多一点
  - funny：搞笑点 / 逗我笑 / 幽默点 / 活泼点 / 好玩一点
  - default：正常点 / 恢复原来 / 别搞笑了 / 像以前那样
- 命中即 `setTemplate(acct, key, { source: 'voice', quote })`，并给**本轮**追加一行 policy：「孩子刚要求你『少说一点』：本轮先用一句话答应下来，然后就按新风格说话」——回复本身就是确认，且已是新风格（时刻差 = 0）。
- 纯函数 `detectStyleIntent(text): { key, lane:'S1', matched } | null`，正负语料单测（含「我妈妈话太多」「我不要你安静」这类必须为 null 的负锚）。

### S2 · LLM 标记慢路（下轮生效）

- 协议段 `STYLE_INTENT_PROTOCOL` 与设备意图协议同位注入（仅 `role=device`）：孩子**明确要求小可改变说话方式**时在回复开头输出 `[[STYLE:quiet|chatty|funny|default]]`，并在回复里用一句话答应；附和/转述/第三人称/否定一律不出（反例 few-shot 照抄 2b 规则 1 的写法）。
- server 在 SSE 转发处剥离标记（不进 worker、不进历史、不进 TTS），命中即 `setTemplate(source:'voice')`；下轮 prompt 已是新模板。
- 一轮至多一个标记；S1 已命中则忽略 S2（同 2b「一轮只派首个」）。

### S3 · 观察 → 执行

- `STYLE_VOICE_MODE=off|observe|execute`（server env，默认 observe 上线）：observe 只记 `[style-intent] observed lane=S1|S2 key=… quote_len=…`，不写表。
- canary：persona allowlist（0010/003/0002）；004 不在名单自然排除。
- 观察 1–2 天看误触发与漏召回，再开 execute；开闸=改 env + pm2 restart。

## 三、语义与规则（要拍板的在前）

| 项 | 推荐 | 备选 |
|---|---|---|
| **谁说了算** | 孩子语音与家长设定**同权**（方案 L2「用户显式=硬约束」），后写覆盖先写，白盒两色可见 | 加**家长锁**：admin 开关 `locked`，锁定时语音只观察不切，小可口头告知「这个要爸爸妈妈来改」 |
| **防抖** | 同账号 10 分钟内最多切 1 次；同模板重复请求不重复记账；每日上限 3 次，超过只观察 | 无上限（风险：反复横跳刷账本 + 每日重生成） |
| **切模板 vs 调维度** | 模板级（4 档） | 维度级微调（「温柔点」+0.15）留 P1.5 |
| **记账** | rule `child_voice_style`，note「孩子说『…』→ 切为「安静小可」」；白盒新色 🔵「孩子要求」；probe `style_template.source` | — |
| **确认话术** | 本轮回复自带（S1 同轮 / S2 本轮标记随回复） | 另起固定短句（否，同 2b 今日教训：追加显迟） |
| **本地音频** | 不处理：模板切换触发次日重生成 | — |

护栏：仅 allowlist 账号；`gentleness` 地板不变；标记只认 4 个 key；S1 词表只收「小可/你 + 说话方式」形态，含糊句交 S2；observe 期数据定词表增删。

## 四、接口清单（改动面）

- 新模块 `style-intent.ts`：`detectStyleIntent(text)`、`STYLE_INTENT_PROTOCOL`、`stripStyleMarks(delta)`、`applyVoiceStyle(acct, key, quote, opts)`（含防抖/锁判定，返回 executed/suppressed reason）。
- `trait-store.ts`：`setTemplate(acct, key, { source, quote })`，rule 按 source 分 `parent_style_template` / `child_voice_style`；`trait_template` 加 `source, locked` 列（ALTER TABLE 幂等）。
- `custom-llm.ts`：S1 挂点 + 本轮 policy 行；S2 协议注入 + 流剥离。
- admin：风格卡显示「当前档 · 来源（家长/孩子）· 设定时间」、家长锁开关、时间线 🔵；`GET/PUT style-template` 增 `source/locked`。
- env：`STYLE_VOICE_MODE`；skill/记忆同步。
- Worker / Android：**零改动**。

## 五、验收（按 9-03 教训：加感知行与时刻差）

| 项 | 判据 |
|---|---|
| S1 正向 | 说「小可你说少一点」→ 同轮 `[style-intent] executed lane=S1 key=quiet` → 本轮回复 ≤2 句且含答应 → `trait_state.talkativeness=0.15` → 白盒 🔵 → 时刻差 0 |
| S2 正向 | 「你能不能别一直说个不停」（不在词表）→ `[[STYLE:quiet]]` 被剥离 → `lane=S2` → 下轮回复短 |
| 负向 | 「我妈妈说话太多了」「我不要你安静」「小明让你安静点」→ 只有 observed，无 executed |
| 家长锁 | 锁开 → `suppressed reason=parent_lock` + 小可口头告知 |
| 防抖 | 连说两档 → 第二次 `suppressed reason=cooldown` |
| 感知行 | 回复轮 `playout metrics played_frames>0`；体感问「她是不是真的变短/变闹了」（问具体） |
| 白盒 | 时间线出 🔵 且 note 带孩子原话；家长端 GET 返回 `source=voice` |

## 六、分期与工作量（均 server 侧）

- **Phase A（约半天）**：`style-intent.ts` + 词表 + 单测（正负语料 ≥30 句）+ observe 模式上线 + 白盒色 → 观察 1–2 天。
- **Phase B（约半天）**：execute + 家长锁 + 防抖 + S2 协议与剥离 + E2E（三台）。
- **Phase C（可选）**：维度级微调、口头禅/称呼（P1-2）、示例对话库（P1-4）。

## 七、风险

- 误切（转述/玩笑/第三人称）：observe 期用真实语料定词表；S2 假阳性用 2b 协议的反例法压。
- 反复横跳：防抖 + 每日上限；账本仍全记（observe 行不写表）。
- 家长设定被孩子覆盖：同权是设计选择，白盒可见 + admin 一键改回 + 可选家长锁。
- 与人格成长的关系：模板切换让特质瞬移，白盒会显示大跳——这是「显式设置=硬约束」的设计内行为，回拉锚随之切换。
