## 3. 逐条建议

### R1 画像层证据化 + 三态 + 家长单条否决（第一优先）

**做什么**：`family_member.interests / personality_notes / recent_emotion` 的每一项改成 `{value, evidence, source_msg_id, confidence, state}`；抽取 schema 给 interests 加 evidence（照抄孩子原话连续片段，服务端子串硬校验——与 promise C1、改名门同一套）；state 初始 `unverified`，**同一事物在 ≥2 场独立会话被明确提及才升 verified**；注入措辞分级：verified 才进「一律/我知道你喜欢」型指令，unverified 只作弱背景或不注入；家长端每条可否决（retracted + 记账），否决后同名不得再升。存量 62 条兴趣全部标 unverified，不删。

**逻辑理由**：这是 I3 的唯一残留违反点。兴趣由 LLM 从单句推断（「孩子明确表达喜欢的」全靠 prompt 自觉），8-23 兴趣污染事件（冷光/拼音被当兴趣）已证明 prompt 约束不是门；改名门的整改（8-26）证明「LLM 交候选+服务端证据硬校验」在同一条链上可行。

**证据链**：
- 小可：`memory-extractor.ts` interests 分支无 evidence（本文档配套盘点）；`prompt-orchestrator.ts` 画像行直接进 data 区；成长账本已能承载 trigger_quote（1742 条 88% 带原话）。
- KnowMe：`_score()` 结构上不可能只存分数不存原话（`AIPMAndy_KnowMe/scripts/analyze.py:173-178`）；小样本降级独立于分数边际，n<20 无条件 low（`analyze.py:200-205`）——小可的「置信度」应按**独立会话提及次数**而不是 LLM 自称。
- Pulse/SOUL：evidence + confidence 贯穿 extractor→dispatcher，`_MIN_CONFIDENCE=0.4` 以下直接 SKIPPED 并发事件（`domain_preference_dispatcher.py:104,201-240`）。
- Inworld 产品合同（报告 §3）：「事实提到多次才进长期」。
- KnowMe 缺的：无任何否决入口（`analyze.py:454-459`）——小可面向儿童且家长在场，必须补。

**收益**：消灭「我知道你喜欢X」误判；家长端「它从哪听来的」有答案；兴趣污染治理从「归一判重」升级为「证据+状态」。
**代价**：抽取字段扩容（沿用 20s/1024tok 预算，扩字段后必须重估——Phase 1 撞过 8s 超时）；存量数据迁移一列；注入措辞分级需 3 天观察期；家长端 UI 一小块。
**验收**：抽 10 条「我知道你…」≥8 条能点开原句；unverified 兴趣不出现在「一律」型指令（日志断言）；家长否决后跨会话不再出现。

### R2 条目 source_msg_id + superseded_by

**做什么**：memory_item / 画像证据加 `source_msg_id`（指向 `conversation.id`，抽取时从刚落库的那批消息取，窗口内旧消息按 text 反查）；memory_item 加 `superseded_by`；改名/又喜欢/不喜欢复活写取代指针；家长删除对话时依赖条目自动降级（I8）。

**证据链**：EverMemOS episode/atomic_fact 带 `parent_id` 到 memcell 粒度（`lancedb/tables/episode.py:42-50`）+ `deprecated_by` 软删检索过滤（`docs/storage_layout.md:198-201`）；Everthine 日记只有 6 字段无 message id（`diary.py:415-425`），家长问「从哪听来的」答不出——正是要避免的形态；小可 conversation 表已有毫秒 ts 与索引（`conversation-store.ts:81-92`），差一列。
补两点源码证据与一个隐藏问题：
- 取代语义的 schema 抄 TrueMemory `fact_timeline`：`superseded_by / valid_from / valid_to / status`，旧条**不删**（`buildingjoshbetter_TrueMemory/truememory/storage.py:90-102`）；渲染旧条抄 VoiceMem 右脑：正文追加「【旧况，约 X 已变化，以更新为准】」并降权 ×0.75（`xzf-thu_VoiceMem/voicemem/rightbrain/brain.py:114-125`）。
- **小可自己也有「覆盖」反模式**：`updateMemoryFields` 对 `personality_notes / recent_emotion` 是 `patch ?? existing` 原地覆盖，账本 insight 行只记 patchSummary 不记旧值（已验证）。VoiceMem 用 158 次实测说明为什么覆盖危险：34% 新旧一字不差、11% 变短丢信息、ASR 噪音回写、来回震荡（`voice_input.py:631-660`），于是默认把 UPDATE 降级成 ADD。小可对应做法：**没通过原话硬校验的 UPDATE 一律降级为 ADD**（旧值带 valid_to 留档），已过硬校验的（改名/又喜欢）才允许取代。
- typed 条目定义成 conversation.db 的**派生物**：带 `source_msg_id` 外键，抽取 prompt 改版可全量重刷（TrueMemory 每 25 条重建的思路，`engine.py:362-365`），conversation.db 就是现成原件柜。

**收益**：可审计因果链闭合（账本已有 from→to，缺「被取代的那条」）；删除权可级联。**代价**：两列 + 抽取处传 id；~1.5 天。

### R3 成长层每日快照 + 退回任意一天 + 噪声地板

**做什么**：`trait_state / trait_template / style_pool` 每日沪时 3 点批前存一份快照（live + 历史，同日覆盖）；admin「退回到某天」端点（按快照 before 还原，记账 rule=`rollback`）；EMA 更新前加噪声地板 ε：|δ| 未超地板不更新不记账；成长账本已有的 `daily_setpoint_decay` 继续。

**证据链**：Everthine 自画像 live+每日快照（`portrait.py:197-222`）、开关关掉字节级回旧行为（`persona.py:118-122`）；Pulse/SOUL `rollback` 按 before 还原 + 审计上限（`governance.py:680-712,806-817`）；Ruby2025 Pulse 无快照无回滚是其最大缺陷（`growth.py:178-210`）；BFI-Adapt 噪声地板 ε=0.1 存在率（`rq_stats.py:386`）。小可现状：重置只有 all/persona 两档（memory p003_persona_growth），退不回昨天；trait 账本 386 条中多少是抖动未统计（本轮未算，属推断）。
**收益**：过关线从「清空表现层仍能说话」升级为「退回任意一天」；抖动不再冒充成长。**代价**：快照表 + 端点 + admin 按钮；ε 取值要用近 14 天账本回放定（别拍脑袋）。

### R4 稳定前缀短卡 + 硬上限截断

**做什么**：systemPrompt 拆两段——**稳定卡**（世界观 / 安全基座 / 设备意图协议 / 称呼与风格指令 / CORE 红线，会话内不变，带 version）前置；**动态尾**（记忆 data 区、课程护栏、onboarding 引导、本轮 policy）后置；整卡设硬上限（建议先量当前分布再定，例如 ≤3.5k 字），超限按优先级截断：安全 > 未兑现约定 > 本通口吻 > MUT > FACT；稳定卡按 version 缓存，变更才重编。

**逻辑理由**：赛马基准（2026-09-03）实测 4.8k 字真 prompt 下首字延迟由 prefill 主导，短提示排名与真 prompt 反转；稳定前缀前置才能命中模型侧前缀缓存（DeepSeek/火山均支持）。近因效应是已知大坑（onboarding 引导必须末尾、世界观开场会盖过引导），所以**动态尾的顺序不能动，只把稳定块前提**。
**证据链**：NVIDIA Voice Memory（报告 §2）「开口只读一份很短的档案」；acore 的教训：预算只写在文档、代码不截断（`doctor.ts:68-82` 只告警）——小可要在代码里截。
**收益**：TTFT 与 token 成本下降（幅度需 A/B，属推断）；prompt 体积有上限后「记忆越多越慢」被封顶。**代价**：重排风险（必须用 003 真 prompt 做 A/B + 三条过关线回归）；缓存 key 与 version 维护。

### R5 抽取时机改「触发 + 分段」

**做什么**：每轮只跑零 LLM 的触发判别（改名/不喜欢/又喜欢/约定/关心事关键词——style-intent S1 词表同款），命中才立即 LLM 抽取（保持改名下一轮生效）；未命中的按每 5 轮一次 + 30 分钟无声或 worker job 结束时收尾一次，窗口=自上次抽取以来的消息（上限 10 轮）。

**证据链**：本轮观察：近 14 天 1754 轮 / 112 场会话，每轮抽取=1754 次 LLM；会话 p50 5 轮、p90 36 轮、max 198——当初「唤醒式 1–2 轮短会话」的前提（8-19 注释）已不成立；VoiceMem/L3 设计「空隙或挂断后整理」；小可 WS 链路已有 close() 补抽先例。
同向证据：VoiceMem 与 TrueMemory 都把抽取放在轮后/会话末冷路（`orchestrator.py:1174-1191`；`docs/architecture.md:35-42`），说话期间只做零 LLM 的预备；Tycho 的硬数字：「一发现不一致就重建模型」的 trigger 策略比按需 orchestrator 多 8 倍 builder 调用、分数反而低 5.4 分（`artifacts/appendix_metrics.json`；README.md:26-33）——每轮重抽同理是负收益。
**收益**：抽取调用约 ÷5～÷10（推断，触发轮占比未测）；规模化后（万台×每日 15 轮）差一个数量级。**代价**：窗口拉长后 LLM 单次输出更多字段（重估 timeout/maxTokens）；「陈旧窗口翻转」问题已用位置锚解决（dislike-undo）。

### R6 评测：KidsBench 自研 adapter + 方向一致率 + 扣分制 rubric

**做什么**：给小可记忆写 `p003_adapter`（7 方法契约已在 KidsBench L1），跑 249 题与 mem0/graphiti/memoryos 同台；月度算特质向量 **方向一致率 DCR**（`max(n↑,n↓)/(n↑+n↓)`）与「位移超地板」存在率，方向不符的变更贡献记 0；风格模板回归用扣分制 rubric（短而准满分，禁长度/辞藻加分）。

**证据链**：KidsBench adapters 目录零 p003（本轮观察）；BFI-Adapt `Adapt_v2=mean(κ·S·1_dir)`（`kappa_dcr_analysis.py:38,454-462`）、`dcr()`（:262-286）纯算术零依赖可直接移植 TS；KnowMeBench 扣分制与 `{score, reasoning}` 路由（`run_eval.py:20-58`）。
题库要补时序题：TrueMemory 的 BEAM-1M 分类目里 preference following 97.1%、contradiction 91.4%，而 **event ordering 只有 19.5%**（`benchmarks/beam/README.md:9-38`）——时间顺序是全行业弱项，小可「上次/上周/先后」类题目要单列；LoCoMo 协议（答案模型固定、评委跑 3 次多数表决，`benchmarks/locomo/EVAL_CONFIG.md:26-36`）可作 adapter 评测的跑法参考。
**收益**：「成长是真是抖」可量化；风格档不被训成话痨；记忆终于在自家评测台上有分数。**代价**：adapter ~2 天；DCR 需要至少 30 天账本；rubric 需人工标 30 题。

### R7（P2）跨会话「上次说到」轻量回放

「刚才」由 worker 会话内 history 覆盖；跨会话「上次说到」只需在会话首轮注入上一会话末 3 轮摘要（conversation 表已有）。不做向量检索。收益中等、代价小，但增加 prompt 体积，排在 R4 之后。

### R8（P2）多说话人预留

一台一称呼槽是当前设计；worker 声纹 sticky slot 只到兜底路（大脑过滤 system 消息）。建议只做预留：worker→大脑传 `speaker=child|adult|unknown` 结构字段，条目带 speaker，**成人语音不写孩子画像**；不做多档案。需 codex 侧合同变更。

### R9（视产品）健康禁忌进 CORE

报告与方案都把「过敏/安全」列为红线首位。小可档案无此字段；若产品会聊吃的，给 family_member 加 `health_taboo`（仅家长可写），注入稳定卡安全段，模型不可改。代价半天。

### R10（P2）约定带「到期应观察到什么」+ 画像简报 checked/assumed

promise 落库时同时写 `expect`（到期那天孩子该说到什么，如「周五说去了游泳课」），到期核对不上就只许问、不许说「我记得你答应过」——Retrodict 每个动作自带 `expect`、第一处不符就掐断（`ryanbbrown_Retrodict/src/arc3/runner.py:526-538`），Tycho 用 SHA-256 把计划逐步锁死（`tycho/workspace/workspace.py:594-650`）。画像简报采用 Retrodict playbook 纪律：每条标「已被原话核实 / 仍是推测」，推测级不许拿来搭多步对话计划，被原话打脸时回原话重推（`prompts.py:32-56`）——这与 R1 的 verified/unverified 是同一件事的两个视角，R4 的短卡就是这份简报的投影。

## 6. 风险与开放问题

1. **抽取扩字段的稳定性**：字段越多弱模型越容易漏格式；扩容必须同步重估 timeout/maxTokens（Phase 1 教训），失败留痕。
2. **prompt 重排的近因效应**：稳定卡前提不能动 onboarding/引导的末尾位置；每次重排都要跑 003 真 prompt 对撞。
3. **置信度定义**：按「独立会话提及次数」而非 LLM 自评；阈值 2 场是起点，用 0002/0010 的 49 条兴趣回放校准。
4. **多说话人**：家长在设备旁说话会写进孩子画像；R8 之前靠家长端否决兜底。
5. **成本口径**：R5 的 ÷5～÷10 是推断，先在一台设备灰度记调用数再全开。
