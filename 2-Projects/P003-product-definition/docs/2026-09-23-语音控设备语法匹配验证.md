## 4. 语法怎么判（人话版）
1. **先挡后认，宁漏勿误**：句子超过 14 字不看；有否定（不要/别/不是/不高/不亮…）、假设（如果/要是）、转述讨论（因为/所以/但是/还是/到底/也/用/说/你看/比较/挺/会/应该/可能/觉得…）、叙述（刚才/已经/又/着/关了灯）、第三人称（他/她/妈妈/老师…）、疑问（为什么/什么/吗，除非同句有「可以/能/帮我」这类请求词）、数字/档位/米数、感受抱怨（太吵/听不清/看不清/安静/啰嗦，除非同句有太亮/太暗/刺眼这类说清物理量的词）、闲聊义（灯会/灯泡/红绿灯/空调/开心/关系/好听/故事…）、以「的」结尾的陈述、「是」「有」开头的陈述——全部不认。
2. **找对象**：灯/灯光/台灯/光/光线/亮度 → 灯光；色温/光谱/暖光/冷光/中性/模式 → 色温；音量/声音/大声/小声/静音 → 音量；读写台 → 读写台电机；台子/高度/设备 → 电机；虚像/画面/显示/距离 → 虚像。两个对象同时出现不认。没有对象时只认少数不歧义的动词（调亮/调暗/开灯/关灯/调暖/调冷/升高一点/降低一点/拉远/拉近/静音）。
3. **找方向和程度**：最/到顶/到底 → 最值标签；太亮/刺眼/晃眼 → 调暗，太暗 → 调亮，太高 → 降，太低/太矮 → 升，太远 → 拉近，太近 → 拉远，声音太大 → 调小；开/关 明确动词优先于抱怨词（「灯太刺眼了关掉吧」→ 关灯）；其余方向词 → 一级标签；冷光/暖光/中性/常规/阅读 这类预设必须带动词（调/换/切/开/到/成/要/给…），光说「冷光」两个字交给词表原句。
4. **查表给标签**：标签号、动作名与 389 条词表同一张表；读写台 vs 设备 的两套标签（27/28/31/32 vs 25/26/29/30）按对象词区分，与词表一致。

## 7. 守卫演进与「样本内」警告
- 原型 v1 只有对象+方向，没有讨论类守卫：额外命中 123 句 / 去重 108 句，其中约 30 句是成人在设备旁**讨论**设备的话，例如「现在声音比较小了」「如果把音量调大一些」「到底是冷光还是冷光」「你现在是冷光」「冷光还原度100哦」「拉远的同时会放大」「近看拉远的这样一种效果」「你开着灯」「新亮点是」——每一句都会被当成命令执行。
- 加了 §4 第 1 条那批守卫后（v2→v4 三轮），这 30 句全部拦住，真意图句只少了「还是太亮了」「又调冷」两句（被「还是」「又」守卫误伤，可接受）。
- **警告**：守卫词是看着这份语料加的，等于在考卷上练习。样本外一定会再出现新的讨论句式，误开火不会是零。但它的失败形态是「某个词没进守卫表」，日志里一眼能看出、一行能修；大模型的失败形态是「这次抽样抽到了」，反例加进去也测不出效果（09-23 08:00 已给证据）。
- 这份语料以成人测试、讨论为主（设备词密度远高于孩子日常聊天），对误开火是**偏难**的考卷。

## 8. 已知会漏的（按「误触发大于漏触发」故意放弃）
- 带「是/还是/又/也/会」的真请求：「还是太亮了」「又调冷」。
- 识别错转：「空调暗一点」（应为 把灯调暗一点）、「就像远一点」（应为 虚像远一点）——「空调」按闲聊词拦，「就像/像+调到最近」这类因为带动词仍能认。
- 无对象碎片：「降低」「常规」「往下走」「靠近一点」。
- 纯感受抱怨：「太吵了」「听不清」「看不清」「安静点」——按 09-23 决定不进设备命令，走别的处理。
- 词表回放里 19 条只能靠词表精确匹配的（掉进/调进/吊井 这类识别错转别名、光说「远一点」「冷光」的裸词）——合用时由词表接住，不损失。

## 9. 建议的落地方式（等拍板）
- **位置**：worker 里词表精确匹配之后、大模型之前，同一条发布链路（同样的 hard-abort、同样的冻结确认句、同样的后台记账，lane 标 `L1g`）。不改服务端、不改端侧。
- **开关**：`DEVICE_GRAMMAR_MODE=off|observe|execute`。先 **observe 3～5 天**：只记日志不执行，后台「语音控设备 24h」卡加一行「语法命中 N / 其中大模型同意 M / 大模型漏掉 K」，用真机队的孩子语料再验一遍误开火；数字干净再切 execute。回退=置 off，无需换装。
- **测试**：本文 §5 的 64 句、§6 的 12 句、§8 的漏句、43 条手写负例、13 条慢路测试句，全部进 Rust 单测（正锚/负锚各自独立，缺一条即红）。
- **工作量**：Rust 约 300 行（守卫表、对象表、五个域的方向规则、单测），一天；出包走家里构建机，空档换装。
- 上线后，大模型慢路只剩语法没认的尾巴，误触发面随之缩小；配合今天 B 组的「无设备词不认暗号」门，两层都是确定性的。
