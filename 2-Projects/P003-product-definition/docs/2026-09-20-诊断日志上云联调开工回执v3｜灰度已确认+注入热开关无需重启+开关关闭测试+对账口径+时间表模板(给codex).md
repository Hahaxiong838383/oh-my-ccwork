## 2. 注入协议（热开关，无需重启）
**位置与形状**（与 09-19 上线时相同）：注入在门 0，**在凭据校验之前**——开启期间该端点对任何请求（含无凭据）都返回注入状态；其它设备通道不受影响。

| 注入 | HTTP | 响应体 | 头 |
|---|---|---|---|
| 429 | 429 | `{ok:false, error_code:"acceptance_override", message:"injected_429", retry_after_ms:60000, request_id:<回显>}` | `Retry-After: 60`（可按你们要求改成别的值，用来与本地 30/60/120 退避序列区分） |

| 500 | 500 | `message:"injected_500"`，无 retry_after_ms | 无 |
| 401 | 401 | `message:"injected_401"` | 无 |
| 403 | 403 | `message:"injected_403"` | 无 |

- 每次开启我回：`status / 开启时刻 / 自动到期时刻 / 撤销时刻`（全部 CST，以服务端时钟为准）。默认一档 15 分钟自动到期、最长 60 分钟；撤销即时。
- 服务端每次被注入命中都记一行 `[diaglog] ⚠️ 验收注入生效 status=<st> source=override until=<到期> rid=<你们的 X-Request-Id>`——这行数量 = 你们在注入窗口内的重试次数，退避间隔从相邻两行时间差看。
