## 0. 结论

- **根因（已验证，v2 按 codex 端侧实读补全机制）**：0006 于 18:05:24 CST（v236 换装触发同步）拿到动态语音 revision 1，其中动态招呼语长 2.1–2.8 s（`在呢在呢，聊点啥好呀` 2520 ms、`嘿，我醒啦，今天想玩什么` 2840 ms 等），**长过唤醒→worker input_ready 的 ~1.8 s**；招呼语尾巴被 worker ASR 听到，二遍模型把它错转成「我想啊怎么了」（←嘿我醒啦今天想玩什么）、「不行了」（←你来了故事继续），与对撞库字符相似度只有 0.50/0.33，穿过原来的 LCS≥0.8 门 → 起幽灵轮（小可回答一个没人问的问题）。内置 9 条招呼语 ≤1.9 s，在 input_ready 之前就播完，所以 18:05 之前没有这个问题。
  端侧机制（codex v237 交接 §1 实读，18:06/18:08 两个 trace）：`inputReadyGateEnabled` 让普通唤醒在招呼语开播约 300 ms 后就**提前开麦**，Worker ready 一到端侧 80 ms 淡出并 cancel 招呼语——开麦到强制停止重叠约 1.5 s，这段就是回灌窗口；网络越快截得越早，用户同时听到「回复被截断」。两个 trace 播的都是 `source=dynamic_current slot=greeting.normal revision=1`，不是内置兜底。
- **worker 修法（18:39:24 CST 已上产）**：开场重叠窗——以建房时刻（≈唤醒）+ 最长招呼语 3.2 s + 余量为截止，说完时刻在截止之前的短句，与对撞库 LCS≥0.3 即判回声丢弃；命令词/急停/退出词豁免；截止之后维持原门。今天两条幽灵句在该门下均命中（0.50/0.33），今天所有真实早句（虚像调到 5 米 / 画面调近一点 / 长句测试）LCS ≤0.17 均放行。
- **要 codex 的（§4）**：端侧发「本地音频在播」信号（start/end + slot + text + duration），worker 按精确窗口而不是估算窗口判回声——这是根治；估算窗口是止血。

### 1.3 为什么原门拦不住

原门：≥4 字 LCS≥0.8 / 2–3 字精确子串 / 1 字一律吞（2026-09-01 立）。它假设回声「只掉字不加字」；但二遍 ASR 对喇叭放出的童声招呼语是**语音层错转**（醒啦→想啊、什么→怎么了、你来了→不行了），字符层相似度掉到 0.3–0.5。拼音层相似度我也算过，对「你来了→不行了」同样无效，所以不能靠文本相似度硬提，只能收窄时间窗后再放宽阈值。

## 2. worker 修法细节（feat/rust-worker `37e634c0b`）

- 时间锚：设备房名 `sn-<SN>-<unix秒>` 的秒 = server 建房时刻 ≈ 唤醒；截止 = 建房秒×1000 + 1000（向下量化补偿）+ `LOCAL_AUDIO_GREETING_MAX_MS`（默认 3200；生成器各 greeting 槽 maxDurationMs ≤3000）+ 500 余量。
- 放宽门：说完时刻（commit 时刻 − eou）≤ 截止，且 ≥2 字，且 `match_command` 无命中、非急停、非退出词 → 与对撞库逐条 LCS，≥0.3 判回声丢弃，日志 `local-audio echo suppressed (opening overlap): '<text>' slot=… lcs=… before_deadline_ms=…`；snapshot 事件 `swallowed kind=local_audio_echo path=overlap:<slot>`。
- 截止之后：原门不变。`LOCAL_AUDIO_GREETING_MAX_MS=0` 关闭新门（零二进制回滚）。
- 已知代价：招呼语还在播时开口说与招呼语相似度 ≥0.3 的短句会被吞（例：「讲个故事」vs「你来了故事继续」LCS 0.5）——用户在招呼语播完后再说不受影响；被吞只需重说。
- 单测：textproc 新增 6 条（0006 两条真实碎片正锚 + 四条真实命令/短句负锚 + 房名解析 + 截止算术），全套 200/200；clippy 无新增 lint（存量 7 处未动）。
- 顺手修：内置词表「吊井」→label 34（二遍误转「调近」，9-05 加进内置、9-06 上午按生产 TSV 同步时被抹掉，`asr_mistranscription_aliases` 单测因此红）；生产 TSV 同步补齐，两侧 md5 `8e05852c…` 一致，重启后生效。

## 4. 端侧信号建议——撤回（codex 已按 v237 方案根治，不加信令字段）

我 v1 提议的 `kind=local_audio` start/end 信令 **撤回**：codex 明确「端侧不会发新信令字段、不改 input_ready 合同」，且 v237 从机制上消灭重叠——普通唤醒**房间连接完成 + 提示音完整结束**之后才开麦，input_ready 不再强制淡出/cancel，播完加 200 ms 尾音保护；动态招呼语只用完整且 ≤1800 ms 的，超长则本次回退内置 1000–1720 ms 短句（不删动态包、不改 revision）。开麦晚于提示音结束 ⇒ 麦克风里根本没有招呼语 ⇒ 回灌窗口为零，worker 侧不需要精确窗口。

worker 的开场重叠窗门**保留为兜底**（v237 未装、或旧包、或任何端侧竞态导致的残余重叠），不与 v237 冲突：v237 之后它应当零命中（`local-audio echo suppressed (opening overlap)` 不再出现），命中即端侧仍有重叠，按 trace 回查。
