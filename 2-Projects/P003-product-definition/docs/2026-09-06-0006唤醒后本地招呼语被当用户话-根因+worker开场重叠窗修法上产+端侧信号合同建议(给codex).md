## 0. 结论

- **根因（机制已由 codex 端侧实读定案）**：v236 及之前，普通唤醒在招呼语开播约 300 ms 后就提前开麦，Worker ready 一到端侧 80 ms 淡出并 cancel 招呼语，开麦到停止重叠约 1.5 s——这段既是「回复被截断」的体感，也是回灌窗口。回灌进 worker 的招呼语碎片被 ASR 错转（例：「我想啊怎么了」←嘿我醒啦今天想玩什么；「不行了」←你来了故事继续），与对撞库字符相似度只有 0.33–0.50，穿过原 LCS≥0.8 门起幽灵轮。两条幽灵句的归因是**强推断**（时序 + 相似度 + 文本形态），不是端侧正文对撞。
- **端侧根治 = v237**（18:57 已装 0006，明早真人）：房间连上 + 提示音完整播完才开麦，input_ready 不再截断，动态招呼语只用 ≤1800 ms 的完整句，超长本次回退内置短句。
- **worker 兜底（v3，19:5x 已上产）**：放宽门只在「本会话第 1 句 + worker 开始听的那一刻音频里已经有人在说（语音起点落在输入环启动后 ≤450 ms）」时启用；v237 类设备提示音播完才开麦，用户就绪后开口的起点 ≥600 ms，**永不进放宽分支**——codex §7.3「就绪后立刻说讲个故事」反例在 v3 下不成立。不按 SN/APK 版本特判，对全部设备同一规则。
- **服务端配套（18:58 已上产）**：`greeting.normal` 生成规格 3000 ms/12 字 → 1800 ms/2–6 字；cover_open/presence_return 不动；下次 revision 起生效。

## 2. worker 修法 v3（feat/rust-worker `fcb9f81ef`；含 `37e634c0b` 初版 + `ebb88e9a8` SN 表 + `0019bb8e0` 词表）

### 2.1 普适判据（替代 SN 特判）

放宽分支同时满足才进：
1. 设备房（房名 `sn-<SN>-<建房秒>`），且 `LOCAL_AUDIO_GREETING_MAX_MS`≠0；
2. **本会话第 1 句**（`user_commit_count == 1`，含被吞的）；
3. **起点判据**：本会话首个 VAD 语音起点距输入环启动 ≤ `LOCAL_AUDIO_OVERLAP_ONSET_MS`（默认 450）——即 worker 开始听的那一刻音频里已经有人在说。旧包（招呼语还在放时麦已开）满足；v237（提示音播完才开麦，就绪显示 ≈ 输入环 +270 ms，人反应 ≥300 ms，VAD 检出 +100–200 ms → 最快 ≈ +600–900 ms）不满足；
4. 说完时刻（commit − eou）≤ 建房秒×1000 + 1000 + 3200 + 500（招呼语最晚播完的上界，作为第二道时间约束）；
5. 命令词（`match_command`）/急停/退出词无命中。

满足后与对撞库逐条 LCS，≥0.3 判回声丢弃，日志 `local-audio echo suppressed (opening overlap): '<text>' slot=… lcs=… before_deadline_ms=… onset_ms=…`；否则落回原门（≥4 字 LCS≥0.8 / 2–3 字子串 / 单字吞）。

对 codex §7.3 反例逐条：v237 下 T+1300 开麦、T+3000 就绪、T+3200 开口 → 起点距输入环启动远大于 450 ms（输入环启动 ≈ 开麦后订阅到音轨 ≈ T+1.5–2.0 s，起点 T+3200 → ≥1.2 s）→ 条件 3 不成立 → **不进放宽分支** → 「讲个故事」走原门（LCS 0.5 < 0.8）→ 不吞。

### 2.2 保留的应急杆（默认空，不用于交付）

`LOCAL_AUDIO_OVERLAP_SKIP_SN_HASHES`（sha256(SN) 逗号表）可对个别设备跳过放宽分支——按川哥要求**不作为方案**，生产 env 里没有此键（曾于 19:44 写入 0006、19:48 撤回，env md5 恢复 `d0bd412276756936`）。只在某台设备出现「起点判据仍误判」的实证时临时使用，并在回执里登记。

### 2.3 单测（203/203，clippy 无新增）

- `overlap_onset_qualifies`：+150/+0/+450 → 进；+451/+700（v237 就绪后开口）→ 不进；无起点 → 不进。
- `v237_first_sentence_after_ready_not_swallowed_when_skipped`（编排负向，决策函数层）：T+4000 说完的「讲个故事」在不设门时会被吞（登记为已知向量，是 v2 的缺陷）；deadline=None 时永不进 swallowed；旧设备碎片「我想啊怎么了」(+2050)/「不行了」(+1320) 正向保留。v3 的起点判据把 v237 场景从「不设门才安全」变成「规则本身不命中」。
- `sn_listed`：表空 → false；hash/小写 SN 命中；非设备房 false。
- 诚实边界：起点判据的 450 ms 阈值来自机制推导 + 今天日志（旧包房间 VAD 起点在输入环启动 +100–300 ms），**没有 v237 真机样本**；明早两房是它的第一次真机验证。
