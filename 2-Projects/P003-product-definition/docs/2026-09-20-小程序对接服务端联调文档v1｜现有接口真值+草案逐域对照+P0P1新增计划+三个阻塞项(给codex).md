## 2. 现成接口合同（P0 可直接接，已验证）

### 2.0 公共约定（按现状冻结，小程序侧 DTO 层适配）

- **Base**：`https://p003.hahaxiong.cc`（备案问题见 §6.1，域名可能换，路径不变）。
- **时间**：epoch 毫秒 `*_ms`；日期 `YYYY-MM-DD`（Asia/Shanghai）。dashboard / weekly-report 若传 `timezone` 且不是 `Asia/Shanghai` → 400 `invalid_timezone`。
- **ID**：userId = `acct-NN`；childId = family_member.id（uuid）；deviceId = `public_id`（`dev_<16hex>`，路由只用它）；SN 只作展示，不作路由参数。
- **错误**：HTTP 状态 + `{ok:false, error, message?}`；401 一律清 token 回登录；429 看 `retry_after_s`。
- **命名**：服务端 JSON snake_case，不改；草案 camelCase 由小程序侧转换。
- **分页**：现有接口无分页；新增列表接口统一 `?limit=&cursor=` → `{ok, items, next_cursor|null, has_more}`。
- **请求 ID**：现有家长接口不回显请求 ID；服务端 P0-0 统一加 `X-Request-Id` 回显，小程序每请求带一个（≤96 字符）。

### 2.1 登录（短信）

```
POST /api/auth/sms/send
  req  {phone: "1[3-9]xxxxxxxxx"}
  200  {ok:true}
  400  bad_phone ｜ 429 rate_limited {reason: interval|phone_hour|phone_day|ip_day, retry_after_s, message}
  502  send_failed ｜ 503 sms_not_configured
  限流：同号 60 秒间隔 / 每小时 5 次 / 每日 10 次；同 IP 每日 20 次

POST /api/auth/sms/verify
  req  {phone, code: "4~8 位数字"}
  200  {ok:true, token:<jwt 30d>, account:{id, nickname}, is_new:boolean}
  401  code_invalid（错码 / 过期 / 超次统一口径，防枚举）｜ 400 bad_request ｜ 502 verify_failed
  首次登录自动建号；nickname 默认「家长+手机尾 4 位」
```

### 2.2 家长 / 孩子档案

```
GET  /api/profile                       → {ok:true, profile: FamilyMember | null}
POST /api/profile {nickname 1..20, birthday "YYYY-MM"|"", gender ≤10}
                                        → {ok:true, profile}   （upsert，一账号一档）
```
⚠️ 家长档更新**不会**同步到已绑设备的 brain 档（只在绑定时且 brain 无档时复制一次）→ §4 P0-4 修。

### 2.3 设备绑定 / 列表

```
POST /api/profile/bind-sn {sn}
  200 {ok:true, sn, brain_opened, synced_profile}   同家长重绑幂等 200
  400 invalid_sn ｜ 404 sn_not_available（台账外 / 停用统一口径）｜ 409 sn_taken

GET  /api/profile/bound-devices
  200 {ok:true, devices:[{sn, public_id, note, status, brain_opened}]}
```
⚠️ `note` 是运营后台内部备注，**小程序不要展示**；§4 P0-3 加家长可编辑 `name` 后接口改回 name。无解绑接口 → §4 P0-5。

### 2.4 配网阶段 B（扫码确认）

设备阶段 A（家庭 Wi-Fi）在设备 SoftAP 本地页完成，由手机系统 Captive Portal / 浏览器打开——**小程序与服务端都不参与，Wi-Fi 密码不经过任何云端**。
阶段 B：设备屏显二维码，内容 = `{sn, nonce, pk}`（格式以设备侧合同为准，家长端 H5 现有解析可复用）。

```
POST /api/parent/pairing/confirm {sn, nonce, pk, pairing_protocol: 2}
  200 {ok:true, session_id, relation:'new'|'owner'}   owner = 本来就绑在当前账号（凭据恢复）
  400 bad_request / invalid_pk ｜ 404 sn_not_available ｜ 409 sn_bound_by_other

GET  /api/parent/pairing/status?session_id=<id>
  200 {ok:true, state:'pending'|'initializing'|'bound'|'expired', sn?, binding_outcome?}
  轮询 2 秒一次；pending→expired 由服务端判定（会话寿命 = 设备 nonce 寿命）
```
另有后台预授权自动认领路径（内测设备免扫码），对小程序透明。

### 2.5 设备实时态 + 今日 / 本周（首页）

```
GET /v1/parent/devices/{public_id}/dashboard[?timezone=Asia/Shanghai]
  200 {ok:true, data:{
        device:{updated_at_ms, online, lid_open, present, brightness_level 0|1|2|null, color_mode, image_distance_m, image_distance_state},
        today:{focus_minutes, guarded_minutes, posture_alert_count},
        week:{total_focus_minutes, daily_average_focus_minutes, daily:[{date, focus_minutes} × 7（近 7 天含今天）]},
        availability:{night_reward:false, percentile:false}
      }}
  404 not_found（非本家长绑定 / 不存在，统一不泄露存在性）
```
- 无快照时 `online=false` 且 device 各字段 null；`daily_average` 只除已过的自然日数。
- 今日 / 周数值现状是「无数据 = 0」，草案要求的 availability 区分见 §4 P0-6。
- 首页状态组合建议：`online && present===true` → 学习中；`online && present===false` → 未学习；`!online` → 离线；`present===null` → 传感器未知（按草案策略展示）。
- 亮度档 0/1/2 = 低/中/高；灯关（`led_enabled=false`）时亮度 / 色温显示「关闭」由小程序判断。

### 2.6 周报硬数据

```
GET /v1/parent/devices/{public_id}/weekly-report[?week_start=YYYY-MM-DD]
  200 {ok:true, data:{week_start, eye_health_rate 0..100|null, guarded_minutes, posture_alert_count,
                      percentile:null, highlights:[], data_quality:{valid_posture_rounds, missing_hours:null}}}
```
默认本周一起；`eye_health_rate = correct/(correct+deviated)`，no_person / failed 不进分母，分母 0 → null。即时计算，**没有「周日 22:00 生成」的快照语义**（§4 P1-2）。

### 2.7 现成但小程序不该用

`POST/GET /api/profile/device`（原型期无 SN 的「设备」表，已被 bind-sn 取代）；`POST /api/auth/invite`（邀请码）；`/api/admin/*`（后台）；`/v1/device/*`（设备凭据）。

## 5. 对草案的合同级反馈（照做会踩的）

1. **配网通道**：草案 §4.3 按「BLE + 手机传 SSID / 密码」建模。我们生产路径是 **SoftAP 两阶段**（阶段 A 设备开热点 + 本地页填家庭 Wi-Fi；阶段 B 扫码确认），BLE 是 P1。ProvisioningSession 里 networkStatus / consecutiveNetworkFailures / SSID 列表在服务端不存在也不应存在；小程序只需 `wx.scanCode` → confirm → 轮询 status。「两次联网失败进一步提示」只能在设备本地页 / 设备端做。
2. **经济域来源假设**：§6.1「来源：业务激励后台，设备与手机显示同一权威余额」——这个后台不存在，家族币现在只在设备存档里。先定 §6.2，再谈字段。
3. **时间格式**：草案要 ISO 8601 带时区；服务端全量 epoch 毫秒 + `YYYY-MM-DD`，不改。
4. **ID 体系**：deviceId 用 `public_id`；不要把 SN 当 ID；childId = family_member.id；userId = `acct-NN`。
5. **错误包 / 分页 / 命名**：按 §2.0 冻结。草案 §10「接口失败要可重试，不能伪装暂无记录」同意——按 HTTP 状态区分失败，200 里的 null / [] 才是空态。
6. **儿童档案是两份**：家长档与设备 brain 档各一份（设备侧语音抽取给 brain 档补画像）。小程序只读写家长档；P0-4 后基础三字段自动同步；画像字段不向小程序开放。
7. **设备型号 model**：服务端无 model 列，也没有从 SN 解析型号的规则。来源三选一（台账录入 / 设备快照上报 / SN 批次规则），请硬件或台账方给；给之前接口回 null。firmwareVersion 只有 Android APK 版本名，无 MCU 固件版本。
8. **周报模型**：现状即时计算。草案的 generatedAt / visibleFrom / visibleUntil 快照模型是 P1 新建；P0 请按「随时查，本周 = 周一至今，上周传 week_start」接。
9. **online 阈值与「本次专注」**：online = 10 分钟窗口已定，草案「待硬件方提供」可关闭；currentFocusedSeconds 服务端由事件推算（P0-7），不是设备实时值，误差 ≤ 一次心跳。
10. 补充：`lastMiniappOpenedAt` 服务端目前不打点（P0-11 加）；`lastDeviceUsedAt` 用最新快照的 server_received_ms。
11. 补充：账号默认昵称「家长+尾 4 位」会把手机尾号带到屏幕上，小程序展示层再脱敏或引导改昵称。

## 6. 阻塞与决策项（川哥 / 产品 / 第三方拍板）

**6.1 域名备案**（阻塞小程序发布，不阻塞开发）
微信小程序 request 合法域名要求 HTTPS + ICP 备案域名（转述：微信平台规则）。服务端现域名部署在香港，此前方案选址就是为绕开备案（推断，未查工信部备案库）。选项：A. 用公司已备案域名在大陆机器做反代到香港 :3001（路径不变，最快，需公司侧配合）；B. 备案新域名（周期以周计）；C. 内测期用「网页备用版」（p003.hahaxiong.cc H5 无备案要求，短信登录已通）。开发期小程序在开发者工具关闭域名校验即可联调。

**6.2 经济域权威归属**（阻塞 P1-1，三方）
建议模型：**收入在设备、支出在服务端、余额服务端权威**。夜航 / 迎新礼 / 宝箱等收入由 Godot 产生，经 Launcher 用 telemetry 通道上报 `coin_earned` 事件（event_id 幂等）；任务奖励发放与亲子约定兑现由家长侧事务在服务端写流水；余额 = Σ设备收入 − Σ服务端支出；设备端显示余额需拉取服务端支出合计（复用 config 轮询）。任务达标由服务端用 daily / focus_segment 判定，不依赖设备。约定「儿童设备端确认」需设备 UI + 事件。与 6 月产品定义一致：家族币只用于约定兑现、不占皮肤等虚拟消耗、永不清零。这需要给 Godot / Launcher codex 一份新合同（cc 写），小程序侧先按 §4 P1-1 接口契约开发、用 mock。

**6.3 账号关系**：冻结 1 家长 : 1 孩子 : N 设备；多家长 / 多孩子不做（6 月已拍板）。草案 §3.3 按此简化，历史归属只需设备侧 unbound_at。

**6.4 手机号获取方式**：微信 getPhoneNumber（转述：需企业主体 + 按次计费）vs 短信验证码（已通、有短信成本）。建议双入口，P0-1 上后默认微信。

**6.5 解绑后数据保留**：法务定；服务端默认只切断家长可见性，不删遥测。

**6.6 设备型号来源**：见 §5.7。
