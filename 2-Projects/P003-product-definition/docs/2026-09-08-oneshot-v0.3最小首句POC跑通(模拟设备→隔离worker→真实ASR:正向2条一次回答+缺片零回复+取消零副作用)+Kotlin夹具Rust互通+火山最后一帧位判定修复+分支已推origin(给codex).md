## 4. 两处对齐（按你 §3）

- **`queued_next` 即队列水位**：= 已 `try_send` 进 worker ASR 发送队列（128 块）的样本高水位，**不是已写供应商 socket，更不是识别完成**；ack/result/evidence 三处字段已改名，`credit_samples` = 组包器还能收的样本（8 s 是受控队列容量；ASR 队列满即 `queue_full` 终态，不宣称无背压）。Android 不得拿它判 ASR ready / 云端成功；识别完成只看 `result.status`。
- **包上限三条同时成立**：总包 ≤ 15 KiB（新增校验 `PacketTooLarge`）、头 ≤ 2 KiB、PCM ≤ 7168 样本；单测 `packet_total_size_limit` 用「14 KiB PCM + 1.7 KiB 头」证实被拒；客户端 640 样本整包实测 ≈1.6 KB 放行。
- **正常 LastNoSeq 与意外 EOF 已区分**：`SttEvent::Interrupted`（中途断连 / 协议错误 / 收流后未见 LastNoSeq 即 EOF）→ ordered 代次 `asr_unavailable` 终态，已 hold 的半段 final 绝不提交（单测 `interrupted_stream_never_commits_held_finals`）；现役路径对 Interrupted 只记日志。
- **顺带发现并修了一个现役 bug**（`f4a4ab754`）：Rust 用 `frame.flag == LastNoSeq(0b0010)` 判最后一帧，火山带序号的最后一帧 flag=0b0011，永远不命中，只能等服务端关 socket（生产每个 job 末尾那条 `asr ws closed by server` WARN 就是它）。POC 首跑把正常终局判成意外 EOF 实证；修法与 Python 版一致（位与），单测 `last_frame_flag_is_bitwise_like_python`。**现役路径影响**：job 末尾流按 LastNoSeq 干净结束，事件仍是同一个 `Closed`，行为不变；该修复随分支走，未部署到生产。
