## 2. Worker 改动（与你回执 §3 的对接点）

### 2.1 边界句按动作族（回执 §7 末「可独立推进」项）

`rejected + reason 含 boundary` 时按动作名前缀选族，方向词 `_up/max/farth/warm` = 上限、`down/min/near/cool/cold` = 下限，辨不出方向播中性句：

| 动作族 | 上限 | 下限 |
|---|---|---|
| `virtual_image_*` | 已经到最远了 | 已经到最近了 |
| `brightness_*` | 已经是最亮了 | 已经是最暗了 |
| `color_temperature_*` | 已经是最暖了 | 已经是最冷了 |
| `volume_*` | 已经是最大声了 | 已经是最小声了 |
| `motor_*`（升降） | 已经到最高了 | 已经到最低了 |
| 辨不出方向（cycle/normal/mute） | 已经调到头了 | |

根因：旧实现只认 `up/max/farther`，`virtual_image_farthest` 不含 `farther` 落到「已经到最低了」（09-04 08:56 五次实录）。与你方 4000062「当前虚像距离已最远」语义对齐。**boundary_reached 不重试、不进 LLM、不播成功句**的守恒合同不变。

### 2.2 result 增量键透传（回执 §3.1「命令 result 继续保留 raw，并增量附带规范化读数、来源和 image_distance_boundary_conflict」）

- Worker 判定仍只读 `payload.semantic_label / action / status / reason`（+ 顶层 `lane` / `idempotency_key`），**增量键不参与任何判定**。
- `payload` 里这四键之外的所有键（含既有 `observed_state`）原样紧凑 JSON 进日志：`device command result … extra={"image_distance_boundary_conflict":true,…}`，截 400 字符。老 APK 无增量键 → `extra=` 空。
- 离线向量：三键透传 / 老包空串 / 超长截断 / 已知键不重复，均已锁死。

### 2.3 慢路压制纠正句（回执之外，川哥 09-04 拍板）

- 触发：LLM 标记 `[[DEV:N]]` 被 `l2_gate` 以 **`not_in_batch`** 压制，且快路没在途、房间有 trace。其余压制原因（execute_off / capability_missing / unknown_label / fast_path_hit / no_trace / multi_label）不提示；非 EXECUTE 名单设备走不到这里。
- 动作：LLM 回复自然播完后追加（`say_after_current`，同设备短句纪律；用户抢话即作废）固定句 **「这个我暂时还不能这样调，你换个更直接的说法再试试」**。
- 为什么不教词表原句：TTS 念出「虚像调到最远」会被你方 KWS（command_word 通道）和本机 ASR 当成新命令（8-27 命令词禁入门同一风险）。纠正句单测拿整张 254 别名表对撞 + 负锚，保证不含任何别名。
- 背景：09-04 08:56 003「画面调到5米」（数值句，未命中词表）→ LLM 标 35 被压制，但 LLM 回复说「好呀，画面离远些啦」= 对孩子的空承诺。纠正句只纠正、不冒充执行。
- 日志锚：`llm device intent suppressed reason="not_in_batch"` → `llm device intent fallback hint queued` → `device reply appended after turn played out`。
