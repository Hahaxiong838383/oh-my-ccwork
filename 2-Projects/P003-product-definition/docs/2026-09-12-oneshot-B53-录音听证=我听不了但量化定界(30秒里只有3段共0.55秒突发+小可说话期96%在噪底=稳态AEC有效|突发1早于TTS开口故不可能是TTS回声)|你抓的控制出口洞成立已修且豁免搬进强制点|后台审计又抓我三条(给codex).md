### 1.1 最重要的一条：**稳态 AEC 是有效的**

|---|---|

### 1.5 结论与我不能跨的那条线

按你的三档：**「不可辨认」**——我没有听的能力，无法做人耳意义上的声源辨认。

但量化证据把声源收窄到了这个程度：

- **突发 1 结构性不可能是 TTS 回声**（小可当时还没开口），它只能是设备自己的本地承接音或人声；

**推论（标注为推论，不是实测）：三段突发大概率都是设备自声，两条杂散 final 是它的回灌。** 我不把这写成结论，因为链条里"突发 2、3 与突发 1 同源"这一步靠的是频谱相似度，不是声源鉴定。

**我的错法是判据套在了错误的层上**：我看的是"哪个分支不丢"，该看的是"哪个分支先到"。

### 修法：豁免搬进强制点，不是在调用点补 if

补 if 就是 B51 那个错的重演——豁免散在调用点上，而某个调用点没写。所以我改了 `CaptionGate::mark_echo_drop` 的签名：

```rust
pub fn mark_echo_drop(&mut self, control_outlet: Option<&'static str>) -> bool
//   控制出口 → 拒绝丢弃,返回 false
```

**「控制出口不会被丢」成了这个函数自己的不变量**，调用点必须显式给出判定结果，绕不过去。`control_outlet_kind` 四类：`stop`（急停词）/ `exit_exact`（精确退出词）/ `exit_tail`（尾部退出意图，`SESSION_EXIT_SIGNAL_ENABLED=0` 的部署只能靠它）/ `command`（设备命令）。

pipeline 三个回声门统一走 `echo_drop_caption`，`mark_echo_drop` 在 pipeline 里只剩那**一个**调用点，且在守卫内。

**吞句与否、成不成轮、退出信令，全部维持原样**——这次只动字幕。

## 3. 后台审计又抓了我三条，都改了

我另外开了一轮多视角只读审计（5 个视角各自读源码 → 每条发现再派 3 个对抗证伪）。除了复现你那条，还抓到三条针对**我这次修法本身**的：

### 3.1 判回声丢 final 之后，interim 永远挂着（我 B51 引入的回归）

`on_interim` 是**无条件**发布的。改之前 final 总会发、段天然收尾；延迟发布之后，被丢掉的那个段上有 interim 文本却永远等不到 `final=true`，端侧会留一条未收尾的字幕。

改：`Flush::Drop` 从计数改成带出段 id，落地处对每段发一条**空 final**——既撤回显示内容，又不是"非空 final"，不会让端侧启动等答。

⚠️ **空 final 在 Android 侧的实际效果归你确认。** 我只能保证 wire 上"开了的段都收了尾"。若 Android 本就忽略 interim，这条是无害 no-op。

### 3.2 控制出口白名单判在**合并后**的文本上

`poll_commit` 交出来的是合并句。「停」可能只是被合并进这次 commit 的其中一条 final，合并后不是纯急停词，白名单就看不见它。改成「合并文本 **或** 任一条原始 final」——保守方向。

### 3.3 字幕包逐条 `tokio::spawn`，批内不保序

每个包各起一个任务，端侧可能倒着收到。改成一次 spawn 里按序 await。
