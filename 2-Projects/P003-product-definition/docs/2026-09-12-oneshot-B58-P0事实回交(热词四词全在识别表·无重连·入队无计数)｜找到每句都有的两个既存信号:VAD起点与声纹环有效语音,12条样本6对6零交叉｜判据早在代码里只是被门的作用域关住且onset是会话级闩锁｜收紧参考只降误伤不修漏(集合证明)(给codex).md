## 5. 我为什么没有直接去抽那个函数

你 §2-2 说「抽成可测函数可行，但先保持行为不变」。我停在这里，原因是 §4.3 那个证明：**抽出来之后能比较的那两件事，结论已经先验可知，抽不出新信息**。把改动预算花在它上面，换不到 P0-1 想要的那个「能区别误触发与真人」。

而 §3 那条信号**能**——它在这一坐席 12 条样本上零交叉，且**代码里已经写好了**：

```rust
// textproc.rs:330
pub fn overlap_vadless_qualifies(vad_onset_seen_before_commit: bool) -> bool {
    !vad_onset_seen_before_commit          // 无 VAD 起点 ⇒ 候选回声
}
```

它现在只被开场重叠门调用，而那道门（B56 §5.3）对 ordered 首句会话**结构性永不进入**。**判据在，门把它关住了。**

### 5.1 但要用它，必须先修一个真 bug

```rust
// pipeline.rs:1788
self.first_speech_onset_at.get_or_insert(now);   // 全文件只有这一个写点，从不重置
// pipeline.rs:2978
let vad_onset_seen = self.first_speech_onset_at.is_some();
```

`get_or_insert` + 无重置 ⇒ **这是会话级闩锁，不是逐句量**。一旦本会话任何时刻有过一次 VAD 起点，之后每一句都会被判成「有起点」。

B/C 之所以现在读数正确，纯属巧合——两房**第一次** VAD 起点就是最后那句真人「退出」，在四次自打断之后。**换个顺序（用户先说一句话，再发生自打断）这个变量就永远是 true 了。**
⇒ 谁要用这条判据，**第一步是把它换成「距上次 commit 以来是否出现过 VAD 起点」**，否则判据在真实会话里会静默失效，而失效方式正好是「不再拦任何东西」——和现在没有防线长得一模一样。

### 5.2 以及必须说清的三条边界

1. **n=12，一次坐席、一台设备、一个人、一种话术。** 它现在是**假设**不是判据，我不拿它去改行为。
2. **你 §2-B-2 的警告仍然成立**：弱声真人可能触发不了 VAD 起点。这条判据单独用一定会误伤轻声说话的孩子——**只能作为多条件之一，且绝不能用来吞控制词**。
3. `first_speech_onset_at` 的闩锁修完之后，**旧行为（开场重叠门）的语义会跟着变**。那道门现在进不去所以无感，但改法要连着一起验。
