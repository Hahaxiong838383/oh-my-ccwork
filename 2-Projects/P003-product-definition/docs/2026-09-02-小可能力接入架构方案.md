# 小可能力接入架构方案（不动语音环，旁挂工具与专家）

> 起因：川哥转来一份针对小可 worker 的能力接入分析（MCP 快工具 / ACP 慢专家 / 播报分桶）。方向对，但它按「开发者语音编码助手」写的——dsh/Grok Build/ACP 对儿童伴学设备无意义。本文把框架翻译到小可的真实能力清单与现有机制，证据标注：【已验证】=读源码/gh 真值；【推断】；【未验证】。
> 状态：方案，待川哥拍板落地顺序。

## 〇、结论

1. **不迁框架**：Pipecat（15.1k★）/LiveKit Agents（13.9k★）/TEN（11.1k★）都活跃【已验证 gh 9-1 push】，但小可 rust 语音环已过三轮真机磨合（打断门/回声对撞/filler 人格化），迁=重踩全部坑。只借它们的三条思路：工具当 sidecar、句子边界再送 TTS、打断即取消当前合成——**这三条小可已经有了**。
2. **快工具走两级**：能一次说完的动作走现有 `[[DEV:N]]` 标记协议扩展（零额外 RTT）；要外部数据回填答案的走 server 侧 tool loop（+1 跳，filler TASK 桶顶住）。
3. **慢任务回灌是唯一要新建的通道**：worker 已有 Android→worker 的 `control` topic 入站（cancel/command_word/session_exit ack 等，control.rs）【已验证】，但 server 侧无 LiveKit 服务端发布能力【server SDK 未验证】；推荐「worker 轮询 job 状态」+「下一轮注入」双路，P0 不碰 server→room 反向发布。（修正：初稿误写「worker 不接收 room data」——只查了 pipeline.rs 就下了全仓结论。）
4. **MCP P0 不上**：小可的工具全是自家 server 内部函数，多一层跨进程 RPC=多延迟多故障点；外部源（内容 CP/家居）≥3 个再上 MCP 网关。ACP 整段不适用。
5. **儿童版权限门**：不是「花钱/删文件」，是家长授权面（对外发消息/改护眼参数/播外部内容）+ 孩子语音=prompt 注入面，工具参数一律白名单校验。

## 一、小可现有机制盘点（全部【已验证】读 feat/rust-worker + server src）

| filler 分桶 | worker filler.rs：GREET/THANKS/EMO/**TASK**/STORY/ASK hints，commit 即播 | tool loop 延长首 token 时的天然占位；TASK 桶=「让我看看哦」 |

## 二、小可的能力清单（按快/慢分，儿童伴学场景）

| 层 | 能力 | 延迟预算 | 接法 |
|---|---|---|---|
| L0 词表快路（在产） | 设备控制六类 | ~0 | worker 白名单直执行（观察→执行待 codex 2b 合同开闸） |
| L1 标记快工具 | 设备控制慢路（在产）、**提醒意图**（只带 intent，时间由 server 确定性解析）、故事/歌曲「模式切换」 | 零额外 RTT | 扩 `[[DEV:N]]` 为 `[[ACT:kind:arg]]`，worker 剥离后执行/上报 |
| L2 tool loop 快工具 | **K12 知识检索**（已调研，RAG ≤300ms）、天气、时间日期、家长留言读取 | +100~500ms | server gemini-llm 加 function calling；filler TASK 桶占位；超 800ms 降级为「我再想想」不阻塞 |
| L3 慢专家 | 跟读发音评测、拍照识题/看图讲解（**摄像头能力【未验证】**）、长绘本整本生成、家长端任务汇总 | 秒~分钟 | job 表 + 回灌通道；派工瞬间播 TASK 桶，完成播一句结果 |
| 决策点 | 儿歌/音乐点播 | — | **需版权源**（CP 合作或家长自有），现有 bilibili 服务不可商用 |

## 三、架构（在现有链路上加，不换）

```
端 Android ── LiveKit ── worker(rust:VAD/打断/filler/标记剥离/词表快路)   零改动主环
                              │  /v1/chat/completions SSE(现有)
                        server brain(custom-llm:人设+记忆+风格+护栏)
                              ├ L1 [[ACT:…]] 标记 ── worker 剥离执行/上报   (扩现有协议)
                              ├ L2 tool loop ── KB / 天气 / 留言 (gemini function calling,server 内函数)
                              └ L3 job 表 ── 后台执行 ──┬ worker 轮询 GET /v1/jobs/:id (短任务 <10s)
                                                        └ 下一轮注入「刚才弄好了」(长任务)
                        家长授权面：device config 下发开关 + 工具参数白名单
```

**为什么丝滑不受影响**：
- 主环零改动：worker 只多一种标记 kind + 一个轮询协程（与现有 echo bank 拉取同款异步 fail-open）；
- L1 不加 RTT；L2 的额外一跳被 filler 覆盖（TASK 桶 1-2s）——**tool 超时 800ms 硬降级**，宁可答「我再查查」也不留静音；
- L3 从不阻塞回合：派工即回话，结果异步；
- 全部 fail-open：任何工具失败=回到今天的纯聊天行为。

## 四、慢任务回灌通道三选一（P0 推荐 A+B）

| 方案 | 机制 | 改动 | 取舍 |
|---|---|---|---|
| A 轮询 | worker 每 2s GET job 状态，完成即插播一句 | worker 一个协程 + server 一个端点 | 简单可靠；<10s 任务体感即时 |
| B 下一轮注入 | job 结果写待播队列，孩子下次开口时 prompt 注入「先说这个」 | server 侧纯 prompt 组装 | 零新通道；被动等孩子开口，适合长任务 |
| C LiveKit 反向 data | server 经 LiveKit 服务端 API 向房间 publish，worker control 入站放行 `src=server` | worker 入站 src 白名单加一项 + server 接 LiveKit 服务端 SDK【未验证】 | 真正主动推；改动集中在 server 侧，P1 再评估 |

## 五、落地顺序（每步独立可回滚）

1. **设备命令观察→执行**（已是 L1 完整实现，只差开闸，受 codex `vad_candidate_id` 合同 BLOCKED）——这一步跑通=快工具范式在真机验证。
2. **L2 tool loop 首接 K12 知识库 + 时间/天气**：gemini-llm.ts 加 function calling；测 TTFT 增量（目标 ≤300ms）；filler TASK 桶覆盖验证。
3. **提醒能力**：MyJavis 范式移植（确定性解析/复述确认/三档触达），触达用设备本地音频 slot + A 轮询。
4. **job 基建 + 首个慢专家**（跟读评测或识题，取决于摄像头能力核实）。
5. 家长授权门贯穿 2-4；外部源 ≥3 个再引 MCP 网关。

## 六、对转发分析的逐条裁决

| 它说 | 裁决 |
|---|---|
| 快/慢两类、慢任务先播 task 桶 | ✅ 采纳，小可 filler TASK 桶就是这个 |
| 工具协议统一 MCP | ⏸ P0 不上（内部函数直调更快），外部源多了再上 |
| 编码能力用 ACP 常驻 dsh/grok | ❌ 不适用儿童设备，整段跳过 |
| 权限单独语音确认（删文件/推 git/花钱） | 🔁 改为家长授权面 + 参数白名单 |
| OpenLive（273★）最贴合 | ❌ 它是「语音改代码」，与小可无关 |
| 若语音环自研不必迁 Pipecat | ✅ 同意，且理由更强（真机磨合资产） |
