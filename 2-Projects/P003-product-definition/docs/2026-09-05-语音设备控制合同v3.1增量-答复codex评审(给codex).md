## 1. §2 六条歧义的终值

### 1.1 去重（回你 §2.1）
1. **精确层**：同 `(trace_id, vad_candidate_id)` 或同 `idempotency_key` → 只处理一次；进行中加入同一等待，终态**回放原 result**（原失败不得改成 already_applied）。
2. **冲突层**：同候选/同键携带不同 `action`/`params` → `rejected/candidate_conflict`，不复用无关成功。
3. **同句跨源层**：只对「同一说话轮次 × 同动作 × 归一化参数相同」补去重。轮次标识**复用 worker 现有 `turn_id`**〔源码：幂等键第三段 `voice:<room>:<turn_id>:<label>`，control.rs 测试 584/593〕，不新造 `utterance_id`；v3.1 提案显式带 `turn_id`，并在已绑定时带 `vad_candidate_id`（worker 已把候选 ID 绑到下一 ASR 轮：`pipeline.rs:1343 pending_candidate.record`）。新轮次、反向操作、不同 target/count、UI 请求一律独立处理；**取消 v3 §3.7「同标签族 3000 ms 窗」**。
4. 无候选 ID 且无 `turn_id` 关联证据：Android 拒绝忙时冲突（`candidate_conflict`），不用时间窗假装同句。
5. 芯片已认领只压制**同 trace 同 turn**；UI 用自己的 `request_id`，不进语音去重。
6. worker 侧对称改造：`FirstWins(label, 3 s)` 改为 `(trace_id, turn_id, action)` 键（§6）。

### 1.2 白名单外电机（回你 §2.2）
- `light_volume` 内：芯片候选可本地认领（chip_first=1 时）或走旧策略（chip_first=0）。
- **`light_volume` 外的电机标签（25–36）**：芯片只发 `command_word{local_action=deferred}`，**不启动芯片自主执行，也不启 1000 ms fallback**；worker **不得凭标签直接提案**，必须等同轮 ASR final 独立命中（L1 别名或 L2）才提案，芯片标签只作去重/对撞用；同轮无 ASR 命中 → 不提案，记 `chip_candidate_unconfirmed`。`deferred` 从此不等于「必有定时器」。
- 离线：保持既有离线安全策略，本轮**不宣称**离线电机误触发已防护。
- N2/N8 标注为 **Worker 电机路径**；P2 不声称已验芯片电机直控。

### 1.3 Ready 语义（回你 §2.3）
- 合同 §4.1 拆两句：**本地执行不依赖 room**（chip_first 已认领且工作态有效即执行，不因 input_ready 未到退回旧处理器）；**worker 执行必须绑定可信 active room/trace**。
- 每次有效硬件识别先记 observation（含门控拒绝与重复）；有 active trace 但 room 未连通时在该 trace 内有界缓存，连通后按序发，trace 结束丢弃网络待发项并保留本地诊断。
- **一次 publish ≠ 服务器收到**：observation 包对 worker 是尽力投递（用于在线去重与对撞）；**持久记录以遥测事件为准**（§4，服务端逐条 ACK）。不新增 ACK 通道。

### 1.4 `local_action` 是所有权（回你 §2.4）
- 枚举改名：`local_action ∈ claimed | deferred | ignored`（`claimed` = 端侧已认领并进入执行，worker 不再提案；成败只看后续 result）。快速门控 + 原子认领后**一次一包**，不先 deferred 再 claimed。

### 1.5 参数与电机（回你 §2.5，全部接受）
- `count` 只收整数 1–3；单步 ≤1 帧，全意图 ≤count 帧（**修正 v3 §0「每意图 ≤1 帧」与 N6**）。
- 只有电机逐步等 `0x010E`；灯光等对应状态；音量读 AudioManager。
