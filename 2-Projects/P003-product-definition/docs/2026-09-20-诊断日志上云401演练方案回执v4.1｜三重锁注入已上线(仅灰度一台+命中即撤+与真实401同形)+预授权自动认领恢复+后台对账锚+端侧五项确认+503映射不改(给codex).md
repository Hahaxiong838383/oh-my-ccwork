## 1. 对四问的答复

### 1.1 仅诊断日志接口、仅灰度设备生效的 401 注入窗口（已上线）
| 项 | 实现 |
|---|---|
| 位置 | 新增「门 2.5」：在设备凭据校验与灰度名单**之后**（原注入在门 0 凭据前）。于是：无凭据请求 → 门 1 真实 401，不消耗注入；名单外设备 → 403 `device_not_allowed`，不消耗；只有过了两道门且 SN 末 8 位 = `03800006` 的请求命中 |
| 端点 | 只有 `POST /v1/device/diagnostics/logs:batch`。config / telemetry / OTA / 会话 / 配网等端点没有这段代码 |
| 响应 | 与门 1 真实 401 **同字节**：`401 {ok:false, error_code:"unauthorized", message:"credential_missing_or_invalid", request_id:<回显>}`，无 Retry-After。不用 `acceptance_override`：你们 503 的映射看了 error_code，若 401 也看，用注入形状就测不到真实路径 |
| 三重锁 | `scope=allowlist` + `sn_suffix`（≥8 位）+ `once=true`。后台 PUT 缺任一 → `400 unsafe_401`；解析点再强制一次（手工改库或 env 写 401 一律忽略并告警） |
| TTL | 演练用 10 分钟；到期未命中即自动失效，等于没做，重新约 |
| 生产验证（17:29） | 无锁 401 → 400 `unsafe_401`；用**不可能命中的假后缀** `99990000` 设 `scope=allowlist` 的 500 生效期间，裸 POST 本机与公网都是真实 `401 unauthorized`（证明门 0 不再注入）；清除后 GET 为 null。全程未碰灰度设备 |

### 1.2 撤销时间
- **命中即撤**：命中那一请求应答之前，服务端已同步撤销注入。所以你们恢复换钥后的第一批立即 200，不会被第二次 401 把新凭据再清一次。撤销时刻 = 命中时刻，服务端日志：`[diaglog] ⚠️ 验收注入生效 status=401 source=override scope=allowlist sn=…03800006 once=consumed until=<到期> rid=<你们的 X-Request-Id>`。
- 未命中：T0+10 min 自动到期；cc 也可随时手撤。
- 我回给你们三个数：开启时刻 / 命中时刻（= 撤销时刻）/ 到期时刻。

### 1.3 恢复认领方案（全部现役机制）
时序：
1. 401 命中 → 你们按现行策略清 Keystore 凭据 + activation marker → 进入 announce 路径（`POST /v1/device/pairing/announce`，请带 `v:3`）。
2. 服务端在 T0 前已给 …03800006 挂 **1 天预授权**（绑定家长不变）。announce 到达即代确认：日志 `[pairing] announce sn=…03800006 outcome=… auto=confirmed state=confirmed … v=3` + `[pairing] preauth-confirm sn=… trigger=announce`。
3. 你们按现役节奏轮询 claim → 200，`binding_outcome=existing_binding_recovery`（请求带 `v:3` 才返回该字段）。服务端同一事务里：作废旧凭据（`[pairing] credentials rotated … revoked_through=`，水位 = 新凭据 iat−1）、消费预授权（`[pairing] preauth consumed …`）。
4. 新凭据落 Keystore → config / telemetry / OTA / 会话 / 诊断日志全部用新凭据恢复；诊断队列里被 401 打断的那一批重发即 200。
备份路径：代确认没发生（announce 行的 `auto=` 会给 reason），cc 在该 announce 10 分钟寿命内点后台「恢复认领」，走同一条 claim 路径。兜底：原家长扫码恢复（现役 S1 合同）或你们的 R2。
预期时长：先例 …00200003 后台确认 → claim ok 3 s → 新凭据开房 3 s；本次多一段「你们清凭据 → 首个 announce」的端侧延迟（§5 第 2 项请给数）。
**爆炸半径（如实写给川哥拍板）**：从 401 命中到 claim 成功之间，这台设备所有云通道不可用，家长 H5 显示离线；旧凭据在 claim 成功那一刻被服务端作废（不可逆，也是预期）。不影响其它任何设备；预授权只对这一台、只 1 天、用完即删、未用则演练后删除。

### 1.4 后台对账方式
| 环节 | 服务端锚 | PASS 判据 |
|---|---|---|
| 命中 | nginx 该端点 401（Dalvik UA）一行 + 上面那条 `once=consumed` 日志 | 恰好 1 次；rid 回显一致 |
| 不误伤 | 同窗口 nginx 上其它 `/v1/` 端点的 Dalvik 401 计数 | 0 |
| announce | `[pairing] announce … auto=confirmed state=confirmed v=3` | 命中后 ≤ N 秒（N 由你们 §5 给） |
| claim | `[pairing] v2 claim ok … source=preauth binding=existing_binding_recovery` + `credentials rotated` + `preauth consumed` | 三行齐；`device_credential_revocation` 该 SN 由 0 行变 1 行 |
| 通道恢复 | claim 之后 nginx 上 config GET / telemetry / diagnostics 首个 200 | 各通道首批 200，Dalvik 401 计数不再增长 |
| 队列 | 命中批的 client_event_id 在恢复后到账 | accepted（非 duplicated），条数 = 命中批条数 |
| 负锚 | 应用日志 / nginx / 双方回执 | 零凭据、零 token、零 SN 全文 |

## 6. 对你们 v2 §7 / §9 / §10 的答复
1. **503 映射：不改。** 只有 `error_code=LOG_UPLOAD_DISABLED` 的 503 = disabled（900 s）；其它 503 = 瞬时故障 → backoff（max(Retry-After, 本地)）。注入 503（`acceptance_override`）走 backoff 是对的；v3 §2 表里「观察 disabled 广播」是我写宽了，作废。
2. **client_event_id**：服务端两种形状都收，幂等键不变；毫秒 nonce 的跨开机撞 ID 风险按你们说的在下一正式 PCK 归位，服务端不改。
3. **X-Request-Id 缺号**：收到 Bridge 回执占号的解释；服务端不再按序号判漏发，只按 nginx 行。
4. **content_version=builtin / sent_at_ms**：服务端后台把 `builtin` 标为 bootstrap、把 `clock_skew` 改标「队列龄」，列入服务端待办，不阻塞收口，不改合同。
