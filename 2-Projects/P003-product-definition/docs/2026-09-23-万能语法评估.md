# 「万能语法」对小可的价值评估（2026-09-23 10:47 CST，cc）

> 来源：川哥附件《万能语法 - 修正版 -2.csv》（20 个句子成分槽 + 日程域优先级/权重 + 5 个日程案例）。
> 评估对象：① 小可理解用户 ② 记忆 ③ 语音控设备（D2 语法层 L1g）。
> 结论先行：**这份表对小可的价值在「当清单用」，不在「当引擎用」。** 收益排序：语音控设备 > 记忆 > 理解用户。表里的优先级/权重按日程域标，套到设备域要按域重标。
> 川哥 10:57 拍板「做好回滚记录，按建议做，在后台记录和观察，通过日志而不是通过大模型观察」→ D2.1（见 `2026-09-23-语音控设备D2改动清单.md` §E/§F、RELEASES）。

## 1. 语音控设备：当审计清单收益高；当运行时解析器不要

**已验证（读源码）** 语法层 15 道守卫对照 20 槽已覆盖 11 槽：句子类型（疑问词、陈述式 是/有/的、叙事词）、语气否定、主语（第三方人物、我开头非请求、你开头陈述）、谓语核心、直接宾语、结果/方向/程度、条件（如果/要是/假如/万一）、连接词复合句、体（已经/刚才/关了灯）、情态推测（可能/应该/好像）、附加从句（>14 字）。未覆盖：**时间（未来/延迟）**、**地点/背景**（原只有 外面/屋里/房间/教室/学校 五词）。

**原型回放**（与 Rust 端在 389 条词表 + 64 条语料句上逐句一致）34 句探针：

| 槽 | 探针 | D2 结果 | D2.1 |
|---|---|---|---|
| 时间未来 | 晚上再关灯 / 明天把音量调小 / 等一下关灯 | 立刻执行 | 不认 `time_future` |
| 时间未来 | 等会儿关灯 / 待会儿调暗 | 被拦（碰巧：「会」在讨论词表） | 不认 `time_future` |
| 地点 | 把客厅的灯关了 / 卧室的灯亮一点 / 厨房灯关掉 | 全部命中我们这盏灯 | 不认 `place` |
| 情态请求 | 能不能把灯调亮一点 | 被「不能」当否定拦掉 | 放行，`modal=true` |
| 体 | 灯关了 | 命中关灯（陈述与命令同形） | 不认 `statement_le` |

其余 8 槽（第三方主语、完成体、推测情态、疑问、复合句、宾语修饰、间接宾语、比较）表现符合设计。

**本轮观察** 三台机 11,156 条真实识别结果（同事演示语料为主，用完已删）：含设备词 719 条，其中未来时间词 4、地点词 4、能不能 2，且全是超长守卫已拦的演示长句。两个洞在现有语料里触发 ≈ 0 次，是「误触发大于漏触发」铁律下的保险，不是当前故障。

**不做运行时 20 槽解析器**：本轮漏斗经验是窄表 + 一票否决赢、宽解析输；语料 34% ≤3 字、61% ≤6 字、无标点；表的必选槽（主语/谓语）在儿童祈使句里常缺省（「亮一点」没主语没宾语）。

**设备域重标表（设计稿）**：表里 结果/方向/程度 标 P3 权重 0.35，设备域是 P0；表里 时间/地点 标 P1，设备域是否决槽。

| 角色 | 槽 |
|---|---|
| 核心三槽 | 谓语核心、直接宾语、结果/方向/程度 |
| 否决槽 | 句子类型非祈使、语气否定、第三方主语、时间未来、条件、地点其它房间、体已完成、情态推测 |
| 放行槽 | 情态请求：能不能/可不可以/行不行 |
| 无关槽 | 连接词、间接宾语、主语限定/修饰、宾语修饰、时态、语态、附加从句 |

顺手的观察：表头编号 1–20 是中文线性语序（时间/条件/地点在主语前，程度在谓语后）——否决槽扫前缀、程度槽扫后缀即可，比全句无位置匹配歧义少。想法，未采纳。

## 2. 记忆：只对约定/关心事的三个槽有收益，量化不了

**已验证** 6 类条目（promise/event/emotion/relation/preference/concern）；字段 = 类型 + ≤40 字自由文本 + 证据原话硬校验，主语只有 promise 的 xiaoke/child 与 relation 人名，时间只有 promise/concern 的 `due_text`；`parseDue` 只认 今天/一会/等下/待会/明天/后天/周几/下次/以后，其余 unknown → 注入端按「下次见面」渲染。

对照 20 槽：有主语和时间的局部，谓语宾语混在自由文本，**没有条件、情态、地点、体**。真有收益的三处：
- 条件槽：川哥日程案例 2 就是「如果不下雨」；带条件的约定现在按硬约定入库，到期没兑现算失约。
- 情态槽：「可能/也许/应该」的计划现在与承诺同等对待，抽取铁律只排除客套话。
- 时间槽词表：`parseDue` 缺 周末/放学/睡觉前/下个月/寒暑假/生日，全落 unknown。

**未知** 收益大小量化不了：11,156 条里像约定/计划的只有 25 条（0.2%），带条件 2、带推测 0；演示语料不是孩子会话。线上孩子的记忆条目没读（隐私）。→ D2.1 只加日志计数（`[memory-slot]` 行，`ops/memory-slot-stats.sh` 数），观察够一段再决定要不要加字段。

**不建议** event/emotion 槽位化：它们是大模型改写的短语，槽位化收益是检索/去重，而消费端是整条塞 prompt，没有槽位查询。

## 3. 理解用户：收益低，开放聊天大模型已覆盖

**已验证** worker 侧确定性理解只有承接音桶分类（ASK/TASK/STORY/DEVICE/EMO/GREET/THANKS/OPINION 词表）+ 附和词表 + 急停词 + 设备漏斗，其余靠大模型。**本轮观察** 疑问标记 13%、设备祈使 4.7%、其余 83% 陈述/闲聊。
前置全量解析只增加延迟并制造第二套与大模型分歧的理解；表的作用只在「工具型意图」的确定性前置（设备、将来的音乐/故事控制、提醒）= 把「对象+方向+程度」推广成「对象+动作+序数」，仍是三槽。句子类型槽可借来把承接音桶边界写清楚——文档收益。
