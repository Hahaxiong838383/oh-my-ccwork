      ▲

### 1.2 S2S 合同（冻结）

- **基址**：`https://kidshub-ai.hahaxiong.cc`，路径 `/api/*`、`/v1/parent/*`。TLS 必须；单请求超时建议 10 秒；只对 GET 与带 `Idempotency-Key` 的写重试。
- **鉴权模型：透传家长 JWT**（选定；理由：cc 侧全部家长接口已按 accountId 隔离，零改动；伙伴密钥泄露半径只在登录口）。
  a. 登录：小程序 getPhoneNumber → 同事服务器用自家 AppID/AppSecret 向微信换手机号 → 调 cc `POST /api/auth/partner/phone-login`（§5 P0-A2，伙伴密钥）→ 得家长 JWT（30 天）。短信登录备用：透传 `POST /api/auth/sms/{send,verify}`。
  b. 业务：同事服务器每次调 cc 带 `Authorization: Bearer <家长 JWT>`。JWT 建议只存同事服务器会话侧、不下发小程序（下发也可，但 401 处理要一致：清会话回登录）。
  c. 到期：JWT 30 天无刷新接口；同事服务器用已存手机号再次调 partner phone-login 静默换新（不发短信、不重新授权）。
- **伙伴密钥**：请求头 `X-Partner-Id: <id>` + `X-Partner-Key: <key>`。cc 侧 env 只存 hash；同事服务器**出口 IP 固定并告知 cc**，cc 按 `X-Real-IP`（nginx `$remote_addr`，即同事服务器 IP，不可伪造）白名单 + 密钥双因子。密钥经安全渠道单独交付，**不进文档 / 聊天 / 仓库**；轮换用双密钥窗口。
- **必带请求头**：
  - `X-Forwarded-For: <终端用户 IP>`——同事服务器必须**覆写**为小程序请求来源 IP（不是追加）。cc 的 nginx 会追加同事服务器 IP，cc 侧终端用户限流取第一跳；不带则所有用户共享一个 IP 桶，短信发送每日 20 次的 IP 窗会拦全体（已验证：短信限流按 XFF 第一跳）。
  - `X-Request-Id: <≤96 字符>`——同事生成、cc 回显（§5 P0-A1），双方对账用。
  - `User-Agent: <同事服务标识>/<版本>`。
- **错误透传**：cc 的 4xx/5xx 与 `{ok:false, error, message?}` 原样或按映射表回给小程序；**不得把失败变成 200 空态**；429 的 `retry_after_s` 必须尊重；401 = 家长 JWT 失效（与伙伴密钥 401 区分：伙伴登录口返回 `partner_unauthorized`）。
- **缓存**：dashboard / weekly-report / daily / wallet 可按「账号 + 键」缓存 30–60 秒；写操作与登录不缓存；写成功后主动失效相关缓存。
- **健康检查**：`GET /api/health`（§5 P0-A5；现有 `/health` 未对外反代）。
- **红线**：同事服务器不落 cc 服务端密钥之外的任何 cc 内部标识；不代填 / 代存 Wi-Fi 密码；不把 SN 全文、手机号、JWT 写进日志或下发到小程序日志。

## 3. 现成接口合同（同事服务器可立即接，已验证）

### 3.0 公共约定（按现状冻结）

- 时间：epoch 毫秒 `*_ms`；日期 `YYYY-MM-DD`（Asia/Shanghai）；dashboard / weekly-report 若传 `timezone` 且不是 `Asia/Shanghai` → 400 `invalid_timezone`。
- ID：userId = `acct-NN`；childId = family_member.id（uuid）；deviceId = `public_id`（`dev_<16hex>`）；SN 只作展示。
- 错误：HTTP 状态 + `{ok:false, error, message?}`；命名 snake_case；新增列表接口 `?limit=&cursor=` → `{ok, items, next_cursor|null, has_more}`；新增写接口支持 `Idempotency-Key` 头（同键同体 24 小时内返回首个结果）。

### 3.1 登录（短信，备用链路）

```
POST /api/auth/sms/send    {phone}        → 200 {ok:true}
   400 bad_phone ｜ 429 rate_limited {reason interval|phone_hour|phone_day|ip_day, retry_after_s, message} ｜ 502 send_failed ｜ 503 sms_not_configured
   限流：同号 60 秒间隔 / 每小时 5 次 / 每日 10 次；同 IP（XFF 第一跳）每日 20 次
POST /api/auth/sms/verify  {phone, code}  → 200 {ok:true, token, account:{id, nickname}, is_new}
   401 code_invalid（统一口径防枚举）｜ 400 bad_request ｜ 502 verify_failed
```

### 3.2 档案（过渡期：= 主孩子，P0-B1 上线后小程序改用 children 接口）

```
GET  /api/profile                                  → {ok:true, profile: FamilyMember|null}
POST /api/profile {nickname 1..20, birthday "YYYY-MM"|"", gender ≤10} → {ok:true, profile}
```

### 3.3 设备绑定 / 列表（过渡期：P0-B3 上线后改用 /api/parent/devices）

```
POST /api/profile/bind-sn {sn}      → 200 {ok:true, sn, brain_opened, synced_profile}
   400 invalid_sn ｜ 404 sn_not_available ｜ 409 sn_taken；同家长重绑幂等 200
GET  /api/profile/bound-devices     → {ok:true, devices:[{sn, public_id, note, status, brain_opened}]}
```
⚠️ `note` 是运营内部备注，不得展示、不得下发小程序。

### 3.4 配网阶段 B（扫码确认）

阶段 A（家庭 Wi-Fi）在设备 SoftAP 本地页完成，小程序、同事服务器、cc 服务端都不参与；Wi-Fi 密码不经过任何云端。阶段 B 小程序 `wx.scanCode` 得二维码 `{sn, nonce, pk}`（格式以设备侧合同为准）→ 提交同事服务器 → 透传：

```
POST /api/parent/pairing/confirm {sn, nonce, pk, pairing_protocol:2}
   200 {ok:true, session_id, relation:'new'|'owner'} ｜ 400 bad_request/invalid_pk ｜ 404 sn_not_available ｜ 409 sn_bound_by_other
GET  /api/parent/pairing/status?session_id=
   200 {ok:true, state:'pending'|'initializing'|'bound'|'expired', sn?, binding_outcome?}   轮询 2 秒
```
P0-B2 上线后 confirm 可带 `child_id`（不带且账号只有一个孩子 → 默认该孩子；多孩子不带 → 400 `child_required`）。

### 3.5 设备实时态 + 今日 / 本周（设备维度）

```
GET /v1/parent/devices/{public_id}/dashboard
   200 {ok:true, data:{
         device:{updated_at_ms, online, lid_open, present, brightness_level 0|1|2|null, color_mode, image_distance_m, image_distance_state},
         today:{focus_minutes, guarded_minutes, posture_alert_count},
         week:{total_focus_minutes, daily_average_focus_minutes, daily:[{date, focus_minutes} × 7]},
         availability:{night_reward:false, percentile:false}}}
   404 not_found（非本家长绑定 / 不存在，统一不泄露）
```
状态组合：`online && present===true` 学习中；`online && present===false` 未学习；`!online` 离线；`present===null` 未知。亮度 0/1/2 = 低/中/高；`led_enabled=false` 显示「关闭」由小程序判断。今日 / 周数值现状「无数据 = 0」，availability 区分见 P0-C1。

- 措辞勘误：PRD / 草案里的「夜航收益 / 昨日方舟收益」是旧世界观说法，G1 正式规则里没有「夜航」结算——收入来自礼包与每日进度。服务端类别按 G1 命名；小程序展示文案（如「昨晚方舟带回 X 家族币」）由产品决定，数据取「昨日全部收入合计」。

**G1 规则要点（服务端照此实现）**
- 逻辑日 = 北京时间 00:00–24:00（与现有 Asia/Shanghai 日聚合一致）。
- 使用日序号：按孩子实际使用日顺序计数（第 1 个使用日 = 首日）；服务端由孩子级 daily（active 日）推得。
- 首日：新手引导 + 新手礼包（一次）；从第 2 个使用日起按使用日序号领每日礼包；礼包表走到最后一条后**循环最后一条**；奖励固定配表、不做随机掉落包。
- 礼包系统只负责资格、领取、发奖，不直接改进度；「首个进度完成」由进度系统按成功事件推进。
- 每日进度：阶段计时（专注时长）→ 阶段奖励 / 金币收取 / 最终奖励；未完成节点锁定态；奖励完整归位后节点才进入完成态（表现层规则，服务端只管结算与状态）。
- 补勤：点击已解锁未完成节点 → 有补勤卡：确认 → 消耗一张 → 补发该日奖励 → 节点完成；无卡：二次确认 → 进入该日进度攒满 → 发奖 → 节点完成。补勤过程结束前节点保持未完成；补勤卡扣除与奖励发放**原子提交**。
- 发奖幂等：每次发放带 `grant_id`（幂等键），重复请求返回首个结果；奖励所属生态缸未解锁 → 「待启用」（游戏内资源，不影响家族币）。

**归属与原则**
- 钱包 owner = `child_id`；余额 / 流水 / 任务 / 约定 / 补勤卡全部以 child_id 为键；家长是操作者不是所有者。
- 收入只由服务端引擎按配表 + 孩子级使用时长产生：`welcome_pack`（新手礼包）、`daily_pack`（每日礼包）、`progress_reward`（每日进度阶段 / 最终奖励）、`task_reward`（家长任务确认）、`attendance_makeup`（补勤补发）、`migration`（老积分迁移）、`adjustment`（后台调账）。**不做「使用 1 分钟 = 1 币」**。哪些 G1 奖励项折算为家族币、各多少 = 配表里的奖励 ID → 家族币映射。
- 支出只有 `promise_redeem`；余额不足拒绝，不负余额、不静默扣到 0。
- 全部写操作事务 + `Idempotency-Key` / `grant_id`；重放返回首个结果，不重复发币 / 扣币。
- 设备不上报经济事件；设备端「领取礼包 / 领阶段奖励 / 使用补勤卡 / 孩子确认约定」是**操作请求**（不是经济数据），走设备凭据通道调服务端奖励事务接口，由服务端裁决与记账（见 P1-1 设备侧经济合同）。设备当前本地钱包与服务端不一致属预期，内测以服务端为准。

## 7. 对草案的合同级反馈（照做会踩的）

1. **配网通道**：草案按「BLE + 手机传 SSID / 密码」建模；生产路径是 SoftAP 两阶段，阶段 A 在设备本地页完成，BLE 是 P1。ProvisioningSession 的 networkStatus / consecutiveNetworkFailures / SSID 列表不在服务端、也不该经过同事服务器。小程序只做扫码 → confirm → 轮询。
2. **经济域来源**：草案 §6.1「业务激励后台」此前不存在，现按拍板 ② 由 cc 服务端新建（§5 P0-E）。字段大体沿用草案，但 owner = child、收入类别改为服务端类别、**没有任何设备事件**、余额 / 达标 / 兑现只认服务端。
3. **账号关系**：草案 §3.3 N:N 关系表简化为 `device.child_id` + 绑定历史；家长 = 账号本人，无多家长与 role / canView 之类授权字段。
4. **时间格式**：epoch 毫秒 + `YYYY-MM-DD`，不用 ISO 8601。
5. **ID 体系**：deviceId = `public_id`；childId = uuid；userId = `acct-NN`；SN 只展示。
6. **错误包 / 分页 / 命名 / 幂等**：按 §3.0；同事服务器不得把失败变 200 空态。
7. **儿童档案两份**：家长侧孩子档 + 设备 brain 档（称呼源）；小程序只读写家长侧；基础三字段自动同步；画像字段不开放。
8. **设备型号 / 固件**：model 无来源先回 null；固件只有 APK 版本名。
9. **周报模型**：P0 即时计算；快照 / 可见窗口 / 建议 / 目标是 P1。
10. **online 阈值**：10 分钟已定；`currentFocusedSeconds` 由服务端事件推算（P0-C2）。
11. 补充：账号默认昵称「家长+尾 4 位」带手机尾号，小程序展示层再脱敏或引导改昵称；`note` 字段不得下发。

## 8. 联调步骤与红线

1. **同事侧先接 §3 现成接口**（走 S2S 基址 + 伙伴登录未上线前先用短信登录透传），把 §1.3 清单填进回执。
2. **cc 上线顺序**：P0-A（A1/A2/A3/A5，A4 内部）→ P0-B → P0-C → P0-E（表 + E1..E4 CRUD，引擎按 §6 开启）→ P0-D → P0-F / P0-G。每项上线给回执（路径 + shape + E2E 证据），同事侧按回执切真数据。
3. **证据格式**：双方回执写清 页面 / 接口 / `X-Request-Id` / 时间戳 / 结果；cc 按请求 ID 对账。
4. **红线**：不把 SN 全文 / 手机号 / JWT / 伙伴密钥写进日志、文档、聊天；小程序包内与同事服务器配置文件外不放任何 cc 密钥；不直连数据库；不用 `/api/admin/*`；余额 / 奖励 / 达标 / 兑现只认服务端结果；小程序不直连设备；不实现 Wi-Fi 密码上传；医疗合规文案只说「记录与守护」。
