> **定稿流程**：team 三发独立撰写 + 三发交叉互评（grok-4.3 / codex gpt-5.5 / gemini-3.1-pro 两轮对抗），cc 整合，川哥拍板（2026-06-10）。
> **阅读约定**：本文是 Web 后台的整合定义层；埋点字段与数据口径细则以 A16 原文为准（见文末附录引用），KidsHub 业务定义以 PRD 功能 15/16/17 为准。本文不重复定义字段，只定义后台「有什么模块、谁来操作、什么约束、为什么服务留存」。

## 一、产品定位与北极星

Web 后台不是纯管理工具，是两台发动机：

1. **留存真相仪表盘**：让团队看见真实的激活与留存（双时钟、闸门 1/2、D30 孩子主动使用占比 ≥40% 生死线），口径错了所有迭代都会修偏（PRD 0.1）；
2. **反馈闭环发动机**：KidsHub 把孩子和家长的真实声音收进来、聚合、决策、回告——没有它，数据只能告诉我们「用户走了」，永远不知道「为什么走」，其余 16 个功能全得盲改（PRD 第四章）。

一切后台模块必先回答：这对留存的贡献是什么？做砸了什么样？

## 二、统一后台架构与业务边界

**一个统一后台，三大模块**（不拆两个系统）：

- **数据看板（看）**：A16 既有 6 页 + 产品运营推导看板；
- **KidsHub 运营台（动）**：反馈闭环的人工操作台，本文核心增量（第六、七章）；
- **运营操作台（管）**：SN/订单与客服工单，保障数据底盘干净（第八章）。

**为什么是一个后台**：数据、反馈、版本、用户、设备、消息中心是同一套业务对象，KidsHub 决策需要用户上下文与激活质量数据，拆两个系统会切断「收集→聚合→决策→回告→状态回写」闭环（PRD KIDSHUB-01）。A16 所写「本数据后台单独制作设计，不依赖其它体系」指**登录账号体系独立**（不接公司权限中台），不是业务上另立门户（A16 §三）。

## 三、角色与权限矩阵

后台从「只能看」升级为「能改状态、能发回告、能动分母」，必须分权。拆 4 类角色，登录页角色自动识别（沿用 A16 账号密码后台配置方式）：

| 角色 | 权限范围 | 核心场景 |
| --- | --- | --- |
| 管理员 | 全局读写 + 账号配置 + 数据导出 | 系统配置、最高决策 |
| 产品经理 | 数据看板（读）+ 主题池复核 + 采纳/金点子库决策 + 版本与致谢 | 版本决策、留存基线监测 |
| KidsHub 运营 | 工单分拣、打标、状态推进、贡献账本、回告发布、复访规则 | 反馈闭环日常运转 |
| 客服专员 | 客服工单池 + SN/订单处理 + 只读看板 | T+5 挽回、退货 SN 清洗 |

**分权红线**：「看数据」「改状态/发回告」「改 SN 分母」三类动作不得混在同一角色——混权会导致数据被误洗或反馈被胡乱采纳。

## 四、数据底座与统一口径

后台所有指标必须遵循统一口径，**后台不许自己发明口径**（A16 数据口径节 + PRD 贯穿性约束「口径四件套」）：

1. 激活率分母用**快递妥投信号**，不用出库数；
2. **毛激活率 / 净激活率（剔退货）/ 激活后 7 天退货率**三数并列报；
3. 退货 SN 从分母剔除且**状态可重置**（翻新二次售出不能直接算已激活）；
4. **双时间戳**（事件实际发生时间 + 数据上报时间），离线补传回溯 ≤7 天；
5. 活跃 = 检测到人在时长单日 ≥15 分钟；有效使用 = 收益领取 + ≥1 次互动；家长开盖不结算夜航（A16 统一口径）。

## 五、数据看板（承接 A16 既有定义）

**A16 既有 6 页全保留**：登录页 / 数据概览（指标卡+趋势+型号与状态分布+全国地图）/ 单用户查询 / 全部用户列表 / 统计页面 / 日期范围查询（A16 §三-§十一），加上 A16 §4.3 产品运营推导看板（激活双指标漏斗 / 首日体验分与 D0×D1 四象限 / step_satisfaction 覆盖率与正向率 / 首周有效使用日达标率 / 业务看板入口）。

**本次整合的增量**：

- **单用户详情页新增「KidsHub 状态区」**：该用户当前等级、总贡献值、历史建议清单与采纳状态——把行为数据和反馈数据放进同一张用户画像（这是统一后台的直接收益）；
- 推导看板与 KidsHub 度量看板（第六章）共用聚合层，前端只渲染（A16 待开发项 §1/§2）。

**留存逻辑链**：让团队看见留存真相；做砸了 = 对着被家长代操作污染的假数据自嗨（PRD 0.1 + A16 读数纪律）。

## 六、KidsHub 运营台 ⭐（核心增量）

KidsHub 的本质：**GitHub 的协作骨架 + 游戏化的儿童表达层**（PRD 功能 15）。前台（设备端）是孩子能理解的语音、鼓励、署名；本章定义的是云端协作后台——结构化收集、真实推进、持续反馈。

### 6.0 解耦总纲：「回应」与「真改」是两条独立链路

- **即时回应链（全自动，无人工参与）**：孩子提交 → AI-01 当场生成共情话术（「我听到啦、记下来啦」）→ 状态自动置「已收到」。这条链路不等运营上班，永不承诺「马上改」；
- **异步决策链（人工拍板）**：后台攒同类反馈 → 运营打标聚合 → 攒够阈值 → 产品决策采纳 / 进金点子库 → 致谢与回告。

这是 PRD 功能 15 关键约束「回应与是否真改解耦」的系统化落地——情绪价值即时到位，版本决策从容攒样本。

### 6.1 跨端反馈工单台

- **做什么**：统一接收三路反馈——孩子语音建议（含音频与 ASR 文本）、家长周报内回答、流失拦截答卷；列表呈现来源端 / 情绪极性 / 主题 / 状态；
- **操作者**：KidsHub 运营；
- **关键约束**：原始记录不可丢；**每条必须带来源端标签（孩子 / 家长）**，共用主题池但不混源（PRD 功能 16 边界）；
- **留存逻辑链**：先把「为什么走」收上来；做砸了 = 意见箱石沉大海，其余功能全是盲改（PRD 功能 15/16）。

### 6.2 正向状态机台

- **做什么**：推进工单状态：已收到 → 评估中 → 已采纳 / 已进金点子库；
- **操作者**：运营推进，产品定终态；
- **关键约束**：**界面上不存在「拒绝 / 关闭 / 驳回」按钮**——全正面态是产品红线不是文案技巧（PRD 功能 15 + KIDSHUB-01 约束②）；单条全链路可查、可审计、可回看；
- **留存逻辑链**：「说了有回音」是孩子继续开口的前提；做砸了 = 一次负面终态就能浇灭表达欲。

### 6.3 主题池（双标签聚合）

- **做什么**：按「情绪极性 + 主题」双标签聚合，同类合并看量级，攒够阈值进版本决策；
- **操作者**：运营初分打标，产品复核；
- **关键约束**：AI 标签仅是建议（见 6.9）；**人工打标是 P0 合格降级**——AI 聚类赶不上不阻塞上线；
- **留存逻辑链**：不聚合就无法从个体吐槽变成版本决策（PRD 功能 15「收集后台」）。

### 6.4 贡献账本

- **做什么**：工单被采纳时，运营人工评质量并记入贡献值 / 等级 / 署名（署名优先复用家长激活时录入的孩子昵称）；
- **操作者**：KidsHub 运营；
- **关键约束**：**按「被采纳的质量」驱动、不按提交数量；不发物质奖励**（防灌水，PRD 功能 15）；KidsHub 默认不发补勤卡（与道具体系解耦，PRD D1-7 横切约束）；
- **留存逻辑链**：沉没成本——贡献值越攒越离不开（PRD C3）；做砸了 = 高贡献孩子留存无抬升，机制白做。

### 6.5 金点子库

- **做什么**：暂不采纳建议的正面归宿；支持翻牌、月度回顾、主题征集时回捞进版本池；
- **操作者**：产品 / 运营；
- **关键约束**：不是回收站，是下期版本候选池；持续盯「金点子库 vs 已采纳比」防止沦为婉拒垃圾桶（PRD 功能 15 质性信号）;
- **留存逻辑链**：「你的点子进了金点子库」让未采纳也是被珍视；做砸了 = 变相拒绝，表达热情熄灭。

### 6.6 版本决策与致谢

- **做什么**：采纳后打「小改 / 大功能」分级 +「规划中 / 开发中 / 已上线」阶段标记；升版时自动生成更新说明致谢名单（含孩子署名）；
- **操作者**：产品主责；
- **关键约束**：孩子端署名与状态展示归功能 15；家长端回告走第七章（功能 17）；
- **留存逻辑链**：「我说的话真的变成了产品」是 KidsHub 最强的高光时刻（PRD 场景④）。

### 6.7 复访触发台（孩子端，L1-L4）

- **做什么**：执行 PRD 功能 15 四级降级规则——L1 入口冷启动（1 周 0 进入→完成专注后弹引导）/ L2 提交后 24h 未查看→派小可在下次主线场景开口 / L3 14 日未提交→出航/破冰里软触发 / L4 等级停滞→转用户访谈流程；后台管规则配置与触发记录；
- **操作者**：系统触发 + 运营查看与调参；
- **关键约束**：**不走推送、不走家长 App**，只在设备端主线场景由小可开口（PRD 功能 15 复访闭环）；
- **留存逻辑链**：防沉睡——KidsHub 不能是一次性玩具（PRD C1 月活提交率）。

### 6.8 流失拦截台（家长端，与复访触发台分开）

- **做什么**：活跃度规则命中流失风险 + 30 天频控 → 给家长推软化单选题；按答案即时分流挽回（嫌没用→解读 / 太贵→搬家券 / 不会用→教程）；答案写原始记录并归并主题池；
- **操作者**：系统触发 + 运营配置规则与挽回内容；
- **关键约束**：30 天频控；必含「只是暂时没空」选项；未作答只记标记不追问（PRD 功能 16）；
- **为什么与 6.7 分开**：孩子复访走设备端小可、家长拦截走小程序推送——触达通道、对象、话术完全不同，杂糅会互相污染频控。

### 6.9 AI 辅助边界（AI-01 在后台的角色）

- **AI 做**：情绪极性识别、主题标签建议、聚类建议、即时回应话术生成、大功能预告文案草稿；
- **人拍板（AI 绝不代劳）**：**采纳决策、终态推进、版本决策、回告发布**——影响用户信任的动作必须人负责（防过度承诺反噬信任，对应小可规格 B.4 幻觉控制同源逻辑）。

### 6.10 KidsHub 度量看板【P0】

- **做什么**：孩子侧漏斗（曝光→进入→开口→提交→查看状态→再次提交→升级）；家长侧漏斗（小程序 PV → KidsHub 主页 UV → 家长访问后孩子 7 日提交率）；金点子库 vs 已采纳比；高/中/低/零贡献分层 30/60/90 日留存曲线；
- **操作者**：产品 / 数据分析；
- **关键约束**：分层自然观察，本版不做 A/B（PRD 功能 15 验证方法）；
- **为什么 P0**：KidsHub 是 P0 功能，验证手段不能晚于功能本身——两道闸门（单次贡献闭环可追踪 / 留存价值兑现）没有看板就无法判定。

## 七、回告路由台（功能 17 专区）

**边界铁律：本章只管家长端定向回告 + 全体公开预告；孩子端回告、播报、状态展示、署名一律归功能 15（第六章），不在此重复。**

- **改动分级路由**：小改·已上线 → 按来源用户 ID 定向推给当初提建议的家长（48h 内）+ 落小程序消息中心可重看；大功能·规划中/开发中 → 公开预告进周报首页 + 设备开机预告位（话术「在做」，不说「已改好」）；
- **送达回写与未达兜底**：回写送达/打开状态；推送 7 天未打开 → 周报二次提醒 + 消息中心常驻红点；
- **措辞模板**：「因为你的建议，小可又进化了」+ 改后对比图（共创化，眼见为实）；
- **亲子纽带联动**：家长代提且关乎孩子的建议被采纳 → 本台仅触发联动条件，孩子端「爸爸/妈妈的心意」展示由 KidsHub（功能 15）承载；
- **留存逻辑链**：「你说的→我们听到了→真的改了」；做砸了 = 反馈石沉大海，比不收集更伤（PRD 功能 17）。

## 八、运营操作台

### 8.1 SN 与订单管理（ACT-01）【口径 P0 · 操作台 P1】

- **口径 P0（聚合层自动生效）**：退货 SN 自动从激活率分母剔除——这是数据正确性问题不是运营功能，P0 不生效则首发数据全脏；P0 期间退货名单由订单系统导入兜底；
- **操作台 P1（人工界面）**：呆滞标记、SN 状态重置（翻新二次售出）、换绑解绑的人工操作页——低频运营动作，P1 上线不影响 P0 数据正确性；
- **留存逻辑链**：清洗脏分母；做砸了 = 呆滞退货机把净激活率全盘污染，永远看不到那批从没上线的设备（PRD 贯穿约束「订单与设备打通」）。

### 8.2 客服挽回工单池（功能 3）【P1，P0 过渡方案见下】

- **做什么**：接收 T+5 仍未激活/未真用的设备名单；列表带**蓝牙上报的本地错误日志**（区分「卡配网」vs「激活了但孩子没真用」）；客服记录外呼挽回结果；
- **操作者**：客服专员；
- **关键约束**：外呼前必看错误日志，话术按卡点精准（PRD 功能 3 L4）；
- **P0 过渡方案（已拍板）**：P0 期间用「未激活名单每日导出 excel」过渡（复用 A16 §八数据导出能力），客服线下跟进；工单池界面 P1 交付；
- **留存逻辑链**：赶在 7 天退货窗口前干预；做砸了 = D0 问题被伪装成「孩子不留存」。

## 十、风险与验收

- **验收闸门（沿用 PRD 功能 15 两道闸门）**：① 单次贡献闭环可追踪——一条反馈从提交到终态全链路状态机可见、可拉回、不漏；② 留存价值兑现——KidsHub 活跃孩子 30/60/90 日留存显著高于低/零贡献孩子 + 上线后留存切片较基线 ≥5 个百分点。两道同过才算达标；
