## 一、九个对账点终裁（R2 互评后共识）

| # | 对账点 | 终裁 | 票型 |

| 1 | **积分 vs 家族币（头号冲突）** | **保留底座、切换口径、统一叫家族币**：现有积分页/账本/奖励列表/兑换记录全复用；**停用「1 分钟=1 积分」时长产出**，产出来源改为夜航收益/迎新礼/任务；老余额 1:1 迁移标记「历史积分迁移」；「创建奖励」改名「新建亲子约定」（内置 5-6 个模板）；兑换升级为 PRD 三段状态机（达成→孩子确认→提醒家长→线下兑现→已兑现，24h 未接住转待兑现+系统安抚）；家族币永不清零、无审批流 | 3/3（互评确认「真切断时长诱导，非换皮」） |

**cc 驳回的两处互评误判**（有 PRD 原文证据）：
- gemini 指控「未激活 T+1/3/5 提醒是 PRD 外编造」——**误判**：PRD 功能 3 原文「未激活提醒按 T+1/T+3/T+5 分级、扣除周末权重」；
- gemini 指控「配网客服介入是臆造」——**误判**：PRD 功能 3 L4 原文「T+5 后人工客服上场，带蓝牙上报的本地错误日志」。
两项均保留在方案内。

## 二、整合后信息架构（五 Tab · 页面级 · 标注状态）

### Tab 1 首页【改造自「设备」】
- 孩子状态卡：昵称 + 学习中/离线状态【保留】
- 设备状态卡：亮度/色温/像距 + VID 静态指南入口 + 操作指南【保留】
- **夜航收益快捷透出**：「昨晚方舟带回 X 家族币」+ 一键去兑换【新增】
- 今日专注 / 本周平均 / 本周柱状图【保留】+ **今日护眼守护次数（坐姿提醒）**【新增】
- **生态缸最小可感知变化快照**（24h 首变/3 天差一点长大，PRD 功能 7 家长可见）【新增】
- 顶部消息铃铛（红点）【新增】；未连接/未建档引导态【保留】

### Tab 2 周报【新增 · 价值报告中心】
- 本周高光 + **护眼硬数字**（守护 X 次 + 用眼时长 + 视光趋势摘要）【新增】
- 一个问题 + 可操作解法（报忧必配解法）【新增】
- 亲子小目标【新增】
- **历史报告详情页**：吸收 V2.0 记录&分享规划（按小时柱状图/使用日历/周月记录/视力折线）【规划吸收】
- **弱召回位**：断档 ≥7 天在周报末尾插「生态缸快干涸了」，不单独推送【新增】
- 就地反馈入口（针对具体结论提问）【新增】
- 分享卡（隐私保护版：默认隐藏儿童姓名头像）【规划吸收】
- 分层推送：爱看的加喜报、长期不看降频改「小可求助信」（并入周报体系不单独发）【新增】

### Tab 3 兑换【改造自「积分」】
- 家族币余额 + 来源摘要（夜航/任务，不再显示时长产出）【改造】
- 亲子约定（预设合同）：5-6 个内置模板 + 自定义【改造自创建奖励】
- 目标进度条【新增】
- **待兑现提醒区**（孩子已确认、等家长线下兑现；24h 未接住显示系统安抚状态）【新增】
- 已兑现打卡流 / 家族币记录 + 兑现记录【改造自兑换记录】

### Tab 4 KidsHub【新增 · 家长主页】
- 孩子贡献时间线（建议内容 + 全正面状态：已收到→评估中→已采纳/进金点子库）【新增】
- 当前等级 + 昵称署名 + 已采纳条数【新增】
- 金点子库进度【新增】
- 「因为孩子的建议，小可进化了」高光卡（接功能 17 联动）【新增】

### Tab 5 我的【保留 + 归口】
- 个人中心（头像/昵称/手机号/退出）【保留】
- 孩子管理（档案 + 身体数据/近视度数 + **预设称呼=小可称呼源** + 家族币记录）【保留+改造】
- 视光报告（手动录验光单，喂周报）【保留】
- 设备管理（改名/型号/SN/移除 + **坐姿采样间隔滚轮配置** + 场景参数预设下发）【保留+新增】
- **消息中心**（所有回告/夜航助攻/兑换提醒/定向改进回告落点，可重看，常驻红点）【新增】
- 设置（权限/隐私管理、时长提醒机制 20/30/45/60min）【规划吸收】+ 使用帮助【保留】

### 模态/推送（非 Tab）
- 夜航助攻：微信模板消息每天 ≤1 条（早晨）【新增】
- 流失拦截：30 天低活 + 30 天频控，打开小程序时软弹窗单选（含「只是暂时没空」即关）【新增】
- 兑换确认推送：孩子确认兑换时同步提醒家长【新增】

## 三、P0 / P1 切分

**P0（6.30 · 7 件事，全部是改造或 PRD 必须项）**：
1. 家族币改造：停时长产出 + 口径切换 + 1:1 迁移 + 三段状态机 + 「新建亲子约定」；
2. 首页改造：夜航收益透出 + 护眼守护次数 + 生态缸快照；
3. 周报基础版：高光 + 护眼硬数字 + 弱召回位（吸收记录&分享骨架）；
4. KidsHub 家长主页基础版：时间线 + 等级 + 署名；
5. 消息中心基础版（回告落点，红点）；
6. 夜航助攻推送（≤1 条/天 + 夜间静默）；
7. 配网增强：异步建档 + 跳过 + 随机昵称兜底 + 双闸门埋点 + T+1/3/5 提醒。

**P0 降级预案**：流失拦截软弹窗如赶不上 → P1 首项（互评分歧点：grok 主张 P0，codex/gemini 接受 P1——cc 倾向 P0 末位、可降级）。

**P1（7.30）**：流失拦截完整答题页 + 即时分流挽回（解读/搬家券/教程）；反馈定向回告完整闭环；视光报告深度融入周报（折线+交叉建议）；VID 智能建议升级（按视力档案动态推荐）；分享卡朋友圈/小红书渠道；坐姿参数细化；多设备切换（V2.0 规划）评估。

## 四、互评红线检查结论

- 「时长换积分」：三家方案均**真切断**（停产出，非改名）✅
- 家族币永不清零/无审批流/不代付：全合规 ✅
- KidsHub 全正面态：全合规 ✅
- 推送纪律：夜航 ≤1 条/天、弱召回并入周报、30 天频控、夜间静默、回告落消息中心——终稿全部显式写入；「7 天未读二次提醒」明确走**下期周报**而非额外推送（互评修正）✅
- 设备控制：终稿不做实时遥控，只做「参数预设下发 + 设备端确认」❗待你终裁（拍板项 1）

## 五、待川哥拍板项

1. **LED 远程控制**：V2.0 表格里是 P0 需求（开关灯+三档亮度+三档色温），但 PRD 附录 C.5 写了「不直接控设备实时交互」。team 终裁推荐「场景参数预设下发、设备端确认执行」折中。**你拍：a. 接受折中（改 V2.0 表格）/ b. 允许实时遥控（改 PRD C.5）/ c. 其他**；
2. **视光报告喂周报**：这条数据线是整合新增（PRD 13 未明确写视光数据），互评提示「潜在编造」——cc 认为是现状资产的合理利用，但要你确认；
3. **「小未→小可」改名范围**：唤醒词/语音词库/UI/「小未AI 规划」文档全改？工程影响需要你和 AI 团队确认节奏；
4. **多孩子/多设备**（V2.0 规划「切换读写台」P2 + 现状一账号一娃一机 + gemini 提示二胎家族币账本纠缠）：P1 评估还是明确延后？
5. **方案落点**：拍板后写入哪——升级 CD83《家长端小程序规格》为完整版小程序产品定义？还是新开文档（与多维表格 Feature List 并行维护）？
