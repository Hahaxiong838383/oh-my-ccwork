## 经验与证据边界

| 容易误判的地方 | 本次证据与后续做法 |
|---|---|
| 服务器 active 就认为手机应当能连 | 家庭2443回包不可达，第三地2443可达、SSH转发原认证成功；区分进程、TCP、认证、目标载荷和客户端实际使用 |
| 服务端发了 SYN-ACK 就认为客户端收到了 | 两侧包头取证，并用同接口可达22端口作正对照；只定位丢包区间，不断言具体运营商、封禁设备或触发原因 |
| 换端口成功就认为永久修好 | 14443复用同一后端；属于增加可用入口。跨IP、跨协议候选配合客户端真实请求检测才能降低再次中断的影响 |
| 给路径故障换密码、SNI或重启后端 | 故障在认证前，原凭据经SSH隧道成功；最小变更只增加入口，旧PID、配置SHA和监听前后保持 |
| 自启等于端到端自愈 | enabled未经过本轮VPS重启；After只排序，Restart=on-failure只处理转发主进程失败，不检测远端可用性或切节点 |
| HY2端口监听或ADB不通就判断电视正常/故障 | 监听只证明服务状态，用户确认电视关机后跳过；手机恢复不能代替电视DNS、实际选路与播放验收 |
| 电视端只改config就能永久切端口 | 旧九文件启动事务仍校验SHA；未来迁移需覆盖主代理、DNS和fallback引用并同步事务/manifest/回退组，避免下次启动拒绝 |
| 探针进程没起来也记成节点失败 | memfd或无扩展名Xray配置显式指定-format json；先确认探针启动，再判断网络；临时进程按PID精确清理 |
