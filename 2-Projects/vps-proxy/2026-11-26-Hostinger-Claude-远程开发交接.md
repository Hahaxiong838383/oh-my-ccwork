# Hostinger Claude 远程开发交接 · 2026-11-26

## 从桌面继续

MacBook Air 和 maxtkf Windows 均双击「Hostinger Claude」。启动器使用本机密钥验证 Hostinger 主机，通过 DMIT 直出节点进入普通用户的同一 tmux 会话。已从两端的实际快捷入口依次接入，核对了节点端口、服务端收到的 SSH 源地址以及同一个 Claude 进程。关闭本地窗口后可接回仍在运行的会话；这次验收覆盖客户端断线和换机，未覆盖 VPS 重启。

07:33（北京时间）最后一次观察时，没有终端连接，Claude 正停在首次启动的主题选择页等待输入。回到该界面后按 Enter 确认主题。使用者自行完成 Claude 授权。

## 线路分工与实测

客户端只为这条 SSH 连接临时拉起本地 Xray，退出后释放监听，无需手工切换系统代理。DMIT 新直出、原有绑定 Proxy302 的节点，以及经丽萨的中转各自独立。Hostinger 上的应用继续使用自身的 HTTP 代理配置。Tailscale 已用作私网管理入口。具体地址、端口和本机恢复路径见私有共享记忆的 `project/Hostinger-Claude` 条目。

以下为 maxtkf 到同一台 Hostinger 的交替采样，单位为毫秒。P90 表示九成按键在该时间内收到远端回显。

| 测试批次 | 路线 | 有效按键 | 中位数 | P90 |
|---|---|---:|---:|---:|
| DMIT 新节点对照 | DMIT 直出 | 36 | 272 | 283 |
| 同批 | DMIT 经丽萨 | 36 | 279 | 291 |
| Tailscale 入网后 | DMIT 经丽萨 | 30 | 276 | 291 |
| 同批 | Tailscale UDP 直连 | 30 | 534 | 662 |
| 同批 | 公网直连 | 30 | 596 | 1094 |

DMIT 新节点上传 13.2–13.9 Mbps、下载 9.3–11.6 Mbps。每个方向测两次，以随机 4 MiB 文件通过 SFTP 往返并校验哈希。新节点省去中转，和经丽萨的打字中位数仅差 7 ms。这些数字反映当时的 Windows 网络；Air 只验了实际选路和接续。线路变慢时按 [Xray 技能的回显测法](../../.claude/skills/xray/SKILL.md)重新采样。

## 登录前的验收边界

| 已验证 | 继续操作 |
|---|---|
| Claude Code 2.1.326 已运行。请求抵达 Anthropic API，未认证请求收到 401。 | Claude 授权后用一个真实请求验收。 |
| Git、gh 已安装，GitHub HTTPS 可以读公开仓库 HEAD。检查时 gh 的用户认证失败。 | 为目标私库授予所需权限，再核对登录身份和目标仓库访问。 |
| 当前工作目录为空，Git 无法生成提交作者身份。 | 确定目标仓库与提交署名，配置 Git 姓名和邮箱，再在仓库中工作。 |

首次授权后的换机验收可用一个只读问题：从一端让 Claude 读取项目中的指定文件，另一端接回并追问刚读到的内容。交接时尚未执行这一步。
