## 实测结果

同一台 X96 X10Pro、同一个 ZGO 出口 `38.49.38.237`，电视内 Java HTTPS 探针经过两个独立回环 SOCKS 入口；正文不经 ADB 传回电脑。下载20MB、上传10MB、1KB小请求，各3轮，串行交替。所有有响应的 Cloudflare 请求均命中 LAX。

重启、校时后的完整一轮（10:41–10:43）：

| 项目 | ZGO Reality | ZGO HY2 |
|---|---:|---:|
| 下载中位数 | 12.6 Mbps，3/3成功 | 30.8 Mbps，3/3成功 |
| 下载各次 | 21.75 / 9.09 / 12.56 Mbps | 33.88 / 25.34 / 30.80 Mbps |
| 上传中位数 | 24.2 Mbps，3/3成功 | 无有效中位数，0/3成功 |
| 上传各次 | 22.65 / 28.96 / 24.19 Mbps | 三次 Connection reset |
| HTTPS响应头中位时间 | 995 ms，3/3成功 | 465 ms，3/3成功 |

HY2下载中位数约为Reality的2.45倍，响应更快；但这不等于整体可靠性更好。统计为含建连开销的单连接有效速率，非VPS峰值；HTTPS响应时间不是ping。HY2可以复用QUIC，Reality未启用multiplex，因此比较的是当前部署的实际体验。

首轮10:38–10:39：Reality下载16.82/16.74/16.81 Mbps；HY2一轮连接关闭，另外两轮25.00/38.00 Mbps。首轮末尾受电视整机重启干扰，6个无JSON样本无效，紧邻重启的上传reset原因未分离，不与完整轮次混算。10:38较早的连接关闭不能归咎于10:39的重启。

进一步服务端debug复核：新连接上传可以成功（28.91、27.16 Mbps），随后仍能复现下载TLS连接关闭及上传reset；说明不是所有HY2上传均不可用。新服务没有异常退出。缓存QUIC连接关闭竞态仅为源码支持的候选解释，尚未证实；不据此调整keepalive或宣称故障已修复。debug已恢复warn。

## 测试期间发现的设备问题

电视于10:39内核崩溃并重启。两项bootreason均为`kernel_panic,null`，pstore文件时间10:39:37.973，与重启后uptime相符。崩溃为地址0x240空指针访问，调用链：

`config_pic_size_fb → vav1_isr_thread_fn → av1_threaded_irq_cb`，模块 `amvdec_av1_fb_v4l`，最终 `Fatal exception`。

这定位到AV1硬解驱动崩溃现场，不能证明由Netflix或HY2触发；本轮未更改固件、解码设置或视频App。

重启后系统时间回到2024-02-28，实际HTTPS出现Chain validation failed。已按NTP同步的home-studio校时，最终时差1秒，Android NTP cache随后恢复有效。没有关闭TLS证书验证。再次冷启动是否重复时钟问题未验证。
