# Display Warp POC — 外屏整画面畸变校正

## 目标

把“看起来像图像拉弯”转换成可验证的完整工程闭环：

```text
内容空间扩展 → 光学逆映射 → 屏幕捕获 → GPU Warp → 目标显示器回显 → 客观验收
```

默认优先实现最小可行 Demo，再接真实玻璃和目标硬件。

## 第一步：钉死目标口径

先判断用户要哪一种结果，不能混用：

| 模式 | 目标 | 代价 |
|---|---|---|
| 安全矩形 | 在畸变区域内找最大内接矩形 | 稳定，但浪费边缘区域 |
| 全 Footprint | 使用完整反射或投影区域，同时保持内容方正 | 需要扩展画布和更完整标定 |

用户出现“全部用上、用满、不裁边、完整屏幕都显示”等表达时，默认选择 **全 Footprint**。此时必须支持输入源短边扩展，不能只做缩放或裁剪。

## 核心模型

### 三个空间必须解耦

1. **内容空间**：虚拟画布，可手动增加短边尺寸。
2. **物理输出空间**：真实显示器分辨率。
3. **观察空间**：经过玻璃反射、曲面或投影面后的人眼/相机结果。

正向光学映射记为 `O = F(P)`，预畸变需要计算逆映射 `P = F⁻¹(O)`。实现时优先用目标像素反查源 UV，避免正向 splatting 产生空洞。

### 标定模型选择

| 阶段 | 推荐模型 |
|---|---|
| 快速模拟 | 参数化弧线、梯形、倾斜和不对称 |
| 稀疏实拍控制点 | TPS/RBF |
| 规则相机模型 | OpenCV 相机标定与透视/畸变模型 |
| 实时渲染 | 预计算 UV 网格 + Metal/OpenGL Shader |

## 三阶段实施法

### 阶段 A：离线算法闭环

产出以下图像：

- 扩展虚拟画布；
- 未校正观察结果；
- 物理屏预畸变图；
- 校正后观察结果；
- Footprint mask；
- 误差热力图；
- 验收 JSON。

门槛至少包含：有效内容覆盖率、平均误差、P95 误差、UV 越界比例。

### 阶段 B：双窗口交互 Demo

- 内屏：控制参数和内容画布尺寸。
- 外屏：全屏显示预畸变结果。
- 参数实时同步，允许切换未校正、预畸变和校正结果。

此阶段验证体验，不要宣称已经“接管整个外屏桌面”。

### 阶段 C：原生整屏 Warp

macOS 推荐：

- ScreenCaptureKit 捕获目标外屏完整桌面；
- `SCContentFilter` 排除当前应用，防止同屏递归回采；
- Metal 网格 Shader 做实时 UV Warp；
- 无边框高层级窗口覆盖外屏；
- 覆盖层 `ignoresMouseEvents = true`；
- 普通 `NSWindow` 控制台放在内屏。

## macOS 实现纪律

### 屏幕识别

- 用 `CGDisplayIsBuiltin` 识别内屏。
- 不依赖 `NSScreen.screens` 顺序。
- 区分 points 与 pixels，Retina 缩放下两者不相等。
- 接受外屏坐标为负数。

### 防递归捕获

同一块屏幕既是捕获源又是输出目标时，必须排除当前应用。连续截图应保持稳定，不能出现逐帧缩放、重复窗口或亮度累积。

### 权限与签名

Screen Recording 权限和应用代码身份绑定。开发构建至少固定：

- Bundle ID；
- designated requirement；
- App 路径；
- 可执行文件名。

否则每次 ad-hoc 重建都可能触发重新授权。正式交付改用 Developer ID + notarization。

### 窗口与启动

- 控制台优先用普通 `NSWindow`，避免 `NSPanel` 在 Space/失焦后不可见。
- 需要时使用 `orderFrontRegardless()` 并激活应用。
- 本机 `.command` 启动器优先直接 `exec` App 二进制；不要把 `open` 成功等同于进程持续运行。

## 阶段 1 标定与安全控制

### 坐标链路必须单一

桌面纹理和标定测试图必须复用同一套镜像与 Warp 坐标函数。推荐顺序：

```text
物理像素 → AA 区归一化 → 镜像 → Warp 逆映射 → 内容采样或测试图着色
```

禁止测试图在镜像前从 Shader 提前返回。否则会出现桌面镜像正确、网格镜像无效的双口径缺陷。

### 测试图必须可判方向

规则网格和矩形边界具有对称性，不能单独证明镜像是否生效。四角必须加入不同颜色或编号的非对称角标，并验收不镜像、水平、垂直和双向四种组合。

### 抗锯齿与性能保护

- 关闭档保留单点采样，用于性能基线和问题定位。
- 性能档使用少量自适应采样，作为高分辨率日常默认。
- 质量档使用更多采样，用于静态标定和质量对比。
- 自动降级只改变运行时有效档位，不覆盖用户保存配置。
- 不能只看 FPS；至少记录 GPU 平均、GPU P95、CPU 和 10 分钟 RSS 趋势。

### 安全恢复

- 建立可校验回滚点，包含源码、配置、SHA-256 和只读演练脚本。
- 暂停、紧急隐藏、外屏断开、休眠和分辨率变化必须先隐藏覆盖层，再停止或重建资源。
- `⌘⌥Esc` 是 macOS 保留组合，紧急隐藏改用 `⌃⌥⌘Esc` 或其他确认未占用的组合。
- 安全动作必须同步覆盖层、控制台按钮和状态文字，禁止 UI 与真实运行状态分叉。
- 显示器变化后重新用 `CGDisplayIsBuiltin` 把控制台定位到内屏。

### 配置版本化

- 参数应用前保留当前版本；历史数量设上限。
- 预设至少绑定外屏像素尺寸，分辨率不匹配时拒绝直接应用。
- 后续应绑定 EDID、玻璃、观察位和标定日期，避免跨硬件误用。

## 验收清单

### 算法

- [ ] 全 Footprint 有效内容覆盖率 ≥ 99%。
- [ ] 平均误差和 P95 误差低于项目门槛。
- [ ] UV 越界比例接近 0%。
- [ ] 增加画布短边后仍通过。

### 系统

- [ ] 外屏桌面、菜单栏和全部窗口被整体 Warp。
- [ ] 内屏控制台可见并可实时调参。
- [ ] 当前应用被捕获过滤器排除。
- [ ] 连续截图无递归回采。
- [ ] 输出窗口和控制窗口位于正确显示器。
- [ ] 目标帧率下 CPU、RSS、日志无异常。
- [ ] 重建后屏幕录制权限不反复失效。
- [ ] 网格、边界、中心线和角标在四种镜像组合下方向正确。
- [ ] 关闭、性能、质量三档抗锯齿可切换，性能不足时安全降级。
- [ ] 全局紧急隐藏不与 macOS 保留快捷键冲突，UI 状态同步。
- [ ] 外屏拔插、休眠、唤醒和分辨率变化时先隐藏再重建。
- [ ] 回滚点校验通过，配置恢复 `--dry-run` 不修改当前 defaults。

### 用户

- [ ] 完整显示模式没有退化为最大内接矩形。
- [ ] 边缘内容可见，文字和直线在观察空间保持可读。
- [ ] 明确说明视觉接管与输入接管的区别。

## 反模式

- 用户要完整利用，却仍按最大内接矩形裁边。
- 只扩大输出窗口，不扩大内容画布。
- 只做浏览器全屏，却宣称处理了其他应用窗口。
- 同屏捕获未排除自身。
- 只看一张截图，不检查连续帧稳定性。
- 用对称网格判断镜像，未增加方向角标。
- 测试图在 Shader 中提前返回，绕过正式画面的镜像或 Warp 链路。
- 只看平均 FPS，不看 GPU P95 和长时间 RSS。
- 使用 macOS 保留快捷键承担紧急恢复。
- 紧急隐藏后不更新控制台状态。
- 每次构建改变代码身份，导致 TCC 权限失效。
- 把鼠标穿透误认为点击坐标已校正。
- 把模拟光学参数误称为真实玻璃标定。
- 把含用户桌面内容的截图提交进仓库；实机截图默认只放 `/tmp`。

## 交付格式

最终输出必须包含：

1. **实施方案**：内容、光学、系统三层架构。
2. **运行入口**：一条可执行命令或双击启动器。
3. **预期效果**：明确安全矩形或全 Footprint。
4. **验收结果**：算法指标 + 实机证据 + 性能状态。
5. **诚实边界**：真实玻璃、目标硬件、输入逆映射分别是否完成。
6. **下一步**：固定机位实拍标定、配置化控制点和目标硬件验证。
