# F5 · 长任务后台句柄（两阶段 yield）——设计与验收契约

> 出处：penguin-harness 调研报告 §7（`1-Inbox/2026-07-26-penguin-harness调研报告.md:92`）。
> 范式：固定窗口内正常等待；窗口到期任务还在跑 → 注册后台注册表、回「进行中」卡附句柄；
> 完成自动推送；**轮询/新消息绝不杀后台任务**（penguin 纪律，红线）。

## 一、完成后的预期效果（川哥可感知的六条）

1. **长任务不再干等**：任务跑超 ~2 分钟（`H_BG_YIELD_MS`，默认 120s）自动转后台，
   卡片落定为「⏳ 已转后台 · 任务 #ab12 · 完成后自动送达」。会话立刻解锁。
2. **后续消息即时响应**：转后台之后你再发消息，不再排在长任务后面干等
   （此前 session 串行，长任务把整条会话堵死——路宁体验差的一半根因）。
3. **完成自动推送**：结果卡标「✅ 完成 · 后台任务 #ab12 · 总耗时」，对得上号。
   失败也推（标句柄+原因），不静默丢。
4. **「进度」随时问**：网关代答（不进引擎），列在跑/最近完成的后台任务：句柄、
   已跑时长、任务摘要。查进度绝不影响任务本身。
5. **「停 #ab12」精确停**；「停」保持现语义（停当前前台任务）。
   **停新任务绝不误杀后台任务**（这是本次最大的工程雷区，见 §三-2）。
6. **重启诚实**：bridge 重启会杀 child 进程——启动时扫描未完成的后台任务，
   推「任务因服务维护中断，请重发」卡，不静默吞。

边界（明说）：
- **owner 默认不启用**（零影响铁律）；`H_BG_YIELD_OWNER=1` 可开，川哥验收后再定。
- 引擎任务预算不变（8–45min 档位照旧）——F5 改的是**等待体验**，不是任务时长上限。
- 转后台后新任务与后台任务**同 cwd 并发**（引擎各自 spawn），有文件竞态可能：
  新任务开始卡带一行「⚠️ 后台还有 #ab12 在跑」提示。这是既有 GROK_QUEUE_TIMEOUT_MS
  机制的同款语义（作者已接受），F5 只是把它变成用户可见可控。
- 群聊暂不启用（流式卡本就单聊 only，转后台卡片语义同群里多人会混乱），单聊先行。

## 二、cc 怎么验证（实施无误的证据链）

1. **单元**：注册表（句柄唯一/注册/完成/列表/落盘恢复 orphan 标记）、
   yield race（快任务不转后台、慢任务转、转后台后完成回调只送达一次）、
   child 级停止（停 A 不碰 B、close 判定不误标）。
2. **全量回归**：bridge 158+ / 控制面 98+，一条不许挂。
3. **对抗 review**（≥3 lens）：①「停」误杀/误标后台任务的时序窗口
   ②双送达（前台已回、后台又推）与零送达 ③重启恢复的漏报/重报。
4. **dev198 集成 E2E**：fake runner（可控时长）走真实注册表+race+送达全链。
5. **真机边界**：真实飞书长任务需要用户真实消息触发（不烧订阅额度自测）——
   这最后一厘米就是川哥的验收剧本（§三），验到「集成全链」为止交棒，说清楚。

## 三、川哥怎么验收（5 分钟剧本，对你任一 user Bot 单聊）

1. 发：「跑个长任务：sleep 150 秒之后输出 done-F5」
   → 先出现流式卡；**约 2 分钟时**卡片变「⏳ 已转后台 · 任务 #xxxx」。
2. **立刻**再发：「1+1 等于几」→ 应很快回答（不再等前面的长任务）。
3. 发：「进度」→ 列出 #xxxx（在跑 · 已 X 分钟 · 任务摘要）。
4. 等 sleep 结束 → 自动收到「✅ 完成 · 后台任务 #xxxx」，正文含 done-F5。
5. 再发一个同款长任务，转后台后发「停 #新句柄」→ 收到停止确认；
   「进度」里它标「已停止」。
6.（可选）叫我重启 bridge 制造中断 → 你收到「任务被中断请重发」卡。

任何一步不符 = 验收不过，打回。

## 四、关键实现决策（已定，含理由）

1. **底座复用**：session-queue 已有「超时解锁不杀任务」半机制（默认关、只 log）。
   F5 在任务层做 `Promise.race(任务, 窗口)`，不动 queue 语义。
2. **停止语义 child 级化（雷区）**：现在 `stop(key)` 置 key 级 stopRequested + 杀全部
   children；转后台后用户对新任务发「停」→ 后台任务 close 时读到 key 级 flag 会被
   误标 stopped（reject 丢结果）。修法：stop 时给被杀 child 打 child 级标记，三个
   runner 的 close 判定改认 child 级（spawn 前拦截仍认 key 级）。
3. **完成路径提函数**：现在 await runTask 之后 ~100 行送达/捕获/记账内联；提成
   `deliverResult()`，前台路径与转后台的 detached continuation 共用——否则后台
   完成路径就是第二份手抄，必然漂移。
4. **落盘**：`<userRoot>/tasks-bg.jsonl` 追加事件（register/finish），用户树隐私域
   （与 traces 同域，不进 git 不出境）；启动扫描 running 未 finish → orphaned+推卡。
5. **句柄**：4 位 hex，用户内唯一即可；卡片/命令都用 `#xxxx`。
