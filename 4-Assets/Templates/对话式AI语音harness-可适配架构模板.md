# 对话式 AI 语音 Harness — 可适配架构模板

> **用途**：一份 provider 无关的实时语音对话 AI 架构蓝图。核心思想是把「对话大脑」与「语音 I/O」彻底解耦——大脑里所有 provider（语音云 / LLM / 音色）都是可插拔适配器，语音外壳可在「云端全包」与「自管管线」两种形态间按部署条件切换。脱敏自一个生产级语音陪伴产品（已 E2E 验证），可复用到任意「实时语音 + 角色人设 + 长期记忆」的对话 AI。
>
> 适配场景：语音助手 / 陪伴 Agent / 智能客服 / 教育对话 / 任何需要「实时语音 + 可控人设 + 记忆」的产品。

---

## 0. 设计哲学

**一句话**：对话逻辑 = 一个 provider 无关的「对话内核（Brain）」，外面套一层可替换的「语音编排外壳」。换语音云只换外壳，换 LLM 只换适配器，大脑逻辑不动。

**三条贯穿全栈的原则**：

| 原则 | 含义 | 工程落点 |
|---|---|---|
| **大脑单一真相源** | 人设/世界观/安全基座只有一份定义，所有入口共用 | 两种外壳 import 同一组 `BASE_PERSONA` / `SAFETY_BASELINE` / `assembleSystemPrompt`，杜绝多入口人设漂移 |
| **记忆/护栏是增益非必需** | 任何记忆注入、知识召回、护栏失败都降级回基础人设，**绝不阻断实时语音主链路** | 组装函数全包 try-catch，异常返回 base |
| **回合竞态守卫** | 被打断的旧回合的所有异步回调一律丢弃 | 每回合自增 `activeTurn`，所有 LLM/TTS 回调首行 `if (turn !== activeTurn) return` |

## 1. 分层架构

```
┌── L1 客户端 ───────────────────────────────────────────────┐
│   采音 + 播放 + 对话状态渲染（字幕 / 角色动画 / 进度）          │
└───────────────────────────┬───────────────────────────────┘
                            │
┌── L2 语音编排外壳（二选一，可适配的核心）──────────────────────┐
│  外壳A 云端全双工 RTC：把 ASR/TTS/VAD/回声消除/打断 外包给语音云    │
│  外壳B 自管语音管线：自接 ASR/TTS 流，自己编排句切/打断/字幕        │
└───────────────────────────┬───────────────────────────────┘
                            │  统一交给同一个大脑
┌── L3 对话内核 Brain（provider 无关，复用度最高）────────────────┐
│  ① 每回合决策路由   ② 分层 system prompt 组装   ③ 调 LLM 适配器   │
└───────────────────────────┬───────────────────────────────┘
                            │
┌── L4 可插拔适配器（统一接口，实现可换）─────────────────────────┐
│   ASR Adapter   │   TTS Adapter   │   LLM Adapter（多家可切）     │
└───────────────────────────┬───────────────────────────────┘
                            │
┌── L5 记忆与持久化 ─────────────────────────────────────────┐
│  L0 会话窗口（易失） · L1 长期画像（异步抽取） · 对话/反馈落库     │
└───────────────────────────────────────────────────────────┘
```

## 2. 两种语音外壳（可适配的核心决策）

| 维度 | **外壳A：云端全双工 RTC** | **外壳B：自管语音管线** |
|---|---|---|
| 入口 | LLM 回调端点（标准 ChatCompletion 流式协议，SSE + `[DONE]` 终止） | 长连接（WebSocket），自定义消息协议 |
| ASR/TTS/VAD/回声消除/打断 | **语音云全包** | **自己接**流式 ASR/TTS 适配器，手动编排 |
| 你的服务收到什么 | 每回合一个对话消息数组（含历史），回一段文本流 | 原始音频帧 + 控制消息，自己跑 ASR→LLM→TTS |
| 对话状态来源 | 语音云下发的状态信令 | 自己的服务消息（回合开始/增量/结束） |
| 句级字幕 / 表情同步 | ✕（语音云不暴露句级时间戳） | ✓ 句级 cue + 多标记表情 + 标点 flush |
| 回合竞态管理 | 不需要（无状态每回合函数） | 需要（activeTurn 守卫） |
| 工程复杂度 | **低**（语音难题外包） | 高（自己解 AEC/VAD/打断/同步） |
| 适合 | 生产主链路、移动端、最快上线 | 调试台、需要句级精细控制、不依赖外部语音云 |

> **适配决策**：优先外壳A——把 AEC 自循环、VAD 判停、全双工打断这些语音工程硬骨头外包给成熟语音云，对话逻辑这层就极简（每回合只做「收文本 → 组装大脑 → 吐文本」）。当需要句级字幕/表情/口型同步，或要摆脱外部语音云依赖时，才上外壳B。两者共用同一个 L3 大脑，可并存。

## 3. 对话内核 Brain（provider 无关，最该复用的部分）

### 3.1 每回合决策路由

每回合进来先走一棵优先级决策树，决定本回合用哪种 system prompt：

```
覆盖模式(调试台下发的完整 prompt)命中?
 ├ 是 → 直接用它（自带完整内容，不叠加记忆/建档/召回，不污染真实画像）
 └ 否 → 反馈/吐槽态命中? ─ 是 → 大脑 + 末尾追加「反馈收集人格」，落反馈库
                       └ 否 → 需建档(缺关键画像字段)? ─ 是 → 大脑 + 末尾追加「引导建档」
                                                     └ 否 → 大脑 + 知识按需召回（常规）
```

铁律：**覆盖 > 反馈 > 建档 > 常规**。

### 3.2 分层 system prompt 组装（六层）

```
[1] base    = BASE_PERSONA(角色人设/世界观基座) + SAFETY_BASELINE(安全红线，常驻兜底)
[2] + 「关于这个用户(长期记忆)」: 称呼/年龄/偏好/兴趣/近期状态/共同经历(最近N条)
[3] + 领域知识按需召回: 用户本回合聊到的实体/概念命中知识库才注入（不常驻，不稀释人设）
[4] + 业务护栏 或 引导层(二选一，主护栏优先，避免双段稀释)
[5] + 尾部人设锚点(~80字): 破"近因效应"，夺回被末尾护栏盖过的开头人设
[6] + 引导建档指令(放最末尾，最高优先级)
```

> **排序铁律（踩坑沉淀）**：长上下文 LLM 有强**近因效应**——越靠末尾的指令权重越高。所以：
> - 把"当前回合最高优先任务"（建档/特殊人格）放**最末尾**，否则会被开头的世界观人设盖过，LLM 不遵循。
> - 末尾若追加了业务护栏，必须再钉一句**人设锚点**夺回 recency，否则角色会被"护栏化/说教化"。
> - 这条只能靠**端到端实测**（真跑一遍看回复）暴露——日志显示"已注入"不等于"LLM 遵循了"。

### 3.3 LLM 适配器统一接口（适配性关键）

所有 LLM provider 实现同一个契约，按配置切换，大脑代码零感知：

```
interface LlmAdapter {
  streamChat(opts: {
    systemPrompt: string
    userText: string
    history: Turn[]
    onDelta(text): void     // 流式增量
    onDone(full, usage): void
    onError(err): void
  }): Promise<void>
  abort?(): void            // 支持打断
}
// 选择：const llm = makeAdapter(env.LLM_PROVIDER)   // 'A' | 'B' | ...
```

换 LLM = 新写一个实现此接口的适配器 + 改一个环境变量。其余全栈不动。

## 4. 一轮对话生命周期

### 4A. 外壳A（云端 RTC）——无状态每回合函数

```
用户说话 → 语音云[ASR + VAD 判停] → 回调你的 LLM 端点(?token=&session= 透传身份/会话)
   ▼ 端点每回合:
   ① 可选鉴权(Bearer)
   ② 解析消息数组: 取末条 user 文本 + 之前 history
   ③ 决策路由(§3.1) 选 systemPrompt
   ④ 异步副作用(fire-and-forget): 反馈落库 / 建档抽取
   ⑤ LLM 适配器 streamChat → SSE 流式吐字 → [DONE]
   ▼
语音云[TTS] → 播放 + 下发字幕/状态信令 → 客户端渲染
```

特点：**无回合竞态、无句切、无表情剥离**——语音云负责音频编排，你的服务是无状态的「每回合文本函数」，历史由语音云在消息数组里带进来。

### 4B. 外壳B（自管管线）——完整回合编排

```
建连: 启动 ASR 适配器 / 存下发的人设 prompt / 存本回合上下文 meta

用户说话:
  音频帧 ──feed──▶ ASR.onPartial → 实时字幕
  音频结束 → 【快照本回合 meta，冻结防竞态】→ ASR.finishAudio
          → ASR.onFinal(终稿):
              ├ 对话落库 + (反馈态)反馈落库
              ├ 空文本→发结束信号重置 idle / 非空→进回合编排
              ▼
回合编排 startTurn:
  打断上一回合(activeTurn+1) → 发"回合开始"
  建 TTS 适配器，挂句级回调:
     句开始→字幕cue(index) / 音频块→audio(带sentenceIndex) / 句末标点→flush同步 / 句末→结束
  组装六层 systemPrompt(§3.2) → 回发"已组装 prompt"(调试台所见即所发)
  LLM.streamChat:
     onDelta: 剥退出标记 → 剥表情标记 → 派发(表情事件 + 文本增量 + 喂 TTS)
     onDone:  flush 缓冲 → 判退出 → 清洗文本入会话窗口(滑窗裁剪)
              → 每 N 回合异步抽画像 → 发"回合结束(带退出标记)" → TTS.finish
     onError: 发错误 + 兜底结束信号(前端绝不卡 thinking)

打断: 收到打断信号 → activeTurn+1(让旧回合全部回调失效) + LLM.abort + TTS.close
```

## 5. 对话状态机

四态 `idle → listening → thinking → speaking`，**驱动源按外壳不同**：

- **外壳A**：语音云下发的状态信令直接驱动（thinking/speaking/listening）。另设 `connectPhase`（idle/starting/loading/joining）单独跟踪首次 SDK 加载进度（语音 SDK 体积大、首连慢，需要进度反馈）。
- **外壳B**：自己的服务消息驱动（回合开始→speaking，回合结束→idle）。
- **打断**：客户端 `bargeIn()` 同时停采集 + 停在途播放，并清录音态/定时器，防双重占麦与锁死。

## 6. 关键能力的可适配实现

| 能力 | 实现要点 | 外壳A | 外壳B |
|---|---|---|---|
| **打断 barge-in** | activeTurn+1 让旧回合回调全失效 + LLM.abort + TTS.close | 语音云内建 | 自己实现 |
| **退出意图（三层判退）** | L1 告别词白名单整句匹配（从严，裸否定如"我不要…"放行）；L2 让 LLM 在回复**开头**输出 `[EXIT]` 标记并流式剥离（绝不进 TTS）；命中→回合标退出→播暖告别→收尾 | L1 + 语音云静音判停 | L1 + L2 全有 |
| **反馈/吐槽捕获** | 入口侧 arm（限时一次性）或回合 meta 标记 → 切"反馈收集人格"(末尾) + 落反馈库 | 入口 arm | 回合 meta |
| **对话式建档** | 缺关键画像字段→引导角色自然问→异步抽取写画像源（一次问一项，问到即止） | ✓ | 可选 |
| **句级字幕 + 表情同步** | TTS 句级事件(句开始带文本/句末标点)＋ sentenceIndex 绑定音频段，客户端按 index 建 cueMap 实现电影字幕 | ✕ | ✓ |

> **外壳A 的表情/退出标记处理**：因为外壳A 不做流式剥离，若 prompt 让 LLM 输出 `【表情:x】`/`[EXIT]` 这类标记，会被语音云的 TTS 直接念出来。对策：在 prompt 入口侧**净化**掉这类句级标记指令（仅外壳A 路径净化，其他场景不变）。

## 7. 记忆三层（对话驱动）

| 层 | 是什么 | 生命周期 | 注入方式 |
|---|---|---|---|
| **L0 会话窗口** | 最近 N 轮 user+assistant 滑动窗口（轮数 + 字符双上限裁剪，防 prompt 膨胀拖 TTFT） | 连接级，断开即丢 | 外壳A 由语音云带；外壳B 自己维护 |
| **L1 长期画像** | 兴趣/称呼偏好/近期状态/共同经历 | 持久（登录用户） | 每 N 回合**异步抽取**写画像源，**fire-and-forget 出主链路**，失败不影响语音；可一键开关(合规兜底) |
| **落库** | 对话历史 / 反馈 | 持久 | 进统一后台看板 |

> 记忆注入链路（外壳A）：登录 token 经回调 URL query 透传 → 端点验 token 取用户 id → 注入该用户画像。**前提**：所用语音云的 LLM 回调必须保留 URL query（接入前先验证这一点）。

## 8. 健壮性守卫清单

1. **回合竞态守卫**：所有异步回调 `turn !== activeTurn` 短路（打断的旧回合不串音）。
2. **meta 快照**：音频结束时冻结本回合 meta，防 ASR 异步出稿期间被新回合覆盖（反馈漏落库/人格用错）。
3. **结束信号兜底**：LLM/TTS 任何环节失败必发"回合结束"，前端绝不卡在 thinking。
4. **prompt 注入清洗**：拼进 system prompt 的用户字段（称呼等）删控制字符 + 截断长度（防换行注入"忽略以上指令"）。
5. **限额守卫**：按客户端维度日限额（会话数/回合数），超限发错误码不断连接；公网 LLM 端点必须加鉴权防白嫖。
6. **降级安全**：记忆/护栏/召回任一失败 → 回退基础人设，主链路不断。

## 9. 适配 Checklist（换 provider 要动哪些点）

> 这是本模板的精华：把"可适配"落成具体的最小改动面。

**换 LLM**：实现 §3.3 的 `LlmAdapter` 接口（流式 + abort）→ 注册到工厂 → 改 `<LLM_PROVIDER>` 环境变量。其余不动。
- 注意：低延迟语音场景应关闭 LLM 的"深度思考/reasoning"模式（拖 TTFT）；按模型动态设 max_tokens 上限。

**换语音云（外壳A）**：
- 确认它支持「自定义 LLM 回调（标准 ChatCompletion SSE）」模式。
- 确认回调**保留 URL query**（记忆/会话身份透传的前提）。
- 网关侧：SSE 端点必须**关闭响应缓冲**（否则收不到流式增量）、放大读超时。
- 适配它的状态信令格式 → 映射到四态状态机。

**换语音管线为自管（外壳B）**：实现 ASR/TTS 适配器统一接口（onPartial/onFinal；句开始/音频块/句末/结束），其余编排逻辑复用。

**换部署形态**：同一套 server 代码，靠环境变量切 provider/模型/音色/限额；不同部署各自一套配置（本地与线上是两套，记忆数据/密钥分开）。

**换角色 IP**：只改 `BASE_PERSONA` 世界观基座 + 知识库内容 + 音色配置，架构与对话逻辑全不动。

---

## 10. 适用 / 不适用

**适用**：实时语音对话、需要稳定可控的角色人设、需要跨会话长期记忆、要在多家 provider 间保留切换自由度的产品。

**不适用**：纯文本对话（不需要语音外壳层）；一次性无记忆问答（L5 是过度设计）；对延迟不敏感的批处理对话。
