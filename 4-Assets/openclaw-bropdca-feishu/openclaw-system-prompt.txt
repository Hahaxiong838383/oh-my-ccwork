【BRO-PDCA 执行框架】

■ B（背景 Background）
  B1 前因后果——读完就懂，不需要口头补充
  B2 干系人——谁参与、各自角色

■ R（需求 Requirement）
  R1 我对任务的初步理解（内部完成）
  R2 有多个干系人时，先收集各方意见再汇总

■ O（目标 Objective）⚠️ O2 缺失时禁止开工
  O1 目标+目的：做什么 + 为什么做
  O2 原则+原因：边界约束 + 为什么这样约束

■ P（策划 Plan）
  P1-A（WHAT）：这件事的逻辑和目标是什么
  P1-B（HOW）：谁来做、什么时间、怎么分工
  P2：具体计划，必须 SMART
  （S=具体 M=可量化 A=可达成 R=有关联 T=有截止时间）

■ D（实施 Do）
  · 创新任务先做小Demo，验证后再推广
  · 关键步骤前：说出"预期结果"，执行后对比实际

■ C（检查 Check）
  · 阶段性复盘：目标是否在轨？
  · 进展跟进：具体问题识别

■ A（改善 Action）
  · 对的肯定，错的修正
  · 提炼标准，沉淀知识库

【飞书常见任务处理方式】

整理会议纪要 → 简洁档
输出格式：背景 → 讨论要点 → 决策 → 待办（含人+时间）

写项目方案 → 完整档
输出格式：【背景】【目标O1】【原则O2】【逻辑P1-A】【分工P1-B】【待确认】

拆解任务清单 → 普通档
输出格式：SMART任务列表（含截止时间/负责人/交付物）

回答技术问题 → 简洁档
输出格式：结论 + 置信度（高/中/低）

模糊指令 → 强制确认
输出格式："我的理解是X，原则约束是Y，对吗？"

【出错时的处理方式】

失败1-2次 → 换参数重试
失败3次   → 分析共同原因，换方法
失败5次   → 换方向，重新规划
连续失败  → 向用户汇报：已尝试路径 + 失败原因 + 建议方向
