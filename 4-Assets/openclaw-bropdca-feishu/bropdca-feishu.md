## 一、BRO 完整说明

### B — Background（背景）

**B1 事情背景**
- 详细陈述前因后果，标准：读完文字无需口头补充
- 明确"今天的讨论在整个计划的哪一步"
- 明确"需要解决什么问题"

**B2 干系人**
- 相关人员清单 + 每个人的角色/为什么需要参与
- 飞书场景：用 @mention 标注，关联任务角色（需求方/执行方/决策者）

**AI 执行规则**：
- B1 信息不足时，不直接猜测 — 先回一句"我理解的背景是 X，请确认"
- B2 有多个干系人且意见可能不一致时 → 升级为普通档/完整档

---

### R — Requirement（需求沟通）

**R1 发起方初步需求**
- 发起者草拟的初步目标 + 原则 + 背后逻辑
- 对于 AI：即我对任务的初步理解（在执行前内部完成）

**R2 团队沟通确认**（完整档必须）
- 收集各方观点 → 合并同类项 → 识别争议 → 达成共识
- 飞书工具：用多维表格收集意见（行=观点，列=目标/原则）

**R2 会议流程（飞书群使用）**：
1. 发起人发 R1 草稿（目标+原则+原因）
2. 各干系人 10 分钟内填写自己的观点
3. AI 汇总、合并同类项、标出争议点
4. 争议升级至 B2 中的决策者（直至 CEO）
5. 输出：最终 O1+O2 + 待办任务

---

### O — Objective（目标共识）

**O1 目标和目的**：做什么 + 为什么做
**O2 原则和原因**：怎么做的边界 + 为什么这样约束

**三层递进**：
```
目标（实）→ 保证大概结果（MBO 最低限度）
原则（虚）→ 保证过程中做正确、高效的模糊决策
目的/原因（底层逻辑）→ 保证执行人遇到新情况能做出最正确的选择
```

> 越靠近 CEO 的 OKR，越需要详细阐述目的和原因。

## 二、PDCA 完整说明

### P — Plan（策划）

**P1-A（WHAT，系统-知）**：
- 这件事的逻辑是什么，最终目标的具象化
- 形式：图谱、思维导图、矩阵分析、战略地图
- 飞书：用飞书白板 / 文档大纲 / 多维表格视图

**P1-B（HOW，统筹-行）**：
- 如何实现 P1-A，找谁协作，什么时间完成
- 形式：流程图、泳道图（时间×职责）
- 飞书：飞书项目 / 任务清单 + 分工表

**P1 详细程度原则**：P1 越详细 = 授权越明确 = 执行方越能自主推进

**P2（计划本身）**：
- 飞书场景：多维表格管理（含截止时间、负责人、交付物、完成标准）
- 必须 Be SMART，五项缺一不可

**探索温度策略**（AI 专属）：
| 档位 × 阶段 | 温度 | 策略 |
|------------|------|------|
| 简洁档（全程）| 🧊 低温 | 直接用已知最优方案 |
| 普通档 P 阶段 | 🌤️ 中温 | 列 2-3 个备选，快速评估选一 |
| 完整档 P 阶段 | 🔥 高温 | 广泛探索，多方案对比后收敛 |
| 完整档 D/C/A  | 🧊 低温 | 专注执行已选方案 |

---

### D — Do（实施）

- 创新任务优先 **Demo**（调动少量资源试点）
- 引用历史成功案例（飞书文档/同步块/链接）
- 按 P2 推进，交付 P2 里定义的交付物

**PP 协议（关键步骤必须）**：
```
[预期] 执行 <操作> 应得到 <预期结果>
[实际] <实际情况>
[惊讶度] 低/中/高
  低 → 继续
  中 → 微调，一句话说明
  高 → 暂停，先向用户报告
```

---

### C — Check（跟进复盘）

**大 CHECK（C1）**：季度/阶段性复盘
- P1 是否仍然最优？
- 整体目标是否在轨？
- 飞书：关联 OKR 多维表格，输出季度复盘文档

**小 check（C2）**：每周例会
- P2 进展跟进，识别具体问题
- 飞书：任务状态更新 + 例会纪要

---

### A — Action（改善更新）

- 对的加以肯定，错的明确修正
- 提炼工作标准，沉淀到飞书知识库
- 更新 O1/O2 → 进入下一轮 BRO-PDCA

## 三、8 大使用场景（飞书适配版）

| 场景 | 适用 | AI 行动 |
|------|------|---------|
| 1. 简洁模式（30%）| 明确任务直接安排 | 直接给 O1+O2+执行，不写 BRO 文档 |
| 2. 普通模式（30%）| 有背景但目标模糊 | B1+B2→O1+O2，确认后执行 |
| 3. 完整模式 A | 创新项目，经验不足 | B→R1→R2→O→PDCA 完整走 |
| 4. 完整模式 B | 创新项目，需统一共识 | B→R1→R2（争议升级决策者）→O→PDCA |
| 5. 会议模式 | 会议讨论场景 | 同场景 3 或 4，输出会议纪要 |
| 6. 个人完整模式 | 个人创新任务 | 自发走完整 BRO 流程 |
| 7. ~~复杂授权（已废弃）~~ | — | — |
| 8. 复杂授权模式 | 复杂任务下放 | 执行方写 R1，授权方确认 → O |

**飞书新增场景**：
- 群@问题答疑 → 简洁档，直接给有依据的答案 + 置信度标注
- 多人群任务分配 → 完整档 P1-B，输出泳道图分工表
- 周报/月报整理 → 普通档，BRO 结构归纳（背景→执行→结果→下一步）

## 四、BRO-PDCA 文化价值观（AI 理解版）

**包容**：遇到问题先从流程/系统归因，不急于找个人问题；为团队成员创造"安全感"

**创新**：鼓励暴露问题，积极解决问题；小 Demo 试错，快速迭代

**持续改善**：量变到质变，不追求一步到位；C+A 闭环缺一不可

**知行合一（You will never be ready）**：
在知中行，在行中知。方法论不是准备好了才用，是边用边学。

## 五、AI 增强协议（mycc 融合）

### 历史预演（普通档/完整档 P1 前必做）
1. 有无同类任务的历史记录？→ 复用成功路径，标记失败路径
2. 有无已知的坑？→ 提前规避
3. 该领域的历史摩擦频率？→ 高频域自动升档

### 惊讶度学习
- 每次"高惊讶度"事件，内部标记对应领域
- 同领域高惊讶度≥3次 → 该领域任务自动升档处理
- 连续2个对话零惊讶 → 可降档处理

### HOT 元认知自动触发
出现以下信号时**立即反思**，不等用户指出：
- 同任务内切换方案 ≥2 次
- 用户纠正（"不对/你搞错了"）
- 给出肯定答案但实际不确定
