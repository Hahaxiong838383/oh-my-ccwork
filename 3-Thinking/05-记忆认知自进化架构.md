│  │                 │  │            │  │                       │  │

│  │ 残差版本链       │  │ 认知框架     │  │ insights×evolution    │  │
│  │ 分层失真预算     │  │             │  │                       │  │
│  └────────────────┘  └────────────┘  └───────────────────────┘  │
│         ▲                                        │               │

- **记忆系统**负责"记住"和"召回"——数据的存、取、淘汰
- **认知沉淀**负责"提炼"——从实践中结晶出可复用方法论
- **自进化闭环**负责"变强"——自动发现问题、修复自己、验证效果

三者形成闭环：记忆提供行为数据 → 自进化发现摩擦 → 改进规则沉淀到认知/记忆 → 下一轮表现更好。

## 二、v4 记忆系统（TurboQuant 架构）

这是整个 mycc 认知内核的基石。当前版本是 **v4**，核心理论来自 TurboQuant (arXiv:2504.19874) 的信息论证明：压缩 4 倍时理论最优失真 ≈ 1/256（99.6% 信息可保留），关键启发是 **基础编码 + 残差修正优于完全替代**，以及 **每层压缩应有明确的失真预算**。

### 2.1 三层存储架构

灵感来源：memU 的 Resource → Item → Category 三层设计

```
层级            文件                     定位              保留周期    大小
──────────────────────────────────────────────────────────────────────
Resource 层   RECENT_EVENTS.md         24h 流水账         滚动 24h   ~32KB
Item 层       memory-items.md          原子事实库（核心）   90-120 天  ~50KB / 274 条
Category 层   MEMORY.md                高层索引指针        长期       轻量
──────────────────────────────────────────────────────────────────────
向量索引       memory-vectors.json      语义检索加速        与 Items 同步  ~1.7MB
```

#### Resource 层：RECENT_EVENTS.md

- 最近 24 小时的操作流水账，格式 `- \`HH:MM\` 事件描述`
- 每次 session 开始必读、结束时追加
- 注入时只取最后 15 行（`loadRecentEvents()` → `.slice(-15)`）
- 超 24h 的事件在清除前必须确认已提取为 Item（失真预算要求）

#### Item 层：memory-items.md（核心层）

这是整个记忆系统的心脏。274 条原子事实，按 20 个命名空间类别组织。

**双命名空间**（借鉴 OpenViking `viking://user/` + `viking://agent/`）：

| 命名空间 | 注入策略 | 示例类别 |
|---------|---------|---------|
| `[user/*]` — 跨项目通用 | **始终注入**，不受关键词过滤 | 偏好、方法论、全局规则、资产-GitHub |
| `[project/*]` — mycc 专属 | 按关键词/语义**匹配注入** | 技术-飞书、Bug-Fix、配置-mycc后端、路径-关键文件 |

**写入规范**：

| 规范 | 来源 | 规则 |
|------|------|------|
| 叶子原则 | OpenViking level=2 | 每条 = 一个独立事实，含"另外/此外"的必须拆分 |
| 时间戳 | MiroFish 时序记忆 | 行末 `[YYYY-MM-DD]`，超 60 天提示 `[可能过期]` |
| 优先级 | mem0 score 系统 | ★★★ 高频 / ★★ 中频 / ★ 低频 |
| 防污染 | deer-flow uploaded_files | 绝不写入临时 URL、一次性 token、调试命令 |
| 矛盾检测 | deer-flow factsToRemove | 新 Item 对比旧 Item，矛盾的直接删除 |

#### Category 层：MEMORY.md

纯索引，每行回答"这个主题还活着吗？去哪看？"。**不用于 context 注入**，防 context 污染。

### 2.2 混合语义检索引擎

核心代码：`context-loader.ts`（588 行）

这是 v4 最核心的算法——三层递进检索，每层成本递增、召回率递增：

```
用户消息
    │
    ├─── 第1层：关键词正则（O(13)，确定性）
    │    13 条 REGEX 规则，精确匹配端口/路径/命令
    │    如：/飞书|机器人|卡片|feishu/i → [project/技术-飞书]
    │
    ├─── 第2层：TF-IDF 模糊匹配（补盲区，最多 +2 类别）
    │    中英文分词 → TF 向量 → Cosine 相似度 > 0.05 入选
    │    v3→v4 升级：Jaccard→Cosine，对长短文本差异更鲁棒
    │
    └─── 第3层：向量语义检索（最深层，最多 +2 类别）
         Qwen3-Embedding-0.6B (512维) → 余弦相似度
         query embed → vectorSearch(topK=30) → 按类别聚合
         类别平均分 > 0.3 才通过
    │
    ▼
 三层去重合并
    │
    ▼
 综合评分：★权重 × 0.5 + 时间衰减 × 0.5
    │
    ▼
 resolveRelations()  ← 残差版本链处理（→Δ / →supersedes）
    │
    ▼
 MMR 去重（λ=0.7 偏重相关性 70% + 多样性 30%）
    │
    ▼
 每类别 Top 10 条，总计 ≤ 3000 字符
```

**级联降级链**：

```
向量搜索失败（Ollama 离线）
    → embed() 返回 null → vectorMatchCategories 返回 []
    → 只用关键词 + TF-IDF（降级到 v3 逻辑）
    → 都无匹配 → 只注入 user/* 类别（最低保障）
```

关键设计：`embed()` 用 10s 超时 + AbortController，失败静默返回 null，**绝不阻塞主流程**。

#### 向量化实现

核心代码：`embedding.ts`（193 行）

```
模型：Qwen3-Embedding-0.6B（Ollama 本地运行，Q4 约 395MB）
维度：512（MRL 裁剪，从默认 1024 截取 → 减半存储/计算）
索引：memory-vectors.json（JSON 格式，每条含 id/category/text/stars/vector）
重建：npx tsx src/scripts/rebuild-index.ts（逐条 embed，失败跳过不阻断）
缓存：_vectorIndexCache + _vectorIndexMtime（同 session 重复读取不触发 IO）
```

索引结构示例：
```json
{
  "model": "qwen3-embedding:0.6b",
  "dimensions": 512,
  "updated_at": "2026-03-27T17:33:00Z",
  "items": [
    {
      "id": "a1b2c3",
      "category": "project/技术-飞书",
      "text": "飞书签名算法 HMAC-SHA256 key=timestamp+newline+secret",
      "stars": 3,
      "vector": [0.123, 0.456, ...]
    }
  ]
}
```

### 2.3 残差版本链（v4 核心特性）

**问题**：v3 的 `→updates:关键词` 让旧 Item 的 score 归零，信息完全丢失。如果新 Item 后来被证明错误，旧版本无法恢复。

**解决方案**：借鉴 TurboQuant 的 `x̃ = Q_mse(x) + ||r|| · Q_qjl(r)`——基线 + 残差增量，替代完全替代。

#### 三个标记

| 标记 | 用途 | 检索行为 | 何时使用 |
|------|------|---------|---------|
| `#base` | 基线事实（低频变化） | 命中时自动拉取所有关联 →Δ | 首次写入 / Δ≥3 时重建 |
| `→Δ:基线关键词` | 增量修正（高频变化） | 命中时自动拉取其基线 | 第 2 次及后续变更 |
| `→supersedes:基线关键词` | 完全重写（核弹选项） | 旧基线 + 所有 Δ 的 score→0 | 基线本身已错误 |

#### 代码实现（resolveRelations 函数）

```typescript
function resolveRelations(items) {
  // 1. 收集所有 supersedes 关键词
  const supersededKeywords = items
    .map(i => i.line.match(/→supersedes:(.+?)(?:\s|\[|#|$)/))
    .filter(Boolean)
    .map(m => m[1].trim().toLowerCase())

  // 2. 应用抑制
  return items.map(item => {
    if (item.line.includes("→Δ:")) return item  // Δ 条目不被抑制
    for (const kw of supersededKeywords) {
      if (item.line.toLowerCase().includes(kw)) {
        return { ...item, score: 0 }  // 被 supersedes → 归零
      }
    }
    return item
  })
}
```

#### 实际示例

```markdown
## [project/路径-记忆系统]

- ★★★ cc-remote V4：阿里云香港 FRP 中转，域名 cli4.hahaxiong.cc [2026-03-15] #base #cc-remote
- ★★ Δ 修复 WebSocket 重连超时 [2026-03-20] →Δ:cc-remote-V4 #cc-remote
- ★★ Δ deploy-user.sh 改为两步写配置（先 HTTP 再 SSL）[2026-03-26] →Δ:cc-remote-V4 #cc-remote
```

检索命中 `#cc-remote` 任何一条时，三条一起返回，展示顺序：基线在前，Δ 按时间升序。

#### 基线重建规则

当同一基线的 Δ 堆叠 ≥3 条时，触发重建：
1. 合并所有 Δ 到新 `#base`
2. 清除旧基线和所有旧 Δ
3. 重新开始增量记录

### 2.4 双时间戳与时间衰减

灵感来源：Supermemory temporal grounding

每条 Item 支持两个日期：
```markdown
- ★★ 老板周四有产品评审 [2026-03-23] [event:2026-03-27]
                      ↑写入日期        ↑事件日期
```

**衰减函数**（代码实现）：

```
事件日期衰减（优先）：
  已过 >7 天   → 0.05（极低）
  已过 1-7 天  → 0.3（参考）
  未来 0-3 天  → 1.0（最相关）
  未来 3-14 天 → 0.8（高）
  更远未来     → 0.6

写入日期衰减（fallback）：
  ≤7 天  → 1.0
  7-30 天 → 线性衰减到 0.5
  30-60 天 → 继续衰减到 0.1
  >60 天  → 0.1
```

**综合评分**：
```
最终分 = ★权重 × 0.5 + 时间衰减 × 0.5
```

### 2.5 分层失真预算（v4 核心理论）

来自 TurboQuant 信息论保证：每层压缩的失真有理论下界 `D ≥ 4^{-b}`。mycc 据此为三层转换定义了可操作的质量标准：

#### Resource → Item（RECENT_EVENTS → memory-items）：保留 ≥95%

| 必须保留 | 允许丢弃 |
|---------|---------|
| 决策结论（做了什么、选了什么方案） | 时间修辞（"先…然后…最后"） |
| 关键参数（端口、路径、版本号） | 中间调试过程 |
| 因果关系（为什么这样做） | 情绪表达 |
| 失败教训（踩了什么坑） | 重复确认对话 |

**自检**："只看这条 Item，下次遇到同样场景能直接复用吗？" 不能 → 丢了关键信息。

#### Item → Category（memory-items → MEMORY.md）：保留 ≥80%

| 必须保留 | 允许丢弃 |
|---------|---------|
| 主题存在性（"有这个东西"） | 具体参数值 |
| 位置指针（"去哪里找"） | 实现细节 |
| 当前状态（运行中/已废弃） | 历史变更过程 |

**自检**："这一行能回答'还活着吗？详情去哪看？'" 不能 → 索引不合格。

#### 违反预算的信号

下次 session 问"上次那个 XXX 怎么配的"却找不到 → 说明 Resource→Item 丢了关键信息，需要补提取。

### 2.6 主动遗忘（Smart Forgetting）

灵感来源：Supermemory

每日 04:00 定时任务自动清理，清理的 Item 移到 `memory-archive.md`（可追溯，不丢失）：

| 规则 | 条件 | 动作 |
|------|------|------|
| 时效清理 | eventDate 过期 >7 天 | 删除 |
| 低频归档 | 写入 >90 天 且 ★<3 | 归档 |
| 强制归档 | 写入 >120 天 | 无条件归档 |

当前已稳定运行 5 天（2026-03-26 确认），memory-items 维持在 ~450 行无增长。

### 2.8 注入触发与 Context Budget

核心代码：`http-server.ts`（560-720 行）+ `chat-memory.ts`

#### 何时注入

```
飞书消息到达
    │
    ├─ 检查 session 是否存在
    │   ├─ 存在且未过期（30min TTL）→ 复用 session，不注入
    │   ├─ 存在但已过期 → onSessionEnd() 生成摘要 → 新建 session，注入
    │   └─ 不存在 → 新建 session，注入
    │
    └─ 仅新 session 时触发 buildCrossSessionContext()
```

**设计原理**：复用 session 时 Claude SDK 保持完整对话历史，再注入等于重复；新 session 需要从记忆恢复上下文。

#### Budget 分配

```
buildCrossSessionContext() 产出：

┌─────────────────────────────────┐
│  第1层：之前对话摘要    ≤800 字符  │ ← chat-memory/*.json
│  第2层：共享项目记忆    ≤800 字符  │ ← context-loader 混合检索
│  第3层：本对话原子事实  ≤400 字符  │ ← per-chat facts
├─────────────────────────────────┤
│  总计                 ≤2000 字符  │ ← 飞书 CLI 引擎轻量版
│  或                   ≤3000 字符  │ ← cc 自身完整版（含 RECENT_EVENTS）
└─────────────────────────────────┘
```

最终注入拼接：
```
message = crossSessionContext + contextPrefix + 用户消息
```

## 四、自进化闭环系统

cc 不只是执行工具，它能**自我诊断、自我修复、自我验证**。

### 4.1 PDCA 闭环

```
观察(Observe)
    │ task-log 摩擦数据 + insights 自动分析
    ▼
假设(Hypothesize)
    │ 新建 E-xx 改进项，标注假设根因
    ▼
改进(Improve)
    │ 三色标签授权 → 实施改进
    ▼
验证(Verify)
    │ 等待真实触发 → 有效则毕业，无效则关闭
    ▼
下一轮观察
```

### 4.2 双路信号交叉验证

**关键发现（2026-03-23）**：单靠内部自省信号密度远不够，必须两路交叉才能形成有效闭环。

| 信号源 | 驱动方式 | 产出 |
|--------|---------|------|
| **insights 摩擦提取**（外部审计） | 每 3 天 09:00 自动运行 | 客观摩擦数据：类别、频率、严重度 |
| **evolution 进化自查**（内部自省） | 每 3 天 09:30 自动运行 | 改进项状态更新、毕业判定 |
| **每日进化提取** | 每日 22:33 | 当天产出总结、补录新观察 |
| **主动遗忘** | 每日 04:00 | 清理过期 memory-items |

数据流：
```
task-log (摩擦标记: —/误诊/返工/超时/具体skill)
    ↓
insights 摩擦提取 (09:00) → 摩擦类别+频率
    ↓
进化自查 (09:30) → evolution-log E-xx 更新
    ↓
已毕业规则 → 沉淀到 CLAUDE.md / memory-items
    ↓
每日进化 (22:33) → 补录当天观察
    ↓
下一轮 insights (3天后)
```

## 六、设计哲学

### 灵感来源图谱

| 来源 | 借鉴了什么 | 在 mycc 中的实现 |
|------|-----------|----------------|
| **TurboQuant** (arXiv:2504.19874) | 基线+残差修正优于完全替代；分层失真有理论下界 | 残差版本链（#base + →Δ）；分层失真预算（95%/80%） |
| **memU** | Resource → Item → Category 三层记忆 | RECENT_EVENTS → memory-items → MEMORY.md |
| **mem0ai/mem0** (★48.9k) | score 评分系统 | ★★★/★★/★ 优先级标注 |
| **OpenViking** | 双空间隔离 + 叶子节点优先注入 | [user/*] / [project/*] 命名空间 + 叶子原则 |
| **OpenClaw** | 混合记忆系统 | 关键词 + TF-IDF + 向量三路检索 |
| **deer-flow** (★25k) | token 预算 + factsToRemove | ≤3000 字符上限 + 矛盾检测 |
| **Supermemory** | temporal grounding + smart forgetting | 双时间戳 + 每日 04:00 主动遗忘 |
| **MiroFish** | 时序记忆 | 时间戳规范 + 过期提示 |

### 五条核心原则

1. **够用就行，先跑起来再迭代** — v1→v2→v3→v4，每版只解决当时最痛的问题
2. **降级优先，永不阻塞** — 向量挂了回退关键词，文件缺失返回空，所有外部调用 fire-and-forget
3. **数据驱动进化** — 不靠直觉改系统，靠 task-log 摩擦数据 + insights 自动分析
4. **写入严格，注入克制** — 叶子原则控制写入质量，注入预算控制 context 成本
5. **每层都有自动化** — 从遗忘到检索到进化，不依赖人工维护（E02 毕业教训）
